## 1. Architectural Summary & Executive Findings

Prior to this audit, progressive disclosure was inconsistently implemented across the web frontend:
1. Only three components utilized any collapsible disclosure mechanism, and one of them (`AuthCardEditorDrawer.tsx`) had its disclosure inverted: mandatory identity fields were hidden inside a section titled "Optional & Advanced Settings" that defaulted to open on edits, while the Google OAuth Client JSON Importer sat outside in the primary flow.
2. Form fields across creation modals, project settings, admin studios, and flow analytics were laid out linearly without hierarchy, overwhelming new users with technical configuration (WIP limits, regex validation, CIDR masks, session TTLs, and Monte Carlo sample sizes) on screens intended for routine tasks.
3. Hidden configuration states had no outward visual indication: when an accordion was collapsed, users and administrators had no way of knowing whether non-default settings were silently active inside.

To solve this systematically, a shared accessible `<AdvancedSection>` component has been built:
- **Default State:** Collapsed (`defaultOpen={false}`) on both create and edit views.
- **Active Overrides Indicator:** Renders an accent badge (e.g. `2 custom settings active`) when collapsed if any setting differs from its baseline default, preventing hidden-state confusion.
- **Auto-Expansion on Error:** Automatically expands if any child input fails validation (`hasErrors={true}`), immediately exposing the invalid control.
- **Accessibility & Zero Inline Styles:** Full keyboard navigation (`Enter` / `Space`), `aria-expanded` synchronization, zero layout shift, and 100% semantic CSS tokens.
