### User Story
As an **AI/workflow engineer authoring and debugging transition interceptors**, I need **`uv run kanban-agent validate-transition` to run the exact production context builder, secret scrubber, repo/MCP toolkits, and verdict parser from the terminal across all 3 harnesses (`in_app_sdk`, `cli_pipe`, `remote_runner`) against either live tools/providers or deterministic fixture cassettes** so that **I can verify stdin spotlighting, read-only repo tool calls, latency, and `kb-transition-verdict/v1` schema compliance locally without clicking through the browser UI**.

**Requirement Traceability:** `S15.3` example 1 (`--agent-config`, `--ticket-file`, `--repo-path`, `--from-state`, `--to-state`, `--print-stdin-context`, `--verbose-tools`, report sections 1-4, exit codes `0`/`2`), `S14.2` (3 harnesses), `S14.3` (`kb-transition-context/v1`, `kb-transition-verdict/v1`), `S15.2` (`FixtureLLMProvider` & `FixtureCLIRunner` cassettes) | Original requirement `#2` | **Dependencies:** `KB-P5-20`, `KB-P5-21`, `KB-P5-22a`, `KB-P5-22b`, `KB-P0-13`

   - `agent/GEMINI.md` (update CLI documentation)
2. **Exact CLI Flags (`S15.3` Example 1 + Fixture Parity with `KB-P5-10`):**
   - `--agent-config PATH` (required: YAML/JSON matching `AgentDefinition` fields `slug`, `harness_kind`, `provider_kind`, `model_id`, `cli_binary_allowlist_id`, `cli_args`, `remote_runner_pool_slug`, `repo_access_mode`, `mcp_allowed_tools`, `system_instructions_md`, `timeout_ms`, plus `allowed_mutable_fields: list[str]`)
   - `--ticket-file PATH` (required: YAML/JSON with `project`, `key`, `summary`, `priority`, `labels`, `description_markdown`, `actor`)
   - `--repo-path PATH` (optional; required when `repo_access_mode != "none"`; accepts either a bare `.git` directory or a local Git checkout whose `.git` object database is read strictly read-only without mutating the working tree)
   - `--head-ref TEXT` (default `"HEAD"`; resolved to 40/64-hex commit SHA)
   - `--from-state TEXT` (required, e.g. `"In Review"`)
   - `--to-state TEXT` (required, e.g. `"Done"`)
   - `--print-stdin-context` (boolean flag: prints full scrubbed `kb-transition-context/v1` YAML in section 1; when omitted, prints summary header + delimiter + redaction count)
   - `--verbose-tools` (boolean flag: prints per-tool arguments, latency, byte count, and truncated output preview)
   - `--provider {ollama,gemini,openai,fixture}` (optional override; defaults to `agent-config` `provider_kind`)
   - `--cassette PATH` (for `FixtureLLMProvider` or `FixtureCLIRunner` replay; forbidden when running live provider/CLI without fixture mode)
   - `--http-cassette PATH` (optional HTTP transport replay from `KB-P5-01`)
   - `--mcp-fixture PATH` (optional YAML mapping canned read-only MCP tool responses for offline runs when no `--database-url` / live MCP server is provided)
   - `--remote-loopback` (for `harness_kind: remote_runner` local validation: spins up an in-process TLS 1.3 mTLS `RunnerWssHub` + `RunnerDaemon` pair from `KB-P5-22a`/`KB-P5-22b` against `--repo-path` so the full WSS wire protocol is exercised locally)
   - `--report {text,json}` (default `"text"`; JSON validates against `kb-validate-transition-report/v1`, `additionalProperties: false`)
3. **Pipeline Execution (Zero Duplicate Logic):**
   - Validates `cli_args` via `assert_runtime_argv` (`KB-P5-16`) up front -> policy failure exits `2` (`BANNED_CLI_FLAG` / `CODEX_SANDBOX_OVERRIDE`).
   - Calls `build_transition_context()` (`KB-P5-19a`), applying `KB-P2-17` `outbound_secret_scrubber` and generating random `delimiter` and `verdict_nonce`. Never prints raw `ephemeral_token` bytes (`<ephemeral-redacted>` shown).
   - Dispatches to `InAppSdkHarness` (`KB-P5-20`), `CliPipeHarness` (`KB-P5-21`), or `RemoteRunnerHarness` (`KB-P5-22a` + `--remote-loopback` `KB-P5-22b`).
   - Parses returned bytes through `parse_verdict_output()` (`KB-P5-19a`) and checks `field_updates` against `allowed_mutable_fields` and `MUTABLE_FIELD_UNIVERSE` (`KB-P5-17a`).
4. **4 Mandatory S15.3 Report Sections & Exit Codes:**
   - **(1) Scrubbed Rendered Context:** `kb-transition-context/v1` YAML (full when `--print-stdin-context`), secret redaction count, `delimiter`, `head_commit`.
   - **(2) `:ro` Repo & MCP Tool Trace:** ordered list of every `repo_*` and MCP read tool invocation (`tool`, `args`, `duration_ms`, `status`, `bytes`).
   - **(3) Latency & Token Telemetry:** `ttft_ms` (where applicable), `total_wall_ms`, `input_tokens`, `output_tokens`, harness kind.
   - **(4) Verdict Schema & Policy Validation:** `status` (`valid` or error code `VERDICT_MALFORMED`, `VERDICT_NONCE_MISMATCH`, `VERDICT_FIELD_NOT_ALLOWED`, `BANNED_CLI_FLAG`, etc.), `decision` (`approve` | `reject`), `verdict_sha256` hex, `forged_candidates`.
   - **Exit Codes:** `0` when the returned verdict is schema-valid AND policy-compliant (both `decision: "approve"` and valid `decision: "reject"` exit `0` because the interceptor functioned validly per S15.3; optional `--require-approve` flag exits `2` on `reject` for CI gate scripts); `2` on schema/policy violation (`VERDICT_*`, `BANNED_CLI_FLAG`, `CODEX_SANDBOX_OVERRIDE`, `TOOL_NOT_PERMITTED`, `REPO_SECRET_PATH_DENIED`); `1` on runtime failure (missing file, git repo unreadable, provider network error).
