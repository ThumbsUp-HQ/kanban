### User Story
As a **security architect**, I need **a unified `principals` table, `users` and `groups` subtype tables, membership edges, and a trigger-maintained `principal_group_closure` that rejects cycles and nesting deeper than 8** so that **nested LDAP/OIDC groups resolve in one indexed join and no membership graph can loop or explode access computation**.

**Requirement Traceability:** `S3.1`, Requirement `#1` (clear security / shared-with), `#13d` (`user` object class) | **Dependencies:** `KB-P1-02`

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/p1_03_principals.py`
   - `database/migrations/sql/p1_03_principals.up.sql`, `database/migrations/sql/p1_03_principals.down.sql`
2. **DDL (S3.1 core columns verbatim: `id`, `principal_type`, `workspace_id`, `status`):**
   ```sql
   CREATE TABLE principals (
       id              UUID PRIMARY KEY DEFAULT uuidv7(),
       principal_type  TEXT NOT NULL CHECK (principal_type IN
                         ('USER','GROUP','AGENT','SCRIPT_EPHEMERAL','SERVICE_PRINCIPAL')),
       workspace_id    UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       status          TEXT NOT NULL DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE','DISABLED')),
       display_name    TEXT NOT NULL CHECK (char_length(btrim(display_name)) BETWEEN 1 AND 200),
       created_at      TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       UNIQUE (id, principal_type)
   );
   CREATE TABLE users (
       id              UUID PRIMARY KEY,
       object_type     object_kind NOT NULL DEFAULT 'user' CHECK (object_type = 'user'),
       principal_type  TEXT NOT NULL DEFAULT 'USER' CHECK (principal_type = 'USER'),
       workspace_id    UUID NOT NULL,
       email           TEXT NOT NULL CHECK (char_length(email) BETWEEN 3 AND 320 AND email ~ '^[^@\s]+@[^@\s]+$'),
       FOREIGN KEY (id, principal_type) REFERENCES principals (id, principal_type) ON DELETE RESTRICT,
       FOREIGN KEY (id, object_type)    REFERENCES objects (id, object_type)       ON DELETE RESTRICT
   );
   CREATE UNIQUE INDEX users_ws_email_uq ON users (workspace_id, lower(email));
   CREATE TABLE groups (
       id              UUID PRIMARY KEY,
       principal_type  TEXT NOT NULL DEFAULT 'GROUP' CHECK (principal_type = 'GROUP'),
       workspace_id    UUID NOT NULL,
       name            TEXT NOT NULL CHECK (char_length(btrim(name)) BETWEEN 1 AND 200),
       external_source TEXT CHECK (external_source IN ('LDAP','OIDC')),
       external_id     TEXT CHECK (external_id IS NULL OR char_length(external_id) <= 1024),
       UNIQUE (workspace_id, name),
       FOREIGN KEY (id, principal_type) REFERENCES principals (id, principal_type) ON DELETE RESTRICT
   );
   CREATE TABLE principal_group_edges (
       member_id     UUID NOT NULL REFERENCES principals(id) ON DELETE RESTRICT,
       group_id      UUID NOT NULL REFERENCES groups(id)     ON DELETE RESTRICT,
       workspace_id  UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       created_at    TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       PRIMARY KEY (member_id, group_id),
       CHECK (member_id <> group_id)
   );
   CREATE TABLE principal_group_closure (
       member_id          UUID NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
       ancestor_group_id  UUID NOT NULL REFERENCES groups(id)     ON DELETE CASCADE,
       workspace_id       UUID NOT NULL,
       depth              SMALLINT NOT NULL CHECK (depth BETWEEN 1 AND 8),  -- shortest path length
       PRIMARY KEY (member_id, ancestor_group_id)
   );
   CREATE INDEX pgc_ancestor_idx ON principal_group_closure (ancestor_group_id, member_id);
   ```
   - Trigger `users_workspace_match_biu` / `groups_workspace_match_biu`: `NEW.workspace_id` must equal `principals.workspace_id` and (users) `objects.workspace_id` -> else `PRINCIPAL_WORKSPACE_MISMATCH`.
3. **Closure maintenance (`principal_group_edges_closure_aiud`, AFTER INSERT OR UPDATE OR DELETE, FOR EACH ROW, function `rebuild_group_closure(p_workspace_id uuid)` SECURITY DEFINER):**
   - Serialize per workspace: `PERFORM pg_advisory_xact_lock(hashtextextended('group_closure:' || p_workspace_id::text, 0));`.
   - BEFORE INSERT/UPDATE guard `principal_group_edges_guard_biu`: member and group must share `NEW.workspace_id` (else `GROUP_EDGE_WORKSPACE_MISMATCH`); if `member_id` is a GROUP and (`NEW.group_id = NEW.member_id` OR `EXISTS (closure row member_id = NEW.group_id AND ancestor_group_id = NEW.member_id)`) -> `GROUP_CYCLE_REJECTED`.
   - Rebuild: recursive CTE over edges for the workspace with `CYCLE member_id SET is_cycle USING path` clause; if any path reaches length `> 8` -> `GROUP_DEPTH_EXCEEDED` (whole statement aborts, edge not persisted); otherwise `DELETE` + `INSERT` closure rows for the workspace with `depth = min(path_length)`.
   - Performance budget: rebuild for a workspace with 500 edges completes in `< 50ms` on the tmpfs test DB (asserted with a generous `< 500ms` test bound to avoid CI flakiness).
4. `REVOKE INSERT, UPDATE, DELETE ON principal_group_closure FROM kanban_app;` (derived table, writable only via the definer function).
5. **Down migration:** drops triggers, functions, then `principal_group_closure`, `principal_group_edges`, `groups`, `users`, `principals`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_03_principals.py`, `database/tests/migrations/test_p1_03_migration.py`
- **Required Test Cases:**
  1. Positive (nested resolution): user U in G1, G1 in G2, G2 in G3 -> closure has `(U,G1,1)`, `(U,G2,2)`, `(U,G3,3)`, `(G1,G2,1)`, `(G1,G3,2)`, `(G2,G3,1)`.
  2. Positive (diamond): U in G1 and G2, both in G3 -> exactly one `(U,G3)` row with `depth = 2`.
  3. Positive (removal): deleting edge `G1->G2` removes `(U,G2)` and `(U,G3)` rows in the same statement.
  4. Negative (cycle): with G1 in G2, inserting `G2 -> G1` raises `GROUP_CYCLE_REJECTED`; self-edge `G1 -> G1` raises `23514`.
  5. Negative (depth): chain of 8 nested groups below U is accepted; adding a 9th level raises `GROUP_DEPTH_EXCEEDED` and the edge row does not exist afterwards.
  6. Negative/security: edge between principals of two workspaces raises `GROUP_EDGE_WORKSPACE_MISMATCH`; as `kanban_app`, `INSERT INTO principal_group_closure` raises `42501`.
  7. Boundary: `principal_type='ROBOT'` raises `23514`; duplicate `lower(email)` in one workspace raises `23505`; email of 321 chars rejected.
  8. Migration up/down: upgrade `p1_03_principals` -> 5 tables exist; downgrade to `previous_of(...)` -> all 5 absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
