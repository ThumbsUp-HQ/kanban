### User Story
As an **AI/LLM systems engineer operating an air-gapped deployment**, I need **an `OllamaProvider` that implements the `LLMProvider` protocol over `httpx.AsyncClient` and refuses to connect to any address outside the admin-pinned `allowed_ollama_cidrs` (checked after DNS resolution, before connect)** so that **local FIM, chat and embedding workloads run 100% offline without becoming an SSRF primitive against `169.254.169.254` or other internal services**.

**Requirement Traceability:** `S10.1 (OllamaProvider row)`, `S10.2 (air_gap_mode egress restricted to approved Ollama CIDRs)`, `S15.2 (cassettes + fault injection)`, `S15.3 (CLI validation)`, original requirement `#2` | **Dependencies:** `KB-P0-12`, `KB-P0-13`

### Scoped Technical Actions
1. **Target Files:**
   - `agent/providers/ollama.py` (new)
   - `agent/providers/net_guard.py` (new - shared resolve-then-check helper reused by KB-P5-04)
   - `agent/providers/registry.py` (new - `build_provider(kind, settings, *, transport=None)` factory used by the CLI and later by the router)
   - `agent/testing/http_cassette.py` (new - `CassetteTransport(httpx.AsyncBaseTransport)`)
   - `agent/testing/cassette.schema.json` (modify the KB-P0-12 cassette JSON Schema: add optional `http_exchanges` block, keep `cassette_version: 1` backward compatible)
   - `agent/cli.py` (modify: add common flag `--http-cassette PATH` that wires `CassetteTransport` into the selected provider; register `ollama` in the provider choices)
   - `agent/GEMINI.md` (update: provider list, failure modes, network contract)
2. **`OllamaSettings` (Pydantic v2, `frozen=True`, `extra="forbid"`):** `base_url: HttpUrl` (scheme `http` or `https`; reject userinfo, query, fragment), `allowed_ollama_cidrs: tuple[IPv4Network | IPv6Network, ...]` (min length 1, no default - empty is a config error), `model_allowlist: tuple[str, ...]` (min length 1), `keep_alive: str = "30m"`, `connect_timeout_s: float = 2.0` (bounds `0.1..10`), `read_timeout_s: float = 30.0` (bounds `1..300`), `mtls_client_cert_path: Path | None`, `mtls_client_key_path: Path | None` (both or neither), `ca_bundle_path: Path | None`.
3. **`net_guard.resolve_and_pin(host, port, allowed_cidrs, *, resolver) -> IPAddress`:**
   - Resolve via an injected `Resolver` protocol (default: `asyncio.get_running_loop().getaddrinfo`). Unit tests inject a fake resolver; zero real DNS.
   - EVERY resolved address must be inside at least one allowed CIDR; if ANY resolved address is outside, raise `EgressDenied(code="OLLAMA_CIDR_DENIED")` (defeats multi-A-record rebinding).
   - Hard deny list applied even if an admin allowlists it: `169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254/128`, `0.0.0.0/8`, `::/128`, `224.0.0.0/4`, `ff00::/8`, and IPv4-mapped forms (`::ffff:169.254.0.0/112`). Raise `EgressDenied(code="OLLAMA_METADATA_DENIED")`.
   - Return the first approved address; the provider connects to that literal IP, sends the original `Host` header, and sets `extensions={"sni_hostname": host}` for TLS. Resolution happens once per request (no cached IP reused past one request).
4. **`OllamaProvider` implementing `LLMProvider` (from KB-P0-12):**
   - `stream_complete(req)` -> `POST /api/generate` with `{"model", "prompt", "suffix" (FIM), "stream": true, "keep_alive", "options": {"temperature", "num_predict"}}`; parse NDJSON lines; each line capped at `64 KiB`, total stream capped at `8 MiB`; yields typed `StreamChunk` objects; emits typed `ProviderTimeout`/`ProviderHTTPError(status)`/`ProviderProtocolError` exceptions (no raw `httpx` exceptions leak).
   - `generate_structured(req)` -> `POST /api/chat` with `"format": <JSON Schema>` and `"stream": false`; parse `message.content` as JSON and validate against the request's Pydantic model; invalid JSON or schema mismatch -> `ProviderSchemaError`.
   - `embed_batch(req)` -> `POST /api/embed` with `{"model", "input": [...]}`; batch size `<= 64` inputs, each `<= 8,192` chars; returns `list[list[float]]`; dimension mismatch across rows -> `ProviderProtocolError`.
   - `health_probe()` -> `GET /api/tags`, returns `HealthStatus(ok, latency_ms, models)`; never raises.
   - Model not in `model_allowlist` -> `ProviderPolicyError(code="MODEL_NOT_ALLOWED")` before any socket work.
   - Client constructed with `follow_redirects=False`, `trust_env=False` (ignore `HTTP(S)_PROXY` env), `max_redirects=0`, `httpx.Timeout(connect=connect_timeout_s, read=read_timeout_s, write=5.0, pool=2.0)`, `verify=ca_bundle_path or True`, `cert=(cert, key)` when mTLS is configured. Any 3xx response -> `ProviderProtocolError(code="REDIRECT_REFUSED")`.
   - Request/response bodies are never logged; logs contain only model id, byte counts, status and latency.
5. **`CassetteTransport`:** replays `http_exchanges` entries from a cassette YAML (`request: {method, path, json_contains}`, `response: {status, headers, ndjson_chunks | sse_chunks | json_body}`, `fault: http_429 | http_500 | timeout | connect_error | malformed_body | oversize_line`) in order; an unmatched request raises `CassetteMismatch` (test fails loudly). Lives under `agent/testing/` so it ships with the fixture system from KB-P0-12.

### Mandatory Feature Unit Tests
- **Test File(s):** `agent/tests/providers/test_ollama.py`, `agent/tests/providers/test_net_guard.py`, `agent/tests/testing/test_http_cassette.py`
- **Cassettes (new, under `tests/fixtures/ai/`):** `ollama_fim_stream_ok.yaml`, `ollama_chat_structured_ok.yaml`, `ollama_chat_structured_invalid_json.yaml`, `ollama_embed_ok.yaml`, `ollama_fault_429.yaml`, `ollama_fault_500.yaml`, `ollama_fault_timeout.yaml`, `ollama_fault_redirect_302.yaml`, `ollama_fault_oversize_line.yaml`
- **Required Test Cases:**
  1. Positive: FIM stream from `ollama_fim_stream_ok.yaml` yields the exact chunk sequence; request body contains `suffix`, `keep_alive`, `temperature`.
  2. Positive: `generate_structured` returns a validated Pydantic object; `embed_batch` returns equal-length vectors.
  3. Contract parity: the same scenario replayed through `FixtureLLMProvider` (KB-P0-12 cassette) and through `OllamaProvider` + `CassetteTransport` produces equal typed outputs.
  4. Security: resolver returning `169.254.169.254` -> `OLLAMA_METADATA_DENIED`, transport never invoked (assert call count `0`).
  5. Security: resolver returning `[10.0.0.5, 8.8.8.8]` with allowlist `10.0.0.0/8` -> `OLLAMA_CIDR_DENIED` (multi-record rebinding).
  6. Security: IPv4-mapped IPv6 `::ffff:169.254.169.254` -> denied.
  7. Security: 302 response -> `REDIRECT_REFUSED`; `HTTPS_PROXY` set in env is ignored (`trust_env=False` asserted).
  8. Security: model not in allowlist -> `MODEL_NOT_ALLOWED` with zero resolver calls.
  9. Fault injection: `429`, `500`, timeout and malformed NDJSON map to `ProviderHTTPError(429)`, `ProviderHTTPError(500)`, `ProviderTimeout`, `ProviderProtocolError`.
  10. Boundary: NDJSON line of `64 KiB + 1` bytes -> `ProviderProtocolError(code="LINE_TOO_LARGE")`; embed batch of `65` -> `ValueError` before network.
  11. Boundary: settings validation rejects empty `allowed_ollama_cidrs`, base URL with userinfo, cert without key.
  12. `health_probe` returns `ok=False` on connect error without raising.
- **Coverage:** `>= 95%` line + branch for `agent/providers/ollama.py`, `agent/providers/net_guard.py`, `agent/providers/registry.py`, `agent/testing/http_cassette.py`. Tests run under `pytest-socket` `--disable-socket --allow-unix-socket`.
