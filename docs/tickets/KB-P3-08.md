### User Story
As a **project member**, I need **a single endpoint that clones an issue (optionally its readable sub-issue tree and attachments, optionally linked back as `RELATES_TO`) with me as creator** so that **templated work can be duplicated without copying anything I am not allowed to read**.

**Requirement Traceability:** Spec S7.2 `8n`; requirement `#8n` | **Dependencies:** `KB-P3-07`, `KB-P2-15`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/issue_copy.py`, `kanban/api/v1/schemas/issue_copy.py`, `kanban/services/issue_copy.py`, `kanban/services/activity.py` (append event).
2. **Endpoint:** `POST /api/v1/issues/{issue_ref}/copy`
   - Capability: `VIEW` on source issue and `EDIT` on the source project. Unreadable source returns `404`; readable without project `EDIT` returns `403 INSUFFICIENT_CAPABILITY`.
   - Request (all default `false`): `{"include_sub_issues": false, "include_attachments": false, "link_as_relates_to": false}`. Unknown keys `422`.
   - Cloned fields (S7.2 `8n`): `summary` prefixed `"[Copy] "` then truncated to `500` chars; `description_markdown` (re-normalized via KB-P2-13); `priority_id`; labels; modules (only when `modules_enabled = TRUE`). Custom field inputs are out of scope until Phase 5 (state this in a code comment and in `message-to-reality-checker.md`). Not copied: assignees, cycle, dates, parent, comments, subscriptions, activity, links (other than the optional new `RELATES_TO`).
   - New issue: fresh `sequence_id` (KB-P1-05), project default state, `created_by_id = original_created_by_id = caller`, initial `board_rank` per KB-P3-02 rule.
   - `include_sub_issues`: copies the readable descendant subtree (preserving structure via `parent_issue_id`) up to depth `6`; unreadable descendants and their subtrees are skipped and counted; more than `200` readable issues in total returns `422 COPY_TOO_LARGE` before any write.
   - `include_attachments`: duplicates readable attachment metadata rows from KB-P2-15 pointing at the same immutable stored blob (no byte re-upload); attachments of skipped issues are not copied.
   - `link_as_relates_to`: creates `object_links(copy -> original, 'RELATES_TO')` via the KB-P3-07 service (top-level copy only).
   - Entire operation runs in one transaction; any failure rolls back all copies.
   - Response `201` + `Location` of the top-level copy:
     ```json
     {"issue": {"key": "KAN-150", "summary": "[Copy] Harden OIDC", "...": "..."},
      "copied_sub_issues": [{"source_key": "KAN-143", "copy_key": "KAN-151"}],
      "skipped": {"restricted_sub_issues": 1}, "copied_attachments": 2, "link_id": null}
     ```
     `skipped.restricted_sub_issues` is a count only (no keys).
3. **Activity events emitted (category `HISTORY`):** `ISSUE_CREATED {key, copied_from: <source issue id>}` on every new copy; `ISSUE_COPIED {copy_id, copy_key, include_sub_issues, include_attachments}` on the source issue; `LINK_CREATED` (two rows, via KB-P3-07) when `link_as_relates_to`.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_issue_copy.py`
- **Required Test Cases:**
  1. Positive: copy with defaults returns `201`, summary `"[Copy] <orig>"`, same description sha256, same priority/labels, `created_by_id == caller`, no assignees, no cycle; `ISSUE_CREATED` with `copied_from` and `ISSUE_COPIED` rows exist.
  2. Security: sub-issue tree where one child lives under an explicit `DENY` for the caller: copy skips it, `skipped.restricted_sub_issues == 1`, and no response field contains the skipped key.
  3. Boundary: 500-char summary copy is truncated to exactly 500 chars; a 201-issue readable tree returns `422 COPY_TOO_LARGE` with zero new rows; depth-6 tree copies with correct parent structure.
  4. Options: `link_as_relates_to` creates one `RELATES_TO` link; `include_attachments` copies only readable attachment rows referencing the same blob hash; modules are not copied when target project has `modules_enabled=false`.
  5. Atomicity: inject a failure on the third sub-issue insert; assert zero copies and zero activity rows persist.
  6. Auth: non-viewer `404`; viewer without project `EDIT` `403`.
- Clean-DB `SAVEPOINT` harness. Coverage `>= 95%`.
