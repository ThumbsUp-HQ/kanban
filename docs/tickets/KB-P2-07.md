### User Story
As a **workspace user authenticating against an enterprise Active Directory or OpenLDAP directory**, I need **an LDAPS / StartTLS authentication card that negotiates TLS 1.2+ strictly prior to any LDAP bind (`TLS_HARD`), verifies custom CA PEM roots and optional SPKI SHA-256 public-key pins, escapes all filter assertions per RFC 4515, verifies my password via an ephemeral bind without storing or logging it, and synchronizes mapped group DNs into workspace groups** so that **cleartext credential leakage, rogue-CA MITM, LDAP filter injection, password retention, and stale group entitlements are prevented**.

**Requirement Traceability:** `S4.2` item 2 (`ldaps://` TLS 1.2+ or `ldap://` + `StartTLS` prior to bind `TLS_HARD`, custom CA PEM / SPKI SHA-256 pin, RFC 4515 escaping `\2a`, `\28`, `\29`, `\5c`, `\00`, ephemeral user-bind password verification), `S4.1` (`auth_provider_cards`), `S3.1` (`groups`, `principal_group_edges`), `S2.5` (permissive license matrix; `ldap3` LGPL-3.0 banned), requirement `#6` | **Dependencies:** `KB-P2-03` (`kb_auth` card storage + envelope), `KB-P2-02` (sessions + CSRF), `KB-P2-06` (`ExternalIdentityAssertion` + `IdentityResolver` protocol in `kanban/auth/identity.py`), `KB-P2-18` (rate limiter `AUTH_LOGIN_IP` / `AUTH_LOGIN_ACCOUNT`)

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/auth/ldap/__init__.py`, `kanban/auth/ldap/config.py`, `kanban/auth/ldap/escape.py`, `kanban/auth/ldap/protocol.py`, `kanban/auth/ldap/group_sync.py`, `kanban/auth/ldap/service.py`
   - `kanban/api/v1/auth_ldap.py` (`POST /api/v1/auth/ldap/{slug}/login` and alias `POST /api/v1/auth/cards/{slug}/ldap-login`)
   - `kanban/tests/fixtures/fake_ldap.py` (in-memory TLS/StartTLS LDAPv3 test server over `ssl.MemoryBIO` / `asyncio` stream pair, compatible with `pytest-socket --disable-socket`)
   - `kanban/pyproject.toml` (add pinned `pyasn1`, `BSD-2-Clause`; avoids `ldap3` `LGPL-3.0` denylist violation and avoids C `libldap` binaries absent from `runtime-slim`)
2. **Card `public_config` schema (`config.py`, Pydantic v2, `extra="forbid"`):**
   - `kind: Literal["LDAP"]`, `url: str` matching `^(ldaps|ldap)://[A-Za-z0-9.-]+(:[0-9]{1,5})?$` (hosts resolving to loopback `127.0.0.0/8` / `::1` or link-local `169.254.0.0/16` / `fe80::/10` rejected unless `KANBAN_AUTH_EGRESS_ALLOW_PRIVATE=true`; RFC1918 allowed for on-prem directories), `transport_mode: Literal["ldaps", "starttls"]` (`ldaps://` requires `"ldaps"`; `ldap://` requires `"starttls"`, cleartext bind mode does not exist in schema).
   - `ca_cert_pem: str | None` (validated X.509 PEM bundle `<= 65536` bytes via `cryptography.x509.load_pem_x509_certificates`), `spki_sha256_pins: list[str]` (`0..4` lowercase 64-hex SHA-256 digests of `SubjectPublicKeyInfo` DER).
   - `service_bind_dn: str | None` (`<= 512` chars; when `None`, user DN template mode is used; when set, secret blob holds JSON `{"bind_dn_password": "..."}` sealed with KB-P2-03 `seal_card_secret`).
   - `base_dn: str` (`1..512` chars), `user_search_filter: str` (default `"(&(objectClass=person)(uid={username}))"`; must contain `{username}` placeholder once and balance parentheses), `subject_attribute: str` (default `"entryUUID"`, e.g. `"objectGUID"` or `"entryUUID"`, immutable directory UUID), `email_attribute: str` (default `"mail"`), `display_name_attribute: str` (default `"cn"`), `member_of_attribute: str` (default `"memberOf"`), `group_dn_map: dict[str, str]` (`<= 200` entries mapping canonical lowercase group DN -> workspace group name `1..200` chars), `timeout_seconds: float` (`1.0..15.0`, default `5.0`).
3. **RFC 4515 filter & RFC 4514 DN escaping (`escape.py`):**
   - `escape_filter_chars(assertion_value: str | bytes) -> str`: encodes UTF-8 bytes escaping `*` -> `\2a`, `(` -> `\28`, `)` -> `\29`, `\` -> `\5c`, `\x00` -> `\00`, and any byte `> 0x7f` or control `< 0x20` as `\<two-hex-lowercase>` when `strict_ascii=True` or exact UTF-8 per RFC 4515 section 3. `render_user_filter(template: str, username: str) -> str` substitutes ONLY `{username}` with `escape_filter_chars(username)` and verifies the resulting filter AST has identical operator count and nesting depth to the template compiled with a dummy literal `"a"` (structural AST invariance check).
   - `normalize_dn(dn: str) -> str`: parses RDN sequence per RFC 4514 (handling escaped `\,`, `\+`, `\"`, `\\`, `\<hex>`), lowercases attribute types and case-insensitive values, and emits canonical string for deterministic `group_dn_map` matching.
4. **TLS-Hard LDAPv3 Wire Client (`protocol.py`, `pyasn1` + stdlib `ssl`):**
   - Implements minimal LDAPv3 BER framing (RFC 4511) for `ExtendedRequest` (`StartTLS` OID `1.3.6.1.4.1.1466.20037`), `BindRequest` (v3 Simple), `SearchRequest` (`wholeSubtree`, `sizeLimit=2`, `timeLimit=5`, `derefAliases=neverDerefAliases` to block alias traversal), and `UnbindRequest`; max inbound BER message `262,144` bytes (`LdapProtocolError("MESSAGE_TOO_LARGE")`).
   - **`TLS_HARD` invariant:**
     - `ldaps`: establish TLS immediately on connect (`ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)`, `minimum_version = ssl.TLSVersion.TLSv1_2`, `check_hostname = True`, `verify_mode = ssl.CERT_REQUIRED`).
     - `starttls`: open plain TCP, send ONLY `ExtendedRequest(StartTLS)` as `messageID=1`, require `resultCode == 0 (success)`, then upgrade transport via `loop.start_tls(..., server_hostname=host)` BEFORE constructing or serializing any `BindRequest`. Any failure aborts and closes transport immediately; no `BindRequest` bytes can ever be written to an unencrypted transport (asserted by state flag `self._tls_established` checked inside `_send_bind`).
   - **SPKI Pinning:** immediately after TLS handshake (and before any `BindRequest`), extract peer leaf DER cert `ssl_object.getpeercert(binary_form=True)`, compute `sha256(cert.public_key().public_bytes(Encoding.DER, PublicFormat.SubjectPublicKeyInfo)).hexdigest()`; when `spki_sha256_pins` is non-empty and digest is not in the list -> abort with `LdapTlsError("SPKI_PIN_MISMATCH")` prior to bind.
5. **Ephemeral User Bind & Service (`service.py`) + Group Sync (`group_sync.py`):**
   - Password held in a mutable `bytearray` created from NFKC-normalized UTF-8 (`1 <= len <= 1024` bytes) and overwritten with `\x00` in `finally` immediately after the user `BindRequest` buffer is written and zeroized. Reject empty password (`""` or whitespace-only if length 0) BEFORE network I/O to block RFC 4513 unauthenticated anonymous simple bind (`401 INVALID_CREDENTIALS`).
   - Step 1 (Search): bind with `service_bind_dn` + unsealed secret (zeroized in `finally`), search `base_dn` with `render_user_filter(template, username)` (`sizeLimit=2`). `0` or `> 1` entries -> perform dummy timing floor and return `401 INVALID_CREDENTIALS`. Extract `user_dn`, `subject` (`objectGUID` 16 raw bytes formatted as canonical UUID string, or UTF-8 string `<= 255` chars), `email`, `display_name`, and `memberOf` DNs.
   - Step 2 (Ephemeral User Bind): open a fresh TLS-verified, SPKI-checked connection (or re-bind on clean connection, never reusing service session privileges afterwards) and execute `BindRequest(version=3, name=user_dn, simple=user_password_buf)` followed immediately by `UnbindRequest`. Non-zero `resultCode` -> `401 INVALID_CREDENTIALS`.
   - Step 3 (Group DN Sync, `sync_ldap_groups(session, workspace_id, principal_id, raw_group_dns, group_dn_map)`): normalize each `memberOf` DN, match against normalized keys of `group_dn_map`; for each matched target group, upsert `principals(GROUP)` + `groups(external_source='LDAP', external_id=normalized_dn)` and synchronize `principal_group_edges` for `(principal_id, group_id)` across all groups managed by this card (adding newly present edges, removing revoked edges for this card's mapped groups; respects KB-P1-03 closure trigger).
   - Step 4: construct `ExternalIdentityAssertion(card_id, subject, email, email_verified=True, display_name, groups=matched_group_names)` and pass to `app.state.identity_resolver.resolve(...)` (`RejectAllIdentityResolver` until KB-P2-08, or `DatabaseIdentityResolver` once KB-P2-08 is installed).
   - Route `POST /api/v1/auth/ldap/{slug}/login` (and alias `/api/v1/auth/cards/{slug}/ldap-login`): requires CSRF (`X-CSRF-Token`), applies `AUTH_LOGIN_IP` and `AUTH_LOGIN_ACCOUNT` (`KB-P2-18`), equalizes response via `timing_floor(floor_ms=120.0)` (`KB-P2-01`), returns identical `401 INVALID_CREDENTIALS` across unknown user, wrong password, disabled card, or non-LDAP card.
6. **Security invariants asserted:** (a) zero `BindRequest` bytes ever traverse a socket prior to TLS 1.2+ handshake and SPKI pin verification; (b) empty password never triggers anonymous bind; (c) hostile `username` cannot alter LDAP filter AST structure; (d) user password and service bind password never appear in DB, logs, exceptions, or heap strings retained after `finally`.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/auth/test_ldap_escape.py`, `kanban/tests/auth/test_ldap_tls_and_bind.py`, `kanban/tests/auth/test_ldap_group_sync.py`
- **Required Test Cases:**
  1. Positive (`ldaps`): `fake_ldap` with TLS 1.3 + custom CA + matching SPKI pin -> service bind -> search -> ephemeral user bind -> `IdentityResolver` receives `ExternalIdentityAssertion` with canonical `subject`, `email`, and mapped `groups`; `objectGUID` 16-byte binary value formats to UUID string.
  2. Positive (`starttls`): `ldap://` sends `StartTLS` extended op first, upgrades TLS, verifies CA + SPKI pin, then binds and authenticates.
  3. Security (`TLS_HARD` downgrade): `fake_ldap` rejects `StartTLS` with `unavailable (52)` -> client aborts with `LdapTlsError`, spy on raw pre-TLS wire bytes confirms `0` occurrences of service password or user password and zero `BindRequest` tags (`0x60`).
  4. Security (TLS version & cert): `fake_ldap` offering only TLS 1.1 or self-signed cert not in `ca_cert_pem` -> connection aborted prior to bind.
  5. Security (SPKI pin mismatch): cert signed by trusted `ca_cert_pem` but with rotated key whose SPKI SHA-256 differs from `spki_sha256_pins` -> `SPKI_PIN_MISMATCH` prior to bind (`0` `BindRequest` bytes sent).
  6. Security (anonymous bind bypass): empty password `""` rejected with `401 INVALID_CREDENTIALS` before opening any LDAP connection; `fake_ldap` configured to accept RFC 4513 empty-password unauthenticated bind is never reached.
  7. Security (RFC 4515 injection): usernames `admin)(|(uid=*`, `*\00admin`, `\2a(objectClass=*)`, `a\b(c)d*` escape to `\2a`, `\28`, `\29`, `\5c`, `\00` and preserve exact filter AST operator count; `fake_ldap` confirms wildcard match does not occur.
  8. Security (ambiguous search & alias): search returning `0` entries or `2` entries -> `401 INVALID_CREDENTIALS` without attempting user bind; `derefAliases` wire field equals `0` (`neverDerefAliases`).
  9. Group DN sync (clean-DB harness): user with `memberOf=[CN=Core-Backend,OU=Groups,DC=corp,DC=example, CN=Unmapped,DC=corp,DC=example]` gets membership in mapped `Core Backend` group (`principal_group_closure` populated); second login with `CN=Core-Backend` removed revokes that edge while leaving non-LDAP groups untouched; case/escaped-comma DN variants match identically.
  10. Rate limit & enumeration: 6th failed login for one username -> `429 RATE_LIMITED`; unknown user vs wrong password vs disabled card produce byte-identical `401 INVALID_CREDENTIALS` bodies (excluding `request_id`).
  11. Boundary & SSRF: BER response of `262,145` bytes -> `MESSAGE_TOO_LARGE`; `url="ldap://127.0.0.1"` rejected by `LdapCardConfig` when `KANBAN_AUTH_EGRESS_ALLOW_PRIVATE=false`; `url="ldaps://dc01.corp"` with `transport_mode="starttls"` rejected.
  12. Secret hygiene: `caplog` at `DEBUG` across success and failure paths contains neither user password nor `bind_dn_password`; `bytearray` buffer passed into ephemeral bind check is all zeros after return.
