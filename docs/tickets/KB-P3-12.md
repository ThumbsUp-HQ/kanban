### User Story
As a **board user dragging cards across columns**, I need **a single-row `COLLATE "C"` Base-62 fractional-rank move endpoint enforcing Soft and Hard WIP limits (with audited AAL2 admin override) plus automatic background rebalancing when keys exceed 32 characters** so that **every drag commits in one row update without reindexing neighbors and column WIP policies cannot be bypassed**.

**Requirement Traceability:** Spec S6.4 items 1 & 3 (`board_rank TEXT COLLATE "C"`, Base-62 midpoints, 1-row mutation, rebalance `> 32` chars, Soft/Hard WIP + admin override justification); S1.3 (`< 12ms` optimistic move backing contract); S11.4 tool 10 (Hard WIP override); requirements `#9j`, `#8c` | **Dependencies:** `KB-P3-02`, `KB-P3-01b`

### Scoped Technical Actions
1. **Target Files:** `kanban/services/board_rank.py`, `kanban/api/v1/issue_move.py`, `kanban/api/v1/schemas/issue_move.py`, `kanban/services/issue_move.py`, `kanban/jobs/board_rebalance.py`, `kanban/cli/jobs.py` (register `board-rebalance`), `kanban/services/activity.py` (append event types).
2. **Fractional Indexing Engine (`kanban/services/board_rank.py`):**
   - Alphabet: `BASE62_ASCII = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"` (`62` chars strictly ordered in ASCII / PostgreSQL `COLLATE "C"`: `'0' (0x30) < '9' (0x39) < 'A' (0x41) < 'Z' (0x5A) < 'a' (0x61) < 'z' (0x7A)`).
   - Canonical rank regex: `^[0-9A-Za-z]{1,256}$` with **non-zero final character** (`rank[-1] != '0'`), guaranteeing an infinite dense midpoint space without exhaustion. (Note: `KB-P3-02` initial rank `"a" + base62(seq).rjust(6, "0")`: if `rank.endswith("0")`, `normalize_rank_bound()` appends `"V"` or treats trailing `'0'` safely, and `allocate_initial_board_rank(seq)` emits `"a" + base62(seq).rjust(6, "0") + "V"` or non-zero suffix; update `KB-P3-02` helper if needed so every persisted key obeys `rank[-1] != '0'`).
   - `midpoint_rank(prev_rank: str | None, next_rank: str | None) -> str`:
     - Raises `RankOrderError` when `prev_rank is not None and next_rank is not None and prev_rank >= next_rank` (bytewise ASCII compare).
     - `prev=None, next=None` -> `"V"`; `prev="a000001", next=None` -> steps forward (`"a000002"`); `prev=None, next="0..."` -> prepends `'0'` prefix + `'V'`; `prev < next` -> computes shortest Base-62 midpoint `m` satisfying `prev < m < next` in ASCII byte order (`prev.encode("ascii") < m.encode("ascii") < next.encode("ascii")`).
   - `generate_evenly_spaced_ranks(count: int) -> list[str]`: produces `count` strictly increasing Base-62 keys of width `<= 7` chars with non-`'0'` last character for rebalancing.
3. **Move Endpoint (`POST /api/v1/issues/{issue_ref}/move`):**
   - Request body (`extra="forbid"`):
     ```json
     {
       "target_state_id": "0193...",
       "after_issue": "KAN-140",
       "before_issue": "KAN-145",
       "wip_override_reason": null
     }
     ```
   - Authorization:
     - Unreadable issue -> `404 NOT_FOUND` (equalized).
     - Archived or deleted issue -> `409 ISSUE_ARCHIVED` / `404`.
     - Intra-column reorder (`target_state_id` omitted or equal to current `state_id`): requires `EDIT`.
     - Cross-column move (`target_state_id != current state_id`): requires both `EDIT` and `TRANSITION` (`403 INSUFFICIENT_CAPABILITY` otherwise). Target state must belong to the same project (`422 INVALID_REFERENCE`).
   - Positioning & locking:
     - Lock the target `workflow_states` row (`SELECT ... FOR UPDATE`) when moving across states (serializes concurrent WIP checks in that column) and lock the moved `issues` row `FOR UPDATE`.
     - Resolve `after_issue` / `before_issue` within the same project and `target_state_id` (non-deleted, non-archived); if missing/other-state/unreadable -> `422 INVALID_ANCHOR`. If both are supplied and `after.board_rank >= before.board_rank` -> `409 ANCHOR_ORDER_CONFLICT` (concurrent move shifted neighbors; client refetches column). When neither is supplied, places card at bottom of target column (`prev = max(board_rank)`). If another card already holds the exact computed rank (concurrent insert at same slot), resolve neighbor ranks inside the lock and recompute so `(state_id, board_rank, id)` stays strictly ordered.
   - **Soft & Hard WIP Enforcement (`S6.4` item 3):**
     - Evaluated only when moving **into** `target_state_id` from a different state (`resulting_count = current_active_count + 1`, where active = non-deleted, non-archived issues in `target_state_id`, counted across the whole column independent of caller per-issue ACLs so Hard WIP is a true project invariant without leaking hidden keys).
     - If `wip_hard_limit IS NOT NULL` and `resulting_count > wip_hard_limit`:
       - Caller lacks `PROJECT_ADMIN` and `SERVER_ADMIN` -> `409 WIP_HARD_LIMIT_EXCEEDED` with `{"hard_limit": 5, "current_count": 5}`.
       - Admin with `app.aal_level < 2` -> `403 AAL2_REQUIRED`.
       - Admin without `wip_override_reason` (`btrim` plain text `10..500` chars) -> `409 WIP_HARD_LIMIT_OVERRIDE_REQUIRED` with `{"hard_limit": 5, "current_count": 5}`.
       - AAL2 Admin with valid `wip_override_reason` -> allowed, emits `WIP_HARD_LIMIT_OVERRIDDEN {issue_id, from_state_id, to_state_id, hard_limit, resulting_count, reason}`.
     - If `wip_soft_limit IS NOT NULL` and `resulting_count > wip_soft_limit`: move succeeds `200` and includes `"wip_warning": {"soft_limit": 3, "resulting_count": 4}`.
   - **Single-Row Mutation:** executes `UPDATE issues SET board_rank = :new_rank, state_id = :target_state_id WHERE id = :id` (touching `1` issue row). Response `200`: `{"issue_key": "KAN-142", "state_id": "...", "board_rank": "a00002AV", "rebalance_scheduled": false, "wip_warning": null}`.
4. **Background Rebalance (`kanban/jobs/board_rebalance.py`):**
   - Triggered asynchronously when `len(new_rank) > 32` (`rebalance_scheduled = true`), and registered in the periodic job runner + CLI `kanban-ctl jobs run board-rebalance [--project KAN]`.
   - Acquires `pg_try_advisory_xact_lock(hashtext('kanban.rebalance.' || state_id::text))`, selects all issues in `(project_id, state_id)` ordered by `board_rank COLLATE "C" ASC, id ASC`, assigns `generate_evenly_spaced_ranks(n)`, bulk-updates changed rows in one transaction, emits one `BOARD_COLUMN_REBALANCED {state_id, reindexed_count, max_prev_len}` activity row on the project, and publishes a single `column.rebalanced` outbox event.
5. **Activity events emitted (category `HISTORY`):** `ISSUE_RANK_MOVED {old_rank, new_rank}` (only on cross-position reorder; suppressed if rank unchanged), `ISSUE_STATE_CHANGED {from_state_id, to_state_id}` (when state changed), `WIP_HARD_LIMIT_OVERRIDDEN`, `BOARD_COLUMN_REBALANCED`.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/services/test_board_rank.py`, `kanban/tests/api/test_issue_move.py`, `kanban/tests/jobs/test_board_rebalance.py`
- **Required Test Cases:**
  1. Property / invariant test (`test_board_rank.py`): 200 sequential head, tail, and adversarial same-slot bisection insertions satisfy `prev.encode("ascii") < mid.encode("ascii") < next.encode("ascii")` and match PostgreSQL `ORDER BY board_rank COLLATE "C"` sort order 100% identically.
  2. Single-row mutation proof: moving card 50 between cards 2 and 3 in a 100-card column updates `board_rank` on `1` row (`99` sibling `board_rank` values remain byte-identical).
  3. Soft & Hard WIP: moving into state with `soft=2, hard=3` as 3rd card returns `200` with `wip_warning`; 4th card as `EDIT`/`TRANSITION` member returns `409 WIP_HARD_LIMIT_EXCEEDED`; as AAL1 admin returns `403 AAL2_REQUIRED`; as AAL2 admin with 5-char reason returns `409 WIP_HARD_LIMIT_OVERRIDE_REQUIRED`; as AAL2 admin with 20-char reason returns `200` and writes `WIP_HARD_LIMIT_OVERRIDDEN`; intra-column reorder at `4/3` cards succeeds for regular `EDIT` member without override.
  4. Security: `EDIT`-only user (no `TRANSITION`) moving across columns gets `403`; non-viewer gets `404`; anchor from another project/state returns `422 INVALID_ANCHOR`.
  5. Rebalance boundary: bisecting between adjacent keys until `len(board_rank) == 33` sets `rebalance_scheduled: true`; running `rebalance_column` preserves the exact `1..N` issue sequence while reducing `max(char_length(board_rank)) <= 7` and emitting `BOARD_COLUMN_REBALANCED`.
