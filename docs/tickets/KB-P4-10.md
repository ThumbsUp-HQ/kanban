### User Story
As a **Project Admin bootstrapping or reshaping a project through an admin agent**, I need **`architect_project` to accept one declarative payload (states, priorities, labels, modules, auto-archive, WIP limits), show a diff plan, and apply it atomically, and `manage_cycles_and_modules` to run cycle lifecycle, modules, and saved views** so that **a project's whole configuration is reviewable before it changes and never lands half-applied.**

**Requirement Traceability:** `S11.4` tools 5-6 (excluding `bind_project_repo`, delivered by KB-P5-19), `S7.2` `8c`/`8f`/`8g`/`8i`/`8p`, `S12.2` (`identifier ~ '^[A-Z][A-Z0-9]{1,9}$'`, `auto_archive_days BETWEEN 1 AND 365`), `S6.4` (views, WIP), requirement `#8`, `#12` | **Dependencies:** `KB-P4-09a`, `KB-P3-01`, `KB-P3-10`, `KB-P3-11`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/admin/project_blueprint.py` (`POST /api/v1/admin/projects/blueprint:plan`, `POST /api/v1/admin/projects/blueprint:apply`), `kanban/projects/blueprint_service.py`, `mcp/surfaces/admin/architect_project.py`, `mcp/surfaces/admin/manage_cycles_and_modules.py`, `mcp/auth.py`.
2. **Blueprint schema (`ProjectBlueprint`, Pydantic `extra="forbid"`):**
   ```yaml
   identifier: {pattern: "^[A-Z][A-Z0-9]{1,9}$"}          # required
   name: {type: string, minLength: 1, maxLength: 120}
   description_markdown: {type: string}                  # <= 524,288 bytes
   states: {type: array, maxItems: 30, items: {name: string, group: {enum: [backlog, unstarted, started, completed, cancelled]}, color: string}}
   state_migrations: {type: object}                       # {"Old State": "New State"} for removed states
   priorities: {type: array, maxItems: 10, items: {name: string, emoji: string}}
   labels: {type: array, maxItems: 200, items: {name: string, exclusive_group: string}}
   modules_enabled: {type: boolean}
   modules: {type: array, maxItems: 100, items: {name: string}}
   default_modules: {type: array, items: string}
   auto_archive_days: {type: [integer, "null"], minimum: 1, maximum: 365}
   wip_limits: {type: object}                             # {"In Progress": {soft: 5, hard: 8}}
   ```
   - `plan` computes a diff against current state (`create`/`update`/`remove` per element) without writing. `apply` re-computes the plan, requires `plan_sha256` (sha256 of the canonical JSON plan returned by `plan`) to match (else `409` -> `PLAN_STALE`), and applies every change in ONE transaction via the KB-P3-01 services.
   - Removing a state that has issues requires a `state_migrations` entry (else `STATE_IN_USE` listing issue count); removing a priority in use likewise (`PRIORITY_IN_USE`). Every project must keep `>= 1` state in `started` and `>= 1` in `completed` (`VALIDATION_FAILED`).
   - Activity `PROJECT_BLUEPRINT_APPLIED` with the plan JSON.
3. **`architect_project`** input: `{action: enum [get, plan, apply, help] (required), project: string (get/plan/apply on existing), blueprint: ProjectBlueprint (plan/apply), plan_sha256: string (apply)}`. `get` returns the current blueprint (round-trippable: `plan` of `get` output yields an empty diff). `get` -> `admin:read`; `plan`/`apply` -> `admin:write`. `summary` response for `plan`:
   ```yaml
   project: KAN
   plan_sha256: 3f9a...e1
   changes:
     states: {create: [In Review], remove: [QA], migrate: {QA: In Review}}
     labels: {create: [qa-needs-work]}
     auto_archive_days: {from: null, to: 30}
   ```
4. **`manage_cycles_and_modules`** input:
   ```yaml
   action: {enum: [list_cycles, create_cycle, update_cycle, start_cycle, complete_cycle, rollover, list_modules, create_module, update_module, list_views, create_view, update_view, help]}   # required
   project: {type: string}             # required except help
   cycle: {type: string}               # name or uuid
   target_cycle: {type: string}        # rollover destination
   module: {type: string}
   view: {type: string}
   name: {type: string, maxLength: 120}
   start_date / end_date: {type: string, format: date}
   view_spec: {type: object}           # layout + filters_json + group_by + sub_group_by (KB-P3-11 DSL)
   ```
   - Cycle status follows `upcoming -> active -> completed` (KB-P3-10); invalid transition -> `INVALID_TRANSITION`. `rollover` moves every issue of `cycle` not in a `completed`/`cancelled` state group into `target_cycle` (must be `upcoming` or `active`) and returns the moved count.
   - Module actions on a project with `modules_enabled=false` -> `MODULES_DISABLED`.
   - Delete actions are intentionally absent (handled by `destructive_lifecycle`, KB-P4-12). `bind_project_repo` is intentionally absent (KB-P5-19).
   - `list_*` -> `admin:read`; others -> `admin:write`. `summary` response for `rollover`:
   ```yaml
   status: rolled_over
   from: Cycle 4
   to: Cycle 5
   moved: 7
   ```
5. **Error codes appended:** `PLAN_STALE`, `STATE_IN_USE`, `PRIORITY_IN_USE` (reuses `INVALID_TRANSITION`, `MODULES_DISABLED`).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_project_blueprint.py` (clean-DB harness), `mcp/tests/admin/test_architect_project.py`, `mcp/tests/admin/test_manage_cycles_and_modules.py`
- **Required Test Cases:**
  1. Positive: `plan` + `apply` creates project `KAN` with 6 states, 5 priorities, 3 labels, modules enabled with defaults, `auto_archive_days=30`; `get` -> `plan` round-trip yields zero changes; create cycles `Cycle 4`/`Cycle 5`, start `Cycle 4`, `rollover` moves exactly the 7 unfinished fixture issues.
  2. Atomicity/security: blueprint whose 200th label violates `exclusive_group` uniqueness applies `0` changes; `apply` with a `plan_sha256` from before a concurrent change -> `PLAN_STALE`; `admin:read`-only key calling `apply` -> `INSUFFICIENT_SCOPE`; non-admin of the project -> `NOT_FOUND`/`INSUFFICIENT_PERMISSION`.
  3. In-use protection: removing `QA` with 3 issues and no migration -> `STATE_IN_USE`; with `state_migrations: {QA: In Review}` issues move and the state is removed; removing the last `completed` state -> `VALIDATION_FAILED`.
  4. Boundary: identifier `kan` / `K` / `KANBANPROJX1` (11 chars) -> `VALIDATION_FAILED`; `auto_archive_days` 0 and 366 -> `VALIDATION_FAILED`; 31 states -> `VALIDATION_FAILED`; `complete_cycle` on an `upcoming` cycle -> `INVALID_TRANSITION`; `create_module` with modules disabled -> `MODULES_DISABLED`.
