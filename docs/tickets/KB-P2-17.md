### User Story
As an **AI and security engineer building Sparkle FIM, embedding pipelines, and workflow transition gates**, I need **a zero-dependency, linear-time `outbound_secret_scrubber` library in `kanban/security/scrubber.py` that deterministically redacts `sk-*`, `ghp_*` / GitHub PATs, `AKIA*` / `ASIA*` AWS keys, PEM private keys, `Bearer` / JWT tokens, and `kb_*` platform keys without retaining raw secret substrings in findings or suffering ReDoS** so that **accidental credentials typed into tickets, comments, or stickies are scrubbed before touching any outbound LLM socket or agent stdin pipe**.

**Requirement Traceability:** `S9.3` item 1 (`outbound_secret_scrubber` redacting `sk-*`, `ghp_*`, `AKIA*`, PEM keys, `Bearer` tokens, `kb_*` keys before touching any socket), `S14.3` item 2 (transition context untrusted strings scrubbed), requirements `#2`, `#7` | **Dependencies:** `KB-P0-01` (monorepo `kanban` package skeleton; placed in `kanban/security/` so both `kanban/` and `agent/` import it cleanly under `agent -> mcp -> kanban -> database`)

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/security/scrubber.py` (`SecretKind`, `ScrubFinding`, `ScrubResult`, `outbound_secret_scrubber`, `scrub_text`)
2. **Typed Return Contract (`kanban/security/scrubber.py`, stdlib `re` + linear string scan only):**
   ```python
   class SecretKind(StrEnum):
       API_KEY = "API_KEY"
       GITHUB_TOKEN = "GITHUB_TOKEN"
       AWS_ACCESS_KEY = "AWS_ACCESS_KEY"
       PRIVATE_KEY = "PRIVATE_KEY"
       BEARER_TOKEN = "BEARER_TOKEN"
       JWT = "JWT"
       KANBAN_KEY = "KANBAN_KEY"


   @dataclass(frozen=True)
   class ScrubFinding:
       kind: SecretKind
       start: int
       end: int
       placeholder: str


   @dataclass(frozen=True)
   class ScrubResult:
       text: str
       redacted: bool
       count: int
       findings: tuple[ScrubFinding, ...]
   ```
   - `ScrubFinding` deliberately omits the matched secret substring so logging or serializing `result.findings` can NEVER leak a credential (`__repr__` verified in unit tests).
   - `outbound_secret_scrubber(text: str) -> ScrubResult` is the primary entry point (called directly by `KB-P5-07` Sparkle pipeline checking `if result.redacted:` and by `KB-P5-06` / `KB-P5-18` / `KB-P5-19a`); `scrub_text(text: str) -> str` returns `outbound_secret_scrubber(text).text`.
3. **Deterministic Redaction Rules & Placeholders (non-overlapping left-to-right span resolution, longest-span wins on ties):**
   1. **PEM Private Key Blocks (`PRIVATE_KEY` -> `[REDACTED:PRIVATE_KEY]`):**
      - Scanned via linear `str.find("-----BEGIN ")` loop (zero catastrophic regex backtracking on unclosed headers!). Matches `-----BEGIN <LABEL>PRIVATE KEY-----` (`RSA `, `EC `, `OPENSSH `, `DSA `, `ENCRYPTED `, or empty `<LABEL>`) through matching `-----END <LABEL>PRIVATE KEY-----` within `16,384` chars; if an opening `-----BEGIN ... PRIVATE KEY-----` has no closing footer within `16,384` chars (e.g. truncated paste in a `1,500`-char Sparkle prefix!), redacts from `-----BEGIN` through the end of the base64 body / end of string!
   2. **Kanban Platform Keys (`KANBAN_KEY` -> `[REDACTED:KANBAN_KEY]`):**
      - Matches `\bkb_(?:agt_eph|agt|doc|adm|setup)_[A-Za-z0-9_-]{16,128}\b`.
   3. **GitHub Tokens (`GITHUB_TOKEN` -> `[REDACTED:GITHUB_TOKEN]`):**
      - Matches `\b(?:ghp|gho|ghu|ghs|ghr)_[A-Za-z0-9]{36,255}\b` and `\bgithub_pat_[A-Za-z0-9_]{22,255}\b`.
   4. **AWS Access Key IDs (`AWS_ACCESS_KEY` -> `[REDACTED:AWS_ACCESS_KEY]`):**
      - Matches `\b(?:AKIA|ASIA)[A-Z2-70-9]{16}\b` (`20` chars total, uppercase alphanumeric).
   5. **OpenAI / Anthropic / Provider `sk-*` Keys (`API_KEY` -> `[REDACTED:API_KEY]`):**
      - Matches `(?<![A-Za-z0-9_-])sk-(?:proj-|ant-api\d{2}-|live-|test-)?[A-Za-z0-9_-]{20,256}\b` (requires `>= 20` token chars after prefix AND at least one digit or mixed-case character so hyphenated English identifiers or CSS variables like `--sk-accent-primary-color` are never false-positived).
   6. **HTTP `Bearer` Authorization Tokens (`BEARER_TOKEN` -> `Bearer [REDACTED:BEARER_TOKEN]`):**
      - Matches `(?i)\b(Bearer)(\s+)[A-Za-z0-9._~+/=-]{20,2048}(?![A-Za-z0-9._~+/=-])`, preserving the original `"Bearer"` keyword + single space and replacing the token value with `[REDACTED:BEARER_TOKEN]`.
   7. **Standalone 3-Segment JWTs (`JWT` -> `[REDACTED:JWT]`):**
      - Matches `\beyJ[A-Za-z0-9_-]{8,512}\.eyJ[A-Za-z0-9_-]{8,1024}\.[A-Za-z0-9_-]{16,1024}\b` when not already covered by rule 6.
4. **Performance & Idempotency Contract:**
   - Idempotent: `outbound_secret_scrubber(result.text)` produces `redacted == False`, `count == 0`, and `text == result.text` (placeholders never re-trigger any rule).
   - Latency budget: `<= 1.0 ms` median on a `2,000`-char Sparkle window (`1,500` prefix + `500` suffix) and linear `O(n)` scaling up to `1 MiB` (`<= 50 ms` on `1,048,576`-char hostile input containing `1,000` unclosed `-----BEGIN RSA PRIVATE KEY-----` headers).
5. **Security invariants asserted:** (a) all 6 S9.3 secret classes (including truncated PEM private keys inside a `1,500`-char prefix window) are redacted with `redacted=True`; (b) `ScrubFinding` and `repr(ScrubResult)` contain zero raw secret characters outside the scrubbed `text`; (c) ordinary issue prose, UUIDs, git SHAs, issue keys, and code identifiers pass with `redacted=False` (so Sparkle FIM is not needlessly aborted by false positives).

  2. Positive (GitHub & AWS): `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_` (`36+` alnum), `github_pat_...`, `AKIAIOSFODNN7EXAMPLE`, and `ASIA...` -> deterministic `[REDACTED:GITHUB_TOKEN]` and `[REDACTED:AWS_ACCESS_KEY]`.
  3. Positive & boundary (PEM private keys - full AND Sparkle-truncated): full `-----BEGIN OPENSSH PRIVATE KEY-----...-----END OPENSSH PRIVATE KEY-----`, `-----BEGIN PRIVATE KEY-----`, `-----BEGIN EC PRIVATE KEY-----`, AND an unclosed PEM key truncated at `1,500` chars (matching `KB-P5-07` prefix truncation!) -> all redact to `[REDACTED:PRIVATE_KEY]` with zero base64 key material surviving.
  4. Positive (`Bearer`, JWT, and `kb_*` keys): `Authorization: Bearer eyJhbGciOi...`, `bearer opaque_tok_1234567890abcdefghij`, standalone JWT `eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0NTY3ODkwIn0.dozjgNryP4J3jVmNHl0w5N_XgL0n3I9PlFUP0THsR8U`, and `kb_agt_`, `kb_agt_eph_`, `kb_doc_`, `kb_adm_`, `kb_setup_` tokens -> all redacted to their deterministic placeholders.
  5. Multi-secret & overlapping spans: single paragraph containing a `Bearer <JWT>` (covered once as `Bearer [REDACTED:BEARER_TOKEN]`, not double-corrupted), a `ghp_` token, and a `kb_adm_` key -> `count == 3`, non-secret surrounding Markdown preserved byte-for-byte, second pass `outbound_secret_scrubber(res.text).redacted is False`.
  6. False-positive guard corpus (MUST return `redacted=False` and unchanged `text`):
     - UUIDv7 `01965a8e-7c12-7000-8000-112233445566` and 40-char git commit SHA `9f2c8b1e4d3a7c6b5e0f1a2b3c4d5e6f7a8b9c0d`
     - Issue/ticket keys `KAN-142`, `KB-P2-17`, `AKIA-12`
     - CSS/code identifiers `--sk-primary-button-background`, `sk-short123`, `task_list_item_identifier_name`, `bearer_of_bad_news = True`
     - File paths `/home/user/kanban/security/scrubber.py` and `https://kanban.hackedyour.info/kanban/projects/KAN/issues/142`
     - Public cert `-----BEGIN CERTIFICATE-----...-----END CERTIFICATE-----` (public X.509 cert is not a `PRIVATE KEY`)
  7. Secret non-retention in metadata: `repr(result.findings)` and `asdict` of every `ScrubFinding` across tests 1-5 contain none of the input secret substrings.
  8. ReDoS / linear-time boundary: `1,048,576`-byte string containing `1,000` unclosed `-----BEGIN RSA PRIVATE KEY-----\nMIIE...` segments and `"Bearer " + "a" * 50000` completes in `< 250 ms`; `2,000`-char Sparkle window completes in `< 5 ms` (median `< 1 ms` recorded in proof file).
