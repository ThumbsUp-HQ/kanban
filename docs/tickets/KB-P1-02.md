### User Story
As a **database platform engineer**, I need **the `workspaces` table, the `object_kind` enum, the shared-PK `objects` registry, and a `register_object()` helper** so that **every first-class entity (all 9 classes) is a registered graph node with a type-pinned composite key that later entity tables and `object_links` reference with `ON DELETE RESTRICT`**.

**Requirement Traceability:** `S12.1`, Requirements `#13a` - `#13i` (9 mandatory object classes) | **Dependencies:** `KB-P1-01`

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/p1_02_objects_spine.py`
   - `database/migrations/sql/p1_02_objects_spine.up.sql`, `database/migrations/sql/p1_02_objects_spine.down.sql`
2. **`workspaces` (not specified column-by-column in the spec; defined here):**
   ```sql
   CREATE TABLE workspaces (
       id                    UUID PRIMARY KEY DEFAULT uuidv7(),
       slug                  TEXT NOT NULL UNIQUE CHECK (slug ~ '^[a-z0-9][a-z0-9-]{1,62}$'),
       name                  TEXT NOT NULL CHECK (char_length(btrim(name)) BETWEEN 1 AND 200),
       trash_retention_days  INTEGER NOT NULL DEFAULT 30 CHECK (trash_retention_days BETWEEN 1 AND 3650), -- S7.2 8q default 30d
       created_at            TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       updated_at            TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
   );
   ```
3. **`object_kind` + `objects` exactly per S12.1 (verbatim columns, defaults, and both UNIQUE constraints)**, plus a workspace FK and supporting indexes:
   ```sql
   CREATE TYPE object_kind AS ENUM (
       'issue', 'sticky', 'doc', 'user', 'project', 'cycle', 'module', 'view', 'page'
   );
   CREATE TABLE objects (
       id              UUID PRIMARY KEY DEFAULT uuidv7(),
       object_type     object_kind NOT NULL,
       workspace_id    UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       project_id      UUID,
       canonical_key   TEXT NOT NULL CHECK (char_length(canonical_key) BETWEEN 1 AND 200),
       display_title   TEXT NOT NULL CHECK (char_length(display_title) BETWEEN 1 AND 500),
       created_by_id   UUID NOT NULL,
       created_at      TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       updated_at      TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       archived_at     TIMESTAMPTZ,
       deleted_at      TIMESTAMPTZ,
       UNIQUE (id, object_type),
       UNIQUE (workspace_id, object_type, canonical_key)
   );
   CREATE INDEX objects_project_idx ON objects (project_id) WHERE project_id IS NOT NULL;
   CREATE INDEX objects_ws_type_live_idx ON objects (workspace_id, object_type) WHERE deleted_at IS NULL;
   CREATE TRIGGER objects_set_updated_at BEFORE UPDATE ON objects FOR EACH ROW EXECUTE FUNCTION set_updated_at();
   CREATE TRIGGER workspaces_set_updated_at BEFORE UPDATE ON workspaces FOR EACH ROW EXECUTE FUNCTION set_updated_at();
   ```
   - `objects.project_id` has no FK here (projects table arrives in KB-P1-04, which adds `objects_project_fk` after `projects` exists).
   - `objects.created_by_id` intentionally has no FK (the first user object is registered with `created_by_id = its own id`; enforced at the app/bootstrap layer).
   - Immutability trigger `objects_guard_bu` (BEFORE UPDATE): raises `OBJECT_TYPE_IMMUTABLE` if `object_type` changes, `OBJECT_ID_IMMUTABLE` if `id` changes, `OBJECT_CREATED_AT_IMMUTABLE` if `created_at` changes.
4. **`register_object()` (SECURITY INVOKER so later RLS applies):**
   ```sql
   CREATE FUNCTION register_object(
       p_object_type object_kind, p_workspace_id uuid, p_project_id uuid,
       p_canonical_key text, p_display_title text, p_created_by_id uuid,
       p_id uuid DEFAULT NULL
   ) RETURNS uuid LANGUAGE plpgsql VOLATILE SECURITY INVOKER AS $$ ... $$;
   ```
   Contract: inserts one `objects` row, returns its id (`COALESCE(p_id, uuidv7())`); NULL `p_workspace_id`, `p_canonical_key`, `p_display_title`, or `p_created_by_id` -> `REGISTER_OBJECT_NULL_ARGUMENT`; `p_object_type IN ('project','user')` with non-NULL `p_project_id` -> `REGISTER_OBJECT_PROJECT_NOT_ALLOWED`; duplicate `(workspace_id, object_type, canonical_key)` surfaces SQLSTATE `23505` unchanged. `GRANT EXECUTE ... TO kanban_app`.
5. **Down migration:** drops `register_object`, triggers, `objects`, `object_kind`, `workspaces` in reverse order.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_02_objects.py`, `database/tests/migrations/test_p1_02_migration.py`
- **Required Test Cases:**
  1. Positive: `register_object('issue', ws, proj, 'KAN-1', 'Title', user)` returns a uuid whose row has `object_type='issue'` and a version-7 id.
  2. Positive: the same `canonical_key` is accepted for two different `object_type` values in one workspace, and for the same type in two workspaces.
  3. Negative: a second `register_object` with the same `(workspace_id, object_type, canonical_key)` raises `23505`.
  4. Negative: `INSERT INTO objects (object_type, ...) VALUES ('epic', ...)` raises `22P02` (invalid enum input).
  5. Negative: `UPDATE objects SET object_type='doc'` raises `OBJECT_TYPE_IMMUTABLE`; `register_object('project', ws, some_uuid, ...)` raises `REGISTER_OBJECT_PROJECT_NOT_ALLOWED`; NULL title raises `REGISTER_OBJECT_NULL_ARGUMENT`.
  6. Boundary: `canonical_key` of 200 chars accepted, 201 chars raises `23514`; `display_title` 500 accepted, 501 rejected; workspace `slug` `'a'` (1 char) rejected, 63 chars accepted.
  7. Boundary: an `UPDATE` sets `updated_at > created_at`; a FK `workspace_id` to a non-existent workspace raises `23503`.
  8. Migration up/down: `MigrationHarness` upgrade `p1_02_objects_spine` -> `pg_type` has `object_kind` with exactly the 9 labels in spec order; downgrade to `previous_of('p1_02_objects_spine')` -> `objects`, `workspaces`, `object_kind`, `register_object` absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
