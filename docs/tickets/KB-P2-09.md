### User Story
As a **server administrator managing authentication cards**, I need **three independent anti-lockout layers - a PostgreSQL constraint trigger preventing zero admin-capable cards, a 15-minute live external-IdP admin handshake gate before disabling `LOCAL_ADMIN`, and a host-shell `kanban-ctl auth emergency-unlock --enable-local-admin` break-glass CLI that writes an indelible `EMERGENCY_BREAK_GLASS_INVOKED` audit record** so that **misconfiguring an IdP can never permanently brick workspace administration, while out-of-band recovery is cryptographically hash-chained**.

**Requirement Traceability:** `S4.3` (Three-Layer Anti-Lockout Safeguards `LOCKOUT_PREVENTED` items 1-3, lines 350-353), `S4.1` (`auth_provider_cards`), `S12.2` (hash-chained `activity_records`), requirement `#6` | **Dependencies:** `KB-P2-03` (`auth_provider_cards` + `kb_auth`), `KB-P2-04` (`local_admin_credentials`), `KB-P2-08` (`user_identities`), `KB-P1-12` (`activity_records` hash chain), `KB-P1-13` (`SERVER_ADMIN` role bindings)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_lockout_prevented_safeguards.py`
   - `kanban/auth/cards/lockout.py` (`LockoutPreventedError`, `assert_local_admin_disable_allowed`, `record_external_admin_handshake`, SQLSTATE mapper)
   - `kanban/cli/__init__.py`, `kanban/cli/ctl.py` (`kanban-ctl` CLI root + `auth emergency-unlock --enable-local-admin`)
   - `kanban/pyproject.toml` (register `[project.scripts] kanban-ctl = "kanban.cli.ctl:main"`)
2. **Layer 1 - PostgreSQL `BEFORE UPDATE OR DELETE` Trigger (`db_trigger`, `S4.3` item 1):**
   - Migration adds `last_admin_handshake_at TIMESTAMPTZ` to `auth_provider_cards`.
   - Defines `kb_auth.card_can_authenticate_active_server_admin(p_card_id uuid, p_provider_kind text, p_workspace_id uuid) RETURNS boolean` (`SECURITY DEFINER`, `SET search_path = pg_catalog, public`):
     - Returns `TRUE` when `p_provider_kind = 'LOCAL_ADMIN'` and `EXISTS` an `ACTIVE` principal in `p_workspace_id` holding role `SERVER_ADMIN` (`KB-P1-13`) who has a row in `local_admin_credentials`.
     - Returns `TRUE` when `p_provider_kind IN ('OIDC','OAUTH2','LDAP')` and `EXISTS` an `ACTIVE` principal in `p_workspace_id` holding role `SERVER_ADMIN` who has a row in `user_identities` with `auth_card_id = p_card_id`.
   - Constraint/trigger `trg_auth_cards_prevent_lockout` (`AFTER UPDATE OF is_enabled, provider_kind, workspace_id OR DELETE ON auth_provider_cards FOR EACH ROW` using post-statement state inside transaction + `pg_advisory_xact_lock(hashtextextended('auth_lockout:' || COALESCE(NEW.workspace_id, OLD.workspace_id)::text, 0))` to prevent concurrent dual-disable race!):
     - Only evaluates when workspace already has `>= 1` active `SERVER_ADMIN` principal (allows empty initial bootstrap before `KB-P2-12` claim).
     - Counts remaining `auth_provider_cards` in that workspace where `is_enabled = TRUE` AND `kb_auth.card_can_authenticate_active_server_admin(id, provider_kind, workspace_id) = TRUE`.
     - If count `= 0`, aborts with `RAISE EXCEPTION 'LOCKOUT_PREVENTED: zero enabled cards can authenticate an active SERVER_ADMIN' USING ERRCODE = 'P0001', DETAIL = 'db_trigger'`.
   - Also adds trigger on `user_identities` (`AFTER DELETE`) and `local_admin_credentials` (`AFTER DELETE`): if an active `SERVER_ADMIN` already existed before the delete and deleting that credential leaves `0` enabled admin-capable cards in the workspace, raises `ERRCODE = 'P0001'`, `LOCKOUT_PREVENTED` (`DETAIL = 'db_trigger'`).
3. **Layer 2 - 15-Minute Live External Handshake Probe Gate (`handshake_probe_15m`, `S4.3` item 2):**
   - `kb_auth.card_record_admin_handshake(p_card_id uuid)`: called by `DatabaseIdentityResolver` (`KB-P2-08`) whenever a principal holding `SERVER_ADMIN` completes a real login on an external (`OIDC`/`OAUTH2`/`LDAP`) card, updating `last_admin_handshake_at = clock_timestamp()`. (Note: synthetic admin config test-handshakes in KB-P2-10 update `last_health_status`, NOT `last_admin_handshake_at`, because S4.3 item 2 specifically requires a verified login handshake on an external `SERVER_ADMIN`-mapped IdP card!).
   - Enforced BOTH in `kanban/auth/cards/lockout.py` (`assert_local_admin_disable_allowed`) AND inside `kb_auth` (`trg_local_admin_disable_probe` when `OLD.provider_kind = 'LOCAL_ADMIN' AND OLD.is_enabled = TRUE AND (TG_OP = 'DELETE' OR NEW.is_enabled = FALSE)`): requires `EXISTS` another card in the same workspace with `provider_kind IN ('OIDC','OAUTH2','LDAP')`, `is_enabled = TRUE`, `kb_auth.card_can_authenticate_active_server_admin(...) = TRUE`, AND `last_admin_handshake_at >= clock_timestamp() - interval '15 minutes'`; otherwise raises `ERRCODE = 'P0001'`, message `'LOCKOUT_PREVENTED: disabling LOCAL_ADMIN requires a verified external SERVER_ADMIN login within 15 minutes'`, `DETAIL = 'handshake_probe_15m'`.
   - `lockout.py` maps PostgreSQL `SQLSTATE 'P0001'` containing `LOCKOUT_PREVENTED` into `LockoutPreventedError(layer: Literal["db_trigger", "handshake_probe_15m"], detail: str)` and registers/exposes helper turning it into RFC 7807 `ProblemException(status=409, code="LOCKOUT_PREVENTED", type="urn:kanban:problem:lockout-prevented")` with extension field `"layer": layer` (consumed by `KB-P2-10` and `KB-P4-09a`).
4. **Layer 3 - Host CLI Emergency Escape Hatch (`kanban-ctl auth emergency-unlock --enable-local-admin`, `S4.3` item 3):**
   - `kanban-ctl` (`argparse`, zero third-party CLI framework needed): `kanban-ctl auth emergency-unlock --enable-local-admin [--workspace <slug_or_uuid>] [--reason <text>]`.
   - Refuses execution without explicit `--enable-local-admin` flag (`exit 2`).
   - Connects using privileged admin DB URL (`KANBAN_ADMIN_DATABASE_URL` or standalone local Unix socket `/run/postgresql` as `postgres`/`kanban_migrator`; refuses unprivileged `kanban_app` connection if `kb_auth.emergency_enable_local_admin` is not granted to `kanban_app` - `REVOKE EXECUTE ON FUNCTION kb_auth.emergency_enable_local_admin FROM PUBLIC, kanban_app; GRANT EXECUTE ... TO kanban_migrator`!).
   - `kb_auth.emergency_enable_local_admin(p_workspace_id uuid, p_os_uid int, p_tty text, p_reason text)` atomically:
     1. Upserts/enables the workspace's `LOCAL_ADMIN` card (`is_enabled = TRUE`, `updated_at = clock_timestamp()`).
     2. Appends an indelible row to `activity_records` (`KB-P1-12` hash-chained ledger) with `event_type = 'EMERGENCY_BREAK_GLASS_INVOKED'` and sanitized JSON metadata `{os_uid, hostname, reason}` (reason stripped of control chars, max `256` chars; zero secrets).
   - Verifies `verify_activity_chain()` remains valid after insert and prints single-line structured confirmation to stdout, exiting `0`.
5. **Security invariants asserted:** (a) no SQL statement or concurrent pair of statements can leave a workspace with an active `SERVER_ADMIN` and zero admin-capable enabled cards; (b) `LOCAL_ADMIN` cannot be disabled if the most recent external `SERVER_ADMIN` login is `> 900s` old or absent; (c) `kanban_app` web/API worker cannot invoke `kb_auth.emergency_enable_local_admin`; (d) every break-glass invocation is permanently chained in `activity_records`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_lockout_safeguards.py`, `kanban/tests/auth/test_lockout_mapping.py`, `kanban/tests/cli/test_emergency_unlock.py`
- **Required Test Cases:**
  1. Layer 1 (`db_trigger`, disable): workspace with 1 `SERVER_ADMIN` having only `LOCAL_ADMIN` credential (or only 1 OIDC `user_identities` row); setting `is_enabled = FALSE` or `DELETE` on that card aborts with `SQLSTATE P0001`, `LOCKOUT_PREVENTED`, `DETAIL = 'db_trigger'`.
  2. Layer 1 (card enabled without admin identity): enabling a second OIDC card that has `0` `SERVER_ADMIN` `user_identities` rows, then disabling the only card that DOES have a `SERVER_ADMIN` identity -> aborts with `db_trigger` (an enabled card nobody with `SERVER_ADMIN` is linked to does not count!).
  3. Layer 1 (concurrency, `@pytest.mark.committed_db`): two external OIDC cards both mapped to `SERVER_ADMIN` (`LOCAL_ADMIN` already disabled); two concurrent transactions simultaneously disabling Card A and Card B -> advisory lock serializes them so exactly 1 commits and the second fails with `LOCKOUT_PREVENTED`.
  4. Layer 2 (`handshake_probe_15m`): `SERVER_ADMIN` is linked to enabled OIDC card AND has `LOCAL_ADMIN`; with `last_admin_handshake_at IS NULL` or `now() - interval '901 seconds'`, disabling `LOCAL_ADMIN` aborts with `DETAIL = 'handshake_probe_15m'`; at `899 seconds` after `kb_auth.card_record_admin_handshake`, disabling `LOCAL_ADMIN` succeeds.
  5. Layer 2 (non-admin login does not satisfy gate): regular `MEMBER` login on OIDC card does NOT update `last_admin_handshake_at`; disabling `LOCAL_ADMIN` still fails with `handshake_probe_15m`.
  6. Error mapping: `LockoutPreventedError` maps `db_trigger` and `handshake_probe_15m` to HTTP `409`, `type="urn:kanban:problem:lockout-prevented"`, `code="LOCKOUT_PREVENTED"`, and `layer` field matching the trigger detail, with zero SQL text in body.
  7. Layer 3 (privilege wall): calling `SELECT kb_auth.emergency_enable_local_admin(...)` as `kanban_app` raises `42501 insufficient_privilege`.
  8. Layer 3 (CLI positive + hash chain): with `LOCAL_ADMIN` disabled (after valid OIDC admin handshake) and OIDC subsequently broken, running `kanban-ctl auth emergency-unlock --enable-local-admin --reason "Okta outage"` as `kanban_migrator` exits `0`, sets `LOCAL_ADMIN.is_enabled = TRUE`, writes `EMERGENCY_BREAK_GLASS_INVOKED` in `activity_records`, and `verify_activity_chain()` returns valid; attempting `UPDATE`/`DELETE` on that activity row raises per KB-P1-12 trigger.
  9. CLI negative: running `kanban-ctl auth emergency-unlock` without `--enable-local-admin` exits `2` and performs zero DB writes; `--reason` of `300` chars is rejected with exit `2`.
