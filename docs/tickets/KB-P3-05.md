### User Story
As a **project member discussing an issue**, I need **threaded Markdown comments with reactions, copyable permalinks and `@mention` resolution that warns before mentioning someone without access** so that **discussion is canonical Markdown and a mention never silently widens who can see the issue**.

**Requirement Traceability:** Spec S7.2 `8k`; S5.1 (canonical Markdown); S3.4 (no ACL widening, no enumeration); requirements `#8k`, `#5`, `#1` | **Dependencies:** `KB-P3-02`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/comments.py`, `kanban/api/v1/schemas/comments.py`, `kanban/services/comments.py`, `kanban/services/mentions.py`, `database/migrations/versions/<rev>_comment_threads_reactions.py`, `kanban/services/activity.py` (append events).
2. **Migration:** create `comment_reactions(comment_id UUID REFERENCES issue_comments(id) ON DELETE CASCADE, principal_id UUID REFERENCES principals(id), emoji TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(), PRIMARY KEY (comment_id, principal_id, emoji))` with `ENABLE` + `FORCE ROW LEVEL SECURITY` and a `SELECT`/`INSERT`/`DELETE` policy delegating to the parent issue's `VIEW` (writes `WITH CHECK principal_id = current_setting('app.principal_id')::uuid`). Add `issue_comments.parent_comment_id UUID REFERENCES issue_comments(id)`, `edited_at TIMESTAMPTZ`, `deleted_at TIMESTAMPTZ` only if KB-P1-09 did not create them (record which columns were added in `message-to-reality-checker.md`).
3. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `GET /api/v1/issues/{issue_ref}/comments?cursor=&limit=` | `VIEW` | `200` | `404`, `422 INVALID_CURSOR` |
   | `POST /api/v1/issues/{issue_ref}/comments` | `COMMENT` | `201` + `ETag` | `404`, `403`, `409 MENTION_ACCESS_WARNING`, `422` |
   | `PATCH /api/v1/comments/{comment_id}` | author only | `200` + `ETag` | `404`, `403 NOT_COMMENT_AUTHOR`, `412`, `428`, `409 MENTION_ACCESS_WARNING`, `409 COMMENT_DELETED` |
   | `DELETE /api/v1/comments/{comment_id}` | author or project `ADMIN` | `204` | `404`, `403` |
   | `PUT /api/v1/comments/{comment_id}/reactions/{emoji}` | `COMMENT` | `200` (idempotent) | `404`, `422 EMOJI_NOT_ALLOWED` |
   | `DELETE /api/v1/comments/{comment_id}/reactions/{emoji}` | `COMMENT` | `204` (idempotent) | `404` |

   - Create body: `{"body_markdown": "...", "parent_comment_id": null, "acknowledge_mentions": []}`. Body passes through `normalize_to_markdown()` (KB-P2-13); normalized size `1..262144` bytes else `422 COMMENT_LENGTH`.
   - Threading: `parent_comment_id` must be a non-deleted top-level comment on the same issue (reply depth max `1`), else `422 INVALID_PARENT_COMMENT`.
   - List: top-level comments ordered by `created_at ASC, id ASC` with nested `replies` (max `200` replies inlined, then `replies_next_cursor`); `limit` `1..100` default `50`.
   - Edit uses `ETag: "<hex body_sha256>"`; `If-Match` required (`428` missing, `412` mismatch). Delete is a soft delete: `deleted_at` set, list returns `{"id", "deleted": true}` with no body.
   - Reactions allowlist: `👍 👎 😄 🎉 😕 ❤️ 🚀 👀` (path segment URL-decoded, exact match after NFC); others `422 EMOJI_NOT_ALLOWED`. Reaction response: `{"emoji": "🚀", "count": 3, "reacted_by_me": true}`.
   - Permalink: every comment includes `"permalink": "/projects/KAN/issues/KAN-142#comment-<uuid>"`.
4. **Mention resolution (`kanban/services/mentions.py`):**
   - `extract_mentions(markdown) -> list[str]`: handles matching `(?<![\w@])@([a-z0-9][a-z0-9_.-]{0,38})` outside fenced code blocks, inline code spans and link URLs; max `50` distinct handles per comment (`422 TOO_MANY_MENTIONS`).
   - For each handle resolve within the caller's visibility boundary only (same-workspace co-viewers per S3.4). Handles that do not resolve or resolve outside the boundary are left as plain text with no warning and no notification (no enumeration signal).
   - Resolved principals lacking `VIEW` on the issue produce `409 MENTION_ACCESS_WARNING`:
     ```json
     {"type": "https://kanban/problems/mention-access-warning", "status": 409, "code": "MENTION_ACCESS_WARNING",
      "title": "Mentioned users cannot see this issue",
      "unauthorized_mentions": [{"handle": "maya", "principal_id": "0193..."}],
      "detail": "Resubmit with acknowledge_mentions to post without granting access."}
     ```
   - Resubmitting with `acknowledge_mentions` containing every listed `principal_id` returns `201`; the mention stays plain text, no ACL row is created, and the response includes `"unnotified_mentions": [...]`. The API never inserts into `resource_acl_entries`.
   - Response `mentions`: `[{"handle": "adam", "principal_id": "...", "has_access": true}]` (only for resolved, in-boundary principals).
5. **Activity events emitted (category `COMMENT`):** `COMMENT_CREATED {comment_id, parent_comment_id, body_sha256, mentioned_principal_ids}`, `COMMENT_EDITED {comment_id, old_sha256, new_sha256}`, `COMMENT_DELETED {comment_id, deleted_by}`, `MENTION_ACCESS_ACKNOWLEDGED {comment_id, principal_ids}`. Reactions write no activity rows (documented to avoid ledger noise).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_comments.py`, `kanban/tests/services/test_mentions.py`
- **Required Test Cases:**
  1. Positive: post top-level comment and reply; list returns nested reply; `permalink` format matches; `COMMENT_CREATED` rows written.
  2. Mention warning: mentioning workspace user `maya` without issue `VIEW` returns `409` listing `maya`; resubmitting with acknowledgement returns `201`; `resource_acl_entries` row count unchanged before/after.
  3. Enumeration: mentioning a handle from another workspace and a nonexistent handle both return `201` with no warning and no `mentions` entry.
  4. Parser: `@adam` inside a code fence, inline code, and inside `https://x/@adam` is not extracted; `email@adam.com` is not extracted; 51 handles returns `422`.
  5. Sanitization/boundary: `<script>` stripped from body; 262144-byte body succeeds, 262145 returns `422`; reply to a reply returns `422 INVALID_PARENT_COMMENT`.
  6. Concurrency/auth: edit by non-author `403`; edit with stale `ETag` `412`; missing `If-Match` `428`; non-viewer `GET` comments `404`.
  7. Reactions: `PUT 🚀` twice yields `count: 1`; `PUT 💩` returns `422`; reacting on a comment in an unreadable issue returns `404`.
- Clean-DB `SAVEPOINT` harness. Coverage `>= 95%`.
