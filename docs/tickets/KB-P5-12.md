### User Story
As a **Workspace or Server Security Administrator**, I need **every custom field scope or principal escalation beyond `(PROJECT, INVOKING_USER)` to require an `AAL2`-verified cryptographic approval bound to the exact `manifest_sha256` (including dual-control `SERVER_ADMIN` approval for `SERVER` scope), with immediate automatic revocation if a single byte of the script or metadata changes** so that **a Project Admin can never self-escalate a script to Workspace/Server scope or silently modify an already-approved privileged script**.

**Requirement Traceability:** `S13.2` (`Scope x Principal` 4-row escalation matrix, `manifest_sha256` binding, `PROJECT_ADMIN_SP` warning, `WORKSPACE_ADMIN` approval, `SERVER_ADMIN` dual-control approval, cache partitioning invariant, single-byte tamper auto-revocation), `S4.2` (`AAL2` WebAuthn/TOTP step-up), `S3.2` (OBO vs Service Principal) | Original requirement `#14` | **Dependencies:** `KB-P5-11`, `KB-P2-05a`, `KB-P2-05b`

2. **DDL & PostgreSQL Auto-Revocation Trigger (`p5_12_custom_field_approvals.py`):**
   ```sql
   CREATE TABLE custom_field_approvals (
       id                        UUID PRIMARY KEY DEFAULT uuidv7(),
       workspace_id              UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
       project_id                UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
       field_id                  UUID NOT NULL REFERENCES custom_field_definitions(id) ON DELETE CASCADE,
       manifest_sha256           BYTEA NOT NULL CHECK (octet_length(manifest_sha256) = 32),
       target_scope              TEXT NOT NULL CHECK (target_scope IN ('PROJECT', 'WORKSPACE', 'SERVER')),
       credential_mode           TEXT NOT NULL CHECK (credential_mode IN ('INVOKING_USER', 'PROJECT_ADMIN_SP', 'SERVER_ADMIN_SP')),
       required_tier             TEXT NOT NULL CHECK (required_tier IN ('PROJECT_ADMIN', 'WORKSPACE_ADMIN', 'SERVER_ADMIN_DUAL')),
       status                    TEXT NOT NULL CHECK (status IN ('PENDING', 'PENDING_SECOND_APPROVER', 'APPROVED', 'REVOKED')),
       requested_by_id           UUID NOT NULL REFERENCES principals(id),
       justification             TEXT NOT NULL CHECK (char_length(btrim(justification)) BETWEEN 10 AND 2000),
       primary_approver_id       UUID REFERENCES principals(id),
       primary_approver_aal      SMALLINT CHECK (primary_approver_aal IS NULL OR primary_approver_aal >= 2),
       primary_approved_at       TIMESTAMPTZ,
       secondary_approver_id     UUID REFERENCES principals(id),
       secondary_approver_aal    SMALLINT CHECK (secondary_approver_aal IS NULL OR secondary_approver_aal >= 2),
       secondary_approved_at     TIMESTAMPTZ,
       sp_warning_acknowledged   BOOLEAN NOT NULL DEFAULT FALSE,
       approval_signature_hmac   BYTEA CHECK (approval_signature_hmac IS NULL OR octet_length(approval_signature_hmac) = 32),
       revoked_at                TIMESTAMPTZ,
       revoked_reason            TEXT,
       created_at                TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       CHECK (secondary_approver_id IS NULL OR secondary_approver_id <> primary_approver_id),
       CHECK (
           (target_scope = 'PROJECT'   AND credential_mode IN ('INVOKING_USER', 'PROJECT_ADMIN_SP')) OR
           (target_scope = 'WORKSPACE' AND credential_mode IN ('INVOKING_USER', 'PROJECT_ADMIN_SP')) OR
           (target_scope = 'SERVER'    AND credential_mode IN ('INVOKING_USER', 'SERVER_ADMIN_SP'))
       )
   );
   ```
   - `ENABLE` + `FORCE ROW LEVEL SECURITY` on `custom_field_approvals`: `SELECT` requires `PROJECT_ADMIN`, `WORKSPACE_ADMIN`, or `SERVER_ADMIN`; `INSERT`/`UPDATE` requires `aal_level >= 2`.
   - Trigger `custom_field_manifest_tamper_revoke AFTER UPDATE ON custom_field_definitions FOR EACH ROW`: whenever `NEW.manifest_sha256 IS DISTINCT FROM OLD.manifest_sha256`, immediately updates all rows in `custom_field_approvals` for `NEW.id` where `status IN ('PENDING', 'PENDING_SECOND_APPROVER', 'APPROVED')` to `status = 'REVOKED'`, `revoked_at = clock_timestamp()`, `revoked_reason = 'MANIFEST_SHA256_CHANGED'`.
3. **Exact S13.2 `Scope x Principal` Matrix & Cache Partitioning (`kanban/custom_fields/approvals.py`):**
   - `(PROJECT, INVOKING_USER)` *(Default)*: `approval_status = "default_no_escalation"` (already gated by `PROJECT_ADMIN` definition in `KB-P5-11`); cache key `(issue_id, field_id, script_version, user_access_hash)` where `user_access_hash = SHA256(sorted_effective_principal_ids_and_acl_epoch_for_caller)` (`32` bytes).
   - `(PROJECT, PROJECT_ADMIN_SP)`: requires `PROJECT_ADMIN` approval with `sp_warning_acknowledged = True` (`422 SP_WARNING_ACK_REQUIRED` if false); cache key `(issue_id, field_id, script_version, b"")`.
   - `(WORKSPACE, INVOKING_USER | PROJECT_ADMIN_SP)`: requires `WORKSPACE_ADMIN` approval (`sp_warning_acknowledged = True` when `PROJECT_ADMIN_SP`); cache key uses `user_access_hash` for `INVOKING_USER` and `b""` for `PROJECT_ADMIN_SP`.
   - `(SERVER, INVOKING_USER | SERVER_ADMIN_SP)`: requires `SERVER_ADMIN_DUAL` - first `SERVER_ADMIN` transitions `PENDING -> PENDING_SECOND_APPROVER`; a **second distinct `SERVER_ADMIN`** transitions `PENDING_SECOND_APPROVER -> APPROVED`; self-second-approval by `primary_approver_id` is rejected (`409 DUAL_CONTROL_DISTINCT_APPROVER_REQUIRED` and DB CHECK). `SERVER` scope sets `audit_every_invocation = True` and bypasses cross-request value caching (`should_cache = False`).
   - Disallowed combinations (`(PROJECT, SERVER_ADMIN_SP)`, `(WORKSPACE, SERVER_ADMIN_SP)`, `(SERVER, PROJECT_ADMIN_SP)`) return `422 ESCALATION_COMBO_INVALID`.
   - `approval_signature_hmac`: computed upon reaching `APPROVED` as `HMAC-SHA256(derive_subkey(KB_AUTH_PEPPER, "custom-field-approval/v1"), field_id || manifest_sha256 || target_scope || credential_mode || primary_approver_id || (secondary_approver_id or 0x00*16))`.
   - `assert_execution_authorized(definition)` (called by `KB-P5-13`): for `(PROJECT, INVOKING_USER)` succeeds immediately; for any escalated tuple verifies an `APPROVED` row exists with `row.manifest_sha256 == definition.manifest_sha256` AND valid `hmac.compare_digest(approval_signature_hmac, expected)`, else raises `ApprovalRevokedError(code="APPROVAL_REVOKED")`.
4. **REST Endpoints (`kanban/api/v1/custom_field_approvals.py` - paths aligned with `KB-P5-15`):**
   - `POST /api/v1/custom-fields/{field_id}/approval-requests` body `{manifest_sha256: str (64-hex), justification: str}`: requires `PROJECT_ADMIN` on the field's project; returns `409 MANIFEST_MISMATCH` if body `manifest_sha256` differs from current `definition.manifest_sha256`; creates `PENDING` row (`201`).
   - `POST /api/v1/custom-field-approvals/{approval_id}/approve` body `{manifest_sha256: str (64-hex), sp_warning_acknowledged: bool = False}`:
     - Session with `aal_level < 2` or `aal2_verified_at` older than `900s` -> `403 AAL2_REQUIRED` (triggers WebAuthn/TOTP step-up in `KB-P5-15`).
     - Caller lacks the required target-tier admin role (`PROJECT_ADMIN` / `WORKSPACE_ADMIN` / `SERVER_ADMIN`) -> `403 INSUFFICIENT_APPROVER_TIER` (or `404` if caller cannot view the project).
     - Submitted `manifest_sha256` != `definition.manifest_sha256` or approval row already `REVOKED` -> `409 MANIFEST_MISMATCH`.
   - `GET /api/v1/custom-fields/{field_id}/approvals`: lists approval history for admins.
   - All transitions write `CUSTOM_FIELD_APPROVAL_REQUESTED`, `CUSTOM_FIELD_APPROVED_PRIMARY`, `CUSTOM_FIELD_APPROVED`, or `CUSTOM_FIELD_APPROVAL_REVOKED` to `activity_records`.

- **Test File(s):**

- **Required Test Cases:**
  1. Positive (all 4 S13.2 rows): `(PROJECT, INVOKING_USER)` requires no extra approval; `(PROJECT, PROJECT_ADMIN_SP)` approved by `PROJECT_ADMIN` at `AAL2` with `sp_warning_acknowledged=True`; `(WORKSPACE, INVOKING_USER)` approved by `WORKSPACE_ADMIN` at `AAL2`; `(SERVER, SERVER_ADMIN_SP)` reaches `PENDING_SECOND_APPROVER` on `SERVER_ADMIN` #1 and `APPROVED` on `SERVER_ADMIN` #2.
  2. Security (tier escalation block): `PROJECT_ADMIN` attempting to approve a `WORKSPACE` or `SERVER` field -> `403 INSUFFICIENT_APPROVER_TIER`; `WORKSPACE_ADMIN` attempting to approve a `SERVER` field -> `403 INSUFFICIENT_APPROVER_TIER`.
  3. Security (dual-control enforcement): same `SERVER_ADMIN` attempting both primary and secondary approval -> `409 DUAL_CONTROL_DISTINCT_APPROVER_REQUIRED` (and rejected by DB `CHECK (secondary_approver_id <> primary_approver_id)` on direct SQL update).
  4. Security (AAL2 freshness): `AAL1` session or `AAL2` session verified `901s` ago -> `403 AAL2_REQUIRED`.
  5. Security (single-byte tamper auto-revocation): approve a `(WORKSPACE, PROJECT_ADMIN_SP)` field -> `assert_execution_authorized` passes; append a single space `" "` to `script_source` (or change 1 key in `output_format_metadata`) -> DB trigger marks approval `REVOKED` (`MANIFEST_SHA256_CHANGED`) and `assert_execution_authorized` raises `APPROVAL_REVOKED`; even if DB trigger were bypassed by tampering `approval_signature_hmac`, HMAC check fails closed.
  6. Security (TOCTOU on approve UI): admin opens approval when hash is `H1`, definition is edited to `H2`, admin submits approve with `manifest_sha256=H1` -> `409 MANIFEST_MISMATCH`.
  7. Security (cache partitioning): `compute_cache_partition_key` produces distinct 32-byte `user_access_hash` values for two users with different group/ACL sets on `INVOKING_USER` fields, `b""` for `PROJECT_ADMIN_SP`, and `should_cache=False` for `SERVER` scope.
  8. Boundary: invalid tuple `(PROJECT, SERVER_ADMIN_SP)` rejected at API (`422 ESCALATION_COMBO_INVALID`) and DB `CHECK`; `PROJECT_ADMIN_SP` with `sp_warning_acknowledged=False` -> `422 SP_WARNING_ACK_REQUIRED`.
