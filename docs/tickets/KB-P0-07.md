### User Story
As an **operator deploying Kanban**, I need **one root `Dockerfile` with exactly the four stages `web-builder`, `py-builder`, `runtime-slim`, and default final stage `standalone`** so that **production containers run as non-root with zero compilers or Node, and `docker run kanban:latest` ships the embedded PostgreSQL 16 bits, with zero secrets in any layer**.

**Requirement Traceability:** `S2.4` (Dockerfile stage contract), `S2.2` (standalone image content), `S3.5` row "Standalone `docker run` Misconfiguration" (zero baked-in keys), Requirement `#3` | **Dependencies:** `KB-P0-01`, `KB-P0-03`

### Scoped Technical Actions
1. **Target Files:** `Dockerfile`, `.dockerignore`, `tests/deploy/__init__.py`, `tests/deploy/test_dockerfile.py`, `Makefile` (targets `image-slim`, `image-standalone`, `hadolint`)
2. **Stage contract (exact names and order, `# syntax=docker/dockerfile:1.7` first line):**
   - `FROM node:22-bookworm-slim@sha256:<digest> AS web-builder`: enable `corepack` with the pinned `packageManager` pnpm; `pnpm install --frozen-lockfile --ignore-scripts`; `pnpm --dir kanban/web build` producing `kanban/web/dist` with `.br`/`.gz` and `sri-manifest.json`.
   - `FROM python:3.12-slim-bookworm@sha256:<digest> AS py-builder`: copy a pinned `uv` binary from `ghcr.io/astral-sh/uv:<version>@sha256:<digest>`; `uv sync --locked --no-dev --no-build-isolation` into `/opt/kanban/.venv` (`UV_PROJECT_ENVIRONMENT`), `UV_COMPILE_BYTECODE=1`.
   - `FROM python:3.12-slim-bookworm@sha256:<digest> AS runtime-slim`: `apt-get install --no-install-recommends tini libpq5 ca-certificates` then remove apt lists; create group/user `kanban` with UID/GID `65532`, no shell (`/usr/sbin/nologin`), no home write; copy `/opt/kanban/.venv` from `py-builder`, application packages, `deploy/` to `/opt/kanban/deploy`, and `kanban/web/dist` to `/opt/kanban/web/dist`; `ENV PATH=/opt/kanban/.venv/bin:$PATH PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 KB_WEB_DIST=/opt/kanban/web/dist`; `USER 65532:65532`; `ENTRYPOINT ["/usr/bin/tini", "--"]`; `CMD ["uvicorn", "kanban.app:create_app", "--factory", "--host", "0.0.0.0", "--port", "8000"]`.
   - `FROM runtime-slim AS standalone` (last stage, therefore default): `USER root`; add the PGDG apt repository (`apt.postgresql.org`, `bookworm-pgdg`) with its signing key verified against a pinned fingerprint `B97B0AFCAA1A47F044F244A07FCC7D46ACCC4CF8`; install `postgresql-16`, `postgresql-16-pgvector`, `util-linux` (for `setpriv`), `--no-install-recommends`, remove apt lists; `install -d -o postgres -g postgres -m 0700 /var/lib/kanban/data/pgdata`, `install -d -o postgres -g postgres -m 2775 /run/postgresql`; `EXPOSE 8080`; `VOLUME /var/lib/kanban/data`; `ENTRYPOINT ["/usr/bin/tini", "--", "/opt/kanban/.venv/bin/python", "/opt/kanban/deploy/standalone/entrypoint.py"]`. The standalone stage remains `USER root` only because the PID-1 entrypoint (KB-P0-08) must start PostgreSQL as `postgres` and drop Uvicorn to `65532` via `setpriv`; this justification is a Dockerfile comment. The entrypoint script itself is implemented in KB-P0-08; this ticket only wires the path.
   - Note on base images: S2.4 names `python:3.12-slim`; this ticket pins the `-bookworm` variant because PostgreSQL 16 packages for the standalone stage come from PGDG `bookworm-pgdg`, and floating `python:3.12-slim` may move to a newer Debian release.
3. **Zero toolchains in `runtime-slim`:** no `gcc`, `cc`, `make`, `node`, `npm`, `pnpm`, `uv`, `pip` binaries on `PATH` in `runtime-slim` (the venv `pip` is excluded by `uv sync`, which does not install pip).
4. **Zero secrets:** No `ARG` or `ENV` whose name matches `(?i)(secret|password|passwd|token|key|kek|pepper)` (except `KB_WEB_DIST`-style non-secret names explicitly allowlisted in the test); no `COPY` of `.env*`, `*.pem`, `*.key`, `keyring.json`. `.dockerignore` excludes `.git`, `.venv`, `node_modules`, `**/__pycache__`, `docs/qa`, `.env*`, `*.pem`, `*.key`, `ci-logs`, `reports`.
5. **Lint:** `hadolint` clean with zero ignored rules, except `DL3008` (pin apt versions) which may be ignored only via an inline `# hadolint ignore=DL3008` with a justification comment that Debian security updates must flow and the base image digest is pinned.
6. **Image size:** record `docker image ls` sizes for both targets (S2.4 targets `~240 MB` for `runtime-slim`; record only, not a pass/fail gate in this ticket).

### Mandatory Feature Unit Tests
- **Test File(s):** `tests/deploy/test_dockerfile.py` (static parse of `Dockerfile`; no Docker daemon required)
- **Required Test Cases:**
  1. Positive: exactly 4 `FROM ... AS <name>` lines with names in order `web-builder`, `py-builder`, `runtime-slim`, `standalone`; the last `FROM` is `standalone`; every external `FROM` image reference contains `@sha256:` followed by 64 hex chars.
  2. Positive: within the `runtime-slim` stage block, a `USER 65532:65532` instruction exists and the `ENTRYPOINT` starts with `/usr/bin/tini`; within `standalone`, `EXPOSE 8080` and `VOLUME /var/lib/kanban/data` exist.
  3. Negative/security: no `ARG`/`ENV` name matches the secret regex; no `COPY`/`ADD` source matches `.env`, `.pem`, `.key`, `keyring.json`; no `ADD` with a remote URL; no `curl ... | sh` pattern.
  4. Boundary: `.dockerignore` contains every entry listed in Scoped Technical Actions item 4.
  5. Positive: the `runtime-slim` `apt-get install` line contains `tini`, `libpq5` and does not contain `gcc`, `build-essential`, `nodejs`, `postgresql`.
