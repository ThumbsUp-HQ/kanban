### User Story
As a **project member assigning work**, I need **to assign issues to principals who can already view the project or to free-text external labels, with an autocomplete that never lists principals outside the project** so that **assignment never grants access, never notifies outsiders and never enumerates users across projects**.

**Requirement Traceability:** Spec S7.2 `8b`; S3.4 (zero cross-scope enumeration); requirements `#8b`, `#1` | **Dependencies:** `KB-P3-02`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/assignees.py`, `kanban/api/v1/schemas/assignees.py`, `kanban/services/assignees.py`, `kanban/api/v1/schemas/issues.py` (add `assignees` to issue serializer), `kanban/services/activity.py` (append events).
2. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `POST /api/v1/issues/{issue_ref}/assignees` | `EDIT` on issue | `201` | `404`, `403`, `422 ASSIGNEE_NOT_ELIGIBLE`, `422 FREE_TEXT_INVALID`, `409 ASSIGNEE_EXISTS`, `422 ASSIGNEE_LIMIT` |
   | `DELETE /api/v1/issues/{issue_ref}/assignees/{assignee_id}` | `EDIT` on issue | `204` | `404` |
   | `GET /api/v1/projects/{project_ref}/assignee-suggestions?q=&limit=` | `VIEW` on project | `200` | `404`, `422` |

   - `POST` body is exactly one of `{"principal": "<uuid>|@handle"}` or `{"free_text": "Vendor: NCC Group"}` (both or neither returns `422`).
   - Principal eligibility: principal type `USER` or `AGENT`, status active, and present in `effective_resource_access` with `VIEW` bit set and deny bit clear for the issue's project. Nonexistent, inactive, other-workspace and non-viewer principals all return the identical `422 ASSIGNEE_NOT_ELIGIBLE` body (no enumeration).
   - Free text: normalized to plain text (KB-P2-13 plain mode, zero-width and tag chars stripped), `btrim` length `1..120`, else `422 FREE_TEXT_INVALID`. Free-text assignees never create ACL rows and are flagged `notify: false`.
   - Limits: max `20` assignees per issue, of which max `10` free text; exceeding returns `422 ASSIGNEE_LIMIT`. Duplicate principal or case-insensitive duplicate free text returns `409 ASSIGNEE_EXISTS`.
   - Suggestions: `q` `1..64` chars (prefix match, case-insensitive, on `users.handle` and `users.display_name`; `%`, `_`, `\` escaped in `ILIKE`), `limit` `1..20` default `10`. SQL joins `effective_resource_access` for the project (`VIEW` allowed, not denied) inside the RLS session; result never includes email, auth card ids or group DNs.
   - Shapes:
     ```json
     // POST response 201
     {"id": "0193...", "kind": "principal", "principal": {"id": "...", "handle": "adam", "display_name": "Adam Outler", "type": "USER"}}
     {"id": "0193...", "kind": "free_text", "free_text": "Vendor: NCC Group", "notify": false,
      "hint": "External free-text label - grants zero access and sends zero notifications"}
     // GET suggestions 200
     {"items": [{"id": "...", "handle": "adam", "display_name": "Adam Outler", "type": "USER"}]}
     ```
   - Issue serializer gains `"assignees": [...]` using the same item shapes.
3. **Activity events emitted (category `HISTORY`):** `ASSIGNEE_ADDED {kind, principal_id | free_text}`, `ASSIGNEE_REMOVED {kind, principal_id | free_text}`.
4. **Security invariants:** autocomplete query count and timing do not depend on principals outside the project; `assignee_id` belonging to another issue returns `404`; free text is never rendered as HTML server-side.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_assignees.py`
- **Required Test Cases:**
  1. Positive: assign a project viewer by `@handle` returns `201`; issue `GET` lists the assignee; `ASSIGNEE_ADDED` row exists.
  2. Security: assigning a user who exists in the workspace but lacks project `VIEW` returns `422 ASSIGNEE_NOT_ELIGIBLE` byte-identical (ignoring request id) to assigning a random UUID; a user with explicit `DENY` on the project is also rejected.
  3. Enumeration: suggestions for `q=a` in project A never include a user who only has access to project B (seed `alice` in B only); response objects contain no `email` key.
  4. Free text: `"Vendor: NCC Group"` stored with `notify: false`; `"<b>x</b>"` stored as `x`; 121 chars returns `422`; zero-width-only string returns `422`.
  5. Boundary: 20th assignee succeeds, 21st returns `422 ASSIGNEE_LIMIT`; 11th free text returns `422`; `q` of 65 chars returns `422`; `q` containing `%_` matches literally.
  6. Delete: removing assignee returns `204` and writes `ASSIGNEE_REMOVED`; deleting an assignee id from another issue returns `404`.
- Clean-DB `SAVEPOINT` harness. Coverage `>= 95%` on touched modules.
