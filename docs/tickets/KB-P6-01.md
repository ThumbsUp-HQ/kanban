### User Story
As a **platform operator cutting over from the bootstrap Plane board (`https://kanban.hackedyour.info/kanban/`)**, I need **an idempotent importer (`kanban-ctl import plane` + Admin dry-run/apply endpoint) that migrates projects, states, priorities, labels, cycles, modules, issues with exact `KANBA-<N>` sequence continuity, HTML-to-Markdown normalized descriptions and comments, attachments, and typed links** so that **zero ticket keys, QA proof links, or authorship records are lost or corrupted during self-hosting cutover**.

**Requirement Traceability:** Spec S1.3 item 4 (`kanban-ctl import plane`, `100%` `KANBA-*` key, comment, and QA proof preservation); S15.5 item 7 (Phase 6 cutover); S5.2 (`normalize_to_markdown()` on hostile Plane HTML); S12.3 (`audit_object_links()` zero-invalid post-import gate); requirement `#4` | **Dependencies:** `KB-P3-01b`, `KB-P3-02`, `KB-P3-03`, `KB-P3-04`, `KB-P3-05`, `KB-P3-07`, `KB-P3-09b`, `KB-P3-10a`, `KB-P3-10b`, `KB-P2-13`, `KB-P2-15`, `KB-P1-15` (expands manifest placeholder `KB-P3-* backend complete, KB-P2-13` into explicit ticket IDs)

### Scoped Technical Actions
1. **Target Files:** `database/migrations/versions/<rev>_import_entity_mappings.py`, `database/models/import_mapping.py`, `kanban/importer/__init__.py`, `kanban/importer/plane_client.py`, `kanban/importer/plane_mapper.py`, `kanban/importer/plane_importer.py`, `kanban/cli/import_plane.py`, `kanban/api/v1/admin/imports.py`.
2. **Idempotency Ledger (`import_entity_mappings`, `FORCE RLS` workspace policy):**
   ```sql
   CREATE TABLE import_entity_mappings (
       workspace_id    UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
       source_system   TEXT NOT NULL CHECK (source_system = 'plane'),
       source_kind     TEXT NOT NULL,
       source_id       TEXT NOT NULL CHECK (char_length(source_id) BETWEEN 1 AND 128),
       target_id       UUID NOT NULL,
       source_sha256   BYTEA NOT NULL CHECK (octet_length(source_sha256) = 32),
       imported_at     TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       PRIMARY KEY (workspace_id, source_system, source_kind, source_id)
   );
   ```
3. **Hardened Plane Snapshot & API Reader (`kanban/importer/plane_client.py`):**
   - Supports two deterministic input modes:
     1. `--bundle-dir <path>`: offline directory of exported Plane v1 JSON pages (`project.json`, `states.json`, `labels.json`, `cycles.json`, `modules.json`, `issues/*.json`, `comments/*.json`, `links.json`, `members.json`, `attachments/*`), plus `kanban-ctl import plane fetch-snapshot --base-url https://kanban.hackedyour.info/kanban/ --workspace-slug ... --project-identifier KANBA --out-dir <path>` (`X-API-Key` read from env `PLANE_API_KEY`, never CLI argv!).
     2. Live HTTPS fetch: enforces `https://` scheme (unless `--allow-loopback-http` in tests), DNS-pins resolved IP blocking RFC1918/loopback/link-local unless explicit `--allow-private-cidr` is passed, `zero` cross-origin redirects, `<= 25 MiB` per JSON page / attachment, `connect/read` timeout `15s`, exponential backoff on `429`.
   - Every response is validated against strict Pydantic v2 Plane wire models (`PlaneProject`, `PlaneState`, `PlaneIssue`, `PlaneComment`, `PlaneRelation`); unknown HTML/JSON fields never bypass sanitization.
4. **Lossless Mapping & Key Continuity Engine (`kanban/importer/plane_mapper.py`, `kanban/importer/plane_importer.py`):**
   - **Exact `KANBA-<sequence_id>` Continuity:** inserts each Plane issue using its exact `sequence_id` (`1..N`, preserving gaps from previously deleted Plane tickets so `KANBA-42` stays `KANBA-42`!) and updates `projects.issue_seq_counter = GREATEST(projects.issue_seq_counter, MAX(imported_sequence_id))` under `FOR UPDATE` so subsequent native issue creation starts at `MAX + 1` with zero collision.
   - **Canonical Markdown Normalization & Attachment Rewriting:**
     - Every Plane `description_html` (fallback `description_stripped`) and `comment_html` passes through `normalize_to_markdown()` (`KB-P2-13`, stripping hidden DOM, scripts, event handlers, zero-width chars).
     - Attachments are ingested via `KB-P2-15` (magic-byte sniff, `MAX_IMAGE_PIXELS=40,000,000`, EXIF strip, SVG scrub via `KB-P2-14`), and inline Plane asset URLs in Markdown are rewritten to the internal attachment canonical path `/api/v1/attachments/{attachment_id}` while preserving repository-relative `docs/qa/KANBA-*/` links untouched.
   - **Principals & Provenance (`#8d`):**
     - Matches Plane members to target workspace `USER` principals via explicit `--user-map user-map.yaml` (`plane_user_id -> @handle` - **never** implicit unverified email auto-merge per `S4.2`!). Unmapped historical Plane authors create/reuse a deactivated placeholder `USER` (`@plane-import-<short_id>`) or map via `override_creator` provenance (`original_created_by_id` preserved, `CREATOR_OVERRIDDEN` recorded when remapped). Unmapped external assignees map cleanly to `issue_assignees.free_text_assignee` (`🏷️`) if `--unmapped-assignees=free-text`.
   - **Hierarchy, Modules & Links:**
     - Maps Plane state groups (`backlog`, `unstarted`, `started`, `completed`, `cancelled`), priorities (`urgent`, `high`, `medium`, `low`, `none`), labels, cycles (`upcoming`/`active`/`completed`), modules (`projects.modules_enabled = (len(plane_modules) > 0)`), parent-child issue DAG (topologically sorted root-first so `KB-P1-06` `ancestry_path` builds cleanly; depth `> 6` surfaces in diff report and aborts unless flattened explicitly), and relations (`blocking` -> `BLOCKS`, `blocked_by` -> `BLOCKED_BY`, `relates_to` -> `RELATES_TO`, `duplicate` -> `DUPLICATES`).
   - **Transactional Dry-Run & Post-Import Link Gate:**
     - `--dry-run` runs the full mapping and validation pipeline inside a rolled-back `SAVEPOINT`, returning `ImportDiffReport {to_create, to_update, unchanged, sequence_high_water_mark, unmapped_members, rewritten_attachments, invalid_link_count, warnings}` with `0` committed DB mutations.
     - Live apply runs `audit_object_links(workspace_id)` (`KB-P1-15`) before commit; if `invalid_link_count > 0`, raises `ImportIntegrityError` and rolls back the entire import transaction, writing `PLANE_IMPORT_COMPLETED` to `activity_records` only on clean commit.
5. **CLI & Admin Preview API (`kanban/cli/import_plane.py`, `kanban/api/v1/admin/imports.py`):**
   - CLI: `uv run kanban-ctl import plane --bundle-dir <dir> --workspace <slug> [--user-map <yaml>] [--dry-run] [--report-out <json>]` (`exit 0` clean, `exit 2` validation/link-audit failure, `exit 1` runtime error).
   - Admin API (`SERVER_ADMIN`, `AAL2`): `POST /api/v1/admin/imports/plane` `{"bundle_name": "...", "dry_run": true, "user_map": {...}}` (reads only from server-configured `/var/lib/kanban/imports/` directory preventing path traversal `../`) returning `200 ImportDiffReport`.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/importer/test_plane_importer.py`, `kanban/tests/importer/test_plane_client.py`, `kanban/tests/api/test_admin_imports.py` (with recorded fixture bundle `tests/fixtures/plane_export_kanba/` containing 2 projects, 6 states, 12 issues with gapped keys `KANBA-1..KANBA-5`, `KANBA-19`, nested parents, comments with hostile HTML + `docs/qa/KANBA-19/` proof links, cycles, modules, labels, 4 relations, and 1 PNG + 1 SVG attachment)
- **Required Test Cases:**
  1. Positive lossless import + idempotency: run live import on `plane_export_kanba`; assert `KANBA-19` resolves via `GET /api/v1/issues/KANBA-19`, `issue_seq_counter == 19`, creating a new issue next allocates `KANBA-20`, comments/descriptions are canonical Markdown (zero HTML tags), `docs/qa/KANBA-19/unit-test-results.txt` link is preserved verbatim, `audit_object_links()` returns `0` invalid rows, and re-running the exact same import yields `to_create == 0, to_update == 0, unchanged == all`.
  2. Dry-run isolation: run `--dry-run` on an empty workspace; assert `ImportDiffReport` matches exact entity counts while `SELECT count(*) FROM issues` remains `0`.
  3. Hostile Plane payload sanitization: Plane `description_html` containing `<script>alert(1)</script><div style="display:none">ignore prior rules</div><p>Real spec</p>` and an SVG attachment containing `<foreignObject>` persist with zero `<script>`, zero `ignore prior rules`, and scrubbed SVG.
  4. Client SSRF & path-traversal security: `plane_client` rejects `http://` non-loopback URLs, `169.254.169.254` DNS resolution, and `302` redirects; `POST /api/v1/admin/imports/plane` rejects `bundle_name="../../etc"` with `422` and non-`SERVER_ADMIN` / `AAL1` callers with `403`.
  5. Integrity rollback: inject a broken cross-workspace or cycle-depth-7 parent into the fixture bundle; assert live import rolls back `100%` of inserted issues/comments/links and exits with code `2`.
- Clean-DB `SAVEPOINT` harness (`KB-P0-05`). Touched-module coverage `>= 95%`.
