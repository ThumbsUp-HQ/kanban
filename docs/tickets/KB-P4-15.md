### User Story
As an **operator running cross-workspace bots (`meatloaf-bot`) alongside repo-pinned IDE/CLI agents (`.gemini/settings.json`, `mcp_config.json`)**, I need **native Global (`/mcp/{surface}`), Workspace-scoped (`/mcp/{surface}/w/{workspace_slug}` or `X-Workspace-Slug`), and Project-scoped (`/mcp/{surface}/w/{workspace_slug}/p/{project_key}` or `X-Project-Key`) MCP connection modes** so that **a global bot can query across workspaces with zero custom wrapper scripts, while a project-pinned IDE connection automatically defaults to its project and physically cannot read or mutate another project.**

**Requirement Traceability:** `S11.1` (Zero-Script URL & Header Connection Scoping: Global, Workspace, Workspace + Project; monotonic narrowing), `S11.2`, `S11.3`, requirement `#1`, `#12` | **Dependencies:** `KB-P4-14`, `KB-P4-03`, `KB-P4-04`, `KB-P4-08`

### Scoped Technical Actions
1. **Target Files:**
   - `mcp/scoping.py` - `ConnectionScope` (`GLOBAL`, `WORKSPACE`, `PROJECT`), URL path + `X-Workspace-Slug` / `X-Project-Key` parser, monotonic intersection validator (`intersect_key_and_connection_scope()`).
   - `mcp/app.py` - mount scoped routes `/mcp/{surface}`, `/mcp/{surface}/w/{workspace_slug}`, and `/mcp/{surface}/w/{workspace_slug}/p/{project_key}` (plus matching `/.well-known/oauth-protected-resource/...` metadata paths) across `agent`, `docs`, and `admin`.
   - `mcp/internal_client.py` - forward resolved `X-KB-Scope-Workspace` and `X-KB-Scope-Project` headers on every `kanban-api` call; bind `(token_sha256, workspace_slug, project_key)` into `Mcp-Session-Id` fingerprint (`KB-P4-01`).
   - `kanban/api/deps.py` & `kanban/resolve/service.py` - support global cross-workspace resolution (`GET /api/v1/resolve` & `/api/v1/search/*` when `workspace` is unbound on a `global` token) and enforce hard session ceiling when `X-KB-Scope-Workspace` / `X-KB-Scope-Project` is set.
   - `mcp/errors.py` - append `KEY_SCOPE_VIOLATION`, `CONNECTION_SCOPE_VIOLATION`, `CONFLICTING_SCOPE_HEADERS` to `McpErrorCode`.
2. **Three Connection Scoping Modes (`mcp/scoping.py`):**
   - **Mode A - Global (`/mcp/{surface}`, no `X-Workspace-Slug` / `X-Project-Key` headers):**
     - If the token is `scope_tier = 'global'`: connection runs in `GLOBAL` mode across all workspaces in `EffectiveWorkspaces(principal) ∩ token.allowed_workspace_ids`.
       - Tools (`search_tickets`, `read_ticket`, `create_ticket`, `search_knowledge`, etc.) accept optional `workspace="<slug>"`.
       - `EntityResolver` resolves prefixed keys (`KANBA-14`, `NETALERTXN-22`) globally across authorized workspaces when unambiguous; if `>= 2` authorized workspaces contain project `APP` (`APP-1`), returns `AMBIGUOUS_IDENTIFIER` with `{workspace, key, title}` candidates and hint `"pass workspace=<slug> or connect via /mcp/agent/w/<slug>"`.
     - If the token itself is `scope_tier = 'workspace'` or `'project'`: connection automatically inherits the token's pinned `workspace_id` (and `project_id`), so a single-project key works seamlessly even against the short `/mcp/agent` URL!
   - **Mode B - Workspace-Scoped (`/mcp/{surface}/w/{workspace_slug}` OR `X-Workspace-Slug: <slug>`):**
     - Resolves `workspace_slug` against `Principal ∩ KeyScope`; if outside `KeyScope`, rejects at `initialize` / call with HTTP `403` `KEY_SCOPE_VIOLATION` (or `404` if caller has zero visibility of that workspace).
     - Pins `SET LOCAL app.workspace_id = <ws_uuid>` on every downstream `kanban-api` call; cross-workspace objects are completely unreachable.
   - **Mode C - Workspace + Project-Scoped (`/mcp/{surface}/w/{workspace_slug}/p/{project_key}` OR `X-Workspace-Slug` + `X-Project-Key`):**
     - Supplying `X-Project-Key` without a workspace (from path, header, or single-workspace token) returns HTTP `400` `VALIDATION_FAILED` (`"X-Project-Key requires X-Workspace-Slug or /w/{slug}"`).
     - Pins both `(workspace_id, project_id)`. Every tool taking an optional `project` parameter (`search_tickets`, `create_ticket`, `begin_work`, `manage_stickies`, `upsert_doc`, `architect_project`, `action="help"`) **auto-fills `project = <project_key>`** when omitted!
     - Any tool call explicitly passing a different `project="OTHER"` or referencing a sibling-project issue key (`NETALERTXN-22` while pinned to `KANBA`) is rejected before mutation with `isError: true`, `code: CONNECTION_SCOPE_VIOLATION` (except read-only display of cross-project `object_links` already permitted by RLS, which never allows mutating the foreign project).
3. **Header vs. Path Consistency & Session Fingerprint:**
   - If both URL path (`/w/kanban/p/KANBA`) and header (`X-Workspace-Slug` / `X-Project-Key`) are present and differ -> HTTP `400` `CONFLICTING_SCOPE_HEADERS`.
   - `Mcp-Session-Id` binds `sha256(token || "\0" || resolved_ws_id || "\0" || resolved_proj_id)`. Reusing a session ID created on `/mcp/agent/w/kanban/p/KANBA` against `/mcp/agent` (global) or `/w/kanban/p/OTHER` returns HTTP `404`.

### Mandatory Feature Unit Tests
- **Test File(s):** `mcp/tests/test_connection_scoping.py`, `kanban/tests/api/test_global_and_scoped_resolution.py`
- **Required Test Cases:**
  1. Positive (Global `meatloaf-bot` Flow): `global` key connects to `/mcp/agent`, runs `search_tickets(query="auth")` returning YAML rows tagged with `workspace: kanban` (`KANBA-4`) and `workspace: general` (`NETALERTXN-12`), and reads `NETALERTXN-12` directly without specifying `workspace` because `NETALERTXN` is globally unique.
  2. Positive (Ambiguous Global Key Disambiguation): two workspaces (`ws_prod`, `ws_stage`) both have project `API` and issue `API-1`; `read_ticket("API-1")` on global `/mcp/agent` returns `AMBIGUOUS_IDENTIFIER` listing both workspaces; `read_ticket("API-1", workspace="ws_prod")` returns `200` YAML for `ws_prod`.
  3. Positive (Project-Pinned Zero-Script Repo Config): global or workspace key connects to `/mcp/agent/w/kanban/p/KANBA` (and repeat test via `/mcp/agent` + `X-Workspace-Slug: kanban` + `X-Project-Key: KANBA`); `create_ticket(title="Test")` without `project=` creates `KANBA-<seq>`, and `search_tickets()` returns only `KANBA-*` issues.
  4. Security (Monotonic Narrowing & Cross-Project Block): while connected to `/mcp/agent/w/kanban/p/KANBA`, calling `update_ticket("NETALERTXN-1", ...)` or `create_ticket(project="GENER", ...)` fails with `CONNECTION_SCOPE_VIOLATION`; presenting a `project=KANBA` key to `/mcp/agent/w/general` fails with HTTP `403 KEY_SCOPE_VIOLATION`.
  5. Security (Conflicting Headers & Session Replay): `POST /mcp/agent/w/kanban` with `X-Workspace-Slug: general` -> HTTP `400 CONFLICTING_SCOPE_HEADERS`; replaying an `Mcp-Session-Id` from `/w/kanban/p/KANBA` on `/mcp/agent` -> HTTP `404`.
