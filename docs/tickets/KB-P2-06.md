### User Story
As a **workspace user signing in through an OIDC or OAuth2 card**, I need **an authorization-code flow with PKCE `S256`, server-stored single-use `state` and `nonce` (128-bit, `TTL = 300s`) bound to my browser, exact `iss`/`aud`/`azp` validation against an algorithm allowlist, rate-limited JWKS refresh, and `private_key_jwt` client authentication** so that **login CSRF, authorization code injection, IdP mix-up, token substitution, `alg` confusion, open redirects, and JWKS flooding cannot yield a session**.

**Requirement Traceability:** `S4.2` item 1 (PKCE `S256`, single-use `128-bit` state + nonce `TTL 300s`, `iss`/`aud`/`azp` pinning, `private_key_jwt`), `S4.1` (`public_config`, `encrypted_secret_blob`), `S2.5` (`joserfc`, `python-jose` banned), requirement `#6` | **Dependencies:** `KB-P2-03` (card storage + envelope), `KB-P2-02` (sessions, CSRF)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_oidc_auth_requests.py`
   - `kanban/auth/oidc/__init__.py`, `kanban/auth/oidc/config.py`, `kanban/auth/oidc/discovery.py`, `kanban/auth/oidc/flow.py`, `kanban/auth/oidc/tokens.py`, `kanban/auth/identity.py` (protocol only)
   - `kanban/api/v1/auth_oidc.py` (`GET /api/v1/auth/oidc/{slug}/start`, `GET /api/v1/auth/oidc/{slug}/callback`)
   - `kanban/tests/fixtures/fake_idp.py` (ASGI fake IdP served through `httpx.MockTransport`)
2. **Card `public_config` schema (`config.py`, Pydantic, `extra="forbid"`):** `kind: Literal["OIDC","OAUTH2"]`, `issuer: HttpsUrl` (OIDC), `authorization_endpoint`, `token_endpoint`, `userinfo_endpoint` (OAUTH2 required; OIDC from discovery), `client_id: str (<=255)`, `client_auth: Literal["client_secret_basic","private_key_jwt"]`, `scopes: list[str]` (OIDC must include `openid`), `subject_claim: str` (default `sub`; OAUTH2 e.g. `id`), `email_claim`, `groups_claim | None`, `allowed_algs: list[Literal["RS256","PS256","ES256","EdDSA"]]` (default `["RS256","ES256"]`). Secret blob (KB-P2-03 envelope) holds `client_secret` or the PEM private key for `private_key_jwt`. All URLs must be `https://`; hosts resolving to loopback or `169.254.0.0/16` / `fe80::/10` are rejected unless `KANBAN_AUTH_EGRESS_ALLOW_PRIVATE=true` (RFC1918 permitted for on-prem IdPs by default).
3. **Discovery & JWKS (`discovery.py`):** fetch `{issuer}/.well-known/openid-configuration` with `httpx.AsyncClient(follow_redirects=False, timeout=httpx.Timeout(5.0))`, max body `256 KiB`; returned `issuer` must equal configured `issuer` byte-for-byte (mix-up defense). JWKS cached per card `TTL 3600s`; unknown `kid` triggers at most one refetch per card per `60s`; JWKS with `> 20` keys or private key members (`d`, `p`, `q`) rejected. Errors surface as `OidcError(code)` and never echo response bodies.
4. **Start (`flow.py`):** create row in `oidc_auth_requests(id, card_id, state_hash BYTEA UNIQUE, nonce BYTEA, code_verifier_sealed BYTEA, browser_binding_hash BYTEA, return_to TEXT, link_intent_id UUID NULL, expires_at, consumed_at)` (kb_auth boundary). `state = secrets.token_bytes(16)`, `nonce = secrets.token_bytes(16)`, `code_verifier = secrets.token_urlsafe(32)` (43 chars), `code_challenge = b64url(sha256(verifier))`, `code_challenge_method=S256`. Browser binding: random 32-byte value in cookie `__Host-kb_oidc` (`Secure; HttpOnly; SameSite=Lax; Path=/; Max-Age=300`), stored as hash. `redirect_uri` fixed to `{KANBAN_PUBLIC_ORIGIN}/api/v1/auth/oidc/{slug}/callback`. `return_to` accepted only if it matches `^/(?![/\\])[A-Za-z0-9/_\-.?=&%]{0,512}$`, else `/`.
5. **Callback:** `error` param -> `400 OIDC_PROVIDER_ERROR` (provider text not echoed). Consume `oidc_auth_requests` row by `sha256(state)` atomically (`consumed_at IS NULL AND expires_at > now()`), require browser binding cookie hash match, then token exchange: `grant_type=authorization_code`, `code`, `redirect_uri`, `code_verifier`; client auth `client_secret_basic` or `private_key_jwt` (`client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer`, assertion claims `iss=sub=client_id`, `aud=token_endpoint`, `jti=uuid4`, `iat`, `exp=iat+60`, signed with card key via `joserfc`). Token response max `64 KiB`.
6. **ID token validation (`tokens.py`, `joserfc` only):** `alg` in card `allowed_algs` (reject `none`, any `HS*`, header `jku`/`x5u`/`jwk` ignored, never fetched); signature by JWKS key matching `kid` and `kty` compatible with `alg`; `iss == issuer`; `aud` contains `client_id`; if `aud` has more than one value then `azp == client_id` required; `exp`, `iat`, `nbf` with `60s` skew; `iat` not older than `600s`; `nonce == stored nonce`. OAUTH2 kind: fetch `userinfo_endpoint` with access token; subject taken from `subject_claim`, must be string or integer, coerced to string, `<= 255` chars.
7. **Output contract (`identity.py`):** `@dataclass(frozen=True) class ExternalIdentityAssertion(card_id: UUID, subject: str, email: str | None, email_verified: bool, display_name: str | None, groups: tuple[str, ...])`; `class IdentityResolver(Protocol): async def resolve(self, assertion, request, link_intent_id: UUID | None) -> ResolvedLogin`. Default resolver until KB-P2-08 is installed: `RejectAllIdentityResolver` -> `403 IDENTITY_NOT_PROVISIONED`. Email is never used for account lookup in this ticket.
8. **Security invariants asserted:** (a) `state` usable once, only within `300s`, only from the browser that started the flow; (b) id_token accepted only from pinned issuer, for this client, with allowlisted asymmetric alg and matching nonce; (c) no redirect target outside the origin; (d) secrets (client secret, private key, code verifier, tokens) never logged or returned.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/auth/test_oidc_flow.py`, `kanban/tests/auth/test_oidc_tokens.py`, `kanban/tests/auth/test_oidc_discovery.py`
- **Required Test Cases (all against `fake_idp.py`):**
  1. Positive OIDC: start -> fake IdP authorize -> callback -> resolver receives assertion with `subject`, `email_verified`; `code_challenge_method=S256` observed by fake IdP and verifier matches challenge.
  2. Positive OAUTH2 (GitHub-style): no id_token, userinfo numeric `id: 4242` -> `subject="4242"`.
  3. Positive `private_key_jwt`: fake IdP verifies assertion signature, `aud=token_endpoint`, `exp - iat == 60`.
  4. Security (state replay): same callback URL submitted twice -> second `400 OIDC_STATE_INVALID`; state after `301s` -> `400`.
  5. Security (login CSRF / browser binding): valid state with missing or different `__Host-kb_oidc` cookie -> `400 OIDC_STATE_INVALID`.
  6. Security (nonce): id_token with a nonce from a different request -> `401 OIDC_TOKEN_INVALID`.
  7. Security (alg confusion): token with `alg=none`; token with `HS256` signed using the RSA public key PEM as HMAC secret; token with `jku` pointing at attacker JWKS -> all `401`.
  8. Security (claims): wrong `iss`, `aud` missing client, multi-`aud` without `azp`, `azp` = other client, `exp` past by 61s, `iat` 601s old -> all `401`; `exp` past by 59s accepted.
  9. Security (mix-up): discovery doc whose `issuer` differs from configured -> `OidcError(ISSUER_MISMATCH)`, no authorize redirect issued.
  10. Security (JWKS flood): 50 tokens with random unknown `kid` within 60s -> exactly 1 JWKS refetch; JWKS containing `d` member rejected.
  11. Security (open redirect): `return_to` values `//evil.example`, `/\evil.example`, `https://evil.example`, `/%2F%2Fevil.example` stored as `/`; `/projects/KAN` preserved.
  12. Security (SSRF config): issuer `https://127.0.0.1/` and `https://169.254.169.254/` rejected at config validation; redirect `302` from discovery endpoint not followed (`OidcError(REDIRECT_REFUSED)`).
  13. Boundary: token response of `64 KiB + 1` -> `OidcError(RESPONSE_TOO_LARGE)`; subject of 256 chars -> `401`.
  14. Secret hygiene: caplog at `DEBUG` across tests 1-3 contains none of client secret, private key PEM, code verifier, authorization code, access token, id_token.
