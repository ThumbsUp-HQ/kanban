### User Story
As a **Workspace or Server Administrator**, I need **`purge_invalid_object_links(p_audit_ids, p_actor_id, p_reason)` that verifies admin privileges, deletes ONLY `FLAGGED_INVALID` links backed by open audit snapshots, stamps the audit rows as purged, blocks raw un-audited `DELETE`s of flagged links, and appends `INVALID_OBJECT_LINK_PURGED` to `activity_records`** so that **invalid graph edges can be cleaned up with a permanent cryptographic audit trail while `ACTIVE` links can never be accidentally purged**.

**Requirement Traceability:** `S12.3` (`purge_invalid_object_links(p_audit_ids UUID[], p_actor_id UUID, p_reason TEXT)`, `INVALID_OBJECT_LINK_PURGED` activity event), `S11.4` tool 11 (`audit_and_purge_object_links`), Requirement `#13j` | **Dependencies:** `KB-P1-15`, `KB-P1-12`

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/p1_16_link_purger.py` (`down_revision` = current single Alembic head)
   - `database/migrations/sql/p1_16_link_purger.up.sql`, `database/migrations/sql/p1_16_link_purger.down.sql`
   - `database/tests/test_p1_16_link_purger.py`, `database/tests/migrations/test_p1_16_migration.py`

2. **Direct-Delete Guard on Flagged Links (`object_links_flagged_delete_guard_bd`):**
   - `BEFORE DELETE ON object_links FOR EACH ROW`: if `OLD.link_state = 'FLAGGED_INVALID'` and `COALESCE(current_setting('kb.in_audited_purge', true), '') <> 'on'`, raises `ERRCODE = 'P0001', MESSAGE = 'FLAGGED_LINK_REQUIRES_AUDITED_PURGE'`. (`ACTIVE` links remain deletable through normal `LINK`-capability operations in KB-P3-07.)

3. **`purge_invalid_object_links(p_audit_ids uuid[], p_actor_id uuid, p_reason text) RETURNS TABLE(purged_audit_id uuid, purged_link_id uuid, activity_id uuid)`:**
   - `VOLATILE SECURITY DEFINER`, `SET search_path = pg_catalog, public`, owned by `kanban_migrator`, `GRANT EXECUTE TO kanban_app`.
   - **Validation & Authorization (all fail closed before mutating any row):**
     1. `p_audit_ids IS NULL OR coalesce(array_length(p_audit_ids, 1), 0) NOT BETWEEN 1 AND 1000` -> `PURGE_AUDIT_IDS_INVALID`. Deduplicate `p_audit_ids` preserving deterministic UUID sort order before locking to prevent lock-order deadlocks.
     2. `p_reason IS NULL OR char_length(btrim(p_reason)) NOT BETWEEN 3 AND 1000` -> `PURGE_REASON_REQUIRED`.
     3. `v_session_actor := app_current_principal_id(); v_ws := app_current_workspace_id();` if `v_session_actor IS NULL OR v_ws IS NULL` -> `RLS_CONTEXT_REQUIRED`; if `v_session_actor IS DISTINCT FROM p_actor_id` -> `PURGE_ACTOR_MISMATCH`.
     4. Verify `app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])` (supports human admins and authorized system `SERVICE_PRINCIPAL`s such as `system:trash-purge` in KB-P3-09b when bound to `WORKSPACE_ADMIN`/`SERVER_ADMIN`) -> else `PURGE_FORBIDDEN`.
   - **Atomic Lock, Check, Delete & Ledger Write:**
     1. Lock all `invalid_object_link_audits` rows matching `id = ANY(v_sorted_ids)` ordered by `id FOR UPDATE`. If count `< cardinality(v_sorted_ids)` or any row has `workspace_id <> v_ws` -> `PURGE_AUDIT_NOT_FOUND`.
     2. If any locked audit row has `purged_at IS NOT NULL` -> `PURGE_ALREADY_EXECUTED`; if `resolved_at IS NOT NULL` -> `PURGE_AUDIT_RESOLVED`.
     3. Lock corresponding `object_links` rows ordered by `id FOR UPDATE`. If a link row is missing -> `PURGE_LINK_MISSING`; if `link_state <> 'FLAGGED_INVALID'` -> `PURGE_ACTIVE_LINK_REFUSED` (whole call aborts, zero rows deleted).
     4. Set `PERFORM set_config('kb.in_audited_purge', 'on', true);`, `DELETE FROM object_links WHERE id = ANY(v_link_ids);`, then reset `PERFORM set_config('kb.in_audited_purge', '', true);`.
     5. Update all open `invalid_object_link_audits` rows on `v_link_ids` (including sibling open audit reasons for the same `link_id`): `purged_at = clock_timestamp(), purged_by_id = p_actor_id, purge_reason = btrim(p_reason)`.
     6. For each purged link, determine activity anchor `(v_obj_id, v_obj_type)`: if `objects` still contains `(ol.source_id, ol.source_type)` in `v_ws`, use `(ol.source_id, ol.source_type)`, else if `(ol.target_id, ol.target_type)` exists in `objects`, use `(ol.target_id, ol.target_type)`, else `(NULL, NULL)` (when both endpoints were dangling); call `append_activity(v_ws, v_obj_id, v_obj_type, p_actor_id, 'INVALID_OBJECT_LINK_PURGED', jsonb_build_object('audit_ids', v_audit_ids_for_link, 'link_id', v_link_id, 'reasons', v_reasons_for_link, 'purge_reason', btrim(p_reason), 'source_key_snapshot', v_src_key, 'target_key_snapshot', v_tgt_key))`.

4. **Down Migration:** Drops `purge_invalid_object_links`, `object_links_flagged_delete_guard_bd`, and its trigger function.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_16_link_purger.py`, `database/tests/migrations/test_p1_16_migration.py`
- **Required Test Cases:**
  1. Positive: flag 2 invalid links via `audit_object_links` (one `ARCHIVED_POLICY_VIOLATION`, one `DANGLING_SOURCE`), invoke `purge_invalid_object_links(ARRAY[a1, a2], admin_id, 'Cleanup archived blockers')` as `WORKSPACE_ADMIN` -> both `object_links` rows are deleted, both `invalid_object_link_audits` rows survive with non-NULL `purged_at`, `purged_by_id = admin_id`, `purge_reason = 'Cleanup archived blockers'`, and 2 `INVALID_OBJECT_LINK_PURGED` rows exist in `activity_records` (`verify_activity_chain(ws)` returns `is_valid = true`).
  2. Positive (multi-reason sibling closure & `SERVICE_PRINCIPAL`): a single link flagged with both `ARCHIVED_POLICY_VIOLATION` and `PERMISSION_SEVERED` purged via one audit ID marks both audit rows purged and deletes the link once; a `SERVICE_PRINCIPAL` bound to `WORKSPACE_ADMIN` succeeds.
  3. Security (bypass & role checks): direct `DELETE FROM object_links` on a `FLAGGED_INVALID` row (even as admin or superuser without the internal GUC) raises `FLAGGED_LINK_REQUIRES_AUDITED_PURGE`, while deleting an `ACTIVE` link succeeds; `MEMBER` or `PROJECT_ADMIN` calling `purge_invalid_object_links` raises `PURGE_FORBIDDEN`; mismatching `p_actor_id <> app_current_principal_id()` raises `PURGE_ACTOR_MISMATCH`; missing RLS context raises `RLS_CONTEXT_REQUIRED`.
  4. Negative (`ACTIVE` refusal & replay): tampering `object_links.link_state` back to `'ACTIVE'` while an audit row is open causes `purge_invalid_object_links` to raise `PURGE_ACTIVE_LINK_REFUSED` and delete `0` links; calling `purge_invalid_object_links` a second time with an already-purged `audit_id` raises `PURGE_ALREADY_EXECUTED`; resolved audit ID raises `PURGE_AUDIT_RESOLVED`; cross-workspace or unknown `audit_id` raises `PURGE_AUDIT_NOT_FOUND`.
  5. Boundary: empty `ARRAY[]::uuid[]` raises `PURGE_AUDIT_IDS_INVALID`; `p_reason = '  '` or `'ab'` (2 chars) raises `PURGE_REASON_REQUIRED`.
  6. Migration up/down: `MigrationHarness` upgrade `p1_16_link_purger` -> function and delete-guard trigger exist; downgrade to `previous_of(...)` -> absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
