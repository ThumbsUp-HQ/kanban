### User Story
As a **project member or agent triaging work**, I need **saved views CRUD across all five native layouts (`list`, `board`, `table`, `calendar`, `timeline`) and a typed filter/group query engine executing strictly inside PostgreSQL `FORCE RLS`** so that **every board, swimlane, table, calendar, Gantt timeline, and MCP filter query evaluates one validated DSL with zero cross-project leakage**.

**Requirement Traceability:** Spec S6.4 items 2-3 (5 native views, 2D `group_by` x `sub_group_by` swimlanes, WIP config); S3.4 (`access_manifest`, indistinguishable `404`); S11.2 item 1 (`search_tickets` filter reuse); requirements `#9j`, `#13h`, `#1` | **Dependencies:** `KB-P3-02`, `KB-P3-01b`, `KB-P1-10`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/views.py`, `kanban/api/v1/schemas/views.py`, `kanban/services/views.py`, `kanban/services/query_engine.py`, `kanban/services/activity.py` (append event types).
2. **Filter & Grouping DSL (`FilterSpec` and `ViewSpec`, Pydantic v2 `extra="forbid"`):**
   - `layout`: enum `list | board | table | calendar | timeline`.
   - `group_by` / `sub_group_by`: enum `none | state | priority | assignee | cycle | module | label` (defaults: `board` -> `group_by="state"`, `sub_group_by="none"`; others -> `"none"`). When `sub_group_by != "none"` and `sub_group_by == group_by`, return `422 DUPLICATE_GROUP_AXIS`. Referencing `"module"` in `group_by`, `sub_group_by`, or `filters.module_ids` when `projects.modules_enabled = FALSE` returns `422 MODULES_DISABLED` (S7.2 `8f`).
   - `filters` (`FilterSpec`, max `50` items per array, max JSON payload `32768` bytes):
     ```json
     {
       "state_ids": ["..."],
       "state_groups": ["backlog", "unstarted", "started", "completed", "cancelled"],
       "priority_ids": ["..."],
       "assignee_ids": ["me", "unassigned", "<principal_uuid>"],
       "has_free_text_assignee": true,
       "label_ids": ["..."],
       "label_match": "any",
       "cycle_ids": ["none", "active", "<cycle_uuid>"],
       "module_ids": ["none", "<module_uuid>"],
       "parent_issue_id": "<issue_uuid>|null",
       "start_date_from": "2026-11-01",
       "start_date_to": "2026-11-30",
       "due_date_from": "2026-11-01",
       "due_date_to": "2026-11-30",
       "overdue_only": false,
       "blocked": true,
       "gate_status": "pending",
       "include_archived": false
     }
     ```
   - Semantics in `compile_issue_filter_predicates(session, project, filters, caller_principal_id)` (`kanban/services/query_engine.py`):
     - Always excludes `objects.deleted_at IS NOT NULL`; excludes `objects.archived_at IS NOT NULL` unless `include_archived=true`.
     - `"me"` resolves to `caller_principal_id`; `"unassigned"` matches issues with zero rows in `issue_assignees`.
     - `label_match`: `"any"` (default) or `"all"`.
     - `overdue_only=true`: `due_date < CURRENT_DATE AND workflow_states.group NOT IN ('completed', 'cancelled')`.
     - `blocked=true`: `EXISTS` an `ACTIVE` `object_links` row with `link_type = 'BLOCKS'` and `target_id = issues.id` whose source issue is readable under RLS and not in `completed`/`cancelled` (or `link_type = 'BLOCKED_BY'` with `source_id = issues.id` pointing to an open readable blocker). Unreadable blockers never influence `blocked` predicates (zero side-channel leakage).
     - `gate_status`: `"pending"` filters `issues.pending_transition_exec_id IS NOT NULL`; `"approved"` / `"rejected"` return `0` rows cleanly until Phase 5 (`workflow_transition_executions`), matching `KB-P4-04`.
     - `sort_by`: enum `board_rank | sequence_id | updated_at | due_date | priority` + `sort_dir`: `asc | desc` (default `board_rank asc` on `board`, `sequence_id desc` elsewhere).
3. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `GET /api/v1/projects/{project_ref}/views` | `VIEW` on project (RLS filters private views) | `200` | `404` |
   | `POST /api/v1/projects/{project_ref}/views` | `VIEW` for private (`is_shared=false`); `EDIT` for shared (`is_shared=true`) | `201` | `404`, `403`, `422` |
   | `GET /api/v1/views/{view_id}` | `VIEW` on view | `200` | `404` |
   | `PATCH /api/v1/views/{view_id}` | owner or project `ADMIN` (`EDIT` required to flip `is_shared=true`) | `200` | `404`, `403`, `422` |
   | `DELETE /api/v1/views/{view_id}` | owner or project `ADMIN` | `204` | `404`, `403` |
   | `GET /api/v1/views/{view_id}/issues?cursor=&limit=` | `VIEW` on view | `200` | `404`, `422 INVALID_CURSOR` |
   | `POST /api/v1/projects/{project_ref}/issues:query` | `VIEW` on project | `200` | `404`, `422` |

   - Creating a view registers an `objects` spine row (`object_type='view'`). When `is_shared=false`, direct `ALLOW` ACL (`VIEW|EDIT|DELETE`) is granted only to `owner_id` (plus project `ADMIN` via RBAC) and project-wide inherited `VIEW` is suppressed per `KB-P1-10` / `KB-P1-13` so other members receive `404` on `GET /api/v1/views/{view_id}`.
   - Query response (`limit` `1..200`, default `50`; cursor = base64url JSON `[sort_value, issue_id]` HMAC-bound to the canonical query hash so a cursor reused with different filters returns `422 INVALID_CURSOR`):
     ```json
     {
       "items": [{"id": "0193...", "key": "KAN-142", "summary": "...", "board_rank": "a00002A", "...": "..."}],
       "groups": [
         {"group_key": "state:0193...", "label": "In Progress", "count": 4,
          "wip": {"soft": 3, "hard": 5, "exceeded": "soft"},
          "sub_groups": [{"sub_group_key": "priority:urgent", "label": "Urgent", "issue_ids": ["0193..."]}]}
       ],
       "timeline_links": [{"source_key": "KAN-140", "target_key": "KAN-142", "link_type": "BLOCKS"}],
       "next_cursor": "eyJ...",
       "total_matching": 18
     }
     ```
     `timeline_links` is populated when `layout == "timeline"` with `ACTIVE` `BLOCKS` links where both endpoints are in the returned readable issue set.
   - View serializer includes `id`, `name` (`1..120` chars), `description_markdown` (`<= 16384` bytes via `normalize_to_markdown`), `layout`, `filters`, `group_by`, `sub_group_by`, `wip_limits_override`, `is_shared`, `owner`, `access_manifest`, and `capabilities`.
4. **Activity events emitted (category `HISTORY`):** `VIEW_CREATED {layout, is_shared}`, `VIEW_UPDATED {changes}`, `VIEW_DELETED {}` recorded against the view object (`VIEW_DELETED` against the project object when row is removed).
5. **Security invariants:** zero raw SQL interpolation; every predicate binds typed SQLAlchemy parameters; `blocked` and `total_matching` execute inside the caller's RLS transaction so restricted issues cannot be inferred via counts or timing.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_views.py`, `kanban/tests/services/test_query_engine.py`
- **Required Test Cases:**
  1. Positive: create shared `board` view (`group_by="state"`, `sub_group_by="priority"`) and `timeline` view; query returns expected grouped buckets, soft WIP status, and `timeline_links` for `BLOCKS` pairs.
  2. Filter DSL matrix: verify `state_groups`, `assignee_ids=["me"]`, `assignee_ids=["unassigned"]`, `label_match="all"` vs `"any"`, `cycle_ids=["none"]`, `overdue_only=true` (excludes `Done` issues with past `due_date`), `blocked=true`, and `gate_status="pending"`.
  3. Security & RLS: private view (`is_shared=false`) created by user A returns `404` (equalized) to co-member user B and is omitted from B's `GET .../views`; `blocked=true` does NOT match an issue whose only `BLOCKS` source lives in an unreadable project `SEC`; `VIEW`-only member creating `is_shared=true` gets `403`.
  4. Modules gate: when `projects.modules_enabled = FALSE`, `group_by="module"` or `filters.module_ids=["..."]` returns `422 MODULES_DISABLED`.
  5. Boundary: `group_by == sub_group_by == "state"` returns `422 DUPLICATE_GROUP_AXIS`; `limit=201` returns `422`; `state_ids` with 51 items returns `422`; cursor from query A replayed against modified filter B returns `422 INVALID_CURSOR`; pagination across 55 issues (`limit=25`) yields 25 + 25 + 5 with zero duplicates.
