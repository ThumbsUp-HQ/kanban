### User Story
As an **operator booting a fresh Kanban instance (`docker run` standalone or production compose)**, I need **zero default passwords (`admin/admin` never exists), a single-use 256-bit `kb_setup_<base64url>` token (`TTL = 60m`) hashed at rest and printed exclusively to container stdout logs when `0` users exist, and a `POST /api/v1/setup/claim` endpoint that atomically provisions the first `SERVER_ADMIN` and forces immediate Passkey or TOTP enrollment** so that **exposed fresh instances cannot be claimed with default credentials and the setup link becomes permanently inert the instant it is claimed or expires**.

**Requirement Traceability:** `S2.2` item 4 (zero default passwords, single-use 256-bit `kb_setup_<base64url>` token `TTL = 60m` printed exclusively to `docker logs`: `First-boot setup URL: http://localhost:8080/setup?token=kb_setup_...`), `S3.5` row "Standalone `docker run` Misconfiguration", `S4.2` item 3 (Argon2id + mandatory Passkey/TOTP `AAL2` for Admin roles), requirement `#3`, `#6` | **Dependencies:** `KB-P0-09` (first-boot CSPRNG keyring), `KB-P2-05a` (TOTP + recovery codes + `mfa_pending` admin enforcement; transitively `KB-P2-04`), `KB-P2-05b` (WebAuthn Passkey first-factor enrollment on `mfa_pending` session), `KB-P2-18` (`SETUP_CLAIM_IP` rate limiter)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_setup_claim_tokens.py`, `database/models/auth.py` (add `SetupClaimToken`)
   - `kanban/auth/setup.py` (`SetupBootstrapService`, `mint_setup_token_if_uninitialized`, `claim_initial_admin`)
   - `kanban/api/v1/auth_setup.py` (`POST /api/v1/setup/claim`, `GET /api/v1/setup/status`)
   - `kanban/app.py` (wire lifespan startup hook calling `mint_setup_token_if_uninitialized` and printing notice exclusively to bootstrap stream when minted)
2. **DDL `setup_claim_tokens`** (`kb_auth` boundary: owned by `kb_auth_owner`, revoked from `kanban_app` and `app_rls_reader`, `FORCE RLS`, accessed solely via `SECURITY DEFINER` functions with `SET search_path = pg_catalog, public`):
   ```sql
   CREATE TABLE setup_claim_tokens (
     id                        UUID PRIMARY KEY DEFAULT uuidv7(),
     token_hmac                BYTEA NOT NULL UNIQUE CHECK (octet_length(token_hmac) = 32),
     created_at                TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
     expires_at                TIMESTAMPTZ NOT NULL,
     revoked_at                TIMESTAMPTZ,
     consumed_at               TIMESTAMPTZ,
     consumed_by_principal_id  UUID REFERENCES principals(id) ON DELETE SET NULL
   );
   ```
   `kb_auth` functions:
   - `kb_auth.setup_is_initialized() RETURNS boolean`: returns `EXISTS (SELECT 1 FROM users LIMIT 1)`.
   - `kb_auth.setup_mint_token(p_token_hmac bytea, p_ttl_seconds int DEFAULT 3600) RETURNS boolean`: acquires `pg_advisory_xact_lock(hashtextextended('kb_setup_claim', 0))`; if `EXISTS (SELECT 1 FROM users)` returns `FALSE` without inserting; otherwise revokes any prior unconsumed `setup_claim_tokens` (`revoked_at = clock_timestamp()`), inserts new row with `expires_at = clock_timestamp() + make_interval(secs => p_ttl_seconds)`, and returns `TRUE`.
   - `kb_auth.setup_consume_and_create_admin(p_token_hmac bytea, p_username text, p_display_name text, p_email text, p_password_hash text) RETURNS TABLE(principal_id uuid, workspace_id uuid, local_card_id uuid)`: acquires the same `kb_setup_claim` advisory lock; verifies `NOT EXISTS (SELECT 1 FROM users)` AND atomically updates matching row `WHERE token_hmac = p_token_hmac AND consumed_at IS NULL AND revoked_at IS NULL AND expires_at > clock_timestamp()` (if `0` rows updated -> returns zero rows, zero side effects); otherwise ensures a default workspace exists (creating `"Default Workspace"` if empty), ensures an enabled `LOCAL_ADMIN` card (`slug = 'local-admin'`) exists, registers `objects(object_type='user')` + `principals(principal_type='USER', status='ACTIVE')` + `users` + `local_admin_credentials` (`KB-P2-04`) + `SERVER_ADMIN` role binding (`KB-P1-13`), sets `consumed_by_principal_id`, appends `FIRST_BOOT_SETUP_CLAIMED` to `activity_records` (`KB-P1-12`), and returns `(principal_id, workspace_id, local_card_id)`.
3. **Token Format, Hashing & Log-Only Emission (`kanban/auth/setup.py`):**
   - Raw entropy: `raw = secrets.token_bytes(32)` (256 bits), formatted `"kb_setup_" + base64.urlsafe_b64encode(raw).rstrip(b"=").decode("ascii")` (exact regex `^kb_setup_[A-Za-z0-9_-]{43}$`, total length `52` chars, matching `KB-P3-35`).
   - At-rest digest: `HMAC-SHA256(derive_subkey(key_material.auth_pepper, "setup/claim-token"), token.encode("ascii"))`. Plaintext token never enters SQL parameters, structured JSON logs, exception messages, `/run/kanban/standalone_status.json`, or any HTTP response.
   - When `mint_setup_token_if_uninitialized` returns a minted token, writes to dedicated stdout bootstrap stream the exact `S2.2` item 4 banner line:
     `First-boot setup URL: {public_origin}/setup?token={token}`
     and immediately overwrites temporary bytearray buffers. When `users` count `>= 1`, emits nothing and mints nothing.
4. **Endpoints (`kanban/api/v1/auth_setup.py`):**
   - `GET /api/v1/setup/status`: unauthenticated, returns `{"initialized": bool}` ONLY (never indicates whether an unexpired token exists, never echoes token metadata).
   - `POST /api/v1/setup/claim`:
     - Rate-limited by `SETUP_CLAIM_IP` (`10 / 3600s` per client IP via `KB-P2-18`).
     - Request model (`extra="forbid"`): `token: str`, `username: str` (`^[a-z0-9][a-z0-9._-]{2,62}$`), `display_name: str` (`1..120` chars after `btrim`), `password: str` (`14..1024` UTF-8 bytes), `email: str | None = None` (defaults to `f"{username}@local.kanban"` when omitted so `KB-P1-03` `users.email` CHECK and `KB-P3-35` 4-field form both succeed).
     - CSRF: requires valid pre-session double-submit CSRF token (`GET /api/v1/auth/session` / `__Host-kb_csrf`) OR `Origin == KANBAN_PUBLIC_ORIGIN` (`KB-P2-02`; `/api/v1/setup/claim` is NOT added to `CSRF_EXEMPT_PATHS`).
     - Validates `token` against `^kb_setup_[A-Za-z0-9_-]{43}$`, computes `token_hmac`, hashes `password` via `KB-P2-04` Argon2id+pepper (`m=64MiB, t=3, p=4`, executing dummy verify on format failure so timing is equalized), and calls `kb_auth.setup_consume_and_create_admin`.
     - Any token failure (malformed, wrong bytes, expired `> 60m`, superseded on restart, already consumed, or instance already initialized) returns the identical `401 SETUP_TOKEN_INVALID` problem document.
     - On success: issues session cookie via `SessionService.create_after_login(..., aal=1, mfa_pending=True)` so the new `SERVER_ADMIN` is gated from `/api/v1/admin/*` (`403 MFA_ENROLLMENT_REQUIRED`) until completing Passkey (`KB-P2-05b`) or TOTP (`KB-P2-05a`) enrollment + recovery code generation; returns `200 {"status": "enrollment_required", "principal_id": str(principal_id), "enrollment_id": str(session.id)}`.
5. **Security invariants asserted:** (a) zero default accounts exist before claim; (b) DB dump of `setup_claim_tokens` yields only peppered HMAC digests; (c) token is usable at most once and only within `3600s` while `0` users exist; (d) newly claimed admin session starts at `mfa_pending=True` and cannot reach admin routes before AAL2 factor enrollment.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/auth/test_setup_claim.py`, `database/tests/test_setup_tokens_boundary.py`
- **Required Test Cases:**
  1. Positive full lifecycle: fresh empty DB -> `mint_setup_token_if_uninitialized` emits `First-boot setup URL: http://localhost:8080/setup?token=kb_setup_...` matching `^kb_setup_[A-Za-z0-9_-]{43}$` -> `GET /api/v1/setup/status` returns `{"initialized": false}` -> `POST /api/v1/setup/claim` returns `200 {"status": "enrollment_required", ...}` and sets `__Host-kb_session` (`mfa_pending=True`) -> calling `/api/v1/admin/auth-cards` immediately returns `403 MFA_REQUIRED` / `MFA_ENROLLMENT_REQUIRED` -> enrolling TOTP (`KB-P2-05a`) elevates session to `aal_level=2` and unlocks admin routes -> `GET /api/v1/setup/status` returns `{"initialized": true}`.
  2. Positive Passkey branch: claim -> register WebAuthn passkey (`KB-P2-05b` soft authenticator on `mfa_pending` first-enrollment path) -> assert passkey -> `aal_level=2`.
  3. Security (single-use replay): submitting the exact same valid `kb_setup_*` token a second time returns `401 SETUP_TOKEN_INVALID` and creates zero duplicate users.
  4. Security (concurrency race, `@pytest.mark.committed_db`): 10 concurrent `POST /api/v1/setup/claim` requests carrying the valid setup token -> exactly `1` returns `200` and `9` return `401 SETUP_TOKEN_INVALID`; `SELECT count(*) FROM users` equals `1`.
  5. Security (TTL expiry): advancing DB/token `expires_at` past `3600s` (`3601s` elapsed) -> `401 SETUP_TOKEN_INVALID`.
  6. Security (restart rotation & post-init silence): restarting before claim mints token T2 and revokes T1 (`T1 -> 401 SETUP_TOKEN_INVALID`, `T2 -> 200`); restarting AFTER claim (`1` user exists) mints `None` and writes nothing to stdout.
  7. Security (at-rest hashing & DB boundary): `SELECT token_hmac FROM setup_claim_tokens` (as superuser) contains neither the `kb_setup_` string nor raw `sha256(token)` (proves peppered HMAC); as `kanban_app`, `SELECT * FROM setup_claim_tokens` raises `42501`.
  8. Security (rate limit & enumeration): 11th failed claim from one IP within 3600s -> `429 RATE_LIMITED`; malformed token (`kb_setup_short`), wrong token, expired token, and post-init token produce byte-identical `401 SETUP_TOKEN_INVALID` bodies (excluding `request_id`).
  9. Boundary & secret hygiene: `13`-char password -> `422 VALIDATION_FAILED` (min 14 chars); `caplog` at `DEBUG` during mint and claim contains neither the `kb_setup_` token nor the password.
