### User Story
As a **security engineer**, I need **opaque server-side sessions referenced by HMAC-signed `__Host-` cookies, rotated on every login and AAL change, expired by idle and absolute timeouts, and protected by session-bound double-submit CSRF on every unsafe method** so that **session fixation, cookie forgery, cookie tossing from sibling subdomains, stolen-cookie longevity, and cross-site request forgery are each blocked at a single choke point**.

**Requirement Traceability:** `S4` (multi-card auth sessions, AAL levels used by S4.2 item 3), `S3.3` (`app.aal_level` binding), requirement `#6` | **Dependencies:** `KB-P2-01` (`PrincipalResolver`, `derive_subkey`, problem model), `KB-P2-03` (`kb_auth` schema and `kb_auth_owner` role)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_sessions.py`, `database/models/auth.py` (add `UserSession`)
   - `kanban/auth/sessions/__init__.py`, `kanban/auth/sessions/service.py`, `kanban/auth/sessions/cookies.py`, `kanban/auth/sessions/csrf.py`, `kanban/auth/sessions/resolver.py`
   - `kanban/api/v1/auth_session.py` (`GET /api/v1/auth/session`, `POST /api/v1/auth/logout`)
   - `kanban/app.py` (install `SessionCookieResolver` and `CsrfMiddleware`)
2. **DDL `sessions`** (owned by `kb_auth_owner`, revoked from `kanban_app`, `FORCE RLS`, accessed only via `kb_auth.*` functions per KB-P2-03 boundary):
   ```sql
   CREATE TABLE sessions (
     id                  UUID PRIMARY KEY DEFAULT uuidv7(),
     token_sha256        BYTEA NOT NULL UNIQUE CHECK (octet_length(token_sha256) = 32),
     principal_id        UUID NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
     workspace_id        UUID NOT NULL,
     auth_card_id        UUID REFERENCES auth_provider_cards(id) ON DELETE CASCADE,
     aal_level           SMALLINT NOT NULL CHECK (aal_level IN (1, 2)),
     aal2_verified_at    TIMESTAMPTZ,
     mfa_pending         BOOLEAN NOT NULL DEFAULT FALSE,
     created_at          TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
     last_seen_at        TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
     idle_expires_at     TIMESTAMPTZ NOT NULL,
     absolute_expires_at TIMESTAMPTZ NOT NULL,
     revoked_at          TIMESTAMPTZ,
     rotated_from_id     UUID
   );
   ```
   Functions: `kb_auth.session_create(...)`, `kb_auth.session_resolve(p_token_sha256 bytea)` (returns row only if `revoked_at IS NULL AND now() < idle_expires_at AND now() < absolute_expires_at`; slides `idle_expires_at` and `last_seen_at` only when `last_seen_at < now() - interval '60 seconds'`), `kb_auth.session_revoke(p_id uuid)`, `kb_auth.session_rotate(p_old_id uuid, p_new_token_sha256 bytea, p_aal smallint) RETURNS uuid` (atomically revokes old, inserts new with `rotated_from_id`, preserves `absolute_expires_at`), `kb_auth.session_revoke_all_for_principal(p_principal uuid)`. There is no function that lists sessions by token or returns `token_sha256`.
3. **Token & cookie (`cookies.py`):**
   - Session token: `secrets.token_bytes(32)`; DB stores only `sha256(token)`.
   - Cookie `__Host-kb_session` value `b64url(token) + "." + b64url(HMAC-SHA256(derive_subkey(session_hmac_key, "session/cookie"), token))`; attributes `Secure; HttpOnly; SameSite=Lax; Path=/`; no `Domain`; no `Max-Age` beyond `absolute_expires_at`.
   - Verification order: parse (max cookie length `128` chars, else reject) -> `hmac.compare_digest` on signature -> only then DB lookup. Invalid signature never reaches the DB.
4. **Timeouts (spec silent; ticket-chosen defaults, configurable):** `KANBAN_SESSION_IDLE_SECONDS=28800` (8h), `KANBAN_SESSION_ABSOLUTE_SECONDS=604800` (7d), `KANBAN_AAL2_FRESH_SECONDS=900` (15m) exposed as `SessionPolicy`. Values outside `[300, 2592000]` fail startup.
5. **Rotation (`service.py`):** `SessionService.create_after_login(principal, workspace, card, aal, mfa_pending) -> IssuedSession` ALWAYS issues a fresh token and revokes any session presented in the request (fixation defense). `SessionService.elevate_aal(session, new_aal=2) -> IssuedSession` calls `session_rotate`, sets `aal2_verified_at`. `logout` revokes and emits `Set-Cookie` clearing both cookies with `Max-Age=0`.
6. **Resolver (`resolver.py`):** `SessionCookieResolver(PrincipalResolver)` returns `PrincipalContext(principal_id, workspace_id, token_scopes=("session",), aal_level, session_id)`; sessions with `mfa_pending=TRUE` resolve only for routes tagged `allow_mfa_pending=True` (dependency `require_full_session` returns `403 MFA_REQUIRED` otherwise).
7. **CSRF (`csrf.py`, ASGI middleware):**
   - Token: `b64url(nonce16) + "." + b64url(HMAC(derive_subkey(session_hmac_key, "session/csrf"), session_id.bytes + nonce16))`; delivered as cookie `__Host-kb_csrf` (`Secure; SameSite=Strict; Path=/`, NOT HttpOnly) and in `GET /api/v1/auth/session` body.
   - Unsafe methods (`POST`, `PUT`, `PATCH`, `DELETE`) on `/api/*` require header `X-CSRF-Token` equal to the cookie AND HMAC-valid for the current session id; mismatch -> `403 CSRF_REJECTED`.
   - Defense in depth: when `Sec-Fetch-Site` is present and not in `{same-origin, none}` -> `403 CSRF_REJECTED`; when `Origin` is present and not equal to `KANBAN_PUBLIC_ORIGIN` -> `403 CSRF_REJECTED`.
   - Exempt list is an explicit constant `CSRF_EXEMPT_PATHS` (initially only pre-session login posts that carry their own state such as OIDC callback `GET`s); adding an entry requires a code comment with justification.
8. **Security invariants asserted:** (a) DB compromise yields no usable cookie (hash only); (b) forged or tossed cookies are rejected before DB access; (c) every privilege change produces a new session id; (d) unsafe cross-site requests are rejected even with a valid session cookie.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/auth/test_sessions.py`, `kanban/tests/auth/test_cookies.py`, `kanban/tests/auth/test_csrf.py`, `database/tests/test_sessions_boundary.py`
- **Required Test Cases:**
  1. Positive: `create_after_login` sets `__Host-kb_session` with exactly `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/` and no `Domain`; `GET /api/v1/auth/session` returns principal id and CSRF token.
  2. Security (fixation): attacker obtains pre-login cookie C0, victim logs in presenting C0 -> new cookie C1 issued, C0 resolves to `401`.
  3. Security (forgery): cookie with valid token but signature from a different key, signature truncated by 1 char, or token bit-flip -> `401`; spy on session repository asserts `session_resolve` was NOT called.
  4. Security (cookie tossing / name confusion): request carrying `kb_session=...` (no prefix) and `__Secure-kb_session=...` only -> unauthenticated; duplicate `__Host-kb_session` headers -> unauthenticated.
  5. Security (rotation on AAL change): `elevate_aal` returns new id; old token -> `401`; new row `rotated_from_id` = old id; `absolute_expires_at` unchanged.
  6. Boundary (idle): fake clock advanced `idle - 1s` -> valid; `idle + 1s` -> `401`. Boundary (absolute): activity every 60s still expires at `absolute + 1s`.
  7. Boundary: `last_seen_at` written at most once per 60s across 10 requests within 30s (assert single UPDATE).
  8. Security (CSRF): `POST` with valid session but missing `X-CSRF-Token` -> `403 CSRF_REJECTED`; token from session A used with session B -> `403`; `Origin: https://evil.example` -> `403`; `Sec-Fetch-Site: cross-site` -> `403`; correct token + same-origin -> `2xx`.
  9. Security (logout): after logout the old cookie -> `401` and response clears both cookies with `Max-Age=0`.
  10. Security (MFA pending): session with `mfa_pending=TRUE` -> `403 MFA_REQUIRED` on a normal route, `200` on a route marked `allow_mfa_pending`.
  11. DB boundary: as `kanban_app`, `SELECT * FROM sessions` -> `42501`; no `kb_auth` function returns `token_sha256`; oversize cookie (129 chars) rejected without DB call.
  12. Config: `KANBAN_SESSION_IDLE_SECONDS=10` -> startup `ValueError`.
