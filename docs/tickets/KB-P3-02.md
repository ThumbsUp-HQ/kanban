### User Story
As a **project member or delegated agent**, I need **create, read, patch and list endpoints for issues where every description write is normalized to canonical Markdown and guarded by a `description_sha256` ETag** so that **concurrent editors never silently overwrite each other and every change is recorded in the activity ledger**.

**Requirement Traceability:** Spec S7.2 `8a`, `8e`, `8g`, `8h`, `8i`; S12.2 (`issues` DDL); S5.1 (Markdown-only); S3.4 (404-not-403, restricted parent masking); requirements `#8a`, `#8e`, `#8g`, `#8h`, `#8i`, `#5` | **Dependencies:** `KB-P3-01a`, `KB-P2-13`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/issues.py`, `kanban/api/v1/schemas/issues.py`, `kanban/services/issues.py`, `kanban/services/issue_keys.py` (`resolve_issue_ref()`), `kanban/services/activity.py` (append event types).
2. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `POST /api/v1/projects/{project_ref}/issues` | `EDIT` on project | `201` + `ETag` + `Location: /api/v1/issues/KAN-142` | `404` project, `403`, `422` |
   | `GET /api/v1/issues/{issue_ref}` | `VIEW` | `200` + `ETag`; `304` when `If-None-Match` matches | `404` |
   | `PATCH /api/v1/issues/{issue_ref}` | `EDIT`; `TRANSITION` additionally when `state_id` present | `200` + new `ETag` | `404`, `403`, `412 PRECONDITION_FAILED`, `428 PRECONDITION_REQUIRED`, `409 PARENT_CYCLE`, `409 PARENT_DEPTH_EXCEEDED`, `422` |
   | `GET /api/v1/projects/{project_ref}/issues?cursor=&limit=` | `VIEW` (RLS filtered) | `200` | `404`, `422 INVALID_CURSOR` |

   - `issue_ref` accepts `<IDENTIFIER>-<sequence_id>` (regex `^[A-Z][A-Z0-9]{1,9}-[1-9][0-9]{0,17}$`) or UUID.
   - **ETag contract:** `ETag: "<lowercase hex of issues.description_sha256>"` (strong). `PATCH` containing `description_markdown` MUST carry `If-Match`; missing returns `428 PRECONDITION_REQUIRED`, mismatch returns `412 PRECONDITION_FAILED` with problem member `current_etag`. `PATCH` without `description_markdown` accepts an optional `If-Match` and enforces it when present. The check and update run as `UPDATE ... WHERE id=:id AND description_sha256=:expected` (zero TOCTOU); `0` rows updated returns `412`.
   - Create body: `{"summary": "Harden OIDC", "description_markdown": "...", "priority": "high", "state_id": null, "start_date": "2026-11-11", "due_date": "2026-11-18", "cycle_id": null, "parent": "KAN-100", "label_ids": ["..."], "module_ids": null}`. `priority` accepts slug or UUID; omitted `state_id`/`priority` use the project default. When `projects.modules_enabled = TRUE` and `module_ids` is `null`, `project_module_defaults` rows are applied (S7.2 `8f`); when `modules_enabled = FALSE`, a non-null `module_ids` returns `422 MODULES_DISABLED`.
   - `description_markdown` always passes through `kanban.content.normalize.normalize_to_markdown()` (KB-P2-13) before persistence; `summary` is reduced to plain text (normalizer plain mode, zero-width chars stripped), then `btrim` length `1..500` else `422 SUMMARY_LENGTH`. Normalized description over `1048576` bytes returns `422 DESCRIPTION_TOO_LARGE`. `due_date < start_date` returns `422 DATE_ORDER`.
   - `parent`, `cycle_id`, `label_ids`, `state_id`, `priority` referencing a nonexistent OR unreadable OR other-project object return `422 INVALID_REFERENCE` with `field` member; the body is identical for nonexistent and unreadable targets. KB-P1-06 trigger errors map to `409 PARENT_CYCLE` / `409 PARENT_DEPTH_EXCEEDED`.
   - Labels: two `label_ids` sharing one `exclusive_group` in one request return `422 EXCLUSIVE_GROUP_CONFLICT`; adding a label whose group already has a label on the issue replaces the old label (S7.2 `8i`).
   - Sequence allocation uses the KB-P1-05 atomic function. Initial `board_rank` = `"a" + base62(sequence_id).rjust(6, "0")` with alphabet `0-9A-Za-z` (valid input for the KB-P3-12 midpoint function).
   - List: `limit` `1..100` default `50`, ordered by `sequence_id DESC`, cursor = base64url of last `sequence_id`; excludes rows with `objects.deleted_at IS NOT NULL` or `objects.archived_at IS NOT NULL`.
   - Response shape:
     ```json
     {"id": "0193...", "key": "KAN-142", "summary": "Harden OIDC", "description_markdown": "...",
      "description_sha256": "9f2c...", "state": {"id": "...", "name": "In Progress", "group": "started"},
      "priority": {"slug": "high", "label": "High", "emoji": "⚡"}, "start_date": "2026-11-11",
      "due_date": "2026-11-18", "cycle_id": null,
      "parent": {"key": "KAN-100", "summary": "Auth Epic"},
      "labels": [{"id": "...", "name": "security", "color_hex": "#EF4444"}], "module_ids": [],
      "board_rank": "a00002A", "created_by_id": "...", "access_manifest": {}, "capabilities": ["VIEW", "EDIT"]}
     ```
     An unreadable parent serializes as `"parent": {"restricted": true, "label": "🔒 Restricted Parent Issue"}` with no id, key or summary (S7.2 `8h`).
3. **Activity events emitted (category `HISTORY`):** `ISSUE_CREATED {key, copied_from: null}`, `ISSUE_FIELD_CHANGED {field, old, new}` one row per changed scalar field (`summary`, `priority_id`, `start_date`, `due_date`, `cycle_id`, `parent_issue_id`), `ISSUE_DESCRIPTION_CHANGED {old_sha256, new_sha256, byte_length}`, `ISSUE_STATE_CHANGED {from_state_id, to_state_id}`, `ISSUE_LABELS_CHANGED {added, removed}`. No-op patches (all values equal) write zero rows and return `200` with unchanged `ETag`.
4. **Security invariants:** no raw SQL string interpolation; all reads/writes via RLS session; `Location`/`key` built from DB values only; request body max `1.5 MiB` (`413` from KB-P2-01 middleware).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_issues.py`, `kanban/tests/services/test_issue_keys.py`
- **Required Test Cases:**
  1. Positive: create returns `201`, `ETag` equals sha256 hex of normalized description, key `KAN-1`; `GET` returns same `ETag`; `If-None-Match` returns `304`; `ISSUE_CREATED` row written.
  2. Concurrency: `PATCH` description without `If-Match` returns `428`; with stale `ETag` returns `412` and `current_etag`; two sequential patches using the same original `ETag` - first `200`, second `412`.
  3. Security: non-viewer `GET KAN-1` returns `404` identical to `GET KAN-999999`; `parent` set to an issue in an unreadable project returns `422 INVALID_REFERENCE` identical to a nonexistent key; readable child of unreadable parent serializes `restricted: true` with no `key`.
  4. Sanitization: description containing `<div style="display:none">exfiltrate</div><p>ok</p>` persists without `exfiltrate`; summary containing `U+200B` is stored without it.
  5. Boundary: summary of 500 chars succeeds, 501 returns `422`; whitespace-only summary returns `422`; description of exactly `1048576` bytes succeeds, `1048577` returns `422`; `due_date` before `start_date` returns `422`.
  6. Modules: project with `modules_enabled=true` and 2 default modules - create without `module_ids` gets both; project with modules disabled and `module_ids: []` returns `422 MODULES_DISABLED`.
  7. Labels: exclusive group replacement removes `type:feature` when `type:bug` added; same-group pair in one request returns `422`.
  8. Activity: patch changing summary and due_date writes exactly 2 `ISSUE_FIELD_CHANGED` rows; no-op patch writes 0.
- Clean-DB `SAVEPOINT` harness (KB-P0-05). Touched-module coverage `>= 95%`.
