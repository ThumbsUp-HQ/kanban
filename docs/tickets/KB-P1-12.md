### User Story
As a **security auditor**, I need **an append-only, monthly-partitioned `activity_records` ledger whose rows form a per-workspace SHA-256 hash chain, reject `UPDATE` and `DELETE` at the trigger and privilege layers, and can be audited end-to-end by `verify_activity_chain()`** so that **every human edit, `CREATOR_OVERRIDDEN` action, login event, ACL mutation, and invalid-link purge is tamper-evident**.

**Requirement Traceability:** `S1.2` (monthly-partitioned immutable SHA-256 hash-chained `activity_records`), `S12.2` (`BEFORE UPDATE OR DELETE -> RAISE EXCEPTION`), `S7.2 8d` (`CREATOR_OVERRIDDEN` via `append_activity`), `S12.3` (`INVALID_OBJECT_LINK_PURGED`), Requirements `#1`, `#8d`, `#8j`, `#13j` | **Dependencies:** `KB-P1-02`, `KB-P1-03`

2. **Ledger & Chain-Head DDL (`p1_12_activity_ledger.up.sql`):**
   ```sql
   CREATE TABLE activity_chain_heads (
       workspace_id  UUID PRIMARY KEY REFERENCES workspaces(id) ON DELETE RESTRICT,
       last_seq      BIGINT NOT NULL CHECK (last_seq >= 0),
       last_hash     BYTEA  NOT NULL CHECK (octet_length(last_hash) = 32),
       updated_at    TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
   );
   REVOKE INSERT, UPDATE, DELETE ON activity_chain_heads FROM kanban_app, app_rls_reader;

   CREATE TABLE activity_records (
       id           UUID        NOT NULL DEFAULT uuidv7(),
       workspace_id UUID        NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       chain_seq    BIGINT      NOT NULL,
       object_id    UUID,
       object_type  object_kind,
       actor_id     UUID        REFERENCES principals(id) ON DELETE RESTRICT,
       event_type   TEXT        NOT NULL CHECK (event_type ~ '^[A-Z][A-Z0-9_]{2,63}$'),
       payload      JSONB       NOT NULL DEFAULT '{}'::jsonb
                                CHECK (jsonb_typeof(payload) = 'object' AND octet_length(payload::text) <= 16384),
       recorded_at  TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       prev_hash    BYTEA       NOT NULL CHECK (octet_length(prev_hash) = 32),
       row_hash     BYTEA       NOT NULL CHECK (octet_length(row_hash) = 32),
       CHECK ((object_id IS NULL) = (object_type IS NULL)),
       PRIMARY KEY (id, recorded_at)
   ) PARTITION BY RANGE (recorded_at);

   CREATE UNIQUE INDEX activity_records_ws_seq_recorded_uq ON activity_records (workspace_id, chain_seq, recorded_at);
   CREATE INDEX activity_records_ws_seq_idx ON activity_records (workspace_id, chain_seq DESC);
   CREATE INDEX activity_records_object_idx ON activity_records (object_id, recorded_at DESC) WHERE object_id IS NOT NULL;
   REVOKE UPDATE, DELETE, TRUNCATE ON activity_records FROM kanban_app, app_rls_reader;
   ```
   *(Note: `object_id`/`object_type` are nullable as a pair so workspace/auth-level security events like `LOCAL_ADMIN_LOGIN_FAILED` in KB-P2-04 and dangling-source link purges in KB-P1-16 record cleanly without a fake `objects` row; `actor_id` is nullable for unauthenticated failed-login audit rows.)*

3. **Partition Maintenance `ensure_activity_partitions(p_ref timestamptz DEFAULT clock_timestamp(), p_months_back int DEFAULT 1, p_months_ahead int DEFAULT 6) RETURNS integer`:**
   - `SECURITY DEFINER`, `SET search_path = pg_catalog, public`, owned by `kanban_migrator`, `GRANT EXECUTE TO kanban_app`.
   - Serializes via `pg_advisory_xact_lock(hashtextextended('activity_partitions', 0))`; bounds `p_months_back BETWEEN 0 AND 24` and `p_months_ahead BETWEEN 0 AND 36` (else `PARTITION_RANGE_INVALID`).
   - Creates missing monthly UTC range partitions `activity_records_yYYYYmMM` for `[YYYY-MM-01 00:00:00+00, next_month)` and revokes `UPDATE, DELETE, TRUNCATE` on each partition from `kanban_app, app_rls_reader`. Called once during `p1_12_activity_ledger.up.sql` to pre-create `-1..+6` monthly partitions around `clock_timestamp()`.

4. **Canonical Hash & Append Trigger / Function:**
   - `compute_activity_row_hash(p_prev_hash bytea, p_workspace_id uuid, p_chain_seq bigint, p_id uuid, p_object_id uuid, p_object_type object_kind, p_actor_id uuid, p_event_type text, p_recorded_at timestamptz, p_payload jsonb) RETURNS bytea` (`IMMUTABLE PARALLEL SAFE`):
     Computes `digest(p_prev_hash || convert_to(concat_ws('|', p_workspace_id::text, p_chain_seq::text, p_id::text, coalesce(p_object_id::text, ''), coalesce(p_object_type::text, ''), coalesce(p_actor_id::text, ''), p_event_type, to_char(date_trunc('microseconds', p_recorded_at) AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"'), p_payload::text), 'UTF8'), 'sha256')`.
   - `activity_records_chain_bi` (`BEFORE INSERT ON activity_records FOR EACH ROW`, `SECURITY DEFINER`):
     - If `NEW.object_id IS NOT NULL`, verifies `(NEW.object_id, NEW.object_type)` exists in `objects` with `workspace_id = NEW.workspace_id` -> else `ACTIVITY_OBJECT_MISMATCH`.
     - Upserts/locks `activity_chain_heads` for `NEW.workspace_id` (`FOR UPDATE`), setting genesis `last_seq = 0, last_hash = decode(repeat('00', 32), 'hex')` on first row; assigns `NEW.chain_seq := head.last_seq + 1`, `NEW.prev_hash := head.last_hash`, `NEW.recorded_at := date_trunc('microseconds', COALESCE(NEW.recorded_at, clock_timestamp()))`, `NEW.row_hash := compute_activity_row_hash(...)` (caller-supplied `chain_seq`/`prev_hash`/`row_hash` are always overwritten), and updates `activity_chain_heads`.
   - `activity_records_immutable_bud` (`BEFORE UPDATE OR DELETE ON activity_records FOR EACH ROW`): raises `ERRCODE = 'P0001', MESSAGE = 'ACTIVITY_LEDGER_IMMUTABLE'`.
   - Helper `append_activity(p_workspace_id uuid, p_object_id uuid, p_object_type object_kind, p_actor_id uuid, p_event_type text, p_payload jsonb DEFAULT '{}'::jsonb) RETURNS uuid` (`VOLATILE SECURITY INVOKER`, `GRANT EXECUTE TO kanban_app`): inserts into `activity_records` and returns `id` (exact signature consumed by KB-P1-07 and KB-P1-16).

5. **Chain Verifier `verify_activity_chain(p_workspace_id uuid) RETURNS TABLE(is_valid boolean, checked_rows bigint, first_broken_seq bigint, first_broken_id uuid, failure_reason text)`:**
   - `STABLE SECURITY DEFINER`, `SET search_path = pg_catalog, public`, `GRANT EXECUTE TO kanban_app`.
   - Scans `activity_records` for `p_workspace_id` ordered by `chain_seq ASC, recorded_at ASC`: returns `(true, 0, NULL, NULL, NULL)` on empty workspace; flags `'SEQ_GAP'` if `chain_seq <> expected`, `'PREV_HASH_MISMATCH'` if `prev_hash` differs from `\x00*32` (seq 1) or prior `row_hash`, `'ROW_HASH_MISMATCH'` if `row_hash <> compute_activity_row_hash(...)`, and `'HEAD_MISMATCH'` if `activity_chain_heads` disagrees with the final row.

6. **Down Migration:** Drops `verify_activity_chain`, `append_activity`, triggers/functions, `activity_records` (cascades partitions), `activity_chain_heads`, `ensure_activity_partitions`, `compute_activity_row_hash`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_12_activity_ledger.py`, `database/tests/test_p1_12_chain_concurrency.py`, `database/tests/migrations/test_p1_12_migration.py`
- **Required Test Cases:**
  1. Positive: appending 5 events via `append_activity` (including object-bound and `(NULL, NULL)` auth events) yields `chain_seq` `1..5`, `prev_hash` of row 1 equal to `32` zero bytes, `prev_hash` of row `k` equal to `row_hash` of row `k-1`, and `verify_activity_chain(ws)` returning `(true, 5, NULL, NULL, NULL)` independent of session `SET LOCAL TIME ZONE`.
  2. Positive (partition rollover): calling `ensure_activity_partitions('2027-11-15T00:00:00Z'::timestamptz, 0, 2)` creates `activity_records_y2027m11`, `y2027m12`, `y2028m01`; inserting rows dated in Dec 2027 and Jan 2028 routes them to distinct child `tableoid` partitions while keeping one continuous `chain_seq` chain across the year boundary (`verify_activity_chain` returns `is_valid = true`).
  3. Negative/security (immutability): as superuser and as `kanban_app`, `UPDATE activity_records SET payload = '{}'` and `DELETE FROM activity_records` fail (`ACTIVITY_LEDGER_IMMUTABLE` / `42501`); client-supplied fake `prev_hash`/`row_hash`/`chain_seq` on direct `INSERT` are overwritten by `activity_records_chain_bi`.
  4. Negative/security (tamper detection): when a superuser temporarily disables user triggers (`ALTER TABLE activity_records DISABLE TRIGGER USER`), (a) mutates `payload` of row 3 -> `verify_activity_chain` returns `(false, ..., 3, <id>, 'ROW_HASH_MISMATCH')`; (b) recomputes row 3's `row_hash` without updating row 4 -> returns `(false, ..., 4, <id4>, 'PREV_HASH_MISMATCH')`; (c) deletes row 2 -> returns `(false, ..., 3, <id3>, 'SEQ_GAP')`.
  5. Concurrency (`@pytest.mark.committed_db`): 16 concurrent connections each append 5 events to the same workspace (`80` total) -> zero deadlocks/duplicate `chain_seq`, `checked_rows = 80`, `verify_activity_chain` returns `is_valid = true`.
  6. Boundary: payload of `16384` bytes succeeds, `16385` bytes raises `23514`; invalid `event_type = 'lowercase'` raises `23514`; non-null `object_id` with NULL `object_type` raises `23514`; object from another workspace raises `ACTIVITY_OBJECT_MISMATCH`.
  7. Migration up/down: `MigrationHarness` upgrade `p1_12_activity_ledger` -> partitioned table + functions exist; downgrade to `previous_of(...)` -> all absent; re-upgrade succeeds.
  - Non-concurrency tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
