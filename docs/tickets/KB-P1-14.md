### User Story
As a **security architect**, I need **`ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` with explicit read and `WITH CHECK` write policies across every tenant-bearing PostgreSQL table, plus a permanent catalog test asserting zero unprotected tenant tables** so that **`kanban_app` and `app_rls_reader` return `0` rows when session context is missing and can never read or mutate out-of-scope data in either production or standalone mode**.

**Requirement Traceability:** `S3.3` (`ENABLE` + `FORCE ROW LEVEL SECURITY`, `set_config('app.principal_id'|'app.workspace_id'|'app.token_scopes'|'app.aal_level', ..., true)`, `objects_select_rls`), `S3.2` (capability enforcement), `S2.2` (identical RLS in standalone), Requirement `#1` | **Dependencies:** `KB-P1-13`, `KB-P1-12`, `KB-P1-11`, `KB-P1-10`, `KB-P1-09`, `KB-P1-08`, `KB-P1-07`, `KB-P1-06`

2. **Session GUC & Capability Helpers (`p1_14_force_rls.up.sql`, `GRANT EXECUTE TO kanban_app, app_rls_reader`):**
   - `app_current_token_scopes() RETURNS text[]` (`LANGUAGE sql STABLE PARALLEL SAFE`): `SELECT COALESCE(string_to_array(NULLIF(current_setting('app.token_scopes', true), ''), ','), '{}'::text[])`.
   - `app_current_aal_level() RETURNS integer` (`LANGUAGE sql STABLE PARALLEL SAFE`): `SELECT COALESCE(NULLIF(current_setting('app.aal_level', true), '')::integer, 0)`.
   - `app_has_object_capability(p_object_id uuid, p_mask integer) RETURNS boolean` (`LANGUAGE sql STABLE PARALLEL SAFE SECURITY INVOKER`):
     ```sql
     SELECT EXISTS (
         SELECT 1 FROM effective_resource_access era
         WHERE era.object_id = p_object_id
           AND era.workspace_id = app_current_workspace_id()
           AND era.principal_id = ANY (app_effective_principal_set())
           AND (era.allow_mask & p_mask) = p_mask
           AND (era.deny_mask  & p_mask) = 0
     );
     ```

3. **`ENABLE` + `FORCE ROW LEVEL SECURITY` & Policies Across All Tenant Tables:**
   Every table in `public` EXCEPT the two global non-tenant catalog tables (`alembic_version`, `link_type_matrix`) MUST execute `ALTER TABLE <tbl> ENABLE ROW LEVEL SECURITY; ALTER TABLE <tbl> FORCE ROW LEVEL SECURITY;` (including all existing `activity_records_y*` partitions, and updating `ensure_activity_partitions()` from KB-P1-12 so newly created monthly partitions also have `ENABLE` + `FORCE ROW LEVEL SECURITY` with zero direct partition policies, enforcing default-deny on direct partition queries while parent `activity_records` queries evaluate parent RLS):
   - **`objects` (`objects_select_rls` verbatim from S3.3):**
     `SELECT` `USING` `workspace_id = app_current_workspace_id() AND EXISTS (SELECT 1 FROM effective_resource_access era WHERE era.object_id = objects.id AND era.principal_id = ANY (app_effective_principal_set()) AND (era.allow_mask & 1) = 1 AND (era.deny_mask & 1) = 0)`.
     `INSERT` `WITH CHECK`: `workspace_id = app_current_workspace_id() AND app_current_principal_id() IS NOT NULL AND (project_id IS NULL OR app_has_object_capability(project_id, 4))` (creating a root `project` requires `app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])`).
     `UPDATE` `USING` / `WITH CHECK`: `workspace_id = app_current_workspace_id() AND app_has_object_capability(id, 4)`; `DELETE` `USING`: `workspace_id = app_current_workspace_id() AND app_has_object_capability(id, 128)`.
   - **Object-Spine Entity Tables (`projects`, `issues`, `cycles`, `modules`, `docs`, `pages`, `stickies`, `views`):**
     - `SELECT`: `workspace_id = app_current_workspace_id() AND app_has_object_capability(id, 1)` (plus on `views`: if `visibility = 'private'`, restricted to `owner_principal_id = app_current_principal_id() OR app_principal_has_role(project_id, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN', 'PROJECT_ADMIN'])`).
     - `INSERT` `WITH CHECK`: `workspace_id = app_current_workspace_id()` AND (`projects`: `app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])`; project-bound entities: `project_id IS NULL OR app_has_object_capability(project_id, 4)`; `pages`: `app_has_object_capability(doc_id, 4)`).
     - `UPDATE` `USING` / `WITH CHECK`: `workspace_id = app_current_workspace_id()` AND (`projects`: `app_has_object_capability(id, 64)`; `issues`: `app_has_object_capability(id, 4) OR app_has_object_capability(id, 8)`; others: `app_has_object_capability(id, 4)`).
     - `DELETE` `USING`: `workspace_id = app_current_workspace_id() AND app_has_object_capability(id, 128)`.
   - **Project Configuration Child Tables (`workflow_states`, `project_priorities`, `project_labels`, `project_module_defaults`):**
     `SELECT`: `workspace_id = app_current_workspace_id() AND app_has_object_capability(project_id, 1)`; `INSERT/UPDATE/DELETE` `USING` + `WITH CHECK`: `workspace_id = app_current_workspace_id() AND app_has_object_capability(project_id, 64)`.
   - **Issue Join & Prose Child Tables (`issue_modules`, `issue_assignees`, `issue_labels`, `issue_subscriptions`, `issue_comments`, `page_versions`):**
     - `issue_modules`, `issue_assignees`, `issue_labels`: `SELECT` requires `app_has_object_capability(issue_id, 1)`; writes require `app_has_object_capability(issue_id, 4)` with matching `workspace_id`.
     - `issue_subscriptions`: `SELECT` requires `app_has_object_capability(issue_id, 1) AND (principal_id = app_current_principal_id() OR app_has_object_capability(issue_id, 64))`; writes require `app_has_object_capability(issue_id, 1) AND (principal_id = app_current_principal_id() OR app_has_object_capability(issue_id, 4))`.
     - `issue_comments`: `SELECT` requires `app_has_object_capability(issue_id, 1)`; `INSERT` `WITH CHECK` requires `author_id = app_current_principal_id() AND app_has_object_capability(issue_id, 2)`; `UPDATE/DELETE` requires `(author_id = app_current_principal_id() AND app_has_object_capability(issue_id, 2)) OR app_has_object_capability(issue_id, 64)`.
     - `page_versions`: `SELECT` requires `app_has_object_capability(page_id, 1)`; `INSERT` `WITH CHECK` requires `app_has_object_capability(page_id, 4)`.
   - **Graph Links & Audit Ledger (`object_links`, `activity_records`, `activity_chain_heads`):**
     - `object_links`: `SELECT` requires `workspace_id = app_current_workspace_id() AND (app_has_object_capability(source_id, 1) OR app_has_object_capability(target_id, 1))` (allows KB-P3-07 to list inbound/outbound links while `objects` RLS masks the unreadable far endpoint); `INSERT` `WITH CHECK` requires `workspace_id = app_current_workspace_id() AND app_has_object_capability(source_id, 16) AND app_has_object_capability(target_id, 1)`; `DELETE` `USING` requires `workspace_id = app_current_workspace_id() AND app_has_object_capability(source_id, 16)`.
     - `activity_records`: `SELECT` requires `workspace_id = app_current_workspace_id() AND ((object_id IS NOT NULL AND app_has_object_capability(object_id, 1)) OR app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN']))`; `INSERT` `WITH CHECK` requires `workspace_id = app_current_workspace_id() AND (actor_id IS NULL OR actor_id = app_current_principal_id())`.
     - `activity_chain_heads`: `ENABLE` + `FORCE RLS` with zero `kanban_app` policies (accessible only via KB-P1-12 `SECURITY DEFINER` triggers/verifier).
   - **Identity & Access Tables (`workspaces`, `principals`, `users`, `groups`, `principal_group_edges`, `principal_group_closure`, `role_bindings`, `resource_acl_entries`, `effective_resource_access`):**
     - `workspaces`: `SELECT` `id = app_current_workspace_id() AND cardinality(app_effective_principal_set()) > 0`; `UPDATE` requires `app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])`.
     - `principals`, `users`, `groups`, `principal_group_edges`, `principal_group_closure`: `SELECT` requires `workspace_id = app_current_workspace_id() AND cardinality(app_effective_principal_set()) > 0`; writes on `principals`/`users`/`groups`/`principal_group_edges` require `workspace_id = app_current_workspace_id() AND app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])`.
     - `role_bindings`: `SELECT` requires `workspace_id = app_current_workspace_id() AND (principal_id = ANY (app_effective_principal_set()) OR app_principal_has_role(project_id, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN', 'PROJECT_ADMIN']))`; writes require `workspace_id = app_current_workspace_id() AND ((scope_type = 'server' AND app_principal_has_role(NULL, ARRAY['SERVER_ADMIN'])) OR (scope_type = 'workspace' AND app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])) OR (scope_type = 'project' AND app_principal_has_role(project_id, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN', 'PROJECT_ADMIN'])))`.
     - `resource_acl_entries`: `SELECT` requires `workspace_id = app_current_workspace_id() AND app_has_object_capability(object_id, 1)`; writes require `workspace_id = app_current_workspace_id() AND app_has_object_capability(object_id, 32)` (`SHARE = 32` or `ADMIN = 64` via `app_has_object_capability(object_id, 32) OR app_has_object_capability(object_id, 64)`).
     - `effective_resource_access`: `SELECT` requires `workspace_id = app_current_workspace_id() AND (principal_id = ANY (app_effective_principal_set()) OR app_has_object_capability(object_id, 1))` (needed so `objects_select_rls` and S3.4 co-viewer manifest queries work without infinite recursion: avoid calling `app_has_object_capability` inside `effective_resource_access`'s own policy! Instead `effective_resource_access_select_rls` uses `workspace_id = app_current_workspace_id() AND cardinality(app_effective_principal_set()) > 0` while `objects` / `principals` RLS still redacts unreadable principals/objects).

4. **Down Migration:** Drops all policies, disables `FORCE` and `ROW LEVEL SECURITY` on the tables above, restores KB-P1-12 `ensure_activity_partitions`, and drops the 3 helper functions.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_14_rls_policies.py`, `database/tests/test_p1_14_rls_catalog.py`, `database/tests/migrations/test_p1_14_migration.py`
- **Required Test Cases:**
  1. Zero-context fail-closed (`kanban_app` and `app_rls_reader`): seed 2 workspaces with projects, issues, comments, docs, pages, stickies, views, links, and activity rows; run `SELECT count(*) FROM <tbl>` across EVERY tenant table as `kanban_app` without calling `set_config` (and again after `set_config('app.principal_id', '', true)`) -> every table returns `0` rows.
  2. Cross-workspace & cross-project isolation: bind `U_ws1` (`MEMBER` on `KAN` in `WS1`, no access to `SEC` in `WS1` or anything in `WS2`); `SELECT` on `issues`, `objects`, `docs`, `stickies`, `views`, `issue_comments`, `activity_records` returns only `KAN` / `WS1` rows and `0` rows from `SEC` or `WS2`.
  3. Write `WITH CHECK` enforcement: as `VIEWER` (`mask = 3`) on `KAN`, `INSERT INTO issue_comments` succeeds (`COMMENT = 2`), while `UPDATE issues SET summary = 'x'` and `INSERT INTO issues` fail with `42501` (new row violates row-level security policy); attempting to `INSERT` an issue with `workspace_id = WS2` while bound to `WS1` raises `42501`.
  4. Explicit-deny & link boundary: adding `DENY VIEW` for `U_ws1` on `KAN-2` immediately hides `KAN-2` from `SELECT * FROM issues` and `SELECT * FROM issue_comments`; an `object_links` row `KAN-1 -> BLOCKS -> SEC-1` is visible in `object_links` to `U_ws1` (`VIEW` on `KAN-1`), while `SELECT * FROM objects WHERE id = sec_1_id` returns `0` rows.
  5. Direct partition query blocked: as `kanban_app` bound to `U_ws1`, querying `activity_records` returns `KAN` activity rows, whereas querying a child partition `SELECT * FROM activity_records_y...` directly returns `0` rows; `app_rls_reader` attempting any `INSERT`/`UPDATE` raises `25006` (`read-only SQL transaction`) or `42501`.
  6. Permanent schema catalog gate (`test_p1_14_rls_catalog.py`): queries `pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace` for `n.nspname = 'public' AND c.relkind IN ('r', 'p') AND c.relname NOT IN ('alembic_version', 'link_type_matrix')` (excluding test-only schema `kb_harness` per KB-P0-05) and asserts **0 rows** have `NOT c.relrowsecurity OR NOT c.relforcerowsecurity`.
  7. Migration up/down: `MigrationHarness` upgrade `p1_14_force_rls` -> catalog check passes; downgrade to `previous_of(...)` -> policies absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
