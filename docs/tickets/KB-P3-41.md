### User Story
As a **project member triaging work from any issue layout**, I need **a breathable right-docked ticket drawer (`640px` editorial prose column + `320px` properties rail) that expands to a dedicated full-screen route and back without remounting**, so that **I can read and edit an issue with generous editorial whitespace, keep unsaved input, scroll position and media state when I toggle `Cmd+Shift+F`, and see the issue's priority and access scope through hoverable emojis instead of cramped status text**.

**Requirement Traceability:** `S7.1` (drawer wireframe, header row `[-> Collapse] [↗ Full Screen] ⚡ KAN-142 🛡️ Project + 2 [🔔 Subscribe] [🔗] [⋯]`), `S7.2 8a` (summary: plain text, `1..500` chars after trim, `Enter` focuses description), `S7.2 8o` (zero-remount `?peek=KAN-142` <-> `/projects/KAN/issues/KAN-142`, `[↗]` or `Cmd+Shift+F`), `S6.1` (`--drawer-w`, `--prose-pad`, `--section-gap`, `--text-body`, `--leading-prose`), `S6.2` (`🛡️` and priority emoji hover contracts), requirements `#8a`, `#8o`, `#9i`, `#15` | **Dependencies:** `KB-P3-34` (AppShell host, router, `shortcuts.ts`), `KB-P3-02` (issue GET/PATCH with `ETag`/`If-Match`)

2. **Zero-remount contract (S7.2 8o, cross-ticket contract):** `IssueSurface` is rendered exactly once by `AppShell`, never by a route element. It switches the CSS class on its root between `.surface--drawer` and `.surface--full`. Proof hooks on the root element:
   - `data-mount-id` = `useState(() => crypto.randomUUID())[0]` (generated once per mount).
   - `data-mount-seq` = value of a module-level counter incremented inside a `useEffect(() => {...}, [])` (no `window` globals).
   - Toggling between `/projects/KAN/issues?peek=KAN-142` and `/projects/KAN/issues/KAN-142` (both directions, 5 round trips) MUST leave `data-mount-id` and `data-mount-seq` unchanged. Opening a different issue key while open also keeps the same mount (data refetch only). Closing the surface (no `peek` and no `:issueKey`) unmounts the inner content; reopening is a new mount (allowed).
3. **`useIssueSurfaceRoute()`** returns `{ issueKey: string | null; projectKey: string | null; mode: 'drawer' | 'full' | null }` derived from `?peek=` (on any `/projects/:projectKey/*` route) or `/projects/:projectKey/issues/:issueKey`. Input hardening: `issueKey` must match `^[A-Z][A-Z0-9]{1,9}-[1-9][0-9]{0,8}$` and its prefix must equal `projectKey`; any other value (e.g. `?peek=javascript:alert(1)`, `?peek=../../admin`, `?peek=OTHER-1` on project `KAN`) yields `issueKey: null` and the `peek` param is removed with `navigate(..., { replace: true })`. `toFullScreenPath(projectKey, issueKey)` and `toPeekPath(location, issueKey)` preserve all other query params (e.g. `?layout=board`) and never build absolute URLs.

6. **Summary (`SummaryField.tsx`, S7.2 8a):** Display is `<h1 id="issue-summary-<KEY>">` containing a `<button class="summary__edit">` (accessible name `Edit summary`). Edit mode is an auto-growing `<textarea aria-label="Summary" maxLength` not used for validation>. Rules: newlines and C0/C1 control chars (`\u0000-\u001F`, `\u007F-\u009F`) are replaced by a single space on input and paste; length is counted in Unicode code points (`[...value.trim()].length`) to match Postgres `char_length(btrim(summary)) BETWEEN 1 AND 500`; `0` -> inline error `Summary cannot be empty.`; `> 500` -> `Summary must be 500 characters or fewer (currently N).`, both in an element with `role="alert"` referenced by `aria-describedby`. `Enter` commits and moves focus to the description slot `focusRef`; `Escape` reverts and returns focus to the edit button; blur commits. Commit = `useOptimisticMutation` `PATCH /api/v1/issues/{issueKey}` body `{ "summary": "<trimmed>" }` with `If-Match: <etag>`; on `412` roll back and show `role="alert"` text `This issue changed since you opened it. Reload to see the latest version.` with a `Reload` button that refetches `qk.issue(issueKey)`. Unsaved draft text lives in component state so it survives the drawer <-> full toggle (proven by e2e).
