### User Story
As a **platform engineer bootstrapping the Kanban monorepo**, I need **a single Python 3.12 `uv` workspace with the four member modules `database`, `kanban`, `mcp`, `agent`, an enforced one-way import contract, and per-module self-describing manifests** so that **every later ticket lands in a reproducible, locked environment where reverse imports fail the build**.

**Requirement Traceability:** `S2.1`, `S2.5`, Requirement `#3` (project structure `[kanban, database, mcp, agent]`), `Apache-2.0` license requirement | **Dependencies:** `None`

3. **Root workspace `pyproject.toml`:**
   ```toml
   [project]
   name = "kanban-platform"
   version = "0.0.0"
   requires-python = ">=3.12,<3.13"
   license = "Apache-2.0"
   dependencies = ["kanban-database", "kanban-core", "kanban-mcp", "kanban-agent"]

   [tool.uv.workspace]
   members = ["database", "kanban", "mcp", "agent"]

   [tool.uv.sources]
   kanban-database = { workspace = true }
   kanban-core = { workspace = true }
   kanban-mcp = { workspace = true }
   kanban-agent = { workspace = true }

   ```
   Every version MUST be pinned with `==` in `[dependency-groups]`; `uv.lock` is committed and carries the sha256 hashes.
4. **Member packages (flat layout, member directory == import package):** Each member `pyproject.toml` declares `name` (`kanban-database`, `kanban-core`, `kanban-mcp`, `kanban-agent`), `requires-python = ">=3.12,<3.13"`, `license = "Apache-2.0"`, build backend `hatchling`, and maps the member directory onto its import package name (e.g. `[tool.hatch.build.targets.wheel.sources] "" = "database"` plus `exclude = ["tests", "pyproject.toml", "GEMINI.md", "AGENTS.md"]`). Internal dependency edges are declared only in the allowed direction: `kanban-core` depends on `kanban-database`; `kanban-mcp` on `kanban-core`; `kanban-agent` on `kanban-mcp`. Each `__init__.py` exports `__version__: str = "0.0.0"` and a one-line module docstring. The import packages are importable after `uv sync --locked` from a working directory outside the repo (installed, not via `cwd` on `sys.path`).
5. **Import contract:** Root `pyproject.toml` contains:
   ```toml
   [tool.importlinter]
   root_packages = ["agent", "mcp", "kanban", "database"]

   [[tool.importlinter.contracts]]
   name = "Unidirectional module layers agent -> mcp -> kanban -> database"
   type = "layers"
   layers = ["agent", "mcp", "kanban", "database"]
   ```
   `uv run lint-imports` exits `0` on the clean tree.
6. **Module manifests:** Each `<module>/GEMINI.md` contains these literal headings: `## Responsibility`, `## Depends On`, `## Depended On By`, `## Inbound Contracts`, `## Outbound Contracts`, `## Performance Budgets`, `## Failure Modes`, filled from S2.1 / S2.4 (e.g. `mcp/GEMINI.md` states it holds zero PostgreSQL credentials and calls `kanban-api` over internal HTTP). `<module>/AGENTS.md` is a relative symlink (`ln -s GEMINI.md AGENTS.md`).
7. **`NOTICE`:** Apache-2.0 NOTICE file naming the project and copyright holder line, with a section `Third-Party Notices` (empty list allowed in this ticket).
8. **Security invariants:** No secrets, tokens, or credentials in any file. No dependency outside the four listed in `new_dependencies` plus their transitive closure. No `GPL`/`AGPL`/`SSPL`/`LGPL` package in `uv.lock`.
