### User Story
As a **UI implementer and as the passive `reality-checker`**, I need **a deterministic Playwright harness that runs every UI spec at desktop 1440x900, tablet 1024x768 and mobile 390x844 against the production CSP, with a strict mock API and a helper that writes numbered, annotated screenshots plus computed-style probes into `docs/qa/<TICKET_ID>/`** so that **every later UI ticket can deliver indisputable visual and measured proof (including proof of the generous whitespace tokens) without a live backend and without silently tolerating CSP violations**.

**Requirement Traceability:** Workspace rules (UI & Visual Proof: "record and annotate screenshots"), `AGENTS.md` UI Specialist Gate (desktop/tablet/mobile screenshots in `docs/qa/<TICKET_ID>/screenshots/`), `S5.4` (production CSP header), `S15.4` | **Dependencies:** `KB-P0-03`

3. **Production CSP in preview (`csp.ts` + `vite.config.ts`):** `PRODUCTION_CSP` is exactly the S5.4 header joined with `; `: `default-src 'none'; script-src 'self'; worker-src 'self'; style-src 'self'; img-src 'self' blob: data:image/png data:image/webp; font-src 'self'; connect-src 'self' wss:; media-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; require-trusted-types-for 'script'; trusted-types kanban-sanitizer dompurify`. `vite.config.ts` sets `preview.headers['Content-Security-Policy'] = PRODUCTION_CSP`.
4. **Guard fixture (`test.ts`):** Extends `@playwright/test` `test` with an auto fixture that, before each test, calls `page.addInitScript` to register a `securitypolicyviolation` listener pushing `{ violatedDirective, blockedURI }` to `window.__cspViolations`, collects `page.on('console')` messages of type `error` and `page.on('pageerror')`, and blocks all requests whose origin is not `http://127.0.0.1:4173` (`route.abort()` and record them). After each test it fails with a readable message if any CSP violation, console error, page error, or off-origin request was recorded. Exports `test`, `expect`.
5. **Mock API (`mockApi.ts`):** `export async function mockApi(page: Page, handlers: MockHandlers): Promise<MockRecorder>` where `MockHandlers = Record<\`${'GET'|'POST'|'PATCH'|'PUT'|'DELETE'} /api/v1/${string}\`, MockResponse | ((req: MockRequest) => MockResponse)>` and `MockResponse = { status?: number; json?: unknown; headers?: Record<string,string>; delayMs?: number }`. Uses `page.route('**/api/v1/**')`; path params via `:name` segments (e.g. `GET /api/v1/issues/:issueKey`). Any `/api/v1/` request with no matching handler responds `599` and records it; the guard fixture fails the test listing unmatched calls. `MockRecorder.calls` exposes method, path, JSON body and headers for assertions (e.g. `X-CSRF-Token` presence). `loadFixture(name)` reads `e2e/fixtures/<name>.json` (name restricted to `/^[a-z0-9-]+$/`, else throws). Default handlers registered by the auto fixture: `GET /api/v1/me` -> `me-adam.json`, `GET /api/v1/system/status` -> `system-status-prod.json`.
6. **Annotated screenshots (`annotate.ts`):**
   ```ts
   export interface Annotation { selector: string; label: string; note?: string; }
   export async function annotatedScreenshot(page: Page, testInfo: TestInfo,
     opts: { name: string; annotations: Annotation[]; fullPage?: boolean }): Promise<string>;
   ```
   - `name` must match `/^[0-9]{2}-[a-z0-9-]+$/`; `QA_TICKET_ID` env must match `/^[A-Z][A-Z0-9]+-[0-9A-Za-z-]+$/`, else throw (prevents path traversal). Output path: `docs/qa/${QA_TICKET_ID}/screenshots/${name}-${testInfo.project.name}.png` resolved from the repo root (`path.resolve(__dirname, '../../../..')`), directory created if missing. When `QA_TICKET_ID` is unset, writes to `test-results/screenshots/` instead (local runs).
   - For each annotation in order `i = 1..n`: resolve `page.locator(selector).first()`, fail if count is `0` or the bounding box has zero width/height. Inject an overlay (inside `page.evaluate`, DOM + CSSOM only, no `<style>` tag, no `style` attribute string, so CSP stays clean) consisting of a `2px` solid `#e11d48` outline box over the element bounding box and a `22px` circular badge with the number `i` (white text, `#e11d48` fill) at the top-left corner of the box, clamped into the viewport.
   - Add a legend strip fixed at the bottom of the viewport (`#111827` background, white `13px` text, `8px 12px` padding) listing `i. label - note` lines and the text `<QA_TICKET_ID> | <project> | <width>x<height>`.
   - Take the screenshot (`animations: 'disabled'`, `caret: 'hide'`), then remove the overlay nodes. Returns the written path; also attaches the file to `testInfo`.
7. **Computed-style probe (`styleProbe.ts`):** `export async function probeStyles(page, testInfo, { name, probes: Array<{ selector: string; props: string[] }> }): Promise<Record<string, Record<string,string>>>` reads `getComputedStyle` values for each prop plus `getBoundingClientRect()` `width`/`height`, and merges them under key `name` into `docs/qa/${QA_TICKET_ID}/computed-styles-${project}.json` (pretty-printed, keys sorted, file rewritten atomically via temp file + rename). Same env/name validation as Action 6.
8. **Base fixtures (`e2e/fixtures/`):** `project-kan.json`: key `KAN`, name `Platform Core`, workspace `Engineering`, states `Backlog`(group `backlog`), `Todo`(`unstarted`), `In Progress`(`started`, `wip_soft: 3`), `In Review`(`started`), `Done`(`completed`), `Canceled`(`cancelled`); priorities `urgent` 🔥, `high` ⚡, `medium` 🔹, `low` 💤, `none`; labels `security`, `type:bug` and `type:feature` (`exclusive_group: "type"`); `modules_enabled: true`; modules `Auth Core`. `issues-kan.json`: at least 12 issues across all states including `KAN-142` (summary `Harden Multi-Card OIDC & LDAPS Auth Studio`, state `In Progress`, priority `urgent`, assignees `@adam`, agent `codex`, free-text `Ext: SecAudit`, created by `@maya` with `creator_overridden: true`, start `2026-11-11`, due `2026-11-18`, module `Auth Core`, cycle `Cycle 4: Sec`, parent `KAN-100`, label `security`), `KAN-143` and `KAN-145` as sub-issues, one issue with `gate_status: "pending"` in `In Review`, one with summary containing `<img src=x onerror=alert(1)>` (hostile text for later XSS assertions). `me-adam.json`: user `@adam` `Adam Outler`, role `PROJECT_ADMIN`. `system-status-standalone.json` and `system-status-prod.json` per the contract `{ deployment_mode, persistent_volume, air_gap_mode, local_llm_endpoint_host, is_server_admin }`.
9. **Sample spec (`e2e/sample/harness.spec.ts`):** Loads `/` (the KB-P0-03 empty `App`), asserts `document.title` and the `Content-Security-Policy` response header equals `PRODUCTION_CSP`, calls `annotatedScreenshot` with name `01-harness-smoke` and 1 annotation on the app root, calls `probeStyles` with name `app-root` on `body` props `font-family`, `font-size`, `line-height`. A second test intentionally triggers an unmatched `GET /api/v1/does-not-exist` inside `test.fail()` to prove the guard fails tests on unmocked calls; a third inside `test.fail()` evaluates `document.head.appendChild(Object.assign(document.createElement('style'), { textContent: 'body{}' }))` to prove inline-style CSP violations fail tests.
