### User Story
As a **Server Administrator managing workspace sign-in (`AAL2` session)**, I need **an Admin Auth Studio screen at `/admin/auth` to create, edit, enable/disable, reorder, and live-probe authentication cards (`OIDC`, `OAUTH2`, `LDAP`, `LOCAL_ADMIN`) with write-only secret fields and explicit `LOCKOUT_PREVENTED` safeguard feedback** so that **sign-in order on `/login` matches our security policy, envelope-encrypted secrets (`client_secret`, `bind_dn_password`) are never echoed to the browser, and accidental administrator lockout is blocked with actionable recovery instructions**.

**Requirement Traceability:** `S4.1` (`auth_provider_cards` schema, `provider_kind`, `slug`, `sort_rank COLLATE "C"`, `last_health_status`, write-only `encrypted_secret_blob`), `S4.2 items 1-4` (PKCE `S256` pinned `iss`/`aud`/`azp`, `LDAPS`/`StartTLS` CA PEM + SPKI pin, `LOCAL_ADMIN` `AAL2`, zero email auto-merge), `S4.3` (3-layer `LOCKOUT_PREVENTED` safeguards lines 350-353), `S6.1` (`--card-pad`, `--card-gap`, `--prop-row-h`, `--section-gap`), `S6.2` (`🛡️`, `🔒`, `⚠️` `<EmojiHint>`), `S3.4` (non-admin renders uniform `Not found or no access`), requirements `#6`, `#9`, `#15` | **Dependencies:** `KB-P3-35` (auth API helpers + `SecondFactorStep` for `AAL2` step-up), `KB-P2-10` (`/api/v1/admin/auth-cards` CRUD, toggle, reorder, test-handshake)

3. **Consumed API contract (`KB-P2-10`, mocked in Vitest + Playwright; any backend path difference documented in `message-to-reality-checker.md`):**
   | Operation | Endpoint | Request Body | Success / Error Codes |
   | :-- | :-- | :-- | :-- |
   | List all cards | `GET /api/v1/admin/auth-cards` | - | `200 { cards: AdminAuthCard[] }` (includes `has_secret: boolean`, `dek_kid`, `last_health_status`, `last_handshake_at`; NEVER secret plaintext) |
   | Create card | `POST /api/v1/admin/auth-cards` | `{ provider_kind, slug, display_name, button_subtext, icon_preset, auto_provision_users, allowed_email_domains, public_config, secret_input? }` | `201`, `409 SLUG_TAKEN`, `422 VALIDATION_FAILED` |
   | Update card | `PATCH /api/v1/admin/auth-cards/{card_id}` | partial metadata + optional `secret_input` (omitted = keep existing secret) | `200`, `409 LOCKOUT_PREVENTED`, `422` |
   | Toggle enable | `PATCH /api/v1/admin/auth-cards/{card_id}/enabled` | `{ is_enabled: boolean }` | `200`, `409 LOCKOUT_PREVENTED` |
   | Reorder card | `POST /api/v1/admin/auth-cards/{card_id}/reorder` | `{ before_card_id: string \| null, after_card_id: string \| null, sort_rank: string }` | `200` |
   | Test handshake | `POST /api/v1/admin/auth-cards/{card_id}/test-handshake` | `{}` | `200 { last_health_status: "HEALTHY" \| "FAILED", latency_ms: number, check_summary: string }` |
   | Delete card | `DELETE /api/v1/admin/auth-cards/{card_id}` | - | `204`, `409 LOCKOUT_PREVENTED` |
4. **Card list, breathable layout & reorder (`AuthStudioPage.tsx`, `AuthCardRow.tsx`, `cardRank.ts`):**
   - Header (`margin-bottom: var(--section-gap)`, `32px`): `<h1>Authentication Studio</h1>`, `🛡️` `<EmojiHint kind="access">` (`content`: `"Simultaneous OIDC, OAuth2, LDAPS/StartTLS, and Local Admin cards. Matching email addresses never auto-merge accounts across cards (bound strictly by auth_card_id + immutable_subject_id)."`), and `+ Add auth card` primary button.
   - Ordered `<ol class="auth-studio-list">` with `row-gap: var(--card-gap)` (`12px`); each `AuthCardRow` uses `padding: var(--card-pad)` (`16px 18px`), `background: var(--bg-surface)`, `border: 1px solid var(--border-subtle)`, `border-radius: var(--radius-lg)`.
   - Row controls: drag grip (`draggable`, native HTML5 drag events, zero external DnD dependency) paired with accessible `Move up` / `Move down` icon buttons (`min-width`/`min-height` `24px`, `44px` coarse hit area on mobile; `LOCAL_ADMIN` stays pinned to the break-glass disclosure slot and its reorder controls are disabled with `aria-label="Local Admin always appears in the break-glass disclosure"`), icon glyph from the frozen `KB-P3-35` allowlist, `display_name`, `.mono` `slug`, `provider_kind` badge, health status chip (`HEALTHY` `--ok-fg`, `UNVERIFIED` `--fg-muted`, `FAILED` `--danger-fg` + `⚠️` `<EmojiHint kind="warning">` showing sanitized `check_summary` and `last_handshake_at`), `Test handshake` button (`aria-busy` while running), `role="switch"` `aria-checked={is_enabled}` toggle (`aria-label="Enable <display_name>"`), `Edit` button, and `Delete` button (disabled on `LOCAL_ADMIN`).
   - `cardRank.ts` computes Base-62 (`0-9A-Za-z`, ASCII `COLLATE "C"` order) lexicographic midpoints (`midpointRank(prev: string | null, next: string | null): string`); reorder applies optimistically via `useOptimisticMutation` (`KB-P3-33`) and rolls back on failure.
5. **Create/Edit drawer & write-only secret hygiene (`AuthCardEditorDrawer.tsx`):**
   - Right-docked drawer (`width: min(640px, 100vw)`, `padding: var(--prose-pad)` `32px 40px`, property rows `min-height: var(--prop-row-h)` `38px`, `role="dialog"`, `aria-modal="true"`, `Escape` closes).
   - Shared fields: `provider_kind` (`OIDC | OAUTH2 | LDAP`, immutable on edit), `slug` (`^[a-z0-9][a-z0-9-]{1,46}[a-z0-9]$`), `display_name` (`1..80`), `button_subtext` (`0..120`), `icon_preset` select, `auto_provision_users` switch, `allowed_email_domains` tag list (normalized lowercase ASCII/punycode hostnames).
   - Per-kind `public_config` & write-only `secret_input` (`type="password"`, `autocomplete="new-password"`):
     - `OIDC` / `OAUTH2`: `issuer_url` (`https://` required), `client_id`, `scopes`, `pkce_method` read-only badge `S256 (enforced)`, `token_auth_method` (`client_secret_basic | private_key_jwt`), write-only `client_secret` or `private_key_pem`.
     - `LDAP`: `server_url` (`ldaps://` or `ldap://` with mandatory `start_tls: true` locked on when scheme is `ldap://`; `ldap://` without `StartTLS` rejected client-side before submit per `S4.2 item 2`), `bind_dn`, `base_dn`, `user_filter`, `ca_pem`, `spki_sha256_pin` (`^[A-Fa-f0-9]{64}$` optional), write-only `bind_dn_password`.
     - `LOCAL_ADMIN` (edit-only): `display_name`, recovery policy summary, `🔒` `<EmojiHint kind="restricted">` (`"Argon2id (m=64MiB, t=3, p=4) + server HMAC pepper + mandatory Passkey or TOTP (AAL2)."`).
   - Write-only contract: on edit when `card.has_secret === true`, secret inputs stay `value=""` with placeholder `"Stored encrypted (dek_kid: <dek_kid>) - leave blank to keep current secret"`, and an explicit checkbox `Replace stored secret` unlocks typing a new secret. On submit (success or error), secret state is overwritten with `''` in `finally` and never stored in TanStack Query cache. If a hostile/buggy mock response ever includes `client_secret`, `bind_dn_password`, `encrypted_secret_blob`, or `wrapped_dek`, `adminAuthApi.ts` strips those keys before returning.
6. **`LOCKOUT_PREVENTED` error banner (`LockoutPreventedBanner.tsx`, `S4.3`):**
   - When toggle, edit, or delete returns `409` with `code === 'LOCKOUT_PREVENTED'`, roll back the optimistic UI state, focus a `role="alert"` banner at the top of the list, and render:
     - `⚠️` `<EmojiHint kind="warning">` (`content`: `"Three-layer anti-lockout safeguard (DB trigger, 15-minute IdP handshake gate, host CLI break-glass)."`).
     - Exact reason mapped from server sub-reason (`reason_code`):
       - `ZERO_ADMIN_CARDS` -> `"Lockout prevented: disabling or deleting this card would leave zero enabled sign-in cards capable of authenticating an active Server Administrator."`
       - `HANDSHAKE_STALE_FOR_LOCAL_DISABLE` -> `"Lockout prevented: Local Administrator cannot be disabled until at least one external Server-Admin identity provider card completes a verified login handshake within the past 15 minutes."`
       - fallback -> `"Lockout prevented: this change would block Server Administrator sign-in."`
     - Collapsible `Emergency host CLI recovery` disclosure displaying `kanban-ctl auth emergency-unlock --enable-local-admin` in `.mono` `<code>` with a `Copy command` button.
7. **Security invariants:** zero `dangerouslySetInnerHTML`, zero inline `style` attributes, zero `console.*` in `features/admin-auth/`, all server strings rendered as React text nodes, CSRF token required on every unsafe call via `apiFetch`.

- **Test File(s):** `kanban/web/src/features/admin-auth/AuthStudioPage.test.tsx`, `kanban/web/src/features/admin-auth/AuthCardEditorDrawer.test.tsx`, `kanban/web/src/features/admin-auth/LockoutPreventedBanner.test.tsx`, `kanban/web/src/features/admin-auth/cardRank.test.ts`
- **Required Test Cases:**
  1. Positive: renders 4 cards in `sort_rank` order with `Primary` indicator on first enabled external card; `Move down` on card 1 computes valid Base-62 midpoint `sort_rank` (`prev < mid < next` under ASCII byte compare) and calls `POST .../reorder`; `Test handshake` updates badge from `UNVERIFIED` to `HEALTHY (42 ms)`.
  2. Write-only secrets & stripping: opening Edit on an existing OIDC card with `has_secret: true` renders empty password input (`value === ""`) and keeps `secret_input` omitted from `PATCH` payload unless `Replace stored secret` is checked; after submit with a new secret, input and state reset to `""`; mocked API response containing `"client_secret": "leak"` is stripped by `adminAuthApi.ts`.
  3. Protocol hardening validation: `OIDC` with `http://idp.example` is rejected before request; `LDAP` with `ldap://dc01.corp` forces `start_tls = true` (cannot be unchecked); invalid `slug` `Bad_Slug` and invalid `spki_sha256_pin` (`63` hex chars) show field alerts and issue zero `POST` requests.
  4. `LOCKOUT_PREVENTED` & rollback: toggling `LOCAL_ADMIN` off when API returns `409 LOCKOUT_PREVENTED` (`reason_code: 'HANDSHAKE_STALE_FOR_LOCAL_DISABLE'`) snaps the switch back to `aria-checked="true"`, focuses `role="alert"`, renders the exact 15-minute handshake message, and exposes the exact CLI string `kanban-ctl auth emergency-unlock --enable-local-admin`.
  5. Security / anti-enumeration & `AAL2`: non-admin user sees `Not found or no access`; hostile `display_name = "<script>alert(1)</script>"` and `check_summary = "<img src=x onerror=alert(1)>"` render as literal text; `403 AAL2_REQUIRED` on toggle opens `SecondFactorStep` and replays the toggle once verified.
  6. Boundary (`cardRank.ts`): `100` sequential insertions at the top of the list maintain strict `a < b` ASCII `COLLATE "C"` ordering without collision.
