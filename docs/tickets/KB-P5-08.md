### User Story
As a **ticket author typing in any Markdown surface**, I need **a blinking `✨` badge at my caret and an inline ghost-text preview that I can accept with `Tab` or a left-click on `✨`, without the document changing or the layout shifting until I accept** so that **AI completions are fast and helpful but never intrude on or corrupt what I am writing**.

**Requirement Traceability:** `S9.1 (state diagram, SparkleOverlayPortal, coordsAtPos, opacity pulse 0.38 <-> 1.0 1.15s, prefers-reduced-motion, Decoration.widget pointer-events none)`, `S9.3 (<150ms)`, `S15.2`, original requirement `#7` | **Dependencies:** `KB-P5-07` (SSE contract), `KB-P3-45` (ProseMirror editor core)

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/web/src/editor/sparkle/sparkleMachine.ts` (new: pure reducer)
   - `kanban/web/src/editor/sparkle/sparkleClient.ts` (new: `fetchSparkle()` SSE client with `AbortController`)
   - `kanban/web/src/editor/sparkle/SparkleCompletionPlugin.ts` (new: ProseMirror `Plugin` + `PluginKey`)
   - `kanban/web/src/editor/sparkle/SparkleOverlayPortal.tsx` (new: React portal for the `18px x 18px` badge)
   - `kanban/web/src/editor/sparkle/sparkle.css` (new)
   - `kanban/web/src/editor/` editor surface factory (modify: attach plugin to `Summary`, `Description`, `Comment`, `Sticky`, `Doc`)
2. **State machine (`sparkleMachine.ts`), states exactly `IDLE | TYPING | FETCHING | READY_BLINKING | ACCEPTED | DISMISSED`:**
   - `IDLE -> TYPING` when `>= 4` printable characters have been typed since the last reset AND selection is collapsed.
   - `TYPING -> FETCHING` after a `320ms` pause; any prior in-flight request is aborted first.
   - `FETCHING -> READY_BLINKING` on `completion` event + `done.status == "ok"` with non-empty text.
   - `FETCHING -> IDLE` on `done.status` in `empty | timeout | secret_scrubbed | unavailable | budget`, on network error, or on a client-side `150ms` + `50ms` grace abort (`200ms` total).
   - `READY_BLINKING -> ACCEPTED` on `Tab` or left-click on `✨` (right-click handling is `KB-P5-09`).
   - `READY_BLINKING -> DISMISSED` on `Escape`, caret move, selection becoming non-empty, or typed character that does not match the next ghost-text character (a matching character advances the ghost text instead).
   - `ACCEPTED -> IDLE` after inserting the suggestion as plain text via one transaction preceded by `closeHistory(tr)` so `Cmd/Ctrl+Z` undoes exactly the insertion. `DISMISSED -> IDLE` immediately.
   - Reducer is pure (no DOM, no timers) so every transition is table-testable; timers live in the plugin view.
3. **`sparkleClient.ts`:** `POST /api/v1/sparkle/complete` with CSRF header, `credentials: "same-origin"`, parses `text/event-stream` with a hand-written line parser (no new dependency), accepts only `completion` and `done` events, rejects unknown events, caps total response at `8 KiB`. The returned text is treated as untrusted: it is rendered only via `textContent`, never `innerHTML`.
4. **Rendering:**
   - Ghost text: `Decoration.widget(selection.from, () => span)` where `span.className = "sparkle-ghost"`, `span.textContent = suggestion`, `aria-hidden="true"`; CSS `pointer-events: none; opacity: 0.45`. The document (`state.doc`) is unchanged while in `READY_BLINKING`.
   - Badge: `SparkleOverlayPortal` absolutely positioned at `editorView.coordsAtPos(selection.from)` relative to the editor container, size `18px x 18px`, `role="button"`, `aria-label="Accept AI suggestion (Tab)"`, `tabIndex={-1}`. Position is applied via CSSOM (`el.style.transform = ...`), never `setAttribute("style")`, to remain compatible with the strict CSP from S5.4 (no runtime CSS-in-JS).
   - Animation: `@keyframes sparkle-pulse { from { opacity: 0.38 } to { opacity: 1.0 } }` `1.15s ease-in-out infinite alternate`; under `@media (prefers-reduced-motion: reduce)` the animation is `none` with a static glow (`opacity: 1`, `box-shadow` token from the design system).
   - A visually hidden `aria-live="polite"` region announces `"Suggestion available. Press Tab to accept."` once per `READY_BLINKING` entry.
   - Zero layout shift: badge and ghost text are out-of-flow / widget decorations; no editor container size change.
5. **Keyboard:** `Tab` is consumed only in `READY_BLINKING`; in all other states `Tab` keeps its existing editor behavior. `Escape` dismisses only in `READY_BLINKING`.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/web/src/editor/sparkle/__tests__/sparkleMachine.test.ts`, `kanban/web/src/editor/sparkle/__tests__/sparkleClient.test.ts`, `kanban/web/src/editor/sparkle/__tests__/SparkleCompletionPlugin.test.ts`, `kanban/web/e2e/sparkle.spec.ts` (Playwright)
- **Fixtures (new, JSON SSE transcripts derived from KB-P5-07 cassettes, under `tests/fixtures/ai/web/`):** `sparkle_stream_ok.json`, `sparkle_stream_empty.json`, `sparkle_stream_secret_scrubbed.json`, `sparkle_stream_timeout.json`, `sparkle_stream_unknown_event.json`, `sparkle_stream_oversize.json`, `sparkle_stream_html_text.json` (completion text `<b>x</b>` to prove `textContent` rendering)
- **Required Test Cases:**
  1. Reducer table: every edge in the S9.1 diagram plus every listed non-edge (e.g. `IDLE` + `Tab` stays `IDLE`) - at least 20 rows.
  2. Debounce: 3 chars -> no fetch; 4th char then `319ms` -> no fetch; `320ms` -> exactly 1 fetch (fake timers).
  3. Abort: typing during `FETCHING` aborts the prior request (`AbortSignal.aborted === true`) and starts a new debounce.
  4. Accept: `Tab` in `READY_BLINKING` inserts text, one undo step removes it, document unchanged before accept (`state.doc.eq(before)`).
  5. Security: `sparkle_stream_html_text.json` renders literal `<b>x</b>` text, no `<b>` element in DOM; `sparkle_stream_unknown_event.json` -> `IDLE`; oversize stream (`> 8 KiB`) -> aborted, `IDLE`.
  6. Fault: `empty`, `secret_scrubbed`, `timeout` fixtures and a rejected `fetch` (network error) -> `IDLE` with no badge.
  7. Dismiss: caret move, `Escape`, mismatched char -> `DISMISSED -> IDLE`; matched char advances ghost text by 1.
  8. Reduced motion: with `matchMedia("(prefers-reduced-motion: reduce)")` true, computed `animation-name` is `none`.
  9. Playwright: badge bounding box is `18x18` within `2px` of `coordsAtPos`; `PerformanceObserver("layout-shift")` total `0` across fetch -> ready -> accept; Tab with no suggestion moves focus as before.
  10. Playwright screenshots at desktop `1440x900`, tablet `834x1112`, mobile `390x844` in `READY_BLINKING`, plus one with `reducedMotion: "reduce"`, each annotated (badge and ghost text outlined with labels).
- **Coverage:** vitest `>= 95%` lines/functions/branches/statements for `kanban/web/src/editor/sparkle/**`.
