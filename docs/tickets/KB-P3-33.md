### User Story
As a **frontend feature implementer**, I need **a single typed API layer generated from the backend OpenAPI document, a stable query-key factory, an optimistic-mutation helper with deterministic rollback, and a resilient realtime client (WebSocket with SSE `Last-Event-ID` fallback)** so that **board drags, property edits and gate state changes apply in under one frame, roll back cleanly on rejection, stay consistent across tabs via realtime events, and never send an unsafe request without CSRF protection**.

**Requirement Traceability:** `S1.3 item 2` (sub-16ms optimistic interactions, `<12ms` drag, non-blocking provisional states), `S2.3` (`/ws`, `/sse` with `Last-Event-ID`), `S3.4` (indistinguishable `404` for unreadable objects), requirement `#9` | **Dependencies:** `KB-P3-02`, `KB-P3-16`

2. **`client.ts`:** `export async function apiFetch<P extends keyof paths, M extends Method>(method: M, path: P, opts?: { params?; query?; body?; ifMatch?: string; signal?: AbortSignal }): Promise<ResponseBody<P, M>>` typed from `schema.gen.ts`. Rules: relative URLs only (`/api/v1/...`; any absolute URL or protocol-relative path throws `ApiClientError('ABSOLUTE_URL_FORBIDDEN')`); path params are `encodeURIComponent`-encoded; `credentials: 'same-origin'`; `Accept: application/json`; for `POST/PATCH/PUT/DELETE` sets `X-CSRF-Token` from cookie `__Host-kb_csrf` (if the cookie is missing, throw `ApiClientError('CSRF_TOKEN_MISSING')` without sending); `If-Match` header when `ifMatch` given; returns parsed JSON; `204` returns `undefined`; response `content-type` not `application/json` or `application/problem+json` on a body-bearing response throws `ApiClientError('UNEXPECTED_CONTENT_TYPE')`; default timeout `15000ms` via `AbortSignal.timeout` combined with caller signal.
3. **`problem.ts`:** `export class ApiProblem extends Error { status; code; title; detail; instance; }` parsed from RFC 7807 bodies (KB-P2-01); unknown/malformed bodies map to `code: 'UNKNOWN'`. `isNotFound(e)` treats `404` uniformly (UI must show "Not found or no access" and never distinguish 403 vs 404). `isPreconditionFailed(e)` for `412` (ETag conflict).
4. **`queryKeys.ts`:** exact factory:
   ```ts
   export const qk = {
     me: () => ['me'] as const,
     systemStatus: () => ['system', 'status'] as const,
     project: (key: string) => ['project', key] as const,
     issues: (projectKey: string, filters: Readonly<Record<string, unknown>>) => ['issues', projectKey, filters] as const,
     issue: (issueKey: string) => ['issue', issueKey] as const,
     activity: (issueKey: string, tab: 'all' | 'comments' | 'history' | 'gates') => ['activity', issueKey, tab] as const,
     access: (objectId: string) => ['access', objectId] as const,
     authCards: () => ['auth', 'cards'] as const,
     docsTree: (projectKey: string) => ['docs', 'tree', projectKey] as const,
     page: (pageId: string) => ['docs', 'page', pageId] as const,
     stickies: (projectKey: string) => ['stickies', projectKey] as const,
   };
   ```
   `queryClient.ts`: `createQueryClient()` with `staleTime: 30000`, `retry: (n, e) => n < 2 && !(e instanceof ApiProblem && e.status < 500)`, `refetchOnWindowFocus: true`.
5. **`optimistic.ts`:** `useOptimisticMutation<TVars, TData, TCache>({ mutationFn, queryKey, apply: (cache, vars) => TCache, onRollbackMessage?: (err) => string })`: `onMutate` cancels in-flight queries for `queryKey`, snapshots cache, writes `apply(snapshot, vars)` synchronously; `onError` restores the exact snapshot and publishes a toast message via `announce()` (an `aria-live="polite"` region exported from `RealtimeStatus.tsx`); `onSettled` invalidates `queryKey`. Requirement: the synchronous `apply` path for a 500-issue board cache completes `< 12ms` (benchmark test with `performance.now()`, median of 20 runs).
6. **`realtime.ts`:** `export class RealtimeClient` with `connect()`, `subscribe(channel: string, handler: (evt: RealtimeEvent) => void): () => void`, `close()`, `state: 'connecting' | 'open' | 'reconnecting' | 'sse-fallback' | 'closed'`, `onStateChange(cb)`.
   - Connects to same-origin `/ws` (`wss:` when page is `https:`); sends `{ "type": "subscribe", "channels": [...] }` after open and on every reconnect.
   - Event envelope validated at runtime: `{ id: string (<= 128 chars), channel: string, type: string, payload: object }`; events failing validation or larger than `256 KiB` are dropped and counted (`droppedEvents`); never `eval`/`Function`.
   - Reconnect: backoff `delay = random(0, min(15000, 500 * 2^attempt))` (full jitter); after 3 consecutive failed WS attempts switch to `EventSource('/sse?channels=...')`, which sends `Last-Event-ID` automatically; keeps tracking `lastEventId`; retries WS every `60000ms` while on SSE and switches back on success.
   - Deduplicates by event `id` (LRU of last 1000 ids) so WS->SSE handover does not double-apply.
   - `useRealtime(channel, handler)` hook subscribes/unsubscribes with component lifecycle; `bindQueryInvalidation(client, queryClient)` maps `issue.updated` -> invalidate `qk.issue(key)` and `qk.issues(projectKey, *)`.
7. **`RealtimeStatus.tsx` (UI surface for this ticket):** A non-blocking status chip rendered in the bottom-left of the viewport, hidden when `open`. States: `reconnecting` -> text `Reconnecting...` with an elapsed seconds counter; `sse-fallback` -> text `Live updates via fallback channel`; `closed` -> `Offline - changes will sync when reconnected`. Chip: `padding: var(--space-2) var(--space-4)` (8px 16px), `margin: var(--space-6)` (24px) from viewport edges, `border-radius: var(--radius-lg)`, `--bg-surface-raised`, `--fg-secondary`, `font-size: var(--text-body)`. `role="status"`, `aria-live="polite"`; never steals focus; never blocks pointer input to the board (no overlay). Also exports `announce(message)` for the shared live region. Dev route `/__dev/realtime` (dev-only, same rule as KB-P3-30) renders buttons to force each state for e2e.
8. **Security invariants:** no tokens in `localStorage`/`sessionStorage`; no API response is ever passed to `dangerouslySetInnerHTML`; WS URL is always derived from `location` (no configurable host); unknown event types ignored.

  4. Realtime (fake WebSocket/EventSource + fake timers + seeded RNG): resubscribes after reconnect; backoff delays bounded by `min(15000, 500*2^n)`; 3 failures -> `sse-fallback`; duplicate event id applied once; oversize (`> 256 KiB`) and schema-invalid events dropped and counted; returns to WS after successful 60s probe.
  5. Boundary: event id of 129 chars dropped; LRU evicts id #1 after 1001 distinct ids; `close()` clears all timers (no pending timers after `vi.runOnlyPendingTimers`).
  6. `RealtimeStatus`: hidden when `open`; `role="status"` text per state; never receives focus on state change.
  7. Python: `export_openapi` output is valid JSON, deterministic across two runs, contains `/api/v1/issues/{issue_key}` path from KB-P3-02.
