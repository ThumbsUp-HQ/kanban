### User Story
As a **homelab evaluator running `docker run -p 8080:8080 kanban:latest`**, I need **a PID-1-supervised entrypoint that initializes and starts an embedded PostgreSQL 16 reachable only over a Unix socket, applies migrations under a migration role, then runs Uvicorn as UID `65532` with all capabilities dropped, and shuts down in a defined order on `SIGTERM`** so that **the container works with zero flags while exposing zero TCP database ports and keeping the web process unable to read PostgreSQL files**.

**Requirement Traceability:** `S2.2` boot lifecycle items 2 and 3, `S3.5` row "Standalone `docker run` Misconfiguration" (`listen_addresses = ''`, `postgres` vs `kanban` UID separation), Requirement `#3` | **Dependencies:** `KB-P0-07`, `KB-P0-10` (the manifest lists only `KB-P0-07`; `KB-P0-10` is required because the container smoke test and boot measurement need `kanban.app:create_app` to answer `GET /`)

### Scoped Technical Actions
1. **Target Files:** `deploy/__init__.py`, `deploy/standalone/__init__.py`, `deploy/standalone/entrypoint.py`, `deploy/standalone/pg_config.py`, `tests/deploy/test_standalone_entrypoint.py`, `tests/deploy/test_standalone_container.py`, root `pyproject.toml` (mypy `packages` adds `deploy`; pytest marker `container`)
2. **Mode selection (`main() -> int`):**
   - If env `DATABASE_URL` is set: log `MODE=external_db`, skip all PostgreSQL steps, and `os.execv` Uvicorn under the same privilege drop as item 6.
   - Else: `MODE=standalone_embedded_pg` and execute items 3-7.
   - If not running as UID `0`: exit `78` with `STANDALONE_REQUIRES_ROOT_ENTRYPOINT` (rootless `--user 1000:1000` over `/tmp/postgresql` per S2.2 item 3 is out of scope for this ticket; see follow-up recommendation).
3. **Cluster init (first boot only, detected by absence of `/var/lib/kanban/data/pgdata/PG_VERSION`):** run as `postgres` via `setpriv --reuid=postgres --regid=postgres --init-groups --inh-caps=-all --no-new-privs`:
   `initdb -D /var/lib/kanban/data/pgdata --encoding=UTF8 --locale=C.UTF-8 --auth-local=peer --auth-host=reject --username=postgres`.
   `pg_config.py` writes, idempotently, `postgresql.auto.conf`-independent settings into `pgdata/conf.d/kanban.conf` (included via `include_dir = 'conf.d'`): `listen_addresses = ''`, `unix_socket_directories = '/run/postgresql'`, `unix_socket_permissions = 0770`, `shared_buffers = 128MB`, `fsync = on`. `pg_hba.conf` is rewritten to exactly:
   ```
   local  all     postgres                         peer
   local  kanban  kanban_migrator                  peer map=kanban_map
   local  kanban  kanban_app                       peer map=kanban_map
   ```
   `pg_ident.conf`: `kanban_map postgres kanban_migrator` and `kanban_map kanban kanban_app`. No `host` lines exist.
4. **Start PostgreSQL:** `pg_ctl -D ... -w -t 10 start -o "-c config_file=..."` as `postgres`. Readiness: `pg_isready -h /run/postgresql` within `10s` else exit `70` with `PG_START_TIMEOUT` after stopping any partial process.
5. **Bootstrap SQL (idempotent, every boot) via `psql -h /run/postgresql -U postgres -v ON_ERROR_STOP=1`:** create roles if missing: `kanban_migrator LOGIN NOSUPERUSER NOCREATEROLE NOBYPASSRLS`, `kanban_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS`; create database `kanban OWNER kanban_migrator ENCODING 'UTF8' TEMPLATE template0` if missing; `CREATE EXTENSION IF NOT EXISTS` `pgcrypto`, `ltree`, `pg_trgm`, `btree_gist`, `vector` in database `kanban`; `ALTER ROLE kanban_migrator LOGIN`.
   **Migrations:** if `/opt/kanban/alembic.ini` exists, run `alembic -c /opt/kanban/alembic.ini upgrade head` as OS user `postgres` (peer map -> `kanban_migrator`) with `DATABASE_URL=postgresql+asyncpg://kanban_migrator@/kanban?host=/run/postgresql`; non-zero exit -> stop PG, exit `70` with `MIGRATION_FAILED`. If absent, log `MIGRATIONS_SKIPPED_NO_ALEMBIC_INI` (Alembic arrives in KB-P1-01). **Privilege drop:** afterwards `ALTER ROLE kanban_migrator NOLOGIN`.
6. **Uvicorn as `kanban` (UID `65532`):** spawn with `subprocess.Popen` (argv list, `shell=False`):
   `setpriv --reuid=65532 --regid=65532 --clear-groups --inh-caps=-all --no-new-privs -- /opt/kanban/.venv/bin/uvicorn kanban.app:create_app --factory --host 0.0.0.0 --port 8080 --proxy-headers --forwarded-allow-ips=""`
   Child env is an explicit allowlist (`PATH`, `KB_WEB_DIST`, `KB_DEPLOYMENT_MODE=standalone`, `DATABASE_URL=postgresql+asyncpg://kanban_app@/kanban?host=/run/postgresql`, `LANG=C.UTF-8`); the parent environment is not inherited. `/var/lib/kanban/data/pgdata` remains `0700 postgres`, so UID `65532` cannot read heap files.
7. **Signals and shutdown order:** install handlers for `SIGTERM` and `SIGINT`: (1) send `SIGTERM` to Uvicorn, wait up to `10s`, then `SIGKILL`; (2) `pg_ctl stop -m fast -t 10` as `postgres`; (3) exit `0`. If Uvicorn exits on its own, stop PostgreSQL and exit with Uvicorn's exit code. If PostgreSQL's postmaster dies (poll `pg_ctl status` every `2s`), terminate Uvicorn and exit `70` with `PG_DIED`.
8. **Logging:** one line per phase to stdout prefixed `[kanban-standalone]` with monotonic elapsed ms (`initdb`, `pg_start`, `bootstrap_sql`, `migrations`, `uvicorn_spawn`). Never log environment values or role passwords.
9. **Security invariants:** every external command is an absolute-path argv list (`/usr/lib/postgresql/16/bin/initdb`, `/usr/lib/postgresql/16/bin/pg_ctl`, `/usr/bin/setpriv`, `/usr/bin/psql` via PG bin dir); zero use of `shell=True`, `os.system`, or string-built commands; every subprocess has a timeout.

### Mandatory Feature Unit Tests
- **Test File(s):** `tests/deploy/test_standalone_entrypoint.py` (subprocess, `os.execv`, `os.getuid`, filesystem paths injected or monkeypatched; zero real processes), `tests/deploy/test_standalone_container.py` (marked `@pytest.mark.container`; requires Docker; excluded from the default unit run with `-m "not container"`)
- **Required Test Cases:**
  1. Positive: first boot (no `PG_VERSION`) issues, in order, `initdb` (with `--encoding=UTF8 --locale=C.UTF-8 --auth-host=reject`), `pg_ctl start`, bootstrap `psql`, `alembic upgrade head` (when `alembic.ini` exists), `ALTER ROLE kanban_migrator NOLOGIN`, Uvicorn `setpriv` spawn; asserted via recorded argv lists.
  2. Positive: warm boot (existing `PG_VERSION`) skips `initdb`; `DATABASE_URL` set -> zero PostgreSQL commands, `execv` of `setpriv ... uvicorn`.
  3. Negative/security: generated `pg_hba.conf` contains zero `host` lines; `kanban.conf` contains `listen_addresses = ''`; the Uvicorn argv contains `--reuid=65532`, `--inh-caps=-all`, `--no-new-privs`; the child env contains no key outside the allowlist; no recorded call used `shell=True`.
  4. Negative: non-root UID -> exit `78`; `pg_isready` never ready -> exit `70` and `pg_ctl stop` was called; Alembic failure -> exit `70`, PG stopped, Uvicorn never spawned.
  5. Boundary: `SIGTERM` handler sends `SIGTERM` to Uvicorn before `pg_ctl stop -m fast`; Uvicorn ignoring `SIGTERM` for `> 10s` (fake clock) receives `SIGKILL`; exit code `0`.
  6. Container smoke (`test_standalone_container.py`): `docker run -d -p 18080:8080 kanban:latest`; within `10s`, `GET http://127.0.0.1:18080/` returns `200`; `docker exec <c> sh -c 'cat /proc/net/tcp /proc/net/tcp6'` shows no listener on port `5432` (hex `1538`); `docker exec <c> ps -o uid,comm` shows `uvicorn` under UID `65532` and `postgres` under the `postgres` UID; `docker stop -t 15` exits within `15s` and logs show Uvicorn stopped before PostgreSQL.
