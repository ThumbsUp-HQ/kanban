### User Story
As a **project member or agent**, I need **to create, list and delete typed `object_links` between any registered objects and copy an issue's canonical URL or `[KEY](url)` Markdown** so that **the Universal Object Graph is navigable while links to objects I cannot read never leak their key, title or id**.

**Requirement Traceability:** Spec S7.2 `8m`; S12.1 (`object_links`, `link_kind`); S12.3 (`FLAGGED_INVALID` surfaced); S3.4; requirements `#8m`, `#13`, `#1` | **Dependencies:** `KB-P3-02`, `KB-P1-11`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/links.py`, `kanban/api/v1/schemas/links.py`, `kanban/services/links.py`, `kanban/services/object_ref.py` (`resolve_object_ref()`), `kanban/settings.py` (add `public_base_url`), `kanban/services/activity.py` (append events).
2. **Object reference resolution (`resolve_object_ref(session, ref: str, expected_type: ObjectKind | None)`):** accepts UUID, issue key (`KAN-142`), or project identifier (`KAN`). Returns `None` for nonexistent and unreadable alike (RLS). Max ref length `64`.
3. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `GET /api/v1/objects/{object_ref}/links` | `VIEW` on object | `200` | `404` |
   | `POST /api/v1/objects/{object_ref}/links` | `LINK` on source, `VIEW` on target | `201` | `404` source, `403 INSUFFICIENT_CAPABILITY`, `422 TARGET_NOT_FOUND`, `422 LINK_TYPE_NOT_ALLOWED`, `422 SELF_LINK`, `409 LINK_EXISTS` |
   | `DELETE /api/v1/links/{link_id}` | `LINK` on source | `204` | `404` (link absent or source unreadable), `403` |
   | `GET /api/v1/objects/{object_ref}/canonical-url` | `VIEW` | `200` | `404` |

   - `POST` body: `{"target": "KAN-7", "link_type": "BLOCKS"}`; `link_type` must be one of the user-creatable kinds `BLOCKS`, `BLOCKED_BY`, `RELATES_TO`, `DUPLICATES`, `VERIFIED_BY_DOC`, `DERIVED_FROM_STICKY` (S7.2 `8m`). System kinds (`PARENT_OF`, `ASSIGNED_TO`, `IN_CYCLE`, `IN_MODULE`, `PROMOTED_TO_DOC`, `EMBEDS_OBJECT`, `GOVERNED_BY_VIEW`) return `422 LINK_TYPE_NOT_USER_CREATABLE`.
   - The `(source_type, link_type, target_type)` tuple is validated against KB-P1-11 `link_type_matrix` before insert (trigger error also maps to `422 LINK_TYPE_NOT_ALLOWED`). Nonexistent and unreadable targets return the identical `422 TARGET_NOT_FOUND` body. Key snapshots are populated from `objects.canonical_key`.
   - Links are stored exactly as requested (no auto-inverse rows). `GET` returns:
     ```json
     {"outbound": [{"id": "...", "link_type": "BLOCKS", "link_state": "ACTIVE",
                    "target": {"id": "...", "type": "issue", "key": "KAN-7", "title": "Add RLS policy"}}],
      "inbound":  [{"id": "...", "link_type": "RELATES_TO", "link_state": "FLAGGED_INVALID",
                    "source": {"restricted": true, "label": "🔒 Restricted Object"}}]}
     ```
     The far endpoint is masked to `{"restricted": true, "label": "🔒 Restricted Object"}` when unreadable: no `id`, `type`, `key`, `title` or key snapshot. `link_state` exposes `FLAGGED_INVALID` (S12.3 `🕸️⚠️`). Max `500` links per direction returned; beyond that `"truncated": true`.
   - Canonical URL: `{"url": "https://kanban.example/projects/KAN/issues/KAN-142", "markdown": "[KAN-142](https://kanban.example/projects/KAN/issues/KAN-142)"}`. Base comes only from `Settings.public_base_url` (env `KANBAN_PUBLIC_BASE_URL`, must be `https://` except `http://localhost` in standalone); the request `Host` header is never used (host-header injection). Markdown link text escapes `[]()` characters.
4. **Activity events emitted (category `HISTORY`):** `LINK_CREATED {link_id, link_type, source_id, target_id}` and `LINK_DELETED {link_id, link_type, source_id, target_id}`, each written twice: once against the source object and once against the target object (caller holds `VIEW` on both at write time).
5. **Security invariants:** `DELETE` of a link whose source is unreadable returns `404` even if the link id is valid; masking is applied per-request with the caller's RLS session; no endpoint returns `target_key_snapshot` for unreadable targets.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_links.py`, `kanban/tests/services/test_object_ref.py`
- **Required Test Cases:**
  1. Positive: `KAN-1 BLOCKS KAN-2` returns `201`; `GET` on KAN-1 lists outbound, on KAN-2 lists inbound; two `LINK_CREATED` rows written.
  2. Masking: link from readable `KAN-1` to `SEC-9` created by an admin; a `KAN`-only viewer sees `restricted: true` with no `key`/`id`/`title` (assert JSON keys exactly).
  3. Enumeration: targeting `SEC-9` (exists, unreadable) and `SEC-99999` (absent) return identical `422 TARGET_NOT_FOUND` bodies.
  4. Matrix: `user -> IN_CYCLE -> doc` style disallowed tuple returns `422 LINK_TYPE_NOT_ALLOWED`; `PROMOTED_TO_DOC` returns `422 LINK_TYPE_NOT_USER_CREATABLE`; self link `422 SELF_LINK`; duplicate `409 LINK_EXISTS`.
  5. Canonical URL: with `KANBAN_PUBLIC_BASE_URL=https://kb.test` and request header `Host: evil.test`, URL starts with `https://kb.test`; Markdown equals `[KAN-1](https://kb.test/projects/KAN/issues/KAN-1)`.
  6. Boundary: `FLAGGED_INVALID` link appears with that `link_state`; `VIEW`-only user `POST` returns `403`; ref longer than 64 chars returns `404`.
- Clean-DB `SAVEPOINT` harness. Coverage `>= 95%`.
