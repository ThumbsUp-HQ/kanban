### User Story
As an **Agent Manager or implementing engineer preparing a ticket for closure**, I need **`uv run kanban-agent validate-qa-packet --ticket-file ... --proof-dir ./docs/qa/<ID>/` to run deterministic passive proof-bundle checks followed by a structured `reality-checker` forensic audit without executing shell commands or visiting URLs** so that **missing specialist reviews, missing responsive screenshots, failing test logs, secret leaks, or fantasy approvals are caught locally with exit code `2` before `complete_work` is ever attempted**.

**Requirement Traceability:** `S15.3` example 4 (`uv run kanban-agent validate-qa-packet --ticket-file ./examples/tickets/kan-142.yaml --proof-dir ./docs/qa/KAN-142/`, report sections 1-4, exit codes `0`/`2`), `S15.4` item 3-5 (UI Specialist Gate, API + UI Dual Specialist Gate, `[DEP]` dependency evaluation gate, passive `reality-checker` `Grade-A READY` requirement), `S15.2` (`FixtureLLMProvider` cassettes) | `AGENTS.md` Mandatory Specialist & QA Gates | **Dependencies:** `KB-P0-13`, `KB-P5-04`, `KB-P2-17`

### Scoped Technical Actions
1. **Target Files:**
   - `agent/qa_validator/schemas.py` (`TicketSpecInput`, `DeterministicCheckResult`, `DodItemAudit`, `QaPacketVerdict`, exported JSON Schema `agent/schemas/kb-qa-verdict-v1.json`)
   - `agent/qa_validator/bundle_inspector.py` (`inspect_proof_directory()` - pure passive read-only filesystem verifier)
   - `agent/qa_validator/auditor.py` (`run_qa_packet_audit()` loading `.agents/agents/reality-checker.md` + passive forensic override + `ProviderRouter.generate_structured`)
   - `agent/cli_commands/validate_qa_packet.py` (`kanban-agent validate-qa-packet`, registered in `agent/cli.py`)
   - `examples/qa_packets/kan-142-ready/` and `examples/qa_packets/kan-142-missing-ui-review/` (compact sample proof directories for deterministic CLI validation)
   - `agent/GEMINI.md` (update)
2. **Passive Read-Only Bundle Inspector (`agent/qa_validator/bundle_inspector.py`):**
   - **Strict Containment & Passive Invariant:** Resolves `proof_dir = proof_dir.resolve(strict=True)`; walks entries rejecting any symlink or path whose `.resolve()` escapes `proof_dir` (`PROOF_SYMLINK_ESCAPE`), rejects FIFOs/sockets/devices, caps individual text file reads at `2 MiB` and total bundle read at `16 MiB` (`PROOF_BUNDLE_TOO_LARGE`), and inspects PNG headers (`89 50 4E 47 0D 0A 1A 0A` + IHDR `width x height`) without decoding untrusted image payloads or spawning any subprocess.
   - Parses `--ticket-file` supporting **both** YAML ticket files (`./examples/tickets/kan-142.yaml`) AND Markdown ticket files with YAML frontmatter (`docs/tickets/KB-*.md`).
   - Deterministic structural checks (`list[DeterministicCheckResult]`, each `{check_id, passed: bool, detail: str}`):
     1. `CORE_ARTIFACTS_PRESENT`: `git-diff.patch`, `unit-test-results.txt`, and `build-check.txt` (or `build-or-typecheck.txt`) exist and are `> 0` bytes.
     2. `UNIT_TESTS_EXIT_ZERO`: `unit-test-results.txt` contains passing summary and zero `FAILED` / non-zero exit markers.
     3. `BUILD_CHECK_CLEAN`: `build-check.txt` contains zero unhandled error exit markers.
     4. `UI_SPECIALIST_GATE`: if `"ui-specialist"` in `gates` (or `[UI]` tag), verifies `ui-specialist-review.md` exists, is non-empty, contains an explicit approval verdict, AND `screenshots/` contains `>= 3` valid `.png` files covering desktop, tablet, and mobile viewports (UNLESS ticket explicitly declares `N/A - Non-UI Ticket` for an API-only `[API]` ticket, in which case `ui-specialist-review.md` is still required while screenshots are `N/A`).
     5. `API_SPECIALIST_GATE`: if `"api-specialist"` in `gates` (or `[API]` tag), verifies both `api-specialist-review.md` and `ui-specialist-review.md` exist and contain explicit approval sign-offs.
     6. `DEPENDENCY_EVALUATION_GATE`: if `new_dependencies` is non-empty (or `[DEP]` tag), verifies `dependency-evaluation.md` exists and references permissive license + SHA-256 hash + architect/engineer sign-offs.
     7. `NO_RAW_SECRETS_IN_PROOF`: scans text artifacts in `proof_dir` with `KB-P2-17` `outbound_secret_scrubber` -> fails if unredacted `sk-*`, `ghp_*`, `AKIA*`, PEM private key, or `kb_adm_*` / `kb_agt_*` live secrets appear.
3. **Forensic `reality-checker` LLM Audit & Anti-Fantasy Post-Check (`agent/qa_validator/auditor.py`):**
   - Loads `.agents/agents/reality-checker.md` from repo root + appends the mandatory passive forensic mode override (forbidding command/web execution and incorporating `docs/qa/<ID>/message-to-reality-checker.md` when present).
   - Spotlights ticket text and proof file contents inside randomized `<<<UNTRUSTED_QA_EVIDENCE_<hex> >>>` delimiters after scrubbing via `KB-P2-17`.
   - When `--deterministic-only` is NOT set, calls `ProviderRouter.generate_structured(..., response_model=QaPacketVerdict)` (`KB-P5-04`):
     - `QaPacketVerdict`: `schema: Literal["kb-qa-verdict/v1"]`, `grade: Literal["A", "B+", "B", "B-", "C+", "C", "F"]`, `readiness: Literal["READY", "NEEDS_WORK", "FAILED"]`, `dod_verdicts: list[{criterion: str, passed: bool, evidence_ref: str}]` (`min_length=1`), `critical_issues: list[str]`, `report_markdown: str` (`1..16384` chars).
   - **Hard Anti-Fantasy Invariant (Code-Enforced, Never Trusted to Model Alone):** If ANY deterministic check failed, OR `verdict.grade != "A"`, OR `len(verdict.critical_issues) > 0`, OR any `dod_verdicts` item has `passed == False`, the auditor overrides/rejects any `readiness == "READY"` claim into `readiness = "NEEDS_WORK"` with `policy_override = "FANTASY_APPROVAL_BLOCKED"`.
4. **CLI `kanban-agent validate-qa-packet` (`S15.3` Example 4):**
   - Flags: `--ticket-file PATH` (required), `--proof-dir PATH` (required), `--provider {gemini,ollama,openai,fixture}` (default `gemini` when configured, or `fixture` with `--cassette`), `--model TEXT` (default `gemini-2.5-flash`), `--cassette PATH`, `--http-cassette PATH`, `--deterministic-only` (runs the 7 deterministic checks offline without an LLM call), `--air-gap`, `--report {text,json}` (default `text`), `--verbose-tools`.
   - Outputs all 4 S15.3 report sections: (1) scrubbed evidence manifest & rendered prompt summary, (2) trace of deterministic checks (`1..7`) and read files (with PNG dimensions), (3) TTFT + wall-clock latency + token count, (4) schema validation status + `grade` + `readiness`.
   - Exit codes: **`0` ONLY when all deterministic checks pass AND `grade == "A"` AND `readiness == "READY"`** (or all deterministic checks pass under `--deterministic-only`); **`2` when `NEEDS_WORK` / `FAILED` / deterministic gate failure / schema violation**; **`1` on runtime error** (unreadable ticket file, missing proof dir).

- **Test File(s):**

- **Cassettes (under `tests/fixtures/ai/`):**
  - `qa_packet_grade_a_ready.yaml` (returns `grade: "A"`, `readiness: "READY"`, all DoD items backed by exact file references)
  - `qa_packet_needs_work.yaml` (returns `grade: "B-"`, `readiness: "NEEDS_WORK"`, cites missing boundary test in `unit-test-results.txt`)
  - `qa_packet_fantasy_approval.yaml` (model hallucinates `grade: "B+"`, `readiness: "READY"` or `grade: "A"`, `readiness: "READY"` while a DoD item has `passed: false` -> blocked by `FANTASY_APPROVAL_BLOCKED`)
- **Required Test Cases:**
  1. Positive (S15.3 example 4): `validate-qa-packet --ticket-file examples/tickets/kan-142.yaml --proof-dir examples/qa_packets/kan-142-ready/ --provider fixture --cassette tests/fixtures/ai/qa_packet_grade_a_ready.yaml` exits `0`, prints all 4 sections, `grade: A`, `readiness: READY`.
  2. Positive (Markdown ticket frontmatter): parses a `docs/tickets/KB-P5-*.md` file directly as `--ticket-file` and enforces its `gates` and `new_dependencies` frontmatter fields.
  3. Negative / specialist gates enforced: `examples/qa_packets/kan-142-missing-ui-review/` (missing `ui-specialist-review.md` or missing mobile `.png` on a `[UI]` ticket, or missing `dependency-evaluation.md` on a `[DEP]` ticket) fails deterministic check `4`/`5`/`6` and exits `2` even if `qa_packet_grade_a_ready.yaml` is replayed (`FANTASY_APPROVAL_BLOCKED`).
  4. Anti-fantasy invariant: replaying `qa_packet_fantasy_approval.yaml` against a complete proof dir downgrades readiness to `NEEDS_WORK`, sets `policy_override="FANTASY_APPROVAL_BLOCKED"`, and exits `2`; `qa_packet_needs_work.yaml` exits `2`.
  5. Security (symlink escape & secret leak): symlink `proof_dir/git-diff.patch -> /etc/passwd` rejected with `PROOF_SYMLINK_ESCAPE` (exit `2`, file never read into prompt); proof bundle containing raw `ghp_1234567890abcdef1234567890abcdef1234` fails `NO_RAW_SECRETS_IN_PROOF` and scrubs the token before any LLM call.
  6. Passive guarantee: monkeypatch/spy on `subprocess.Popen`, `asyncio.create_subprocess_exec`, and `asyncio.create_subprocess_shell` asserts `0` subprocess invocations during `validate-qa-packet`; `pytest-socket` `--disable-socket` passes.
  7. Boundary: file `> 2 MiB` or bundle `> 16 MiB` rejected with `PROOF_BUNDLE_TOO_LARGE`; `--deterministic-only` runs with `0` provider calls; `--report json` validates against `kb-qa-verdict-v1.json`.
- **Coverage:** `>= 95%` line + branch across `agent.qa_validator` and `agent.cli_commands.validate_qa_packet`.

5. `docs/qa/<TICKET_ID>/report-sample.json` - Captured `--report json` output for both `READY` and `FANTASY_APPROVAL_BLOCKED` runs.
