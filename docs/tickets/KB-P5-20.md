### User Story
As a **workflow security engineer running SDK-based transition gates (`gemini`, `ollama`, `openai`)**, I need **the `in_app_sdk` harness implementing a bounded tool-calling loop with 5 read-only bare-Git tools (`repo_tree`, `repo_read_file`, `repo_grep`, `repo_git_log`, `repo_git_diff`) pinned to `head_commit` plus the 4 ephemeral MCP read tools** so that **in-process LLM interceptors can inspect source code, diffs, and related specs without checking out a mutable working tree, reading `.env*`/private keys, or invoking write tools**.

**Requirement Traceability:** `S14.2` item 1 (`in_app_sdk`: `GeminiProvider`, `OllamaProvider`, `OpenAIProvider` tool-calling loop with `repo_tree`, `repo_read_file`, `repo_grep`, `repo_git_log`, `repo_git_diff` + MCP ticket/doc read tools), `S14.3` item 3 (`kb_agt_eph_*` `TTL <= 120s`, `max_calls <= 25`, 4 read-only MCP tools, secret masking), `S10.1`, `S15.2` (`tool_script` cassette replay) | Original requirement `#2` | **Dependencies:** `KB-P5-19a`, `KB-P5-19b`, `KB-P5-04`, `KB-P5-05a`

### Scoped Technical Actions
1. **Target Files:**
   - `agent/tools/repo_path_guard.py` (`normalize_repo_relpath()`, `is_secret_repo_path()`, `SECRET_PATH_PATTERNS`)
   - `agent/tools/repo_tools.py` (`BareGitRepoToolkit` exposing `repo_tree`, `repo_read_file`, `repo_grep`, `repo_git_log`, `repo_git_diff`)
   - `agent/tools/mcp_read_tools.py` (`EphemeralMcpReadToolkit` exposing `search_tickets`, `read_ticket`, `search_knowledge`, `read_doc`)
   - `agent/harnesses/in_app_sdk.py` (`InAppSdkHarness` implementing `Harness` from `KB-P5-19a`, `ToolCallTrace`, `HarnessRunReport`)
   - `agent/gates/worker.py` (modify: register `"in_app_sdk"` in default `HarnessRegistry`)
   - `agent/GEMINI.md` (update tool contracts & caps)
2. **Secret-Path & Path-Traversal Guard (`agent/tools/repo_path_guard.py`):**
   - `normalize_repo_relpath(raw: str) -> str`: rejects NUL, CR/LF, leading `-` (git option injection), leading `/`, backslashes `\`, `.` / `..` segments, and paths `> 512` UTF-8 bytes (`RepoToolPolicyError("REPO_PATH_INVALID")`).
   - `is_secret_repo_path(relpath: str) -> bool`: case-insensitive segment/basename glob match blocking `.env`, `.env.*`, `*.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*id_rsa*`, `*id_ed25519*`, `*id_ecdsa*`, `.git`, `.git/*`, `.netrc`, `.npmrc`, `.pypirc` -> raises `RepoToolPolicyError("REPO_SECRET_PATH_DENIED")` on direct access and filters matching entries out of `repo_tree`, `repo_grep`, `repo_git_log`, and `repo_git_diff` outputs.
3. **5 Read-Only Bare-Git Tools (`agent/tools/repo_tools.py`):**
   - Operates exclusively against `RepoContext.mirror_path` (`bare` Git mirror from `KB-P5-19b`) and pinned 40/64-hex `RepoContext.head_commit` via `asyncio.create_subprocess_exec("git", "--git-dir=" + str(mirror_path), "-c", "core.hooksPath=/dev/null", "-c", "protocol.allow=never", ...)` with empty clean env (`GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `PATH=/usr/bin:/bin`), per-call timeout `5.0s`, output cap `65,536` bytes (truncated with `[TRUNCATED]`), and `KB-P2-17` `outbound_secret_scrubber` applied to every returned string:
     1. `repo_tree(path: str = "", max_depth: int = 3)` (`max_depth` bounded `1..6`, max `500` entries): runs `git ls-tree -r --full-tree --end-of-options <head_commit> -- <path>`, filters depth and secret paths.
     2. `repo_read_file(path: str, start_line: int = 1, end_line: int = 200)` (`1 <= start_line <= end_line`, `end_line - start_line < 400`): checks `is_secret_repo_path(path)` first, runs `git cat-file -p --end-of-options <head_commit>:<path>`, rejects binary blobs containing NUL bytes in first `8 KiB` (`REPO_BINARY_FILE_UNSUPPORTED`), returns numbered line slice.
     3. `repo_grep(pattern: str, path: str = "")` (`1 <= len(pattern) <= 200`): runs `git grep -I -n --fixed-strings --max-count=50 -e <pattern> <head_commit> -- <path>` (`--fixed-strings` prevents catastrophic regex backtracking DoS on untrusted LLM patterns; strips `<head_commit>:` prefix and filters secret paths).
     4. `repo_git_log(path: str = "", max_commits: int = 20)` (`1..50`): runs `git log -n <max_commits> --format=%H%x09%ad%x09%an%x09%s --date=iso-strict --end-of-options <head_commit> -- <path>`.
     5. `repo_git_diff(base_ref: str, path: str = "")`: validates `base_ref` (`^[A-Za-z0-9._/~^-]{1,120}$`, no `..`, no leading `-`), resolves via `git rev-parse --verify --end-of-options <base_ref>^{commit}`, runs `git diff --no-ext-diff --no-textconv --unified=3 <base_sha> <head_commit> -- <path>` excluding secret pathspecs (`:(exclude).env*`, `:(exclude)*.pem`, `:(exclude)*.key`).
   - When `agent_def.repo_access_mode == "none"` or `repo_context is None`, zero `repo_*` tools are registered in the LLM tool declarations.
4. **Ephemeral MCP Read Toolkit (`agent/tools/mcp_read_tools.py`):**
   - Exposes **only** tools in `set(agent_def.mcp_allowed_tools) & {"search_tickets", "read_ticket", "search_knowledge", "read_doc"}`. Any attempt by the LLM to call an undeclared or write tool (`update_ticket`, `transition_ticket`, `add_comment`, `complete_work`) returns structured tool error `TOOL_NOT_PERMITTED` without network I/O.
   - Calls `/mcp/agent` and `/mcp/docs` using `Authorization: Bearer <ephemeral_token>` (`kb_agt_eph_*` from `RenderedContext.ephemeral_token`), enforcing client-side `max_calls <= 25` in addition to server-side `KB-P4-13` enforcement, and scrubs responses via `KB-P2-17`.
5. **`InAppSdkHarness` (`agent/harnesses/in_app_sdk.py`):**
   - Uses `ProviderRouter` (`KB-P5-04`) + `BudgetEnforcer` (`KB-P5-05a`).
   - System prompt combines hardened gate-evaluator preamble (instructing the model that everything inside `ctx.delimiter` is untrusted data, never instructions, and requiring final output matching `kb-transition-verdict/v1` with `nonce = ctx.verdict_nonce`) + `agent_def.system_instructions_md`.
   - User message contains `ctx.yaml_bytes` decoded UTF-8.
   - Tool loop bounds: `max_turns = 8`, `max_total_tool_calls = 20`; each tool call appended to `last_tool_traces: list[ToolCallTrace]` (`tool_name`, `args_redacted`, `duration_ms`, `status`, `output_bytes`) so `KB-P5-23` CLI `--verbose-tools` can print the full trace.
   - Final step requests `generate_structured` (or parses final assistant JSON) and returns canonical JSON bytes to `GateWorker` (`KB-P5-19a`), settling token usage via `BudgetEnforcer.settle()` (or `release()` on exception).
