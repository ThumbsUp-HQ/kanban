### User Story
As a **platform security engineer and Project Admin**, I need **a deterministic fuel-metered Tier A `Wasmtime` sandbox (`<= 50M` fuel, `<= 32 MiB` RAM, `<= 500ms` wall clock, zero host filesystem/env/socket imports), an ACL-partitioned custom field execution API, and `/mcp/admin` tool 7 `manage_custom_fields_and_scripts`** so that **95% of computed fields and synchronous workflow hooks execute in `< 2ms` cold start with hard resource bounds, zero cross-user ACL cache leakage, and 100% MCP administrative parity**.

**Requirement Traceability:** `S13.3` item 1 (Tier A `Wasmtime` default: `<= 50M` instructions/fuel, `<= 32 MiB` linear memory, `<= 500ms` wall clock, zero host FS/env, `< 2ms` cold start), `S13.2` (cache partitioning by `(issue_id, field_id, script_ver, user_access_hash)`, `SERVER` scope audit on every invocation), `S11.4` tool 7 (`manage_custom_fields_and_scripts`), `S2.5` (`wasmtime` `Apache-2.0`) | Original requirements `#14`, `#12` | **Dependencies:** `KB-P5-12`, `KB-P4-09a`, `KB-P4-09b`

2. **Tier A `Wasmtime` Sandbox (`kanban/sandbox/wasm_runner.py`):**
   - Engine configured once per process: `Config.consume_fuel = True`, `Config.epoch_interruption = True`, `Config.wasm_threads = False`, `Config.wasm_reference_types = False`, `Config.wasm_simd = True`, `Config.cranelift_opt_level = "speed"`; pre-compiled `wasmtime.Module` cached in an LRU (`max 128` entries keyed by `sha256`) so warm instantiation stays `< 2ms`.
   - **Zero Host Capabilities:** `Linker(engine)` defines **zero** WASI (`wasi_snapshot_preview1` / `wasip2`) imports, zero host filesystem, zero environment variables, zero clock/random syscalls, and zero network functions. Any `.wasm` binary declaring an import outside `env.kb_output(ptr: i32, len: i32)` is rejected at validation/upload time (`WASM_FORBIDDEN_IMPORT`).
   - Guest ABI (`kb-wasm-abi/v1`): guest exports `memory`, `kb_alloc(len: i32) -> i32`, and `kb_run(ptr: i32, len: i32) -> i32` (`0` = ok, non-zero = error); host writes UTF-8 JSON input (`<= 262,144` bytes) into guest slice via `kb_alloc`, invokes `kb_run`, and captures the single buffer passed to `env.kb_output` (`<= 65,536` bytes).
   - Hard per-invocation bounds (`WasmRunLimits`, configurable downward only - e.g., `KB-P5-17a` passes `timeout_ms <= 25`):
     - `max_fuel: int = 50_000_000` (`<= 50_000_000`, enforced via `store.set_fuel(limits.max_fuel)`).
     - `max_memory_bytes: int = 33_554_432` (`<= 32 MiB`, enforced via `store.set_limits(memory_size=33_554_432, table_elements=1024, instances=1, tables=1, memories=1)` AND module initial/max memory page inspection rejecting `> 512` 64KiB pages).
     - `timeout_ms: int = 500` (`<= 500ms`, enforced via background monotonic epoch ticker incrementing engine epoch every `5ms` + `store.set_epoch_deadline(ceil(timeout_ms / 5))` inside `asyncio.to_thread` bounded by `asyncio.timeout`).
   - Deterministic error codes: `SCRIPT_FUEL_EXHAUSTED`, `SCRIPT_MEMORY_LIMIT`, `SCRIPT_TIMEOUT`, `WASM_FORBIDDEN_IMPORT`, `WASM_BINARY_INVALID`, `SCRIPT_OUTPUT_TOO_LARGE`, `SCRIPT_TRAP`.
3. **`approved_wasm_modules` DDL:**
   - Columns: `id UUID PK`, `workspace_id UUID NOT NULL`, `project_id UUID REFERENCES projects(id)`, `sha256 BYTEA NOT NULL CHECK (octet_length(sha256) = 32)`, `name TEXT NOT NULL`, `wasm_bytes BYTEA NOT NULL CHECK (octet_length(wasm_bytes) BETWEEN 8 AND 1048576)`, `approved_by_id UUID NOT NULL REFERENCES principals(id)`, `created_at TIMESTAMPTZ NOT NULL`, `UNIQUE (workspace_id, sha256)`. `ENABLE` + `FORCE ROW LEVEL SECURITY` (`PROJECT_ADMIN` / `WORKSPACE_ADMIN` + `AAL2` `WITH CHECK`). Upload validates compilation and zero forbidden imports before persisting.
4. **Custom Field Executor & Partitioned Cache (`kanban/custom_fields/executor.py`):**
   - `execute_for_issue(issue_key, field_id, caller, *, force_refresh: bool = False)`:
     1. Loads issue and field under caller's RLS context (`404` if either unreadable).
     2. Calls `assert_execution_authorized(definition)` (`KB-P5-12`); if revoked/unapproved -> `409 APPROVAL_REVOKED`.
     3. Computes partition key via `compute_cache_partition_key` (`KB-P5-12`). Unless `force_refresh` or `target_scope == "SERVER"`, returns cached `custom_field_values` row if `expires_at > now()`.
     4. Builds JSON input `{schema: "kb-field-input/v1", issue: {id, key, summary, description_markdown, state, priority, labels}, scope: target_scope, credential_mode}`. For `tier == "wasm"` with `egress_allowlist == []`, executes directly via `TierAWasmRunner`; for `tier == "nsjail"`, delegates to `TierBRunner` (default `UnavailableTierBRunner` returns `503 SANDBOX_UNAVAILABLE_IN_STANDALONE` until `KB-P5-14` binds `TierBNsjailRunner`).
     5. Validates raw JSON output through `validate_field_output_value(definition.output_format, definition.output_format_metadata, raw_value)` (`KB-P5-11`); invalid output -> `422 SCRIPT_OUTPUT_SCHEMA_INVALID`.
     6. Upserts `custom_field_values` (`TTL = 300s`) when `should_cache` is true; when `target_scope == "SERVER"`, writes mandatory `CUSTOM_FIELD_SERVER_INVOKED` row to `activity_records` on **every** invocation (S13.2 row 4).
5. **REST & `/mcp/admin` Tool 7 (`manage_custom_fields_and_scripts`):**
   - REST (`kanban/api/v1/custom_field_execution.py` - matches `KB-P5-15` item 2):
     - `GET /api/v1/issues/{issue_key}/custom-fields`: returns list of `{field_id, slug, name, output_format, output_format_metadata, value, computed_at, last_latency_ms, tier, token_scope, credential_mode, status}` computing missing `wasm` values on read.
     - `POST /api/v1/issues/{issue_key}/custom-fields/{field_id}/execute`: forces fresh execution (`force_refresh=True`).
     - `POST /api/v1/projects/{project}/wasm-modules`: `PROJECT_ADMIN` + `AAL2` uploads & validates `.wasm` module, returning `sha256` hex.
   - MCP tool 7 (`manage_custom_fields_and_scripts` on `/mcp/admin`, calling internal REST API with `kb_adm_*` surface binding, `EntityResolver`, `InlineSafeDumper` YAML, LOD `summary|standard|full`):
     - Actions: `help`, `list_fields`, `upsert_field`, `delete_field` (`confirm: true` required), `upload_wasm_module`, `request_escalation`, `approve_escalation`, `execute_field`.

- **Required Test Cases:**
  1. Positive: `echo_cvss.wasm` computes `severity_pill` `{level: "high", score: 8.8, label: "8.8 High"}` in `< 10ms` (warm `< 2ms` median over 100 runs); `require_qa_proof_link.wasm` returns allow/reject deterministically.
  2. Security (WASI / host isolation): `wasi_fs_import.wasm` declaring `wasi_snapshot_preview1.fd_read` or `path_open` -> rejected with `WASM_FORBIDDEN_IMPORT` at upload and at runtime.
  3. Boundary / DoS (`<= 50M` fuel, `<= 32 MiB`, `<= 500ms`): `infinite_loop.wasm` terminates with `SCRIPT_FUEL_EXHAUSTED` (and with huge fuel but sleep/spin + `timeout_ms=50` terminates with `SCRIPT_TIMEOUT` in `< 150ms`); `mem_grow_64mb.wasm` attempting `memory.grow` past `32 MiB` fails with `SCRIPT_MEMORY_LIMIT`.
  4. Security (cache partitioning S13.2): on an `INVOKING_USER` field, User A (with `SEC` group) and User B (without `SEC` group) execute the field on `KAN-142` -> two distinct rows in `custom_field_values` with different `user_access_hash`; User B never receives User A's cached value. On a `PROJECT_ADMIN_SP` field, single shared cache key (`user_access_hash == b""`) is reused.
  5. Security (revoked approval & SERVER audit): editing `script_source` after approval causes `execute` on an escalated field to return `409 APPROVAL_REVOKED`; executing an approved `SERVER`-scope field 3 times writes 3 `CUSTOM_FIELD_SERVER_INVOKED` rows in `activity_records` and stores `0` rows in `custom_field_values`.
  6. Tier B fallback before `KB-P5-14`: field with `tier="nsjail"` returns `503 SANDBOX_UNAVAILABLE_IN_STANDALONE` cleanly without crashing.
  7. MCP tool 7: `upsert_field`, `upload_wasm_module`, `request_escalation`, `approve_escalation`, `execute_field`, and `delete_field` (unconfirmed preview vs `confirm: true`) verified via `InlineSafeDumper` YAML; `kb_agt_*` key rejected.
