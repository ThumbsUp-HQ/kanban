### User Story
As an **execution agent following the kanban workflow**, I need **single-call `begin_work`, `transition_ticket`, and `complete_work` tools that run atomically server-side, report a held transition as `status: pending_agent_gate`, and refuse closure while child blockers are open or QA is not `READY`** so that **workflow state on the board always reflects verified work and an agent never misreads a held transition as completed.**

**Requirement Traceability:** `S11.2` items 5-7, `S14.1` (202 Accepted + provisional hold), `S7.2` (`8h` parent DAG), requirement `#12` | **Dependencies:** `KB-P4-05`, `KB-P3-05`, `KB-P3-07`, `KB-P3-10`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/issue_workflow.py` (3 composite endpoints), `kanban/issues/workflow_service.py`, `mcp/surfaces/agent/begin_work.py`, `mcp/surfaces/agent/transition_ticket.py`, `mcp/surfaces/agent/complete_work.py`, `mcp/surfaces/agent/proof.py` (`VerificationProof` model), `mcp/errors.py`, `mcp/auth.py` (all three -> `agent:write`).
2. **Composite endpoints (single PG transaction each, `If-Match` optional):**
   - `POST /api/v1/issues/{id}/begin-work` body `{plan_markdown}`: assign caller principal (no-op if already assigned), move to the lowest-`sort_rank` state with `group = 'started'`, set `cycle_id` to the project's single `active` cycle when the issue has none, post `plan_markdown` as a comment (normalizer applied). Returns `200` with the issue or `202` when a transition hold is reported (see Action 5).
   - `POST /api/v1/issues/{id}/transition` body `{to_state, comment_markdown?, verification_proof?}`.
   - `POST /api/v1/issues/{id}/complete-work` body `{summary_markdown, verification_proof, to_state?}` (default: lowest-rank `completed` state).
3. **`begin_work` input:** `{identifier: string (required), plan_markdown: string (required, 1..65,536 bytes)}`. Errors: `NO_STARTED_STATE` when the project has no `started` group state. Sample `summary` response:
   ```yaml
   status: started
   key: KAN-142
   state: In Progress
   assignees: ["@adam"]
   cycle: Cycle 4
   comment: KAN-142#c-0196ed40
   ```
4. **`transition_ticket` input:** `{identifier: string (required), to_state: string (required), comment_markdown: string (<= 65,536 bytes), verification_proof: VerificationProof}`. Moving to a `completed` group state is rejected with `USE_COMPLETE_WORK`. Sample response (committed):
   ```yaml
   status: transitioned
   key: KAN-142
   from_state: In Progress
   to_state: In Review
   ```
5. **`pending_agent_gate` response shape (stub contract until KB-P5-18):** when kanban-api returns `202` with `{execution_id, active_agent, from_state, to_state}`, the tool returns `isError: false` with:
   ```yaml
   status: pending_agent_gate
   key: KAN-142
   from_state: In Review
   to_state: Done
   execution_id: 0196ed40-7b2a-7000-8000-112233445566
   active_agent: forensic-code-check
   hint: transition is held; poll read_ticket for the gate verdict
   ```
   In this ticket kanban-api never emits `202` (no hooks exist yet); the shape is exercised via `httpx.MockTransport` contract tests and a `WorkflowGateHook` protocol in `workflow_service.py` whose default implementation returns `None` (no hold). KB-P5-18 supplies the real implementation.
6. **`complete_work` input:** `{identifier (required), summary_markdown (required, 1..65,536 bytes), verification_proof (required), to_state (optional)}`. Server checks, in order:
   - **Open child blockers:** any child issue (`parent_issue_id = id`, recursive via `ancestry_path`) whose state group is not `completed`/`cancelled`, and any `BLOCKS` link from an issue in a non-terminal state targeting this issue -> `409` -> `OPEN_CHILD_BLOCKERS` listing up to 20 blocker keys (unreadable blockers listed as `redacted: 1 hidden blocker`, never their key).
   - **QA verdict:** `verification_proof.reality_checker.verdict` must equal `READY` and `grade` must equal `A`, else `QA_VERDICT_NOT_READY`.
   - Then transitions, posts `summary_markdown` + a rendered proof table as a comment, and writes activity `WORK_COMPLETED` with the proof packet JSON.
   Sample response:
   ```yaml
   status: completed
   key: KAN-142
   state: Done
   proof: {qa_dir: docs/qa/KAN-142/, artifacts: 6, verdict: READY}
   ```
7. **`VerificationProof` (Pydantic v2, `extra="forbid"`):**
   ```yaml
   qa_dir: {pattern: "^docs/qa/[A-Z][A-Z0-9]{1,9}-[0-9]{1,18}/$"}
   artifacts: {type: array, maxItems: 50, items: {pattern: "^docs/qa/[A-Z][A-Z0-9]{1,9}-[0-9]{1,18}/[A-Za-z0-9._/-]{1,200}$"}}
   reality_checker: {verdict: {enum: [READY, NEEDS_WORK]}, grade: {pattern: "^[A-F]$"}, report_path: {same pattern as artifacts}}
   ci_run_url: {type: string, format: uri, pattern: "^https://"}
   ```
   Any path containing `..`, `//`, or a ticket key different from `identifier` -> `VALIDATION_FAILED`.
8. **Error codes appended to `McpErrorCode`:** `NO_STARTED_STATE`, `USE_COMPLETE_WORK`, `OPEN_CHILD_BLOCKERS`, `QA_VERDICT_NOT_READY`, `INVALID_TRANSITION` (target state not in the issue's project), `TRANSITION_HELD` (issue has non-null `pending_transition_exec_id`).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_issue_workflow.py` (clean-DB harness), `mcp/tests/agent/test_workflow_tools.py`, `mcp/tests/agent/test_pending_gate_contract.py` (`httpx.MockTransport`)
- **Required Test Cases:**
  1. Positive: `begin_work` on a `Todo` issue assigns caller, moves to `In Progress`, attaches the active cycle, posts the plan comment, all in one transaction; `transition_ticket` to `In Review` succeeds; `complete_work` with a valid READY/A proof moves to `Done` and writes `WORK_COMPLETED` activity containing the proof JSON.
  2. Blockers/security: open child -> `OPEN_CHILD_BLOCKERS` listing the child key; open inbound `BLOCKS` from an issue in a project the caller cannot read -> list contains `redacted: 1 hidden blocker` and no key; `verdict: NEEDS_WORK` -> `QA_VERDICT_NOT_READY`; artifact path `docs/qa/KAN-142/../../etc/passwd` -> `VALIDATION_FAILED`; proof for `KAN-143` used on `KAN-142` -> `VALIDATION_FAILED`.
  3. Gate contract: MockTransport `202` response yields the exact `pending_agent_gate` YAML keys in Action 5; issue with non-null `pending_transition_exec_id` -> `TRANSITION_HELD`.
  4. Boundary/atomicity: `begin_work` where comment insert fails (forced via 65,537-byte plan) leaves assignee and state unchanged; project with zero `started` states -> `NO_STARTED_STATE`; `transition_ticket` to `Done` -> `USE_COMPLETE_WORK`; 51 artifacts -> `VALIDATION_FAILED`; project with no active cycle leaves `cycle_id` null.
