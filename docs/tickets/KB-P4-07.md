### User Story
As a **security owner whose confidential `SEC-*` project shares a workspace with public projects**, I need **every MCP agent write to a broader-audience project to be blocked once that agent's session or credential has read from a narrower-audience project**, and as an agent I need **`add_comment` and `link_objects` that work with human keys** so that **an indirect prompt injection in a public ticket cannot make an agent copy confidential ticket text onto a public ticket.**

**Requirement Traceability:** `S3.5` (Session Read-Taint High-Water Mark, `CROSS_SCOPE_TAINT_CONFIRMATION_REQUIRED`), `S11.2` item 8, `S12.1` (`link_kind`), `S7.2` `8k`/`8m`, requirement `#12`, `#1` | **Dependencies:** `KB-P4-05`, `KB-P4-06`, `KB-P3-07`, `KB-P3-05`, `KB-P1-13`

### Scoped Technical Actions
1. **Target Files:** `database/migrations/versions/<rev>_mcp_read_taint.py`, `database/models/mcp_read_taint.py`, `kanban/security/read_taint.py` (`TaintRecorder`, `TaintGuard` FastAPI dependencies), wiring in `kanban/api/v1/issues.py`, `search.py`, `comments.py`, `links.py`, `issue_trees.py`, `issue_workflow.py`, `mcp/surfaces/agent/add_comment.py`, `mcp/surfaces/agent/link_objects.py`, `mcp/errors.py`, `mcp/auth.py` (both tools -> `agent:write`).
2. **DDL:**
   ```sql
   CREATE TABLE mcp_read_taint (
       workspace_id   UUID NOT NULL,
       taint_key      BYTEA NOT NULL CHECK (octet_length(taint_key) = 32),
       key_kind       TEXT NOT NULL CHECK (key_kind IN ('session', 'credential')),
       project_id     UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
       first_read_at  TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       expires_at     TIMESTAMPTZ NOT NULL,
       PRIMARY KEY (taint_key, project_id)
   );
   ```
   `ENABLE` + `FORCE ROW LEVEL SECURITY` (workspace policy). `taint_key` = `sha256(Mcp-Session-Id)` for `session` rows (expires with session idle TTL `3600s`) and `sha256(subject token)` for `credential` rows (expires `8h` after last read). Recording both prevents escaping taint by opening a new MCP session with the same credential.
3. **Recording (`TaintRecorder`):** applied only to requests carrying `X-KB-MCP-Session` (requests from the `mcp-gateway` service principal without that header are rejected `400`). Every response that returns issue, comment, link, or search data records each distinct `project_id` present in the response (upsert, extends `expires_at`). Masked/unreadable rows are not recorded.
4. **Guard (`TaintGuard`):** applied to every MCP-originated write: `issues` PATCH, `issue-trees` POST, `begin-work`, `transition`, `complete-work`, comments POST, links POST. For the write's target project `P_B` (for links: both endpoint projects), the write is rejected with `409` problem type `cross-scope-taint` when any tainted `P_A` exists such that `Audience(P_B) ⊄ Audience(P_A)`, where `Audience(P)` = set of `principal_id` with VIEW (`allow_mask & 1 = 1 AND deny_mask & 1 = 0`) on project `P` in `effective_resource_access`. Single SQL:
   ```sql
   SELECT t.project_id FROM mcp_read_taint t
   WHERE t.taint_key = ANY($1) AND t.expires_at > clock_timestamp() AND t.project_id <> $2
     AND EXISTS (SELECT 1 FROM effective_resource_access b
                 WHERE b.object_id = $2 AND (b.allow_mask & 1) = 1 AND (b.deny_mask & 1) = 0
                   AND NOT EXISTS (SELECT 1 FROM effective_resource_access a
                                   WHERE a.object_id = t.project_id AND a.principal_id = b.principal_id
                                     AND (a.allow_mask & 1) = 1 AND (a.deny_mask & 1) = 0))
   LIMIT 1;
   ```
   Writes into the same project or into a project whose audience is a subset are allowed. Blocked writes emit activity `MCP_TAINT_BLOCKED` (session key hash, source project id, target project id, tool name). Phase 4 provides NO agent-side override: the error hint instructs the agent to ask a human to perform the write in the web UI. MCP mapping -> `CROSS_SCOPE_TAINT_CONFIRMATION_REQUIRED` with `tainted_by: <project key>` only when the caller can VIEW that project (it always can, since it read it).
5. **`add_comment` input:** `{identifier: string (required), body_markdown: string (required, 1..65,536 bytes), reply_to: string (comment id, optional)}`. Body passes the normalizer (KB-P2-13). Upstream `409` mention warning (KB-P3-05) -> `MENTION_ACCESS_WARNING` listing handles; comment is NOT posted unless `ack_mentions: true` is passed. Sample `summary` response:
   ```yaml
   status: commented
   key: KAN-142
   comment: KAN-142#c-0196ed41
   ```
6. **`link_objects` input:** `{source: string (required, key|uuid), target: string (required), link_type: enum [BLOCKS, RELATES_TO, DUPLICATES, VERIFIED_BY_DOC] (required), action: enum [add, remove] default add}`. `source`/`target` resolve as `issue` keys or doc identifiers via `EntityResolver`; matrix violations from KB-P1-11 (`422`) -> `LINK_TYPE_NOT_ALLOWED`; self-link -> `VALIDATION_FAILED`. Sample response:
   ```yaml
   status: linked
   link: {source: KAN-142, type: BLOCKS, target: KAN-150}
   ```
7. **Error codes appended:** `CROSS_SCOPE_TAINT_CONFIRMATION_REQUIRED`, `MENTION_ACCESS_WARNING`, `LINK_TYPE_NOT_ALLOWED`.
8. **Schema budget check:** `mcp/tests/test_schema_budget.py` asserts the `/mcp/agent` `tools/list` JSON is `<= 1,850` tokens using the KB-P4-03 approximate tokenizer (spec S11.1 budget).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/security/test_read_taint.py` (clean-DB harness), `mcp/tests/agent/test_add_comment.py`, `mcp/tests/agent/test_link_objects.py`, `mcp/tests/test_schema_budget.py`
- **Required Test Cases:**
  1. Positive: `add_comment` on `KAN-142` posts Markdown; `link_objects(KAN-142, KAN-150, BLOCKS)` creates a link with key snapshots; `remove` deletes it.
  2. Exfiltration (canary): fixture projects `SEC` (audience {adam}) and `PUB` (audience {adam, maya, guest}); session reads `SEC-1` (description contains canary `CANARY-7f3a`), then `add_comment` on `PUB-1` -> `CROSS_SCOPE_TAINT_CONFIRMATION_REQUIRED`; DB shows `0` new comments containing `CANARY-7f3a`; `MCP_TAINT_BLOCKED` activity row present.
  3. Session-escape: after the read in case 2, a NEW `Mcp-Session-Id` with the same credential writing to `PUB-1` is still blocked (credential taint); a different credential with no reads is allowed.
  4. Allowed paths: after reading `PUB-1`, writing to `SEC-1` (narrower audience) succeeds; writing into the same project `SEC` succeeds; `link_objects(SEC-1 -> PUB-1)` is blocked because `PUB` audience is broader.
  5. Boundary: session taint expired at `3600s + 1` and credential taint at `8h + 1` (frozen clock) -> write allowed; 65,537-byte comment -> `VALIDATION_FAILED`; mention of a user without access -> `MENTION_ACCESS_WARNING` and no comment until `ack_mentions: true`; `link_type="PARENT_OF"` -> `VALIDATION_FAILED` (not in enum); matrix violation -> `LINK_TYPE_NOT_ALLOWED`.
  6. Missing header: write from `mcp-gateway` principal without `X-KB-MCP-Session` -> `400`.
  7. Budget: `/mcp/agent` tools/list `<= 1,850` approximate tokens.
