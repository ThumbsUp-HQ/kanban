### User Story
As an **AI/LLM systems engineer tuning Sparkle**, I need **`uv run kanban-agent validate-sparkle` to run the exact production `run_sparkle_pipeline()` from the terminal for a given Markdown string with a `|` cursor marker, as a specific user's RLS scope, against a live or fixture provider, and print the scrubbed prompt, retrieval trace, latency and output validation** so that **I can verify FIM latency, RLS filtering and ghost-text output without the browser**.

**Requirement Traceability:** `S15.3 example 2 and report items (1)-(4), exit codes 0/2`, `S9.3`, `S15.2`, original requirement `#7` | **Dependencies:** `KB-P5-07`, `KB-P0-13`

### Scoped Technical Actions
1. **Target Files:**
   - `agent/cli_commands/validate_sparkle.py` (new; registered in the KB-P0-13 subcommand registry)
   - `agent/cli.py` (modify: register `validate-sparkle`)
   - `examples/sparkle/seed_rls_demo.sql` (new: demo seed for manual runs)
   - `agent/GEMINI.md` (update: CLI usage)
2. **Flags (exact):** `--provider {ollama,gemini,openai,fixture}`, `--model TEXT`, `--input-markdown TEXT`, `--project KEY` (project identifier, e.g. `KAN`), `--as-user @handle`, `--cassette PATH` (required when `--provider fixture`, forbidden otherwise), `--http-cassette PATH` (optional, KB-P5-01), `--iterations N` (default `1`, range `1..500`, prints p50/p95/p99 when `> 1`), `--surface {summary,description,comment,sticky,doc}` (default `description`), `--report {text,json}` (default `text`), `--database-url` (default env `DATABASE_URL`), plus common `--verbose-tools`.
3. **Cursor marker parsing:** exactly one unescaped `|` is required; `\|` is a literal pipe. Zero or more than one unescaped marker -> exit `2` with `CURSOR_MARKER_INVALID`. Text before the marker -> `prefix`, after -> `suffix`.
4. **RLS scope (`--as-user`):**
   - Resolves `@handle` to a principal via the users table under a lookup-only query; unknown handle -> exit `2` `PRINCIPAL_NOT_FOUND`.
   - Refuses to run if the connected DB role has `rolbypassrls = true` or `rolsuper = true` (`SELECT rolsuper, rolbypassrls FROM pg_roles WHERE rolname = current_user`) -> exit `2` `RLS_BYPASS_ROLE_REFUSED`. The CLI must exercise the same RLS path as production.
   - Binds context exactly as the endpoint does; calls `run_sparkle_pipeline()` from KB-P5-07 (no reimplementation of any pipeline step).
5. **Report (S15.3 items 1-4):** (1) rendered prompt after scrubbing incl. redaction count and context delimiters (snippet text shown only for objects the `--as-user` principal can read, which is guaranteed by RLS); (2) retrieval trace: returned `object_id` + canonical key + chunk index, `retrieval_status`, and provider route trace; (3) TTFT, total wall-clock, token count; (4) validation status: `ok` / `empty` / `timeout` / `secret_scrubbed` / `unavailable` and the output filter actions applied. JSON report schema `kb-sparkle-report/v1` with `additionalProperties: false`.
6. **Exit codes:** `0` when `status == "ok"`; `2` for schema/policy outcomes (`secret_scrubbed`, filter drop to `empty`, invalid marker, RLS-bypass refusal, unknown user, p95 over `150ms` when `--iterations > 1`); `1` for runtime errors (DB unreachable, provider unavailable).
7. **`examples/sparkle/seed_rls_demo.sql`:** creates workspace + projects `KAN` and `SEC`, user `@adam` with `VIEW/EDIT` on `KAN` only, an issue in `SEC` containing canary `SEC-CANARY-7731` and an issue in `KAN` about PKCE/LDAP; embeddings inserted with fixed vectors so the `SEC` issue is the nearest neighbor of the demo input.
