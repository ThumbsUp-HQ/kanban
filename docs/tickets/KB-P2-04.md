### User Story
As a **server administrator using the break-glass Local Admin card**, I need **password verification with Argon2id (`m = 64 MiB`, `t = 3`, `p = 4`) over an HMAC-SHA256 peppered input, identical responses and timing for unknown users, wrong passwords and locked accounts, and per-account plus per-IP throttling** so that **an offline database dump cannot be cracked without the pepper, and online guessing, username enumeration, and hashing-cost denial of service are blocked**.

**Requirement Traceability:** `S4.2` item 3 (Argon2id parameters, pepper, AAL2 required for admins), `S2.2` item 1 (`KB_AUTH_PEPPER`), `S2.5` (`argon2-cffi`), requirement `#6` | **Dependencies:** `KB-P2-02` (sessions), `KB-P2-03` (`kb_auth` boundary, `auth_provider_cards`), `KB-P2-18` (rate limiter; dependency added by drafter because the manifest scope requires per-account/per-IP limits)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_local_admin_credentials.py`, `database/models/auth.py` (add `LocalAdminCredential`)
   - `kanban/auth/local/__init__.py`, `kanban/auth/local/hashing.py`, `kanban/auth/local/service.py`

   - `pyproject.toml` of `kanban` (add pinned `argon2-cffi`)
2. **DDL** (kb_auth boundary: owned by `kb_auth_owner`, revoked from `kanban_app`, `FORCE RLS`):
   ```sql
   CREATE TABLE local_admin_credentials (
     principal_id   UUID PRIMARY KEY REFERENCES principals(id) ON DELETE CASCADE,
     username       TEXT NOT NULL UNIQUE CHECK (username ~ '^[a-z0-9][a-z0-9._-]{2,62}$'),
     password_hash  TEXT NOT NULL CHECK (password_hash LIKE '$argon2id$%'),
     pepper_kid     TEXT NOT NULL DEFAULT 'pepper-v1',
     updated_at     TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
   );
   ```
   Functions: `kb_auth.local_get_credential(p_username text)` (returns `principal_id, password_hash, pepper_kid` or zero rows), `kb_auth.local_set_password_hash(p_principal uuid, p_hash text)` (rehash on parameter upgrade), `kb_auth.local_admin_create(...)` (SERVER_ADMIN + AAL2 or setup-claim context only; KB-P2-12 uses it).
3. **Hashing (`hashing.py`):**
   - `PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4, hash_len=32, salt_len=16, type=Type.ID)`.
   - Input pipeline: `unicodedata.normalize("NFKC", password)` -> UTF-8 -> length check `8 <= len(bytes) <= 1024` (rejected before any hashing) -> `hmac.new(auth_pepper, pw_bytes, sha256).digest()` -> `base64.b64encode` -> Argon2id.
   - `verify(stored_hash, password) -> bool` and `needs_rehash(stored_hash) -> bool`; on successful verify with `needs_rehash` -> `kb_auth.local_set_password_hash`.
   - `DUMMY_HASH`: computed once at import with the same parameters from a random secret; used on the miss path.
   - Hashing runs in a thread via `anyio.to_thread.run_sync` behind `asyncio.Semaphore(KANBAN_ARGON2_CONCURRENCY, default 4)`; if a permit is not acquired within `2s` -> `503 AUTH_BUSY` (bounds memory to `4 x 64 MiB`).
4. **Login (`service.py` + route):**
   - Request `{"username": str (<= 64 chars), "password": str (<= 1024 chars)}`; route enforces CSRF exemption is NOT granted (login form sends `X-CSRF-Token` from a pre-session CSRF cookie issued by `GET /api/v1/auth/session`).
   - Order: rate-limit checks `AUTH_LOGIN_IP` (key = client IP) and `AUTH_LOGIN_ACCOUNT` (key = normalized username) -> LOCAL_ADMIN card enabled check -> credential lookup -> Argon2 verify (real hash or `DUMMY_HASH`) -> result.
   - Every failure (unknown user, wrong password, LOCAL_ADMIN card disabled, principal status not `ACTIVE`, length violation) returns the identical `401 INVALID_CREDENTIALS` problem body and still performs exactly one Argon2 verification.
   - Success: `SessionService.create_after_login(..., aal=1, mfa_pending=True)` because every Local Admin holds an admin role (S4.2 item 3); MFA completion is delivered by KB-P2-05a. Successful login resets `AUTH_LOGIN_ACCOUNT` bucket.
   - Activity: append `LOCAL_ADMIN_LOGIN_SUCCEEDED` / `LOCAL_ADMIN_LOGIN_FAILED` (actor or `NULL`, card id, hashed IP via `make_key`) using the KB-P1-12 activity append helper; the submitted username is not logged on failure.
5. **Security invariants asserted:** (a) stored hash is useless without `KB_AUTH_PEPPER`; (b) response body, status, headers and Argon2 call count are identical across all failure classes; (c) concurrent hashing memory is bounded; (d) password bytes never appear in logs, exceptions, or activity rows.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/auth/test_local_hashing.py`, `kanban/tests/auth/test_local_login.py`
- **Required Test Cases:**
  1. Positive: correct credentials -> `200`, session cookie issued with `mfa_pending=TRUE`, `aal_level=1`.
  2. Parameters: produced hash string contains `$argon2id$v=19$m=65536,t=3,p=4$`.
  3. Security (pepper): hash produced under pepper P1 does not verify when the service runs with pepper P2; raw `argon2.PasswordHasher().verify(hash, password)` without HMAC step returns false/raises.
  4. Security (enumeration, body): unknown user, wrong password, disabled LOCAL_ADMIN card, `SUSPENDED` principal -> byte-identical bodies (excluding `request_id`) and status `401`.
  5. Security (enumeration, work): spy on `PasswordHasher.verify` asserts exactly 1 call for each case in test 4.
  6. Security (enumeration, timing, bounded): 50 unknown-user vs 50 wrong-password attempts; `abs(median delta) <= 15ms` (reported in proof file).
  7. Security (rate limit): 6th failed attempt for one username within 900s -> `429 RATE_LIMITED`; 21st attempt from one IP across distinct usernames -> `429`; success resets account bucket.
  8. Security (cost DoS): `KANBAN_ARGON2_CONCURRENCY=1`, hold the permit, second login -> `503 AUTH_BUSY` after `2s` (fake timer).
  9. Boundary: 7-byte password and 1025-byte password -> `401 INVALID_CREDENTIALS` with 1 dummy verify; 1024-byte password accepted; NFKC: full-width `Ｐａｓｓ...` verifies against hash of ASCII `Pass...`.
  10. Rehash: stored hash with `t=2` verifies, then stored hash updated to `t=3`.
  11. Secret hygiene: caplog at `DEBUG` and all activity rows contain neither the password nor the username of failed attempts.
