### User Story
As a **backend engineer**, I need **the `issues` table matching the S12.2 DDL, a race-free per-project `sequence_id` allocator, and a Markdown-aware `build_markdown_tsvector()`** so that **every issue gets a unique human key (`KAN-42`), a tamper-evident description hash, and full-text search that is not polluted by fence markers or link URLs**.

**Requirement Traceability:** `S12.2` (`issues` DDL), `S7.2 8a` (summary 1-500), `8e` (date CHECK), `S5.1` (Markdown-only), Requirement `#8a`, `#8e`, `#10`, `#13a` | **Dependencies:** `KB-P1-04`, `KB-P1-03`

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/p1_05_issues.py`
   - `database/migrations/sql/p1_05_issues.up.sql`, `database/migrations/sql/p1_05_issues.down.sql`
2. **`build_markdown_tsvector(md text) RETURNS tsvector`** - `LANGUAGE plpgsql IMMUTABLE PARALLEL SAFE`, defined BEFORE `issues`. Steps, in order, on `coalesce(md,'')`:
   1. Remove fence delimiter lines and their info strings: lines matching `^\s{0,3}(```|~~~).*$` (code content between fences stays indexed).
   2. Images `!\[([^\]]*)\]\([^)]*\)` -> `\1`; links `\[([^\]]*)\]\([^)]*\)` -> `\1`; reference definitions `^\s{0,3}\[[^\]]+\]:\s*\S+.*$` -> empty.
   3. Autolinks `<https?://[^>]+>` and bare `https?://\S+` -> empty.
   4. Markdown punctuation `[#*_>`|~]` -> space.
   5. `RETURN to_tsvector('english'::regconfig, result);`
3. **`issues` DDL verbatim from S12.2** with ONE documented deviation: `cycle_id` is created as a plain `UUID` column; KB-P1-08 adds `FOREIGN KEY (cycle_id) REFERENCES cycles(id) ON DELETE SET NULL` once `cycles` exists.
   ```sql
   CREATE TABLE issues (
       id                          UUID PRIMARY KEY,
       object_type                 object_kind NOT NULL DEFAULT 'issue' CHECK (object_type = 'issue'),
       workspace_id                UUID NOT NULL,
       project_id                  UUID NOT NULL REFERENCES projects(id) ON DELETE RESTRICT,
       sequence_id                 BIGINT NOT NULL,
       summary                     TEXT NOT NULL CHECK (char_length(btrim(summary)) BETWEEN 1 AND 500),
       description_markdown        TEXT NOT NULL DEFAULT '' CHECK (octet_length(description_markdown) <= 1048576),
       description_sha256          BYTEA GENERATED ALWAYS AS (digest(description_markdown, 'sha256')) STORED,
       state_id                    UUID NOT NULL REFERENCES workflow_states(id),
       pending_transition_exec_id  UUID,
       priority_id                 UUID NOT NULL REFERENCES project_priorities(id),
       created_by_id               UUID NOT NULL REFERENCES users(id),
       original_created_by_id      UUID NOT NULL REFERENCES users(id),
       creator_modified_by_id      UUID REFERENCES users(id),
       creator_modified_at         TIMESTAMPTZ,
       start_date                  DATE,
       due_date                    DATE,
       cycle_id                    UUID,                                   -- FK added by KB-P1-08
       parent_issue_id             UUID REFERENCES issues(id) ON DELETE SET NULL,
       ancestry_path               ltree NOT NULL,
       board_rank                  TEXT COLLATE "C" NOT NULL,
       search_tsv                  tsvector GENERATED ALWAYS AS (
                                       setweight(to_tsvector('english', coalesce(summary, '')), 'A') ||
                                       setweight(build_markdown_tsvector(description_markdown), 'B')
                                   ) STORED,
       CHECK (due_date IS NULL OR start_date IS NULL OR due_date >= start_date),
       UNIQUE (project_id, sequence_id),
       FOREIGN KEY (id, object_type) REFERENCES objects (id, object_type) ON DELETE RESTRICT
   );
   CREATE INDEX issues_search_tsv_gin ON issues USING gin (search_tsv);
   CREATE INDEX issues_project_rank_idx ON issues (project_id, state_id, board_rank COLLATE "C");
   CREATE INDEX issues_parent_idx ON issues (parent_issue_id) WHERE parent_issue_id IS NOT NULL;
   ```
4. **Sequence allocation `allocate_issue_sequence(p_project_id uuid) RETURNS bigint`** (SECURITY DEFINER, `GRANT EXECUTE TO kanban_app`):
   ```sql
   UPDATE projects SET issue_seq_counter = issue_seq_counter + 1
    WHERE id = p_project_id RETURNING issue_seq_counter INTO v_seq;
   IF v_seq IS NULL THEN RAISE EXCEPTION USING ERRCODE='P0001', MESSAGE='PROJECT_NOT_FOUND'; END IF;
   ```
   The row lock on `projects` serializes concurrent allocators; numbers are gap-free unless the caller's transaction rolls back (gaps after rollback are acceptable and documented in the function comment).
   App flow (documented in `COMMENT ON FUNCTION`): `allocate_issue_sequence` -> `register_object('issue', ws, project, identifier || '-' || seq, summary, user)` -> `INSERT INTO issues`.
5. **Integrity trigger `issues_validate_biu` (BEFORE INSERT OR UPDATE):**
   - `NEW.workspace_id = projects.workspace_id` else `ISSUE_WORKSPACE_MISMATCH`.
   - `objects.canonical_key = projects.identifier || '-' || NEW.sequence_id` and `objects.project_id = NEW.project_id` else `ISSUE_SPINE_MISMATCH`.
   - `NEW.sequence_id <= projects.issue_seq_counter` else `ISSUE_SEQUENCE_NOT_ALLOCATED`.
   - `workflow_states.project_id` and `project_priorities.project_id` equal `NEW.project_id` else `ISSUE_STATE_PROJECT_MISMATCH` / `ISSUE_PRIORITY_PROJECT_MISMATCH`.
   - On UPDATE: `sequence_id`, `project_id` immutable (`ISSUE_KEY_IMMUTABLE`).
   - On INSERT: `ancestry_path` is set by the trigger, never trusted from input: `text2ltree(replace(NEW.id::text,'-',''))` when `parent_issue_id IS NULL`, else `parent.ancestry_path || text2ltree(replace(NEW.id::text,'-',''))`. (Locking, cycle and depth rules are KB-P1-06.)
6. **Down migration:** drops triggers, `allocate_issue_sequence`, `issues`, then `build_markdown_tsvector`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_05_issues.py`, `database/tests/test_p1_05_sequence_concurrency.py`, `database/tests/migrations/test_p1_05_migration.py`
- **Required Test Cases:**
  1. Positive: full app flow creates issue `KAN-1`; `description_sha256` equals Python `hashlib.sha256(desc.encode()).digest()`; updating the description changes the hash.
  2. Positive (tsvector): description ``"see [docs](https://evil.example/path)\n```python\nfoo_bar()\n```"`` -> `search_tsv @@ to_tsquery('english','docs')` true; `to_tsquery('english','evil')` false; `to_tsquery('english','python')` false (info string stripped); `foo_bar` content searchable.
  3. Negative (CHECKs): summary `'   '` and 501 chars raise `23514`; `due_date < start_date` raises `23514`; description of 1048577 bytes raises `23514` while 1048576 bytes is accepted.
  4. Negative/security: inserting `description_sha256` or `search_tsv` explicitly raises `428C9`; a state from another project raises `ISSUE_STATE_PROJECT_MISMATCH`; `sequence_id` larger than the counter raises `ISSUE_SEQUENCE_NOT_ALLOCATED`; client-supplied `ancestry_path` is overwritten.
  5. Negative: `UPDATE issues SET sequence_id = sequence_id + 1` raises `ISSUE_KEY_IMMUTABLE`; `allocate_issue_sequence(uuidv7())` raises `PROJECT_NOT_FOUND`.
  6. Concurrency (`@pytest.mark.committed_db`): 20 concurrent connections call `allocate_issue_sequence` on one project -> returned set equals `{1..20}`, no duplicates, final `issue_seq_counter = 20`.
  7. Boundary: `IMMUTABLE` volatility of `build_markdown_tsvector` confirmed via `pg_proc.provolatile = 'i'`; empty description yields a valid tsvector.
  8. Migration up/down: upgrade `p1_05_issues` -> `issues`, `build_markdown_tsvector`, `allocate_issue_sequence` exist; downgrade to `previous_of(...)` -> absent; re-upgrade succeeds.
  - Non-concurrency tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
