### User Story
As a **database platform engineer**, I need **an async Alembic migration chain, idempotent least-privilege PostgreSQL roles, the five required extensions, a `uuidv7()` generator, RLS context helper functions, and a reusable migration up/down test harness** so that **every later Phase 1 schema ticket ships as a reversible, privilege-separated migration that is proven on a clean database**.

**Requirement Traceability:** `S2.2 item 2` (extensions installed, `alembic upgrade head` under `kanban_migrator`, privilege drop), `S3.3` (`kanban_app NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS`, `set_config(..., true)`), `S9.3` / `S2.4` (`app_rls_reader` read-only), `S12.1` (`DEFAULT uuidv7()`), `S15.1 items 1-3`, Requirement `#13` | **Dependencies:** `KB-P0-05`

2. **Migration conventions (binding for every KB-P1 ticket):**
   - Revision IDs are descriptive strings `p1_NN_<slug>`; file `database/migrations/versions/<rev>.py`; DDL lives in `database/migrations/sql/<rev>.up.sql` and `<rev>.down.sql`.
   - `down_revision` = the single current head at implementation time. `uv run alembic -c database/alembic.ini heads` MUST print exactly one head after every ticket.
   - `database/migrations/sqlfile.py` exposes `execute_sql_file(name: str) -> None`. It MUST execute the file through the raw asyncpg connection using the simple query protocol (multi-statement + `$$` bodies are rejected by prepared statements):
     ```python
     from alembic import op
     from sqlalchemy.util import await_only


     def execute_sql_file(name: str) -> None:
         sql = (SQL_DIR / name).read_text(encoding="utf-8")
         raw = op.get_bind().connection.dbapi_connection.driver_connection  # asyncpg.Connection
         await_only(raw.execute(sql))
     ```
     `name` MUST match `^p[0-9]_[0-9]{2}[a-z]?_[a-z0-9_]+\.(up|down)\.sql$`; any other value raises `ValueError` (no path traversal).
   - Error convention for all PL/pgSQL: `RAISE EXCEPTION USING ERRCODE = 'P0001', MESSAGE = '<UPPER_SNAKE_CODE>'` (matches S4.3 `LOCKOUT_PREVENTED`). Tests assert on the message token.
   - Every `SECURITY DEFINER` function: owned by `kanban_migrator`, `SET search_path = pg_catalog, public`, `REVOKE EXECUTE ... FROM PUBLIC`, then explicit `GRANT EXECUTE ... TO kanban_app`.

3. **`database/migrations/env.py`:** async (`async_engine_from_config` + `connection.run_sync(do_run_migrations)`); DSN from env `KANBAN_MIGRATOR_DATABASE_URL` (missing -> `RuntimeError("KANBAN_MIGRATOR_DATABASE_URL is required")`, never a hard-coded default); optional env `KANBAN_MIGRATOR_SET_ROLE=kanban_migrator` issues `SET ROLE kanban_migrator` before migrating (test harness path, superuser connection); `transaction_per_migration=True`; `compare_type=True`; offline mode raises `RuntimeError` (no SQL file emission).

4. **`database/bootstrap/roles.sql` (run as superuser, idempotent, zero secrets):**
   ```sql
   DO $$
   BEGIN
     IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'kanban_migrator') THEN
       CREATE ROLE kanban_migrator LOGIN; END IF;
     IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'kanban_app') THEN
       CREATE ROLE kanban_app LOGIN; END IF;
     IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'app_rls_reader') THEN
       CREATE ROLE app_rls_reader LOGIN; END IF;
   END $$;
   -- Always re-assert attributes (a pre-existing role must be downgraded, never trusted):
   ALTER ROLE kanban_migrator NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION BYPASSRLS;
   ALTER ROLE kanban_app      NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS;
   ALTER ROLE app_rls_reader  NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS;
   ALTER ROLE app_rls_reader  SET default_transaction_read_only = on;
   ```
   Passwords are NOT set here (KB-P0-08 entrypoint sets them from `keyring.json`). `kanban_migrator` is `BYPASSRLS` because it owns all tables and all `SECURITY DEFINER` functions; it is used only by `alembic` and is never handed to the web/MCP process (S2.2 item 2 privilege drop).
5. **`database/bootstrap/extensions.sql` (superuser):** `CREATE EXTENSION IF NOT EXISTS` for exactly `pgcrypto`, `ltree`, `pg_trgm`, `btree_gist`, `vector`; then `REVOKE CREATE ON SCHEMA public FROM PUBLIC; GRANT USAGE, CREATE ON SCHEMA public TO kanban_migrator; GRANT USAGE ON SCHEMA public TO kanban_app, app_rls_reader;`.
6. **`p1_01_baseline.up.sql`:**
   ```sql
   CREATE FUNCTION uuidv7() RETURNS uuid LANGUAGE plpgsql VOLATILE PARALLEL SAFE AS $$
   DECLARE
     unix_ms bigint := floor(extract(epoch FROM clock_timestamp()) * 1000);
     b bytea := gen_random_bytes(16);
   BEGIN
     b := overlay(b PLACING substring(int8send(unix_ms) FROM 3) FROM 1 FOR 6);
     b := set_byte(b, 6, (get_byte(b, 6) & 15) | 112);   -- version 7
     b := set_byte(b, 8, (get_byte(b, 8) & 63) | 128);   -- RFC 9562 variant 10xx
     RETURN encode(b, 'hex')::uuid;
   END $$;

   CREATE FUNCTION app_current_principal_id() RETURNS uuid LANGUAGE sql STABLE PARALLEL SAFE AS
     $$ SELECT NULLIF(current_setting('app.principal_id', true), '')::uuid $$;
   CREATE FUNCTION app_current_workspace_id() RETURNS uuid LANGUAGE sql STABLE PARALLEL SAFE AS
     $$ SELECT NULLIF(current_setting('app.workspace_id', true), '')::uuid $$;

   CREATE FUNCTION set_updated_at() RETURNS trigger LANGUAGE plpgsql AS
     $$ BEGIN NEW.updated_at := clock_timestamp(); RETURN NEW; END $$;

   ALTER DEFAULT PRIVILEGES FOR ROLE kanban_migrator IN SCHEMA public
     GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO kanban_app;
   ALTER DEFAULT PRIVILEGES FOR ROLE kanban_migrator IN SCHEMA public
     GRANT SELECT ON TABLES TO app_rls_reader;
   ALTER DEFAULT PRIVILEGES FOR ROLE kanban_migrator IN SCHEMA public
     REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC;
   GRANT EXECUTE ON FUNCTION uuidv7(), app_current_principal_id(), app_current_workspace_id() TO kanban_app, app_rls_reader;
   ```
   `NULLIF(..., '')` is mandatory: after a previous `SET LOCAL` the GUC reads `''` (not NULL) on the same pooled connection, and `''::uuid` would raise instead of yielding zero rows. `TRUNCATE` is never granted to `kanban_app`.
   `p1_01_baseline.down.sql` drops the 4 functions and reverses the 3 default-privilege statements. Roles and extensions are NOT dropped by downgrade (cluster-level, owned by bootstrap).
7. **Test harness:**
   - Root `conftest.py`: before `alembic upgrade head` on `kanban_template`, call `bootstrap_cluster(superuser_dsn)`; run alembic with `KANBAN_MIGRATOR_SET_ROLE=kanban_migrator`.
   - `database/tests/conftest.py` fixtures (built on KB-P0-05 `db_session` SAVEPOINT fixture): `app_session` (executes `SET LOCAL ROLE kanban_app` inside the outer test transaction), `bind_ctx(session, principal_id, workspace_id)` helper issuing the S3.3 `set_config(..., true)` statement, `superuser_session` (no role switch).
   - `database/tests/migration_harness.py`: `class MigrationHarness` (async context manager) creating database `kanban_mig_<uuid4hex>` from `template0`, running bootstrap, exposing `upgrade(rev)`, `downgrade(rev)`, `previous_of(rev) -> str` (reads `ScriptDirectory`), `fetch(sql) -> list[Record]`; drops the database on exit even on failure. Mark tests using it `@pytest.mark.migration`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_01_baseline.py`, `database/tests/migrations/test_p1_01_migration.py`, `database/tests/test_sqlfile.py`
- **Required Test Cases:**
  1. Positive: `pg_roles` shows `kanban_app` with `rolsuper=false, rolbypassrls=false, rolcreatedb=false, rolcreaterole=false`; `kanban_migrator` with `rolsuper=false, rolbypassrls=true`; `app_rls_reader` `rolconfig` contains `default_transaction_read_only=on`.
  2. Positive: `pg_extension` contains exactly the 5 extensions `pgcrypto, ltree, pg_trgm, btree_gist, vector` (others allowed only if `plpgsql`).
  3. Positive: 1000 calls to `uuidv7()` return distinct values; every value has version nibble `7` and variant bits `10`; values generated in two calls 2ms apart sort ascending by byte order.
  4. Negative/security: as `kanban_app`, `CREATE TABLE x(i int)` in `public` raises `42501`; `SET ROLE kanban_migrator` raises `42501`.
  5. Negative/security: `bootstrap_cluster` run against a pre-created `kanban_app` role that has `BYPASSRLS` results in `rolbypassrls=false` (attribute re-assertion).
  6. Boundary: `app_current_principal_id()` returns NULL when unset, returns NULL after `set_config('app.principal_id','',true)`, and returns the uuid when set; a value `'not-a-uuid'` raises `22P02`.
  7. Negative: `execute_sql_file("../../etc/passwd")` and `execute_sql_file("p1_01_baseline.sql")` raise `ValueError`.
  8. Migration up/down: `MigrationHarness` upgrade `p1_01_baseline` -> functions `uuidv7`, `app_current_principal_id`, `app_current_workspace_id`, `set_updated_at` exist; downgrade to `base` -> all 4 absent; upgrade again succeeds.
  9. Migration round-trip (global, permanent): `upgrade head` -> `downgrade base` -> `upgrade head` completes and `pg_dump --schema-only` output of first and last upgrade is byte-identical after stripping comment lines.
  - Non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
