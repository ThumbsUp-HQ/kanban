### User Story
As a **workspace member or first-boot operator**, I need **a calm, breathable sign-in page that lists every enabled authentication card in the Server Admin's order, hides the break-glass Local Administrator path behind an explicit disclosure, walks me through Passkey or TOTP second factor, and lets me claim a fresh install from the one-time `/setup?token=kb_setup_...` URL** so that **I can sign in without guessing which provider to use, no account is ever merged by email, and the setup token never leaks into browser history, logs, or the DOM**.

**Requirement Traceability:** `S4.3` (login wireframe lines 331-348, `LOCKOUT_PREVENTED` context lines 350-353), `S4.2 items 1-4` (OIDC PKCE handled server-side, LDAPS ephemeral bind, Local Admin Argon2id + Passkey/TOTP AAL2, zero email auto-linking), `S2.2 item 4` (single-use `kb_setup_<base64url>` token, `TTL = 60m`, spec line 144), `S6.1` (spacing tokens), `S6.2` (`<EmojiHint>`), `S5.4` (CSP: no inline style, no remote fetch), requirements `#6`, `#9`, `#15` | **Dependencies:** `KB-P3-34` (app shell + router `/login`, `/setup`), `KB-P2-10` (public `GET /api/v1/auth/cards`), `KB-P2-12` (`POST /api/v1/setup/claim`)

3. **Consumed API contract (mocked in vitest + Playwright; owned by KB-P2-04/05/06/07/10/12):**
   | Purpose | Request | Success | Errors rendered |
   | :-- | :-- | :-- | :-- |
   | List enabled cards | `GET /api/v1/auth/cards` | `{ "cards": [{ "id", "slug", "provider_kind": "OIDC"\|"OAUTH2"\|"LDAP"\|"LOCAL_ADMIN", "display_name", "button_subtext": string\|null, "icon_preset" }] }` ordered by `sort_rank` | network error -> retry panel |
   | OIDC/OAUTH2 start | full-page `window.location.assign('/api/v1/auth/cards/' + encodeURIComponent(slug) + '/start?next=' + encodeURIComponent(next))` (server performs PKCE `S256`, `state`, `nonce`) | 302 by server | - |
   | LDAP bind | `POST /api/v1/auth/cards/{slug}/ldap-login` `{ username, password }` | `{ "status": "authenticated" }` or `{ "status": "mfa_required", "challenge_id", "methods": ["webauthn","totp","recovery"] }` | `INVALID_CREDENTIALS`, `RATE_LIMITED` |
   | Local Admin password | `POST /api/v1/auth/local/login` `{ username, password }` | `{ "status": "mfa_required", "challenge_id", "methods": [...] }` | `INVALID_CREDENTIALS`, `RATE_LIMITED` |
   | Passkey assertion | `POST /api/v1/auth/webauthn/assertion/options` `{ challenge_id }` -> `navigator.credentials.get({ publicKey })` -> `POST /api/v1/auth/webauthn/assertion/verify` `{ challenge_id, credential }` | `{ "status": "authenticated" }` | `WEBAUTHN_FAILED`, `CHALLENGE_EXPIRED` |
   | TOTP | `POST /api/v1/auth/totp/verify` `{ challenge_id, code }` | `{ "status": "authenticated" }` | `INVALID_CREDENTIALS`, `CHALLENGE_EXPIRED`, `RATE_LIMITED` |
   | Recovery code | `POST /api/v1/auth/recovery/verify` `{ challenge_id, code }` | `{ "status": "authenticated" }` | same as TOTP |
   | Setup claim | `POST /api/v1/setup/claim` `{ token, username, display_name, password }` | `{ "status": "enrollment_required", "enrollment_id" }` | `SETUP_TOKEN_INVALID` (covers used, expired, malformed), `RATE_LIMITED` |
   | Enroll passkey | `POST /api/v1/auth/webauthn/registration/options` `{ enrollment_id }` -> `navigator.credentials.create` -> `.../registration/verify` | `{ "status": "enrolled", "recovery_codes": string[10] }` | `WEBAUTHN_FAILED` |
   | Enroll TOTP | `POST /api/v1/auth/totp/enroll` `{ enrollment_id }` -> `{ "secret_base32", "otpauth_uri" }`; `POST /api/v1/auth/totp/enroll/verify` `{ enrollment_id, code }` | `{ "status": "enrolled", "recovery_codes": string[10] }` | `INVALID_CREDENTIALS` |
   Endpoint paths not yet fixed by the backend tickets are defined here as the frontend contract; the `api-specialist-review.md` MUST confirm each path or record the agreed rename.
4. **Login layout (breathable, Plane-calm):** Page background `--bg-canvas`; centered panel `max-width: 560px`, `padding: var(--space-10)` (40px) desktop/tablet and `var(--space-6)` (24px) mobile, `border: 1px solid var(--border-subtle)`, `border-radius: var(--radius-lg)`, `background: var(--bg-surface)`. Vertical rhythm: header -> card list -> divider -> disclosure separated by `--section-gap` (32px). Card list is a `<ul role="list">` with `gap: var(--card-gap)` (12px). Each `AuthCardButton` is a full-width `<button type="button">` with `padding: var(--card-pad)` (16px 18px), `min-height: 56px` (>= `--tap-min`), icon glyph (24px, `aria-hidden="true"`) + `display_name` (`--text-body`, weight 600) + optional `button_subtext` (`--fg-secondary`, 0.8125rem) + `Primary` badge on the FIRST non-`LOCAL_ADMIN` card only. Divider text `or Local Administrator` with hairlines (`--border-subtle`). Header: `🛡️` EmojiHint + `<h1>` text `Kanban Workspace Sign-in`.
5. **Card rendering rules (hostile input):**
   - `icon_preset` maps through a frozen allowlist `{ key: '🔑', building: '🏢', github: '🐙', gitlab: '🦊', lock: '🔐' }`; any other value renders `🔑`. Icons are decorative (`aria-hidden="true"`), the accessible name of the button is `Continue with ${display_name}` for OIDC/OAUTH2 and `Sign in with ${display_name}` for LDAP.
   - `display_name` and `button_subtext` render as React text only (never `dangerouslySetInnerHTML`), are clamped to 80 / 120 characters with a trailing `...`, full value exposed via `title`.
   - `LOCAL_ADMIN` cards never render as a top-level button; they power the disclosure. If no `LOCAL_ADMIN` card is enabled, the disclosure is not rendered.
   - Zero cards (`cards: []`): render an empty state `No sign-in methods are enabled. A Server Admin can restore access with: kanban-ctl auth emergency-unlock --enable-local-admin` with the command in a `<code>` block and a `Copy` button.
   - Card order equals API order; the client never re-sorts.
6. **LDAP and Local Admin forms:** Selecting an LDAP card expands `LdapLoginForm` inline below it (`aria-expanded` on the card button, `aria-controls` -> form id). Inputs: `username` (`autocomplete="username"`, `spellcheck="false"`, max 256), `password` (`type="password"`, `autocomplete="current-password"`, max 1024). Local Admin disclosure is a `<button aria-expanded>` with text `Sign in with Local Admin + Passkey / TOTP`; the panel contains the same 2 inputs. On submit the password string is sent, then the component state value is overwritten with `''` in a `finally` block and the input `value` cleared (no password retained after the request; unit test asserts). Submit button disabled while pending (`aria-busy="true"`).
7. **Second factor (`SecondFactorStep`):** Rendered when `status = 'mfa_required'`. Tabs (`role="tablist"`) in the order of `methods`: `Passkey`, `Authenticator code`, `Recovery code`. Passkey: button `Use passkey` triggers assertion; if `window.PublicKeyCredential` is undefined the tab shows `This browser does not support passkeys. Use an authenticator code.` and is `aria-disabled`. TOTP input: `inputmode="numeric"`, `autocomplete="one-time-code"`, pattern `^[0-9]{6}$`, submit auto-fires when 6 digits are entered; non-digits are stripped on input. Recovery input: pattern `^[A-Za-z0-9-]{8,32}$`. `CHALLENGE_EXPIRED` returns the user to the password step with message `Your sign-in session expired. Start again.`
8. **Error copy (no user enumeration, no server detail echo):** `INVALID_CREDENTIALS` -> `Sign-in failed. Check your credentials and try again.` (identical text for unknown user, wrong password, wrong code). `RATE_LIMITED` -> `Too many attempts. Try again in N seconds.` where `N` = integer `Retry-After` header clamped to `1..3600` (non-numeric -> 60). `WEBAUTHN_FAILED` -> `Passkey verification failed. Try again or use an authenticator code.` Any other problem -> `Sign-in is unavailable right now (code: <code>).` where `<code>` is shown only if it matches `^[A-Z_]{1,40}$`. Errors render in a `role="alert"` region placed above the form; focus moves to the alert.
9. **Setup claim (`/setup?token=...`):**
   - On mount, read `token` from `location.search`, then IMMEDIATELY call `history.replaceState(null, '', '/setup')` so the token leaves the address bar and history. Keep the token only in a `useRef` (never state that renders, never `localStorage`/`sessionStorage`, never logged). Validate client-side against `^kb_setup_[A-Za-z0-9_-]{43}$` (256-bit base64url); invalid or missing -> render `This setup link is invalid or has already been used. Check the container logs for the current setup URL.` with no form.
   - Step 1 form: `username` (`^[a-z0-9][a-z0-9._-]{2,63}$`), `display_name` (1-120), `password` + `confirm` (min 14 chars, max 1024, must match; strength hint text only, no library). Submit -> claim.
   - Step 2 enrollment (mandatory, no skip button): choice `Register a passkey` (recommended, first) or `Set up an authenticator app`. TOTP shows `secret_base32` in a `.mono` block grouped in 4-char chunks plus a `Copy setup key` button and the `otpauth_uri` in a copyable `<code>` (no QR library; out of scope), then a 6-digit verify input.
   - Step 3 recovery codes: render the 10 codes in a 2-column `.mono` list, `Copy all` and `Download .txt` (Blob + `URL.createObjectURL`, revoked after click), checkbox `I stored these recovery codes somewhere safe` must be checked to enable `Continue to workspace`. Codes are cleared from memory when leaving the step.
   - Progress indicator `Step N of 3` (`aria-current="step"`).
10. **EmojiHint usage (exact hover texts):**
    - Header `kind="access"` 🛡️, `label="About sign-in security"`, content: `Sign-in cards are listed in the order set by your Server Admin. Accounts link by card and subject ID only, never by matching email.`
    - Local Admin disclosure `kind="restricted"` 🔒, `label="About Local Administrator sign-in"`, content: `Break-glass Local Administrator. Requires password plus Passkey or TOTP (AAL2). Use only when your identity provider is unavailable.`
    - Rate-limit alert `kind="warning"` ⚠️, `label="About sign-in rate limits"`, content: `Sign-in attempts are limited per account and per network address to block password guessing.`
    - Setup step 3 `kind="restricted"` 🔒, `label="About recovery codes"`, content: `Each recovery code works once. They are shown only now and are stored server-side as hashes.`
    - Card icons (`🔑 🏢 🐙 🦊 🔐`) are decorative `aria-hidden="true"` next to visible text (not EmojiHints).
