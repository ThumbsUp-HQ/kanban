### User Story
As a **knowledge or spec-writing agent**, I need **six intent tools on `/mcp/docs` to search, read, write, and link Docs/Pages and Project Stickies, including atomic Sticky-to-Doc promotion** so that **architecture knowledge stays in canonical Markdown with ACLs preserved, without exposing any ticket-execution or admin tool on this surface.**

**Requirement Traceability:** `S11.3` items 1-6, `S8.1` (ltree `max_depth <= 10`, 6 sticky colors), `S8.2` (promotion triggers, ACL copy verbatim, `PROMOTED_TO_DOC`), `S11.1` (`kb_doc_*`, budget `~1,350` tokens), requirement `#11`, `#12` | **Dependencies:** `KB-P4-03`, `KB-P4-02a`, `KB-P3-15`, `KB-P3-14`, `KB-P3-17`, `KB-P3-07`

### Scoped Technical Actions
1. **Target Files:** `mcp/surfaces/docs/__init__.py` (registry; removes `ping_docs`), `mcp/surfaces/docs/search_knowledge.py`, `read_doc.py`, `upsert_doc.py`, `manage_stickies.py`, `promote_sticky_to_doc.py`, `link_knowledge.py`, `mcp/markdown_sections.py` (`section_patch` helper), `mcp/auth.py` (`search_knowledge`, `read_doc` -> `docs:read`; others -> `docs:write`).
2. **`search_knowledge`** input: `{query: string (required, 1..500), kinds: array enum [doc, page, sticky] (default all), project: string, limit: int 1..50 default 20, cursor: string}`. Uses KB-P3-17 over docs/pages/stickies; each hit carries a heading-anchored snippet `<= 300` chars. Response (`summary`):
   ```yaml
   total: 1
   items:
     - {kind: page, key: "docs/arch/auth-studio", title: Auth Studio, anchor: "#pkce-s256", snippet: "Mandatory PKCE (S256), single-use 128-bit state..."}
   ```
3. **`read_doc`** input: `{identifier: string (required; page path, doc/page/sticky uuid, or "help"), lod: enum [summary, standard, full] default standard}`. `summary`: `{kind, key, title, breadcrumbs, version_seq}`; `standard`: + `body_markdown`, `etag`, `access` pill; `full`: + `access_manifest`, `outline` (headings), `links`. Response (`summary`):
   ```yaml
   kind: page
   key: docs/arch/auth-studio
   title: Auth Studio
   breadcrumbs: [Architecture, Auth Studio]
   version_seq: 7
   ```
4. **`upsert_doc`** input: `{identifier: string (omit to create), parent: string, title: string (1..200), body_markdown: string (<= 1,048,576 bytes), mode: enum [replace, append, section_patch] default replace, section_heading: string (required when mode=section_patch), if_match: string (64 hex; required on update)}`.
   - `section_patch` (implemented in `mcp/markdown_sections.py`): locates the first ATX heading whose text equals `section_heading` (case-sensitive, outside fenced code blocks) and replaces content up to the next heading of the same or higher level; heading not found -> `SECTION_NOT_FOUND`; duplicated heading text -> `AMBIGUOUS_IDENTIFIER`.
   - Create under a parent at depth 10 -> `VALIDATION_FAILED` (ltree `max_depth <= 10`). `412` -> `CONFLICT_ETAG`. Response: `{status: created|updated, key, version_seq, etag}`.
5. **`manage_stickies`** input: `{action: enum [list, create, edit, recolor, help] (required), project: string (required except help), sticky: string (uuid; edit/recolor), body_markdown: string (<= 65,536 bytes), color: enum [amber, mint, sky, lavender, coral, slate]}`. Every returned sticky includes server-computed `promotion_recommended` (KB-P3-15 heuristic). Response for `list` (`summary`):
   ```yaml
   project: KAN
   stickies:
     - {id: 0196ed42-..., color: amber, title: "Auth notes", promotion_recommended: true}
   ```
6. **`promote_sticky_to_doc`** input: `{sticky: string (required), parent: string (target page path, optional), title: string (optional)}`. Calls `POST /api/v1/stickies/{id}/promote-to-doc` (KB-P3-15, single transaction, ACL rows copied verbatim, `PROMOTED_TO_DOC` link). Already-promoted sticky -> `ALREADY_PROMOTED`. Response: `{status: promoted, doc: docs/notes/auth-notes, link: PROMOTED_TO_DOC}`.
7. **`link_knowledge`** input: `{source: string (doc/page/sticky ref, required), target: string (issue key, cycle, module, or project ref, required), target_kind: enum [issue, cycle, module, project] (required), link_type: enum [RELATES_TO, VERIFIED_BY_DOC, DERIVED_FROM_STICKY] default RELATES_TO, action: enum [add, remove] default add}`. Matrix violation -> `LINK_TYPE_NOT_ALLOWED`.
8. **Error codes appended:** `SECTION_NOT_FOUND`, `ALREADY_PROMOTED` (plus reuse of `LINK_TYPE_NOT_ALLOWED` defined in KB-P4-07; if KB-P4-07 is not yet merged, define it here - the enum value is identical).
9. **Isolation:** `/mcp/docs` `tools/list` returns exactly these 6 names; budget test asserts `<= 1,350` approximate tokens.

### Mandatory Feature Unit Tests
- **Test File(s):** `mcp/tests/docs/test_docs_tools.py` (in-process kanban app on the clean-DB harness), `mcp/tests/test_markdown_sections.py`
- **Required Test Cases:**
  1. Positive: create page under `Architecture`, `append`, then `section_patch` the `## PKCE` section; `read_doc` returns updated body and `version_seq` incremented each write; `search_knowledge("PKCE")` returns the page with anchor `#pkce`; `manage_stickies(create)` with a 700-char body returns `promotion_recommended: true`; `promote_sticky_to_doc` creates a doc whose ACL rows equal the sticky's (row-by-row comparison) and a `PROMOTED_TO_DOC` link.
  2. Security: `read_doc` of a page in a project the caller cannot VIEW -> `NOT_FOUND` byte-identical to a missing path; `kb_doc_` key on `/mcp/agent` -> `403 SURFACE_KEY_MISMATCH`; `upsert_doc` body with hidden `display:none` text stored without it; `docs:read`-only key calling `upsert_doc` -> `INSUFFICIENT_SCOPE`.
  3. Section patch edge cases: heading inside a fenced code block is ignored; missing heading -> `SECTION_NOT_FOUND`; two identical headings -> `AMBIGUOUS_IDENTIFIER`; patching the last section replaces to end of document.
  4. Boundary: page at depth 10 accepts no child (`VALIDATION_FAILED`); sticky body 65,537 bytes -> `VALIDATION_FAILED`; `color: "red"` -> `VALIDATION_FAILED`; promote twice -> `ALREADY_PROMOTED`; stale `if_match` -> `CONFLICT_ETAG`.
  5. Isolation + budget: `tools/list` returns exactly the 6 names; schema `<= 1,350` approximate tokens.
