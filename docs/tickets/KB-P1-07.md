### User Story
As a **project administrator correcting ticket provenance**, I need **a database trigger that allows changing `issues.created_by_id` only for `PROJECT_ADMIN` or `SERVER_ADMIN` session principals, records who changed it and when, never alters `original_created_by_id`, and appends an immutable `CREATOR_OVERRIDDEN` activity entry** so that **creator attribution cannot be forged by standard users or by bypassing the API**.

**Requirement Traceability:** `S7.2 8d`, `S1.2` (audit ledger covers creator overrides), Requirement `#8d` | **Dependencies:** `KB-P1-05`, `KB-P1-12`, `KB-P1-13`

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/p1_07_creator_provenance.py`
   - `database/migrations/sql/p1_07_creator_provenance.up.sql`, `database/migrations/sql/p1_07_creator_provenance.down.sql`
2. **`issues_creator_insert_bi` (BEFORE INSERT ON issues):** forces `NEW.original_created_by_id := NEW.created_by_id`, `NEW.creator_modified_by_id := NULL`, `NEW.creator_modified_at := NULL` (client values ignored).
3. **`issues_creator_provenance_bu` (BEFORE UPDATE OF created_by_id, original_created_by_id, creator_modified_by_id, creator_modified_at ON issues, SECURITY DEFINER):**
   ```text
   IF NEW.original_created_by_id IS DISTINCT FROM OLD.original_created_by_id -> RAISE 'CREATOR_PROVENANCE_IMMUTABLE'
   IF NEW.created_by_id IS NOT DISTINCT FROM OLD.created_by_id:
        IF NEW.creator_modified_by_id IS DISTINCT FROM OLD.creator_modified_by_id
           OR NEW.creator_modified_at IS DISTINCT FROM OLD.creator_modified_at -> RAISE 'CREATOR_PROVENANCE_IMMUTABLE'
        RETURN NEW
   v_actor := app_current_principal_id();  IF v_actor IS NULL -> RAISE 'RLS_CONTEXT_REQUIRED'
   IF NOT app_principal_has_role(NEW.project_id, ARRAY['PROJECT_ADMIN','SERVER_ADMIN']) -> RAISE 'CREATOR_OVERRIDE_FORBIDDEN'
   IF NOT EXISTS (SELECT 1 FROM users WHERE id = v_actor) -> RAISE 'CREATOR_OVERRIDE_ACTOR_NOT_USER'
   NEW.creator_modified_by_id := v_actor;  NEW.creator_modified_at := clock_timestamp();
   UPDATE objects SET created_by_id = NEW.created_by_id WHERE id = NEW.id;
   PERFORM append_activity(NEW.workspace_id, NEW.id, 'issue', v_actor, 'CREATOR_OVERRIDDEN',
       jsonb_build_object('from_user_id', OLD.created_by_id, 'to_user_id', NEW.created_by_id,
                          'original_created_by_id', OLD.original_created_by_id));
   ```
   - `app_principal_has_role()` (KB-P1-13) evaluates bindings for the session principal and its groups: `SERVER_ADMIN` at `SERVER` scope, `PROJECT_ADMIN` at `PROJECT` scope for `NEW.project_id`. `WORKSPACE_ADMIN` is NOT accepted (S7.2 8d names only `PROJECT_ADMIN` / `SERVER_ADMIN`).
   - `append_activity()` signature is the one delivered by KB-P1-12; use it unchanged.
   - The new `created_by_id` must reference `users` (existing FK) and must belong to the same workspace -> else `CREATOR_OVERRIDE_WORKSPACE_MISMATCH`.
4. **Down migration:** drops both triggers and their functions.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_07_creator_provenance.py`, `database/tests/migrations/test_p1_07_migration.py`
- **Required Test Cases:**
  1. Positive: session principal with `PROJECT_ADMIN` binding on the project changes `created_by_id` U1 -> U2; row shows `created_by_id=U2`, `original_created_by_id=U1`, `creator_modified_by_id=<admin>`, non-NULL `creator_modified_at`; `objects.created_by_id = U2`; exactly one `activity_records` row with `event_type='CREATOR_OVERRIDDEN'` and payload `from_user_id=U1`, `to_user_id=U2`.
  2. Positive: `SERVER_ADMIN` (SERVER scope) can override; a user who is `SERVER_ADMIN` only through group membership can override.
  3. Negative/security: `MEMBER` raises `CREATOR_OVERRIDE_FORBIDDEN`; `WORKSPACE_ADMIN` raises `CREATOR_OVERRIDE_FORBIDDEN`; `PROJECT_ADMIN` of a different project raises `CREATOR_OVERRIDE_FORBIDDEN`; no activity row is written in any of these cases.
  4. Negative/security: any role updating `original_created_by_id` raises `CREATOR_PROVENANCE_IMMUTABLE`; directly setting `creator_modified_by_id` without changing creator raises `CREATOR_PROVENANCE_IMMUTABLE`.
  5. Negative: override without RLS context raises `RLS_CONTEXT_REQUIRED`; target user from another workspace raises `CREATOR_OVERRIDE_WORKSPACE_MISMATCH`.
  6. Boundary: INSERT with client-supplied `original_created_by_id <> created_by_id` and non-NULL `creator_modified_at` stores `original_created_by_id = created_by_id` and NULL modified fields; an UPDATE touching only `summary` writes no activity row.
  7. Migration up/down: upgrade `p1_07_creator_provenance` -> both triggers exist; downgrade to `previous_of(...)` -> absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
