### User Story
As a **workspace user, administrator, or delegated MCP/CLI agent**, I need **a single capability bitmask evaluator enforcing explicit-deny precedence and On-Behalf-Of (`User ∩ AgentGrant ∩ TokenScope`) narrowing, paired with an anti-enumeration `access_manifest` serializer and `GET /api/v1/objects/{id}/access` endpoint** so that **every object surfaces transparent sharing metadata (`Users`, `Groups`, `Agents`, `Inherited Scope`, `Explicit DENY`) without leaking principals across visibility boundaries or elevating an agent above its invoking human**.

**Requirement Traceability:** `S3.2` (capabilities `VIEW..DELETE`, explicit deny precedence, delegated OBO intersection `EffectivePerms(u, r) ∩ AgentGrant(a, r) ∩ TokenScope(t)`, autonomous service agents), `S3.4` (`access_manifest`, same-workspace co-viewers vs redacted `{ "redacted": true, "label": "1 External Collaborator" }`, indistinguishable `404` `<= 5ms` jitter), `S3.1` (`principals`, `groups`), requirement `#1` | **Dependencies:** `KB-P1-13` (`resource_acl_entries`, RBAC role bindings, `effective_resource_access`), `KB-P2-01` (`PrincipalContext`, `get_rls_session`, `load_or_404`, `timing_floor`)

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/security/permissions.py` (`Capability`, `SCOPE_CAPABILITY_MAP`, `parse_token_scope_mask`, `evaluate_capabilities`, `require_capability`)
   - `kanban/security/access_manifest.py` (`AccessManifest`, `build_access_manifest` + Pydantic response models)
   - `kanban/api/deps.py` (extend `PrincipalContext` with optional `agent_principal_id: UUID | None = None` for OBO delegation without breaking existing 5-arg callers)
   - `kanban/api/v1/objects_access.py` (`GET /api/v1/objects/{object_id}/access`, registered in `build_v1_router()`)
2. **Capability Bitmask & OBO Intersection (`kanban/security/permissions.py`):**
   - `class Capability(IntFlag)` matching `KB-P1-13` bit positions (`S3.3` bit `0` = `VIEW`):
     `NONE = 0`, `VIEW = 1 << 0` (`1`), `COMMENT = 1 << 1` (`2`), `EDIT = 1 << 2` (`4`), `TRANSITION = 1 << 3` (`8`), `LINK = 1 << 4` (`16`), `SHARE = 1 << 5` (`32`), `ADMIN = 1 << 6` (`64`), `DELETE = 1 << 7` (`128`), `ALL = 0xFF`.
   - `parse_token_scope_mask(token_scopes: Sequence[str]) -> Capability`:
     - Interactive browser `"session"` scope -> `Capability.ALL`.
     - Explicit capability/MCP scopes map additively via `SCOPE_CAPABILITY_MAP` (`"read"` / `"agent:read"` / `"docs:read"` / `"admin:read"` -> `VIEW`; `"comment"` -> `VIEW | COMMENT`; `"write"` / `"agent:write"` / `"docs:write"` -> `VIEW | COMMENT | EDIT | TRANSITION | LINK`; `"share"` -> `VIEW | SHARE`; `"admin:write"` -> `ALL & ~DELETE`; `"admin:destructive"` -> `ALL`); unknown or empty scopes -> `Capability.NONE` (fail closed).
   - `async def evaluate_capabilities(session: AsyncSession, principal_ctx: PrincipalContext, object_id: UUID) -> Capability`:
     - Helper `_principal_mask(principal_id)` aggregates `effective_resource_access` for `{principal_id} ∪ (SELECT ancestor_group_id FROM principal_group_closure WHERE member_id = principal_id)` on `object_id`: `allow = bit_or(allow_mask)`, `deny = bit_or(deny_mask)`, returning `Capability(allow & ~deny)` (Explicit Deny Precedence: any `DENY` bit on the principal or any ancestor group clears that capability).
     - **Human or Autonomous Service Agent (`principal_ctx.agent_principal_id is None`):** `effective = _principal_mask(principal_ctx.principal_id) & parse_token_scope_mask(principal_ctx.token_scopes)`.
     - **Delegated User Agent (`OBO`, `principal_ctx.agent_principal_id is not None`):** verifies both human `principal_id` and `agent_principal_id` are `ACTIVE` in `principals`, then computes exact `S3.2` intersection:
       `effective = _principal_mask(principal_ctx.principal_id) & _principal_mask(principal_ctx.agent_principal_id) & parse_token_scope_mask(principal_ctx.token_scopes)`.
   - `async def require_capability(session: AsyncSession, principal_ctx: PrincipalContext, object_id: UUID, required: Capability) -> Capability`:
     - Computes `caps = await evaluate_capabilities(session, principal_ctx, object_id)`.
     - If `Capability.VIEW not in caps`: calls `not_found()` (`404 NOT_FOUND`, never `403`, preserving S3.4 anti-enumeration).
     - If `(caps & required) != required`: raises `ProblemException(status=403, code="INSUFFICIENT_CAPABILITY", title="Insufficient Capability", detail=None)`.
     - Returns `caps` so callers can populate `"capabilities": capabilities_to_names(caps)` on serializers (`KB-P3-01a`, `KB-P3-02`).
3. **Anti-Enumeration `access_manifest` Serializer (`kanban/security/access_manifest.py`):**
   - `async def build_access_manifest(session: AsyncSession, caller: PrincipalContext, object_id: UUID) -> AccessManifest`:
     - First calls `require_capability(..., Capability.VIEW)` (raises `404` if caller cannot view `object_id`).
     - Computes `inherited_scope`: `{kind: "private" | "project" | "workspace", scope_label: str, workspace_id: UUID, workspace_name: str, project_id: UUID | None, project_key: str | None, project_name: str | None}` and compact `pill_label` (e.g. `"Project + 2"` when `explicit_grant_count == 2`, `"Project"` when `0`, `"Private + 1"` when private with 1 direct share) + `explicit_grant_count: int`.
     - **Visibility Boundary Rule (`S3.4` items 1-2):** a target principal `P` holding an ACL/role grant or explicit `DENY` on `object_id` is **in-boundary** for caller `C` iff `P.workspace_id == C.workspace_id` AND (`C` holds workspace-level visibility / project membership with `P` in `C.workspace_id`, whereas cross-workspace principals, `SCRIPT_EPHEMERAL` tokens, or principals outside a restricted single-object guest caller's co-viewer set are **out-of-boundary**).
     - In-boundary entries populate typed lists matching S3.4 wireframe and `KB-P3-41` / `KB-P3-49`:
       - `users`: `[{principal_id, handle, display_name, capabilities: list[str], grant_source: "project_owner" | "project_role" | "workspace_role" | "direct_share"}]` (never exposes `users.email` to non-admins unless configured; handle + display_name only).
       - `groups`: `[{principal_id, name, member_count: int, external_source: "LDAP" | "OIDC" | null, capabilities: list[str], grant_source}]` (`external_id` / raw LDAP DN is NEVER included per S3.4 item 2).
       - `agents`: `[{principal_id, display_name, principal_type: "AGENT" | "SERVICE_PRINCIPAL", provider_badge: str | null, scope_summary: str, capabilities: list[str]}]`.
       - `deny_overrides`: `[{principal_id: UUID | None, principal_type: str, display_name: str, redacted: bool, denied_capabilities: list[str]}]` (if denied principal is out-of-boundary, `principal_id=None, display_name="1 Restricted Principal", redacted=True`).
     - Out-of-boundary entries are NEVER emitted with names, emails, handles, UUIDs, or group DNs; they are emitted strictly as `redacted_entries: [{"redacted": true, "label": "<N> External Collaborator(s)"}]` plus integer `redacted_count: int`.
4. **Endpoints (`GET /api/v1/objects/{object_id}/access` & `POST /api/v1/objects/{object_id}/access/agent-kill-switch`):**
   - `GET /api/v1/objects/{object_id}/access`: executes inside `async with timing_floor(floor_ms=25.0):` using `get_rls_session` (`KB-P2-01`). Returns `200 AccessManifest` for readable objects and jitter-equalized `404 NOT_FOUND` for non-existent or unreadable UUIDs.
   - `POST /api/v1/objects/{object_id}/access/agent-kill-switch`: powers the S3.4 `[ Kill Switch ]` control consumed by `KB-P3-49`. Requires `Capability.SHARE` or `Capability.ADMIN` on `object_id` (`404` if lacking `VIEW`, `403 INSUFFICIENT_CAPABILITY` otherwise), atomically upserts explicit `DENY` `Capability.ALL` rows in `resource_acl_entries` for every active `AGENT` and `SERVICE_PRINCIPAL` holding access on `object_id`, writes an immutable `AGENT_ACCESS_KILLED` record to `activity_records`, refreshes `effective_resource_access`, and returns `200 AccessManifest` with `agents: []` and the newly populated `deny_overrides`.
5. **Security invariants asserted:** (a) OBO effective capability bitmask is always a subset of each of `User`, `AgentGrant`, and `TokenScope`; (b) explicit `DENY` on any group overrides `ALLOW` from any other group or direct ACL; (c) out-of-boundary principals leak zero UUID, email, handle, or LDAP DN; (d) `GET /api/v1/objects/{id}/access` produces indistinguishable `404` responses (`<= 5ms` median delta) for absent vs unreadable objects.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/security/test_permissions_and_obo.py`, `kanban/tests/security/test_access_manifest.py`, `kanban/tests/api/test_objects_access_endpoint.py`
- **Required Test Cases:**
  1. Positive RBAC + ACL union: user with project `VIEW | COMMENT` plus direct `EDIT` ACL on issue `KAN-1` evaluates to `VIEW | COMMENT | EDIT`.
  2. Security (explicit deny precedence): user in `Core Backend` (`ALLOW VIEW|EDIT`) AND `Contractors` (`DENY EDIT`) evaluates to `VIEW` only; nested group `SubContractors -> Contractors` inherits the `DENY EDIT` via `principal_group_closure`.
  3. Security (OBO intersection narrowing): user holds `VIEW | EDIT | DELETE` on `KAN-1`, agent principal holds `VIEW | EDIT` on project `KAN`, token carries `token_scopes=("agent:read",)` -> `evaluate_capabilities` returns `VIEW` only; widening token to `("agent:write",)` returns `VIEW | EDIT` (never `DELETE` because agent lacks `DELETE`); invoking OBO on confidential project `SEC-1` where agent has `VIEW | EDIT` on `SEC` (misconfigured broad agent) but human user has `NONE` -> returns `Capability.NONE` (`404 NOT_FOUND`).
  4. Security (disabled principal / unknown scope): OBO with `DISABLED` agent principal -> `Capability.NONE`; `token_scopes=("unknown:scope",)` -> `Capability.NONE`.
  5. Positive `access_manifest`: project `KAN` with 2 direct users, 2 groups (`Core Backend` LDAP-synced 11 members, `SecOps` OIDC 4 members), 1 service `AGENT`, and 1 `DENY` group produces `pill_label`, `users`, `groups` (accurate `member_count`), `agents`, and `deny_overrides` matching S3.4.
  6. Security (anti-enumeration redaction): attach an out-of-boundary collaborator (`external_user` email `secret@partner.example`, handle `@secret_ext`, LDAP DN `CN=Secret,OU=Partner,DC=corp`) to `KAN-1`; serialized `AccessManifest` JSON contains `redacted_count >= 1`, `{"redacted": true, "label": "1 External Collaborator"}`, and zero occurrences of `secret@partner.example`, `secret_ext`, `CN=Secret`, or the external principal's UUID; in-boundary LDAP group entry also omits `CN=...` `external_id`.
  7. Security (404 vs 403 discipline): `require_capability(..., Capability.EDIT)` raises `404 NOT_FOUND` when caller lacks `VIEW`, and `403 INSUFFICIENT_CAPABILITY` when caller holds `VIEW` only.
  8. Endpoint, agent kill-switch & statistical timing: `GET /api/v1/objects/{id}/access` returns `200` for co-viewer; `POST /api/v1/objects/{id}/access/agent-kill-switch` returns `403 INSUFFICIENT_CAPABILITY` for `VIEW`-only caller, and for `SHARE`/`ADMIN` caller revokes active `AGENT`/`SERVICE_PRINCIPAL` access (`agents == []`), appends `AGENT_ACCESS_KILLED` to `activity_records`, and causes subsequent OBO/service agent reads on `object_id` to receive `404 NOT_FOUND`; across 100 alternating requests for (a) random UUID and (b) existing `SEC-1` UUID unreadable to caller, status (`404`), headers, and body (excluding `request_id`) are identical and `abs(median(a) - median(b)) <= 5ms`.
