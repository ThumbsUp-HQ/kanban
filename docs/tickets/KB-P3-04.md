### User Story
As a **Project or Server Administrator correcting imported or mis-attributed tickets**, I need **an admin-only endpoint to change `Created by` with a mandatory reason, and an issue serializer exposing full provenance** so that **the `🔄` indicator and hover tooltip show who changed the creator, when and why, backed by an immutable `CREATOR_OVERRIDDEN` record**.

**Requirement Traceability:** Spec S7.2 `8d`; S11.4 tool 10 (`override_ticket_provenance`, mandatory `reason`); requirement `#8d` | **Dependencies:** `KB-P3-02`, `KB-P1-07`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/issue_provenance.py`, `kanban/api/v1/schemas/issue_provenance.py`, `kanban/services/issue_provenance.py`, `kanban/api/v1/schemas/issues.py` (add `provenance`), `database/migrations/versions/<rev>_creator_override_reason.py` (only if the KB-P1-07 trigger payload lacks `reason`).
2. **Endpoint:** `PATCH /api/v1/issues/{issue_ref}/created-by`
   - Request: `{"created_by": "<uuid>|@handle", "reason": "Imported from Plane under bot account"}`.
   - Authorization order: (a) caller lacks `VIEW` -> `404 NOT_FOUND` (equalized); (b) caller lacks `PROJECT_ADMIN` on the issue's project and `SERVER_ADMIN` -> `403 INSUFFICIENT_CAPABILITY`; (c) session `app.aal_level < 2` -> `403 AAL2_REQUIRED` (S4.2 item 3: AAL2 mandatory for admin roles).
   - Validation: `reason` plain text, `btrim` length `10..500` else `422 REASON_REQUIRED`; `created_by` must be an active `USER` principal with project `VIEW`, else `422 CREATOR_NOT_ELIGIBLE` (identical body for nonexistent); equal to current `created_by_id` returns `422 CREATOR_UNCHANGED`.
   - Implementation: in the RLS transaction run `SELECT set_config('app.override_reason', :reason, true)` then `UPDATE issues SET created_by_id = :new WHERE id = :id`. The KB-P1-07 trigger enforces admin role, sets `creator_modified_by_id`/`creator_modified_at`, preserves `original_created_by_id` and inserts `CREATOR_OVERRIDDEN`. If that trigger's activity payload does not include `reason`, this ticket's migration replaces the trigger function to add `"reason": current_setting('app.override_reason', true)` and `"old_created_by_id"`, `"new_created_by_id"`; the API never writes a second activity row.
   - A trigger rejection (e.g., role revoked mid-request) maps to `403 INSUFFICIENT_CAPABILITY`.
   - Response `200`: full issue serializer.
3. **Provenance serializer** added to every issue response:
   ```json
   "provenance": {
     "created_by": {"id": "...", "handle": "maya"},
     "original_created_by": {"id": "...", "handle": "bot-import"},
     "overridden": true,
     "creator_modified_by": {"id": "...", "handle": "adam"},
     "creator_modified_at": "2026-11-11T18:20:00Z",
     "reason": "Imported from Plane under bot account"
   }
   ```
   `overridden` is `created_by_id <> original_created_by_id OR creator_modified_at IS NOT NULL`. `reason` is read from the latest `CREATOR_OVERRIDDEN` activity row. Principals outside the caller's visibility boundary serialize as `{"redacted": true, "label": "1 External Collaborator"}` (S3.4).
4. **Activity events emitted:** `CREATOR_OVERRIDDEN {old_created_by_id, new_created_by_id, reason}` (category `HISTORY`, written by the KB-P1-07 trigger; registered in `ActivityEventType`).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_issue_provenance.py`
- **Required Test Cases:**
  1. Positive: AAL2 project admin overrides creator with a 20-char reason; response `provenance.overridden == true`, `original_created_by` unchanged, exactly one `CREATOR_OVERRIDDEN` row with `reason`.
  2. Security: `EDIT` member gets `403 INSUFFICIENT_CAPABILITY`; non-viewer gets `404`; AAL1 admin gets `403 AAL2_REQUIRED`; direct `UPDATE issues SET created_by_id` as non-admin session is rejected by the trigger (regression guard).
  3. Validation boundary: reason of 9 chars returns `422`, 10 chars succeeds, 501 chars returns `422`; same creator returns `422 CREATOR_UNCHANGED`; non-viewer target user returns `422 CREATOR_NOT_ELIGIBLE` identical to random UUID.
  4. Redaction: viewer outside admin's group boundary sees `creator_modified_by` as `redacted: true`.
  5. Second override keeps the first `original_created_by_id` and writes a second activity row.
- Clean-DB `SAVEPOINT` harness. Coverage `>= 95%`.
