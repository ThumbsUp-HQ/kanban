### User Story
As a **platform administrator or security auditor**, I need **`audit_object_links(p_workspace_id)` and incremental database triggers that detect all 6 S12.3 invalidity classes, transition offending `object_links` rows to `FLAGGED_INVALID`, and capture full endpoint snapshots in `invalid_object_link_audits`** so that **broken, archived-blocking, soft-deleted, type-corrupted, cross-workspace, or ACL-severed links never fail silently or disappear without forensic proof**.

**Requirement Traceability:** `S12.3` (all 6 invalidity classes, `FLAGGED_INVALID`, `invalid_object_link_audits` snapshots), `S12.1` (`object_links.link_state`), Requirement `#13j` | **Dependencies:** `KB-P1-11`, `KB-P1-13`, `KB-P1-14`

2. **`invalid_link_reason` Enum & `invalid_object_link_audits` DDL (`p1_15_link_auditor.up.sql`):**
   ```sql
   CREATE TYPE invalid_link_reason AS ENUM (
       'DANGLING_SOURCE',
       'DANGLING_TARGET',
       'SOFT_DELETED_ENDPOINT',
       'ARCHIVED_POLICY_VIOLATION',
       'TYPE_MATRIX_VIOLATION',
       'CROSS_WORKSPACE_LEAK',
       'PERMISSION_SEVERED'
   );

   CREATE TABLE invalid_object_link_audits (
       id               UUID PRIMARY KEY DEFAULT uuidv7(),
       workspace_id     UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       link_id          UUID NOT NULL,          -- No FK CASCADE: audit row MUST survive link purge (KB-P1-16)
       reason           invalid_link_reason NOT NULL,
       link_snapshot    JSONB NOT NULL CHECK (jsonb_typeof(link_snapshot) = 'object'),
       source_snapshot  JSONB CHECK (source_snapshot IS NULL OR jsonb_typeof(source_snapshot) = 'object'),
       target_snapshot  JSONB CHECK (target_snapshot IS NULL OR jsonb_typeof(target_snapshot) = 'object'),
       detected_at      TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       resolved_at      TIMESTAMPTZ,
       purged_at        TIMESTAMPTZ,
       purged_by_id     UUID REFERENCES principals(id) ON DELETE RESTRICT,
       purge_reason     TEXT CHECK (purge_reason IS NULL OR char_length(btrim(purge_reason)) BETWEEN 3 AND 1000)
   );
   CREATE UNIQUE INDEX invalid_link_audits_open_uq
       ON invalid_object_link_audits (link_id, reason)
       WHERE purged_at IS NULL AND resolved_at IS NULL;
   CREATE INDEX invalid_link_audits_ws_open_idx
       ON invalid_object_link_audits (workspace_id, detected_at DESC)
       WHERE purged_at IS NULL AND resolved_at IS NULL;

   ALTER TABLE invalid_object_link_audits ENABLE ROW LEVEL SECURITY;
   ALTER TABLE invalid_object_link_audits FORCE ROW LEVEL SECURITY;
   REVOKE INSERT, UPDATE, DELETE ON invalid_object_link_audits FROM kanban_app, app_rls_reader;
   ```
   - RLS `SELECT` policy `invalid_link_audits_select_rls`: `workspace_id = app_current_workspace_id() AND app_principal_has_role(NULL, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN'])` (or `PROJECT_ADMIN` on `(source_snapshot->>'project_id')::uuid` / `(target_snapshot->>'project_id')::uuid`).
   - Immutability guard `invalid_link_audits_guard_bud`: `BEFORE DELETE` always raises `LINK_AUDIT_RECORD_IMMUTABLE`; `BEFORE UPDATE` allows changing ONLY `(resolved_at, purged_at, purged_by_id, purge_reason)` and rejects edits to `id`, `workspace_id`, `link_id`, `reason`, `link_snapshot`, `source_snapshot`, `target_snapshot`, `detected_at` (`LINK_AUDIT_SNAPSHOT_IMMUTABLE`).

3. **Six-Reason Detection Semantics (`audit_object_links(p_workspace_id uuid, p_as_of timestamptz DEFAULT clock_timestamp()) RETURNS TABLE(audit_id uuid, link_id uuid, reason invalid_link_reason)`):**
   - `VOLATILE SECURITY DEFINER`, `SET search_path = pg_catalog, public`, `GRANT EXECUTE TO kanban_app`. Caller under `kanban_app` must have `app_current_workspace_id() = p_workspace_id` and hold `SERVER_ADMIN` or `WORKSPACE_ADMIN` (or be invoked from an internal trigger `pg_trigger_depth() > 0`), else raises `AUDIT_LINKS_FORBIDDEN`.
   - Evaluates every row `ol` in `object_links` for `p_workspace_id` against all 6 classes (one link can emit multiple distinct `reason` rows if multiple violations apply):
     1. **Class 1 (`DANGLING_SOURCE` / `DANGLING_TARGET`):** `objects` row `src` for `ol.source_id` is `NULL` or `src.object_type <> ol.source_type` -> `DANGLING_SOURCE`; `objects` row `tgt` for `ol.target_id` is `NULL` or `tgt.object_type <> ol.target_type` -> `DANGLING_TARGET`.
     2. **Class 2 (`SOFT_DELETED_ENDPOINT`):** `(src.deleted_at IS NOT NULL AND src.deleted_at <= p_as_of - make_interval(days => ws.trash_retention_days))` OR `(tgt.deleted_at IS NOT NULL AND tgt.deleted_at <= p_as_of - make_interval(days => ws.trash_retention_days))` (endpoints still inside the retention window are NOT flagged yet unless `p_as_of` advances past grace).
     3. **Class 3 (`ARCHIVED_POLICY_VIOLATION`):** `(ol.link_type = 'BLOCKS' AND src.archived_at IS NOT NULL AND tgt.archived_at IS NULL AND tgt.deleted_at IS NULL AND NOT EXISTS (SELECT 1 FROM issues i JOIN workflow_states s ON s.id = i.state_id WHERE i.id = tgt.id AND s.state_group IN ('completed', 'cancelled')))` OR `(ol.link_type = 'BLOCKED_BY' AND tgt.archived_at IS NOT NULL AND src.archived_at IS NULL AND src.deleted_at IS NULL AND NOT EXISTS (SELECT 1 FROM issues i JOIN workflow_states s ON s.id = i.state_id WHERE i.id = src.id AND s.state_group IN ('completed', 'cancelled')))`.
     4. **Class 4 (`TYPE_MATRIX_VIOLATION`):** `NOT EXISTS (SELECT 1 FROM link_type_matrix m WHERE m.source_type = ol.source_type AND m.link_type = ol.link_type AND m.target_type = ol.target_type)`.
     5. **Class 5 (`CROSS_WORKSPACE_LEAK`):** `src IS NOT NULL AND tgt IS NOT NULL AND (src.workspace_id <> tgt.workspace_id OR src.workspace_id <> ol.workspace_id)`.
     6. **Class 6 (`PERMISSION_SEVERED`):** `src IS NOT NULL AND tgt IS NOT NULL` AND (`NOT EXISTS (SELECT 1 FROM effective_resource_access es JOIN effective_resource_access et ON es.principal_id = et.principal_id WHERE es.object_id = ol.source_id AND et.object_id = ol.target_id AND es.principal_id = ol.created_by_id AND (es.effective_mask & 1) = 1 AND (et.effective_mask & 1) = 1)`).
   - For each detected `(link_id, reason)`: sets `object_links.link_state = 'FLAGGED_INVALID'` and inserts into `invalid_object_link_audits` (`ON CONFLICT (link_id, reason) WHERE purged_at IS NULL AND resolved_at IS NULL DO NOTHING`) storing `to_jsonb(ol)`, `to_jsonb(src)`, `to_jsonb(tgt)`.
   - Auto-healing before purge: if a previously flagged reason on a non-purged link no longer holds (e.g., archived issue unarchived or ACL restored), sets `resolved_at = p_as_of` on that open audit row, and if `0` open audit rows remain for `ol.id`, restores `object_links.link_state = 'ACTIVE'`.

4. **Incremental Trigger Path (`audit_object_links_for_object(p_object_id uuid)`):**
   - `AFTER UPDATE OF archived_at, deleted_at, workspace_id ON objects` and `AFTER INSERT OR UPDATE OR DELETE ON resource_acl_entries, role_bindings` invoke `audit_object_links_for_object` to immediately evaluate all `object_links` touching the affected object(s) within the same transaction.

5. **Down Migration:** Drops incremental triggers, `audit_object_links_for_object`, `audit_object_links`, `invalid_object_link_audits`, and `invalid_link_reason`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_15_link_auditor.py`, `database/tests/migrations/test_p1_15_migration.py`
- **Required Test Cases:**
  1. Class 1 (`DANGLING_SOURCE` & `DANGLING_TARGET`): create valid links, simulate catalog/FK corruption as superuser (`SET LOCAL session_replication_role = replica; DELETE FROM objects ...`), run `audit_object_links(ws)` -> both links transition to `FLAGGED_INVALID` with `DANGLING_SOURCE` (`source_snapshot IS NULL`) and `DANGLING_TARGET` (`target_snapshot IS NULL`).
  2. Class 2 (`SOFT_DELETED_ENDPOINT`): set `objects.deleted_at = now() - interval '10 days'` on endpoint (retention `30` days) -> `audit_object_links(ws, now())` flags `0` rows; `audit_object_links(ws, now() + interval '21 days')` flags `SOFT_DELETED_ENDPOINT`.
  3. Class 3 (`ARCHIVED_POLICY_VIOLATION` via incremental trigger): issue `KAN-1` (`In Progress`) has `KAN-0 BLOCKS KAN-1`; setting `objects.archived_at = clock_timestamp()` on `KAN-0` immediately flips the link to `FLAGGED_INVALID` (`ARCHIVED_POLICY_VIOLATION`) in the same statement without manually calling `audit_object_links`; unarchiving `KAN-0` sets `resolved_at` and restores `link_state = 'ACTIVE'`.
  4. Class 4 (`TYPE_MATRIX_VIOLATION`): delete a tuple from `link_type_matrix` as superuser after creating a matching link -> `audit_object_links(ws)` flags `TYPE_MATRIX_VIOLATION`.
  5. Class 5 (`CROSS_WORKSPACE_LEAK`): bypass insert trigger via `session_replication_role = replica` to create a link whose target is in `WS2` -> `audit_object_links(ws1)` flags `CROSS_WORKSPACE_LEAK`.
  6. Class 6 (`PERMISSION_SEVERED` via incremental trigger): creator `U1` creates `KAN-1 -> RELATES_TO -> SEC-1` while holding `VIEW` on both; adding `DENY VIEW` for `U1` on `SEC-1` immediately flips the link to `FLAGGED_INVALID` with `PERMISSION_SEVERED`.
  7. Security & idempotency: running `audit_object_links(ws)` twice produces `1` open audit row per `(link_id, reason)` (no duplicates); `MEMBER` calling `audit_object_links` raises `AUDIT_LINKS_FORBIDDEN`; `DELETE FROM invalid_object_link_audits` raises `LINK_AUDIT_RECORD_IMMUTABLE`; KB-P1-14 `test_p1_14_rls_catalog.py` continues to pass (`FORCE RLS` enabled on `invalid_object_link_audits`).
  8. Migration up/down: `MigrationHarness` upgrade `p1_15_link_auditor` -> table, enum, functions, triggers exist; downgrade to `previous_of(...)` -> absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
