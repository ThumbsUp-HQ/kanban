### User Story
As a **Project Admin configuring sandboxed scripted fields** (and as a **Member reading a ticket**), I need **the `Custom Fields (Admin-Defined 🧪)` properties-rail section, an admin-only custom field definition editor, and the escalation approval request/approve UI** so that **scripted values render safely in all 7 typed output formats, standard users can never reach the editor, and every scope/credential escalation is visibly bound to a `manifest_sha256` and an `AAL2` step-up**.

**Requirement Traceability:** `S7.1` (drawer wireframe rail rows `Custom Fields (Admin-Defined 🧪)`, `CVSS Vector [🧪 8.8 High ↻]`), `S6.2` (`🧪` EmojiHint row), `S13.1` (admin-only gate, 7 output formats, never raw HTML), `S13.2` (Scope x Principal matrix, `AAL2` approver tier, tamper auto-revocation), `S13.3` (Tier A / Tier B labels) | Original requirement `#14`, `#9`, `#15` | **Dependencies:** `KB-P5-13`, `KB-P3-42`

   - `kanban/web/src/features/custom-fields/CustomFieldValue.tsx` (7-format renderer)
   - `kanban/web/src/features/custom-fields/CustomFieldDefinitionEditor.tsx`

   - `kanban/web/src/routes/projects/settings/custom-fields.tsx` (route `/projects/:projectKey/settings/custom-fields`)
   - Rail mount point edit in the properties rail component delivered by `KB-P3-42` (append the section after `Labels`).
2. **Endpoints consumed (delivered by KB-P5-11 / KB-P5-12 / KB-P5-13; use the exact paths those tickets implemented and record any rename in `message-to-reality-checker.md`):**
   - `GET /api/v1/projects/{project}/custom-fields` (definitions visible to caller)
   - `GET /api/v1/issues/{issue_key}/custom-fields` (cached values + `last_latency_ms`, `tier`, `token_scope`, `credential_mode`)
   - `POST /api/v1/issues/{issue_key}/custom-fields/{field_id}/execute` (refresh)
   - `POST|PATCH /api/v1/projects/{project}/custom-fields[/{field_id}]` (admin create/edit; server returns computed `manifest_sha256`)
   - `POST /api/v1/custom-fields/{field_id}/approval-requests` and `POST /api/v1/custom-field-approvals/{approval_id}/approve`
3. **Rail display (`CustomFieldsRailSection`):**
   - Section header literal `Custom Fields (Admin-Defined 🧪)`; one row per field: label (left), value pill `[🧪 <rendered value> ↻]` (right).
   - `🧪` is rendered via `<EmojiHint emoji="🧪">` with popover content: execution tier (`Wasmtime` or `nsjail`), token scope (`PROJECT` / `WORKSPACE` / `SERVER`), principal (`INVOKING_USER` / `PROJECT_ADMIN_SP` / `SERVER_ADMIN_SP`), and last compute latency in `ms`.
   - `↻` button (`aria-label="Refresh <field label>"`) calls execute; while in flight the button is `aria-busy="true"` and disabled; double-click issues exactly 1 request (in-flight dedupe).
   - Error states map server codes to inline text without modal: `SCRIPT_TIMEOUT` -> `Timed out`, `SCRIPT_FUEL_EXHAUSTED` -> `Compute limit reached`, `APPROVAL_REVOKED` -> `Approval revoked - admin re-sign required`, `SANDBOX_UNAVAILABLE_IN_STANDALONE` -> `Tier B unavailable in standalone`, any other -> `Unavailable`. Raw server `detail` strings are never rendered.
   - When the project has `0` definitions the section is not mounted (no empty header).
4. **7-format renderer (`CustomFieldValue`), never raw HTML (S13.1):**
   - `text`: plain text, `max 280` chars then ellipsis + full text in `title`.
   - `number`: `Intl.NumberFormat` with `maximumFractionDigits` from metadata (default `2`); non-finite -> `Unavailable`.
   - `badge`: text pill, color from metadata enum mapped to design tokens only (no arbitrary hex from server).
   - `markdown_snippet`: rendered through the existing safe Markdown renderer (DOMPurify path from Phase 3); `dangerouslySetInnerHTML` with server strings is forbidden; images and raw HTML disabled; `max 2,000` chars.
   - `url`: only `https:` / `http:` schemes accepted (else rendered as plain text), anchor has `rel="noopener noreferrer nofollow"` + `target="_blank"`, link text = hostname.
   - `json_table`: `<table>` with text cells only, caps `50` rows x `10` columns, overflow footer `+N more rows`.
   - `severity_pill`: enum `low | medium | high | critical` -> token colors; unknown value -> `Unavailable`.
5. **Admin definition editor (`CustomFieldDefinitionEditor`):**
   - Route renders only when the caller's project capability set includes `ADMIN`; otherwise renders the standard 404 page (anti-enumeration parity with S3.4; no "forbidden" wording).
   - Fields: `name`, `slug` (`^[a-z0-9][a-z0-9-]{1,62}$`), `output_format` (select of the 7 formats), `output_format_metadata` (JSON textarea validated client-side against the format schema before submit; server stays authoritative), `script_source` (monospace textarea, never evaluated client-side), `target_scope` (`PROJECT` default), `credential_mode` (`INVOKING_USER` default), `egress_allowlist` (list of `/api/v1/...` GET paths).
   - After save, show server `manifest_sha256` (hex, copyable) and approval status chip (`Default (no approval needed)`, `Pending approval`, `Approved by <tier>`, `Revoked`).
   - Editing `script_source` or `output_format_metadata` on a field with an elevated approval shows a confirm dialog with literal text `Saving changes manifest_sha256 and immediately revokes the current approval.` before submit.
6. **Escalation approval UI (`EscalationApprovalPanel`):**
   - Shows the S13.2 row for the requested `(target_scope, credential_mode)` and the required approver tier (`PROJECT_ADMIN`, `WORKSPACE_ADMIN`, `SERVER_ADMIN` dual-control).
   - `PROJECT` + `PROJECT_ADMIN_SP` displays the explicit warning banner `⚠️ This field will run with Project Admin service-principal credentials for every viewer.`
   - `Approve` triggers the AAL2 step-up flow from `KB-P2-05` (WebAuthn / TOTP) when the server answers `403 AAL2_REQUIRED`; the approve request carries the displayed `manifest_sha256`; a `409 MANIFEST_MISMATCH` response renders `Definition changed since you opened it - reload to review` and disables Approve.
   - Approve button is hidden (not merely disabled) for callers whose tier is below the required approver tier.
7. **Security invariants:** zero `dangerouslySetInnerHTML` in `features/custom-fields/` (enforced by an ESLint `no-restricted-syntax` rule scoped to that folder or a unit test grep); no inline styles that violate `style-src 'self'`; all server strings rendered as React text nodes.

  2. Positive: refresh click sends exactly 1 `POST .../execute` even on double-click; new value replaces old; `aria-busy` toggles.
  3. Security: `markdown_snippet` value `<img src=x onerror=alert(1)>**b**` renders no `img` element and no `onerror` attribute; `url` value `javascript:alert(1)` renders as plain text with no anchor; `badge` metadata color `#ff0000;background:url(x)` is ignored and token color used.
  4. Security: non-admin visiting `/projects/KAN/settings/custom-fields` sees the 404 page; Approve button absent for a `PROJECT_ADMIN` when required tier is `WORKSPACE_ADMIN`.
  5. Boundary: `json_table` with `120` rows x `14` columns renders `50 x 10` + `+70 more rows`; `text` of `281` chars is truncated with ellipsis.
  6. State: `403 AAL2_REQUIRED` on approve opens step-up prompt and retries once after success; `409 MANIFEST_MISMATCH` disables Approve with the literal message; editing script on an approved field shows the revoke confirm text.
  7. Error mapping: each listed server code maps to its literal inline text; unknown code -> `Unavailable`; raw `detail` never appears in DOM.
