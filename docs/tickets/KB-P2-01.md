### User Story
As a **kanban API engineer**, I need **a single `/api/v1` router tree whose every request runs inside an RLS-bound database transaction, returns RFC 7807 problem documents, carries a validated request id, and answers unreadable objects with a timing-equalized `404`** so that **every later endpoint inherits principal binding, anti-enumeration and non-leaking errors by construction instead of by convention**.

**Requirement Traceability:** `S3.3` (`SET LOCAL` context binding under `kanban_app`), `S3.4` item 2 (indistinguishable `404`, `<= 5ms` jitter), `S2.2` item 1 (key names `MASTER_KEK`, `KB_AUTH_PEPPER`, `SESSION_HMAC_KEY`), requirement `#1` | **Dependencies:** `KB-P1-17`, `KB-P0-10`

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/api/__init__.py`, `kanban/api/v1/__init__.py` (exports `build_v1_router() -> APIRouter`)
   - `kanban/api/v1/health.py` (single `GET /api/v1/healthz` returning `{"status":"ok"}` with zero DB access, used as router smoke route)
   - `kanban/api/problems.py`
   - `kanban/api/request_id.py`
   - `kanban/api/deps.py`
   - `kanban/api/timing.py`
   - `kanban/security/__init__.py`, `kanban/security/keys.py`
   - `kanban/app.py` (modify: mount `build_v1_router()` under `/api/v1`, register problem handlers + request-id middleware)
2. **Router layout:** `kanban/api/v1/<area>.py` per resource area; each exposes `router = APIRouter(prefix="/<area>", tags=["<area>"])`. `build_v1_router()` is the only place routers are included. No route outside `/api/v1` may touch the database.
3. **RFC 7807 problem model (`kanban/api/problems.py`):**
   - `class Problem(BaseModel)`: `type: str` (`urn:kanban:problem:<code>`), `title: str`, `status: int`, `code: str` (`^[A-Z][A-Z0-9_]{2,63}$`), `detail: str | None`, `request_id: str`, `errors: list[FieldError] | None` (field path + message only, never the submitted value).
   - `class ProblemException(Exception)` with `code`, `status`, `title`, `detail`.
   - Handlers for `ProblemException`, `RequestValidationError` (`422 VALIDATION_FAILED`, values stripped from `errors`), `StarletteHTTPException`, and a catch-all `Exception` -> `500 INTERNAL_ERROR` with `detail=None`.
   - Media type `application/problem+json`. Responses never include stack traces, exception class names, SQL text, SQLSTATE, file paths, or the echoed request body. Catch-all logs the exception server-side with `request_id`.
   - Helper `not_found() -> NoReturn` raising `404 NOT_FOUND` with fixed `title="Not Found"` and `detail=None`. `403` MUST NOT be used for object reads; a code comment states this rule and cites S3.4.
4. **Request id (`kanban/api/request_id.py`):** pure ASGI middleware. Inbound `X-Request-ID` accepted only if it matches `^[A-Za-z0-9-]{8,64}$`; otherwise (absent, CR/LF, Unicode, oversize) a new `uuid4().hex` is generated. Value stored in a `contextvars.ContextVar`, echoed in the `X-Request-ID` response header and in every problem body, and injected into log records via a `logging.Filter`.
5. **Key material provider (`kanban/security/keys.py`):**
   - `class KeyMaterial` (frozen, `__repr__` returns `KeyMaterial(<redacted>)`) holding `master_kek: bytes`, `master_kek_kid: str` (default `kek-v1`), `auth_pepper: bytes`, `session_hmac_key: bytes`; each key exactly `32` bytes, else `KeyMaterialError` (fail closed at startup).
   - `load_key_material() -> KeyMaterial`: source order `KANBAN_KEYRING_FILE` (JSON object with keys `MASTER_KEK`, `KB_AUTH_PEPPER`, `SESSION_HMAC_KEY`, optional `MASTER_KEK_KID`; values base64url without padding; file must be mode `0600` or stricter and not a symlink, else refuse) then env vars `KANBAN_MASTER_KEK`, `KANBAN_AUTH_PEPPER`, `KANBAN_SESSION_HMAC_KEY` (base64url). Missing or short key -> `KeyMaterialError`; there is no default key.
   - `derive_subkey(root: bytes, purpose: str, length: int = 32) -> bytes` using HKDF-SHA256 (`cryptography.hazmat.primitives.kdf.hkdf.HKDF`, `salt=None`, `info=b"kanban/" + purpose.encode()`); `purpose` must match `^[a-z0-9][a-z0-9./-]{2,63}$`. All later HMAC uses (session cookies, CSRF, signed URLs, media proxy) MUST derive purpose-separated subkeys through this function.
6. **RLS request dependency (`kanban/api/deps.py`):**
   - `@dataclass(frozen=True) class PrincipalContext`: `principal_id: UUID`, `workspace_id: UUID`, `token_scopes: tuple[str, ...]`, `aal_level: int` (`1` or `2`), `session_id: UUID | None`.
   - `class PrincipalResolver(Protocol)`: `async def resolve(self, request: Request) -> PrincipalContext | None`. Default `DenyAllResolver` returns `None`. Resolver installed on `app.state.principal_resolver` (KB-P2-02 replaces it).
   - `async def get_principal(request) -> PrincipalContext`: `None` -> `401 AUTHENTICATION_REQUIRED` with `WWW-Authenticate` omitted. The principal is NEVER read from client-supplied headers, query, or body (no `X-Principal-Id`, no `X-Workspace-Id`).
   - `async def get_rls_session(principal = Depends(get_principal)) -> AsyncIterator[AsyncSession]`: opens a session from the KB-P1-17 factory, begins a transaction, binds context via the KB-P1-17 `SET LOCAL` binder (`app.principal_id`, `app.workspace_id`, `app.token_scopes`, `app.aal_level`), yields, commits on success, rolls back on any exception. Context is bound before the first statement; a session yielded without bound context is a bug and must raise.
7. **404 timing equalization (`kanban/api/timing.py`):**
   - `class TimingFloor`: async context manager `async with timing_floor(floor_ms: float = 25.0, clock=time.monotonic, sleep=asyncio.sleep)`; on exit (normal or exception) sleeps `max(0, floor - elapsed)`.
   - `async def load_or_404(session, stmt)`: executes a single RLS-filtered `SELECT` and calls `not_found()` when no row; non-existent and unreadable objects follow the identical code path (same query, same branch). Router code for object reads MUST use `load_or_404` wrapped in `timing_floor`.
8. **Security invariants asserted by this ticket:** (a) no request can reach a DB statement without principal context bound; (b) the response for "object exists but unreadable" is byte-identical (except `request_id`) to "object does not exist"; (c) no 5xx/4xx body discloses internals.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_problems.py`, `kanban/tests/api/test_request_id.py`, `kanban/tests/api/test_rls_dependency.py`, `kanban/tests/api/test_timing.py`, `kanban/tests/security/test_keys.py`
- **Required Test Cases:**
  1. Positive: `GET /api/v1/healthz` -> `200`, response carries generated `X-Request-ID` (32 hex chars).
  2. Positive: a test route using `get_rls_session` with a stub resolver returning a `PrincipalContext` observes `current_setting('app.principal_id', true)` equal to the stub principal inside the request (clean-DB `SAVEPOINT` harness from KB-P0-05).
  3. Security (header spoofing): request with `X-Principal-Id`, `X-Workspace-Id`, `?principal_id=` and default `DenyAllResolver` -> `401 AUTHENTICATION_REQUIRED`; DB never touched (assert session factory not called).
  4. Security (context leak): two sequential requests with different principals on the same pooled connection; second request sees only its own `app.principal_id`; after the request `current_setting('app.principal_id', true)` is empty/NULL on the returned connection.
  5. Security (error disclosure): route raising `RuntimeError("SELECT secret FROM x at /srv/app.py")` -> `500`, body `code=INTERNAL_ERROR`, body contains none of `SELECT`, `/srv/`, `RuntimeError`, `Traceback`; content type `application/problem+json`.
  6. Security (validation echo): `422` body for a field submitted as `"<script>alert(1)</script>"` does not contain the submitted string.
  7. Security (request-id log injection): inbound `X-Request-ID` values `abc\r\nX-Evil: 1`, `a` * 65, `short`, `ä-unicode-id-12` are each replaced with a generated id; a valid `req-0123456789` is echoed unchanged.
  8. Anti-enumeration: route using `load_or_404` + `timing_floor` returns identical status, headers (excluding `X-Request-ID`, `Date`) and body (excluding `request_id`) for (a) random UUID and (b) existing object hidden by RLS.
  9. Timing (deterministic): `timing_floor` with fake clock/sleep sleeps exactly `floor - elapsed` and `0` when elapsed exceeds floor; sleep also runs when the body raises.
  10. Timing (statistical, bounded): 200 alternating requests for case 8a and 8b against the real app; `abs(median(a) - median(b)) <= 5ms`.
  11. Keys: valid keyring file loads; file mode `0644` -> `KeyMaterialError`; symlinked keyring -> `KeyMaterialError`; 31-byte key -> `KeyMaterialError`; no source at all -> `KeyMaterialError`; `repr(KeyMaterial)` contains no key bytes or base64 of them.
  12. Keys: `derive_subkey(k, "session/cookie") != derive_subkey(k, "session/csrf")`; invalid purpose `"Session Cookie"` -> `ValueError`; RFC 5869 test vector 1 adapted via HKDF primitive matches.
