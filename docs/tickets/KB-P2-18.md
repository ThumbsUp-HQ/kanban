### User Story
As a **security engineer**, I need **one rate limiter interface with a PostgreSQL implementation for standalone mode and a Valkey implementation for the production stack, applied to routes by a decorator keyed on HMAC-hashed client identifiers and a spoof-resistant client IP** so that **credential stuffing, MFA brute force, setup-token guessing, and expensive-endpoint abuse are throttled identically in both deployment modes without storing raw IPs or usernames**.

**Requirement Traceability:** `S2.4` (`valkey` row: "sliding-window rate buckets"), `S2.2` (standalone uses PostgreSQL, zero Valkey), requirements `#3`, `#6` | **Dependencies:** `KB-P2-01` (problem model, `derive_subkey`), `KB-P1-18` (deployment-mode broker selection pattern: PG in standalone, Valkey in prod)

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/security/ratelimit/__init__.py`, `kanban/security/ratelimit/base.py`, `kanban/security/ratelimit/pg.py`, `kanban/security/ratelimit/valkey.py`, `kanban/security/ratelimit/decorator.py`, `kanban/security/client_ip.py`
   - `database/migrations/versions/<rev>_rate_limit_buckets.py`
2. **Interface (`base.py`):**
   ```python
   @dataclass(frozen=True)
   class RateLimitPolicy:
       name: str  # ^[a-z0-9_.]{3,48}$
       limit: int  # 1..100000
       window_seconds: int  # 1..86400
       fail_mode: Literal["closed", "open"] = "closed"


   @dataclass(frozen=True)
   class RateLimitDecision:
       allowed: bool
       remaining: int
       retry_after_seconds: int


   class RateLimiter(Protocol):
       async def hit(self, policy: RateLimitPolicy, key: bytes) -> RateLimitDecision: ...
       async def reset(self, policy: RateLimitPolicy, key: bytes) -> None: ...
   ```
   Algorithm in both backends: sliding-window counter (current fixed window count + previous window count weighted by remaining overlap), computed from a single server-side clock (PG `clock_timestamp()` or Valkey `TIME`), never the app clock.
3. **Key hashing:** callers pass raw identifiers to `make_key(policy, *parts: str) -> bytes` which returns `HMAC-SHA256(derive_subkey(session_hmac_key, "ratelimit/key"), policy.name + "\x1f" + "\x1f".join(parts))`. Raw IPs, usernames, emails, and tokens are never persisted or logged.
4. **PG backend (`pg.py`):** table `rate_limit_buckets(policy TEXT, key_hash BYTEA CHECK (octet_length(key_hash)=32), window_start TIMESTAMPTZ, count INT, PRIMARY KEY (policy, key_hash, window_start))` owned by NOLOGIN role `kb_infra_owner` (created here), `REVOKE ALL FROM PUBLIC, kanban_app`, and accessed via `SECURITY DEFINER` function `kb_infra.rate_limit_hit(p_policy text, p_key bytea, p_limit int, p_window_s int) RETURNS TABLE(allowed bool, remaining int, retry_after int)` (schema `kb_infra` created here) using `INSERT ... ON CONFLICT DO UPDATE SET count = rate_limit_buckets.count + 1` in one statement; rows older than `2 * window` deleted opportunistically (max 500 rows per call).
5. **Valkey backend (`valkey.py`):** `ValkeyRateLimiter(client: ValkeyCommands)` where `ValkeyCommands` is a `Protocol` with `async def eval(script: str, numkeys: int, *args) -> list[int]`. Single Lua script (constant `SLIDING_WINDOW_LUA`) performing `TIME`, `INCR` current window key, `PEXPIRE 2*window`, `GET` previous key, returning `[allowed, remaining, retry_after]`. Key format `kb:rl:{policy}:{hex(key_hash)}:{window_index}`. No concrete Valkey client package is added in this ticket (client dependency deferred to the ticket that wires the prod Valkey connection; recorded in `message-to-reality-checker.md`).
6. **Client IP (`client_ip.py`):** `resolve_client_ip(scope, trusted_proxies: Sequence[IPv4Network | IPv6Network]) -> str`. Uses ASGI `scope["client"][0]`; `X-Forwarded-For` honoured only when the direct peer is inside `KANBAN_TRUSTED_PROXIES` (CIDR list, default empty), walking right-to-left and returning the first address not in the trusted set. Malformed entries -> fall back to direct peer. IPv4-mapped IPv6 normalized to IPv4. IPv6 clients bucketed by `/64`.
7. **Decorator (`decorator.py`):** `rate_limited(policy: RateLimitPolicy, key_func: Callable[[Request], Sequence[str]])` FastAPI dependency factory. On deny -> `429 RATE_LIMITED` problem with `Retry-After` header. On backend exception: `fail_mode="closed"` -> `503 RATE_LIMIT_UNAVAILABLE`; `fail_mode="open"` -> allow and log `WARNING` with policy name only.
8. **Predefined policies** (constants in `__init__.py`, consumed by later tickets): `AUTH_LOGIN_ACCOUNT` (5 / 900s), `AUTH_LOGIN_IP` (20 / 900s), `AUTH_MFA_VERIFY` (5 / 300s), `SETUP_CLAIM_IP` (10 / 3600s), `MEDIA_PROXY_PRINCIPAL` (120 / 60s), `ATTACHMENT_UPLOAD_PRINCIPAL` (30 / 60s). Spec does not define these numbers; they are ticket-chosen and documented in the module docstring.
9. **Factory:** `build_rate_limiter(settings) -> RateLimiter` returns PG backend when `KANBAN_DEPLOYMENT_MODE=standalone` or no `KANBAN_VALKEY_URL`, else Valkey backend.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/security/test_ratelimit_pg.py`, `kanban/tests/security/test_ratelimit_valkey.py`, `kanban/tests/security/test_ratelimit_decorator.py`, `kanban/tests/security/test_client_ip.py`
- **Required Test Cases:**
  1. Positive (PG, clean-DB harness): policy 5/60s, 5 hits allowed with `remaining` 4..0, 6th denied with `retry_after_seconds` in `[1, 60]`.
  2. Positive (Valkey): same contract against `FakeValkey` test double that executes the script semantics in Python (test double lives in `kanban/tests/security/fakes.py`); both backends pass one shared parametrized contract test module.
  3. Security (credential stuffing): 1000 hits spread over 1000 distinct account keys from one IP -> per-IP policy denies after 20.
  4. Security (XFF spoof): untrusted peer `203.0.113.9` sends `X-Forwarded-For: 127.0.0.1` -> resolved IP `203.0.113.9`; trusted proxy `10.0.0.2` with `X-Forwarded-For: 198.51.100.7, 10.0.0.3` and trusted set `10.0.0.0/8` -> `198.51.100.7`; garbage `X-Forwarded-For: ', ,%00'` -> direct peer.
  5. Security (IPv6 rotation): 30 addresses inside one `/64` share a bucket.
  6. Security (privacy): after 10 hits with key part `alice@example.com` and IP `198.51.100.7`, `SELECT * FROM rate_limit_buckets` (as test superuser) contains neither string nor their UTF-8 bytes; caplog has neither.
  7. Boundary (window slide): with frozen server clock helper, counts from previous window weighted correctly at 25%, 50%, 99% overlap.
  8. Boundary (fail mode): backend raising `ConnectionError` -> `503 RATE_LIMIT_UNAVAILABLE` for `closed`, `200` for `open`.
  9. Decorator: deny response is `application/problem+json`, `code=RATE_LIMITED`, header `Retry-After` integer.
  10. Concurrency (`@pytest.mark.committed_db`): 50 concurrent `hit` calls on limit 10 -> exactly 10 allowed.
  11. Policy validation: `limit=0`, `window_seconds=86401`, name `Bad Name` -> `ValueError`.
