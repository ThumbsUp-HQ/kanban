### User Story
As a **security engineer operating the Multi-Card Auth Studio**, I need **every IdP client secret and LDAP bind password stored only as AES-256-GCM ciphertext under a per-card DEK wrapped by `MASTER_KEK`, with the auth tables unreachable from the general `kanban_app` role except through narrow `SECURITY DEFINER` functions** so that **a SQL injection, a database dump, or a serializer bug cannot disclose any auth secret, and a ciphertext moved between cards fails to decrypt**.

**Requirement Traceability:** `S4.1` (`auth_provider_cards` DDL, `encrypted_secret_blob`, `wrapped_dek`, `dek_kid`), `S2.2` item 1 (`MASTER_KEK`), `S2.5` (`pyca/cryptography`), requirement `#6` | **Dependencies:** `KB-P1-17`, `KB-P2-01` (uses `KeyMaterial` from `kanban/security/keys.py`)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_auth_provider_cards.py`
   - `database/models/auth.py` (`AuthProviderCard` mapped class)
   - `kanban/security/envelope.py`
   - `kanban/auth/__init__.py`, `kanban/auth/cards/__init__.py`, `kanban/auth/cards/repository.py`, `kanban/auth/cards/schemas.py`
2. **kb_auth data boundary (created here, reused by KB-P2-02, -04, -05a, -05b, -06, -07, -08, -09, -12):**
   - Migration creates `NOLOGIN NOINHERIT NOBYPASSRLS` role `kb_auth_owner` and schema `kb_auth` owned by it. `REVOKE ALL ON SCHEMA kb_auth FROM PUBLIC`; `GRANT USAGE ON SCHEMA kb_auth TO kanban_app`.
   - Auth tables live in `public` (spec naming) but are owned by `kb_auth_owner`; `REVOKE ALL ON auth_provider_cards FROM PUBLIC, kanban_app, app_rls_reader`; `ENABLE` + `FORCE ROW LEVEL SECURITY` with single policy `kb_auth_owner_all FOR ALL TO kb_auth_owner USING (true) WITH CHECK (true)`.
   - `kanban_app` reaches the table only through `SECURITY DEFINER` functions in schema `kb_auth`, each declared `SET search_path = pg_catalog, public` and owned by `kb_auth_owner`; `REVOKE EXECUTE ... FROM PUBLIC` then `GRANT EXECUTE ... TO kanban_app` per function.
   - Functions in this ticket: `kb_auth.card_list_enabled_public()` (returns only `slug, display_name, button_subtext, icon_preset, provider_kind, sort_rank` of enabled cards), `kb_auth.card_get_for_login(p_slug text)` (enabled card row incl. ciphertext columns), `kb_auth.card_admin_upsert(...)`, `kb_auth.card_admin_get(p_id uuid)`, `kb_auth.card_admin_list()`, `kb_auth.card_rewrap(p_id uuid, p_wrapped_dek bytea, p_old_kid text, p_new_kid text)`. Every `card_admin_*` and `card_rewrap` function raises `ERRCODE '42501'` unless `app_effective_principal_set()` contains a principal holding role `SERVER_ADMIN` (KB-P1-13 role bindings) AND `current_setting('app.aal_level', true) = '2'`.
3. **DDL:** exactly the `auth_provider_cards` statement from S4.1 (columns, CHECKs, defaults, `slug` regex `^[a-z0-9][a-z0-9-]{1,46}[a-z0-9]$`, `sort_rank TEXT COLLATE "C"`, `dek_kid DEFAULT 'kek-v1'`, `last_health_status DEFAULT 'UNVERIFIED'`). Add `CHECK ((encrypted_secret_blob IS NULL) = (wrapped_dek IS NULL))` and `updated_at` trigger.
4. **Envelope encryption (`kanban/security/envelope.py`), `pyca/cryptography` `AESGCM` only:**
   - `class KekProvider(Protocol)`: `def current_kid(self) -> str`, `def get(self, kid: str) -> bytes` (unknown kid -> `UnknownKekError`). `StaticKekProvider(keys: Mapping[str, bytes], current: str)` built from `KeyMaterial` (`master_kek_kid -> master_kek`). KMS adapters are out of scope.
   - Blob format (both DEK wrap and secret blob): `version(1 byte = 0x01) || nonce(12 bytes, os.urandom) || ciphertext || tag(16 bytes)`.
   - AAD binding (prevents cut-and-paste between cards and between fields): secret blob AAD = `b"kanban/card-secret/v1|" + card_id.bytes + b"|" + provider_kind.encode()`; wrapped DEK AAD = `b"kanban/card-dek/v1|" + card_id.bytes + b"|" + dek_kid.encode()`.
   - API: `seal_card_secret(card_id, provider_kind, plaintext: bytes, kek: KekProvider) -> SealedSecret(encrypted_secret_blob, wrapped_dek, dek_kid)`; `open_card_secret(card_id, provider_kind, sealed, kek) -> bytearray`; `rewrap_dek(card_id, sealed, kek, new_kid) -> SealedSecret` (re-wraps DEK only; `encrypted_secret_blob` bytes unchanged).
   - Per-card DEK: `AESGCM.generate_key(bit_length=256)`, held in a `bytearray` and overwritten with zeros in a `finally` block after use. `open_card_secret` returns `bytearray` so callers can zeroize; document "best effort in CPython" in the docstring.
   - Any `InvalidTag`, wrong version byte, truncated blob (`< 29` bytes), or unknown kid raises `EnvelopeDecryptError(code)` with codes `TAG_MISMATCH`, `BAD_VERSION`, `TRUNCATED`, `UNKNOWN_KID`; the message never contains key, nonce, or ciphertext bytes.
   - Plaintext cap: `<= 16384` bytes (`EnvelopeInputError` above it).
5. **Serializer invariant (`kanban/auth/cards/schemas.py`):** `AuthCardPublic` (fields exactly: `slug`, `display_name`, `button_subtext`, `icon_preset`, `provider_kind`) and `AuthCardAdmin` (all non-secret columns + `has_secret: bool`). Neither model declares `encrypted_secret_blob`, `wrapped_dek`, `client_secret`, `bind_password`, or `secret`. `AuthProviderCard.__repr__` omits ciphertext columns.
6. **Repository (`kanban/auth/cards/repository.py`):** thin async wrapper calling only the `kb_auth.*` functions via `text()` with bound parameters; `rewrap_all(session, kek, new_kid) -> int` iterates admin list and calls `rewrap_dek` + `kb_auth.card_rewrap`, returning count rewrapped.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/security/test_envelope.py`, `database/tests/test_auth_provider_cards.py`, `kanban/tests/auth/test_card_repository.py`
- **Required Test Cases:**
  1. Positive: seal then open round-trips `b"client-secret-\x00\xff"`; `wrapped_dek` and `encrypted_secret_blob` both start with `0x01` and differ between two seals of the same plaintext (nonce + DEK randomness).
  2. Security (GCM tag tamper): flip 1 bit in each of: version byte, nonce, ciphertext body, last tag byte, of both blobs -> each raises `EnvelopeDecryptError` with the expected code (`BAD_VERSION` or `TAG_MISMATCH`).
  3. Security (cut-and-paste): sealed blob from card A opened with card B's id -> `TAG_MISMATCH`; card A blob opened with `provider_kind="LDAP"` instead of `"OIDC"` -> `TAG_MISMATCH`; swapping `wrapped_dek` between cards -> `TAG_MISMATCH`.
  4. Security (kid downgrade): `dek_kid` changed in the row to `kek-v0` (unknown) -> `UNKNOWN_KID`; changed to another known kid -> `TAG_MISMATCH` (kid is in AAD).
  5. Boundary: truncated blob of 28 bytes -> `TRUNCATED`; plaintext of 16384 bytes seals; 16385 bytes -> `EnvelopeInputError`.
  6. Rotation: seal under `kek-v1`, `rewrap_dek` to `kek-v2`, open with provider containing both -> plaintext matches; `encrypted_secret_blob` bytes identical before and after; provider containing only `kek-v1` fails with `UNKNOWN_KID` after rewrap.
  7. DB boundary (clean-DB harness): as `kanban_app`, `SELECT * FROM auth_provider_cards` -> `permission denied` (`42501`); `SELECT encrypted_secret_blob FROM kb_auth.card_list_enabled_public()` -> undefined column error; `kb_auth.card_admin_list()` without SERVER_ADMIN context -> `42501`; with SERVER_ADMIN but `app.aal_level = '1'` -> `42501`; with SERVER_ADMIN + AAL2 -> rows returned.
  8. DB DDL: slug `-bad`, `a`, `UPPER`, 49-char slug rejected; `provider_kind='SAML'` rejected; secret blob set with NULL `wrapped_dek` rejected by CHECK; `search_path` hijack attempt (create `public.lower()` shadow as test superuser, call function) does not alter function result because function pins `search_path`.
  9. Serializer: `AuthCardPublic.model_json_schema()` and `AuthCardAdmin.model_json_schema()` property names contain none of `encrypted_secret_blob`, `wrapped_dek`, `client_secret`, `bind_password`, `secret`; `repr()` and `str()` of a loaded `AuthProviderCard` contain no ciphertext hex/base64; `json.dumps(AuthCardAdmin(...).model_dump())` contains no secret bytes.
  10. Logging: with `caplog` at `DEBUG`, a full seal/open/rewrap cycle emits no record containing the plaintext, DEK, or KEK bytes (hex or base64).
