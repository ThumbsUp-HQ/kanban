### User Story
As a **security architect**, I need **RBAC `role_bindings`, object-level `resource_acl_entries` (`ALLOW` / `DENY` capability bitmasks), `app_effective_principal_set()`, `app_principal_has_role()`, and a trigger-maintained `effective_resource_access` table implementing `(InheritedRBAC U DirectAllowACL) \ EffectiveDenyACL`** so that **PostgreSQL `FORCE RLS` evaluates nested-group inheritance and explicit-deny overrides in an $O(1)$ indexed lookup without any group-ALLOW bypassing a direct or group DENY**.

**Requirement Traceability:** `S3.2` (8 capabilities, Explicit Deny Precedence formula), `S3.3` (`effective_resource_access`, `app_effective_principal_set()`), `S3.1` (`principal_group_closure` integration), Requirement `#1` | **Dependencies:** `KB-P1-03`, `KB-P1-04`

2. **Capability Bitmask & RBAC Role Enum (`p1_13_access_control.up.sql`):**
   - Fixed capability bit positions (`INTEGER` `0..255`, matching `S3.3` `(allow_mask & 1) = 1` for `VIEW`):
     `VIEW = 1`, `COMMENT = 2`, `EDIT = 4`, `TRANSITION = 8`, `LINK = 16`, `SHARE = 32`, `ADMIN = 64`, `DELETE = 128`.
   - `capability_bit(p_name text) RETURNS integer` (`IMMUTABLE PARALLEL SAFE`): maps the 8 uppercase names above to `1, 2, 4, 8, 16, 32, 64, 128`, else raises `INVALID_CAPABILITY_NAME`.
   - `CREATE TYPE rbac_role AS ENUM ('SERVER_ADMIN', 'WORKSPACE_ADMIN', 'WORKSPACE_MEMBER', 'WORKSPACE_GUEST', 'PROJECT_ADMIN', 'MEMBER', 'VIEWER');`
   - `rbac_role_mask(p_role rbac_role) RETURNS integer` (`IMMUTABLE`): `SERVER_ADMIN -> 255`, `WORKSPACE_ADMIN -> 255`, `PROJECT_ADMIN -> 255`, `WORKSPACE_MEMBER -> 31` (`VIEW|COMMENT|EDIT|TRANSITION|LINK`), `MEMBER -> 31`, `VIEWER -> 3` (`VIEW|COMMENT`), `WORKSPACE_GUEST -> 0`.

3. **DDL (`role_bindings`, `resource_acl_entries`, `effective_resource_access`):**
   ```sql
   CREATE TABLE role_bindings (
       id            UUID PRIMARY KEY DEFAULT uuidv7(),
       workspace_id  UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       principal_id  UUID NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
       role          rbac_role NOT NULL,
       scope_type    TEXT NOT NULL CHECK (scope_type IN ('server', 'workspace', 'project')),
       project_id    UUID REFERENCES projects(id) ON DELETE CASCADE,
       created_at    TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       CHECK (
           (scope_type = 'server'    AND role = 'SERVER_ADMIN' AND project_id IS NULL) OR
           (scope_type = 'workspace' AND role IN ('WORKSPACE_ADMIN', 'WORKSPACE_MEMBER', 'WORKSPACE_GUEST') AND project_id IS NULL) OR
           (scope_type = 'project'   AND role IN ('PROJECT_ADMIN', 'MEMBER', 'VIEWER') AND project_id IS NOT NULL)
       ),
       UNIQUE NULLS NOT DISTINCT (workspace_id, principal_id, role, scope_type, project_id)
   );
   CREATE INDEX role_bindings_principal_idx ON role_bindings (principal_id, workspace_id);
   CREATE INDEX role_bindings_project_idx   ON role_bindings (project_id) WHERE project_id IS NOT NULL;

   CREATE TABLE resource_acl_entries (
       id               UUID PRIMARY KEY DEFAULT uuidv7(),
       workspace_id     UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       object_id        UUID NOT NULL REFERENCES objects(id)    ON DELETE CASCADE,
       principal_id     UUID NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
       effect           TEXT NOT NULL CHECK (effect IN ('ALLOW', 'DENY')),
       capability_mask  INTEGER NOT NULL CHECK (capability_mask BETWEEN 1 AND 255),
       created_by_id    UUID REFERENCES principals(id) ON DELETE SET NULL,
       created_at       TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       UNIQUE (object_id, principal_id, effect)
   );
   CREATE INDEX resource_acl_object_idx ON resource_acl_entries (object_id);

   CREATE TABLE effective_resource_access (
       object_id       UUID    NOT NULL REFERENCES objects(id)    ON DELETE CASCADE,
       principal_id    UUID    NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
       workspace_id    UUID    NOT NULL,
       allow_mask      INTEGER NOT NULL CHECK (allow_mask BETWEEN 0 AND 255),
       deny_mask       INTEGER NOT NULL CHECK (deny_mask  BETWEEN 0 AND 255),
       effective_mask  INTEGER GENERATED ALWAYS AS (allow_mask & (~deny_mask)) STORED,
       PRIMARY KEY (object_id, principal_id)
   );
   CREATE INDEX era_principal_obj_idx ON effective_resource_access (principal_id, object_id);
   REVOKE INSERT, UPDATE, DELETE ON effective_resource_access FROM kanban_app, app_rls_reader;
   ```

4. **Session Helpers (`GRANT EXECUTE TO kanban_app, app_rls_reader`):**
   - `app_effective_principal_set() RETURNS uuid[]` (`STABLE PARALLEL SAFE SECURITY DEFINER`, `SET search_path = pg_catalog, public`): reads `v_p := app_current_principal_id()`; if `v_p IS NULL` or `principals.status <> 'ACTIVE'` (or `workspace_id <> app_current_workspace_id()`), returns `'{}'::uuid[]`; otherwise returns `ARRAY[v_p]` concatenated with all `pgc.ancestor_group_id` from `principal_group_closure pgc JOIN principals gp ON gp.id = pgc.ancestor_group_id` where `pgc.member_id = v_p AND gp.status = 'ACTIVE'`.
   - `app_principal_has_role(p_project_id uuid, p_roles text[]) RETURNS boolean` (`STABLE SECURITY DEFINER`, `SET search_path = pg_catalog, public`): returns `TRUE` iff `role_bindings` contains a row with `principal_id = ANY (app_effective_principal_set())`, `role::text = ANY (p_roles)`, `workspace_id = app_current_workspace_id()`, and scope matching (`scope_type = 'server'`, OR `scope_type = 'workspace'`, OR `scope_type = 'project' AND project_id = p_project_id AND p_project_id IS NOT NULL`). Consumed directly by KB-P1-07, KB-P1-16, KB-P2-03, and KB-P5-16.

5. **Materialization Engine (`rebuild_effective_access_for_workspace(p_workspace_id uuid)` & `rebuild_effective_access_for_object(p_object_id uuid)`, `SECURITY DEFINER`):**
   - Serializes per workspace via `pg_advisory_xact_lock(hashtextextended('era:' || p_workspace_id::text, 0))`.
   - Computes rows **only for `ACTIVE` non-group concrete principals** (`principal_type IN ('USER', 'AGENT', 'SERVICE_PRINCIPAL', 'SCRIPT_EPHEMERAL')`) by expanding each principal `p` to `Q(p) = {p} U {active ancestor groups of p in principal_group_closure}`:
     - **CRITICAL DENY INVARIANT:** Because all group `ALLOW`s and all group/direct `DENY`s for `p` are folded via `bit_or` into `p`'s single `(object_id, p)` row (`allow_mask`, `deny_mask`), the S3.3 predicate `era.principal_id = ANY (app_effective_principal_set()) AND (era.allow_mask & 1) = 1 AND (era.deny_mask & 1) = 0` matches ONLY `era.principal_id = p` and can NEVER let a group `ALLOW` bypass a direct or sibling-group `DENY`.
     - **Scope Inheritance Rules:**
       1. `SERVER_ADMIN` / `WORKSPACE_ADMIN` in `Q(p)` -> `InheritedRBAC = 255` on all objects in `p_workspace_id`.
       2. `AGENT` / `SERVICE_PRINCIPAL` without admin role -> `InheritedRBAC = 0` unless explicitly bound on the project (`role_bindings`) or granted via `resource_acl_entries` (S3.2 autonomous agent rule: never inherits broad `WORKSPACE_MEMBER` access implicitly).
       3. Project-scoped objects (`objects.project_id IS NOT NULL`, or `objects.object_type = 'project'` where target project is `objects.id`): inherits `bit_or(rbac_role_mask(role))` from project `role_bindings` on that project plus `WORKSPACE_MEMBER` bindings, **except** if a `resource_acl_entries` `DENY` exists on the parent `project` object for `Q(p)`, that project-level `DENY` also propagates into `deny_mask` of child objects in that project!
       4. Workspace-scoped objects (`objects.project_id IS NULL` and `object_type <> 'project'`): `user` objects inherit `VIEW (1)` for active `WORKSPACE_MEMBER`s; workspace `doc`/`page`/`sticky`/`view` objects inherit `WORKSPACE_MEMBER` (`31`) unless private (`views.visibility = 'private'` when `views` table exists -> only `owner_principal_id` gets `255` and admins get `255`).
       5. Direct `resource_acl_entries` on `object_id` for `q IN Q(p)` fold `capability_mask` into `allow_mask` (`effect = 'ALLOW'`) and `deny_mask` (`effect = 'DENY'`). Rows where `allow_mask = 0 AND deny_mask = 0` are omitted.
   - Triggers: workspace/principal/edge/role/ACL/object changes (`objects` INSERT/UPDATE of `project_id`/DELETE, `principals` UPDATE of `status`, `principal_group_edges` AFTER I/U/D, `role_bindings` AFTER I/U/D, `resource_acl_entries` AFTER I/U/D, and `views` visibility/owner changes if `views` exists) automatically refresh `effective_resource_access` in the same transaction; guards validate same-workspace FKs (`ACL_WORKSPACE_MISMATCH`, `ROLE_BINDING_WORKSPACE_MISMATCH`).

6. **Down Migration:** Drops triggers, materialization & helper functions, `effective_resource_access`, `resource_acl_entries`, `role_bindings`, `rbac_role_mask`, `rbac_role`, `capability_bit`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_13_access_control.py`, `database/tests/migrations/test_p1_13_migration.py`
- **Required Test Cases:**
  1. Positive (RBAC + nested groups): user `U` in `G1 -> G2 -> G3`; `G3` bound as `MEMBER` (`31`) on project `KAN`; creating issue `KAN-1` populates `effective_resource_access(KAN-1, U)` with `allow_mask = 31, deny_mask = 0, effective_mask = 31`; `app_effective_principal_set()` under `U` returns `{U, G1, G2, G3}`.
  2. Security (Explicit Deny Precedence across group vs direct & sibling groups): with `G1` holding `ALLOW VIEW|EDIT` (`5`) on `KAN-1`, adding `DENY EDIT` (`4`) directly on `U` (or on sibling group `G_contractors` containing `U`) updates `(KAN-1, U)` to `allow_mask = 31, deny_mask = 4, effective_mask = 27`; adding `DENY VIEW` (`1`) makes `(allow_mask & 1) = 1 AND (deny_mask & 1) = 0` evaluate to `FALSE` via the exact S3.3 `ANY (app_effective_principal_set())` query, and zero group rows exist in `effective_resource_access`.
  3. Security (Project-level DENY inheritance & principal disable): `DENY VIEW` for `G_contractors` on project `KAN` sets `(deny_mask & 1) = 1` on `KAN` AND on child issues inside `KAN`; setting `principals.status = 'DISABLED'` on `U` removes `U`'s effective access and causes `app_effective_principal_set()` to return `'{}'`.
  4. Security (Agent non-inheritance & `app_principal_has_role`): an `AGENT` principal in the workspace with no explicit project binding/ACL has `0` rows in `effective_resource_access` for `KAN-1`; `app_principal_has_role(kan_id, ARRAY['PROJECT_ADMIN','SERVER_ADMIN'])` returns `TRUE` for `PROJECT_ADMIN` on `KAN` and `SERVER_ADMIN` (direct or via group), and `FALSE` for `WORKSPACE_ADMIN`, `MEMBER`, or `PROJECT_ADMIN` of another project.
  5. Negative/security: cross-workspace `role_bindings` or `resource_acl_entries` raise `ROLE_BINDING_WORKSPACE_MISMATCH` / `ACL_WORKSPACE_MISMATCH`; invalid `(scope_type='project', role='SERVER_ADMIN')` or `capability_mask = 0` / `256` raises `23514`; as `kanban_app`, direct `INSERT INTO effective_resource_access` raises `42501`.
  6. Dynamic reactivity: deleting edge `G1 -> G2` immediately drops `U`'s inherited access on `KAN-1` in the same statement.
  7. Migration up/down: `MigrationHarness` upgrade `p1_13_access_control` -> 3 tables, `rbac_role`, and helper functions exist; downgrade to `previous_of(...)` -> absent; re-upgrade succeeds.
  - All non-migration tests run under the KB-P0-05 clean-DB `SAVEPOINT` harness; touched-module coverage `>= 95%`.
