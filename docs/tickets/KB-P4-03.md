### User Story
As an **LLM agent with a finite context window**, I need **every MCP parameter to accept human keys (`KAN`, `KAN-142`, `In Progress`, `@adam`, `Cycle 4`) or UUIDs interchangeably, and every response rendered as null-stripped inline YAML at a selectable level of detail** so that **I never spend tool calls on UUID lookups and responses cost `~78-89%` fewer tokens than raw REST JSON.**

**Requirement Traceability:** `S11.1` pillars 1-3 (`EntityResolver`, `action="help"` progressive disclosure, `InlineSafeDumper` + LOD tiers), `S1.1` item 3, requirement `#12` | **Dependencies:** `KB-P4-01`, `KB-P0-12` (provides `PyYAML` in `uv.lock` via the cassette loader; this ticket adds no new dependency)

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/api/v1/resolve.py` - `GET /api/v1/resolve?kind=<kind>&ref=<ref>&project=<project-ref>` (RLS session from KB-P2-01).
   - `kanban/resolve/service.py` - `ResolutionService` with per-kind resolvers and a provider registry.
   - `mcp/resolver.py` - `EntityResolver` (client side, request-scoped memo cache).
   - `mcp/yaml_out.py` - `InlineSafeDumper`, `dump_yaml()`, `strip_empty()`.
   - `mcp/lod.py` - `Lod` enum + per-entity field projections.
   - `mcp/help.py` - `build_help()`.
   - `mcp/bench/token_benchmark.py` + `mcp/tests/fixtures/issues_raw_rest.json` (20 issues, full REST payload incl. nulls).
2. **Resolution rules (`ResolutionService`):** kinds `project`, `issue`, `state`, `user`, `cycle`, `module`, `label`, `hook`.
   - UUID (RFC 4122 regex) -> direct RLS lookup; any kind.
   - `project`: identifier regex `^[A-Z][A-Z0-9]{1,9}$` (from `projects.identifier` CHECK, S12.2) or exact case-insensitive `name`.
   - `issue`: `^([A-Z][A-Z0-9]{1,9})-([0-9]{1,18})$` -> `(projects.identifier, issues.sequence_id)`.
   - `user`: `@handle` (case-insensitive) or exact email only when caller shares a workspace; `me` resolves to the caller.
   - `state`, `cycle`, `module`, `label`: case-insensitive exact name within the required `project` context; missing project context -> `VALIDATION_FAILED` with hint `"pass project=<KEY>"`. `module` when `projects.modules_enabled = false` -> `MODULES_DISABLED`.
   - `hook`: resolver slot is registered through `ResolutionService.register_provider("hook", provider)`; this ticket ships the provider interface and a test stub only (real `workflow_transition_hooks` backend wired by KB-P5-17).
   - Zero matches or unreadable rows -> `404` (indistinguishable, timing-equalized helper from KB-P2-01). More than one match -> `409` with up to `5` candidates `{key, title}` -> MCP `AMBIGUOUS_IDENTIFIER` listing candidates.
   - Input caps: `ref` `<= 200` chars, control characters rejected (`422`).
3. **Client resolver (`mcp/resolver.py`):** `await resolver.resolve(kind, ref, project=None) -> ResolvedRef(id, kind, key, title)`; memoizes per tool call (never across sessions, so ACL changes apply immediately). Batch helper `resolve_many()` dedupes identical refs.
4. **YAML output (`mcp/yaml_out.py`):** `InlineSafeDumper(yaml.SafeDumper)`:
   - `strip_empty()` recursively removes `None`, `[]`, `{}`, `""` (keeps `0` and `False`).
   - Lists of scalars and dicts with `<= 4` scalar values render in flow style (`labels: [security, auth]`); multi-line strings render as literal block `|`; keys keep insertion order (`sort_keys=False`); `allow_unicode=True`; width `120`.
   - Never emits Python tags (`!!python/...`); dumping a non-primitive type raises `TypeError`.
   - Markdown fields are emitted verbatim (no HTML conversion).
5. **LOD tiers (`mcp/lod.py`):** `Lod = summary | standard | full`. Projection tables for `issue`, `doc`, `sticky`, `project`. Issue projection (used by KB-P4-04+):
   - `summary`: `key`, `summary`, `state`, `priority`, `assignees` (handles), `gate` (only when pending).
   - `standard`: summary + `description_markdown`, `labels`, `cycle`, `modules`, `parent`, `start_date`, `due_date`, `links` (`[type, key]`), `etag`, `access` (pill string e.g. `"Project + 2"`).
   - `full`: standard + `access_manifest`, `custom_fields`, `comments` (latest 50), `activity` (latest 50), `gate_verdicts`, `provenance` (`created_by`, `original_created_by`, `creator_modified_by`).
   - Unknown `lod` value -> `VALIDATION_FAILED`.
6. **JIT help (`mcp/help.py`):** any tool receiving `identifier="help"` or `action="help"` returns, instead of executing, live project data from kanban-api: valid `states` (name + group), `priorities`, `labels` (with `exclusive_group`), `cycles` (name + status), `modules` (omitted when disabled), `custom_fields` (empty until Phase 5), `agents` (empty until Phase 5), plus the tool's own parameter summary. Sample:
   ```yaml
   tool: update_ticket
   project: KAN
   states: [Backlog, Todo, In Progress, In Review, Done, Cancelled]
   priorities: [urgent, high, medium, low, none]
   labels: [security, auth, qa-needs-work]
   cycles: [{name: Cycle 4, status: active}]
   params: {identifier: "KAN-142 | uuid", description_mode: "append | replace"}
   ```
7. **Error codes appended to `McpErrorCode`:** `MODULES_DISABLED`.
8. **Token benchmark (`mcp/bench/token_benchmark.py`):** deterministic approximate tokenizer `len(re.findall(r"\w+|[^\w\s]", text))`; compares `json.dumps(raw)` of the 20-issue fixture against `dump_yaml(project(issues, Lod.summary))`; prints both counts and the reduction percentage; exit code `1` if reduction `< 78%`.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_resolve.py` (clean-DB harness), `mcp/tests/test_resolver.py`, `mcp/tests/test_yaml_out.py`, `mcp/tests/test_lod_help.py`, `mcp/tests/test_token_benchmark.py`
- **Required Test Cases:**
  1. Positive: `KAN`, `KAN-142`, `In Progress` (project KAN), `@adam`, `Cycle 4`, label `security`, and a UUID each resolve to the expected id; `me` resolves to caller.
  2. Security: an issue in a project the caller cannot VIEW returns `404` identical in body to a non-existent key; `@handle` of a user in another workspace returns `404`; `ref` containing `\x00` -> `422`.
  3. Ambiguity/boundary: two labels named `Bug` and `bug` in one project -> `AMBIGUOUS_IDENTIFIER` with 2 candidates; 7 matches -> exactly 5 candidates returned; `ref` of 201 chars -> `422`; `module` on a project with `modules_enabled=false` -> `MODULES_DISABLED`; `state` without project -> `VALIDATION_FAILED`.
  4. YAML: nested `None`/`[]`/`{}`/`""` removed at every depth while `0` and `False` survive; `["a","b"]` renders flow style; multi-line Markdown renders as `|` block and round-trips byte-identical through `yaml.safe_load`; dumping a `set` raises `TypeError`; output contains no `!!python`.
  5. LOD: issue at `summary` has exactly the summary keys (minus empties); `full` includes `access_manifest`; `lod="huge"` -> `VALIDATION_FAILED`; `help` for a project with modules disabled omits `modules`.
  6. Benchmark: `test_token_benchmark.py` asserts reduction `>= 78%` on the fixture.
