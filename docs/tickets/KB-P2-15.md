### User Story
As a **project collaborator pasting or uploading diagrams and screenshots**, I need **`/api/v1/projects/{id}/attachments` to verify magic bytes, enforce `<= 25 MiB` and `MAX_IMAGE_PIXELS = 40,000,000` decompression-bomb guards, re-encode raster images stripping all EXIF/XMP/IPTC metadata, scrub `.svg` uploads via the SVG sanitizer, and serve blobs only through `300s` RLS-checked signed URLs with `.svg` sandbox + `Content-Disposition: attachment` headers** so that **extension spoofing, pixel bombs, GPS metadata leaks, unauthorized blob reads, and direct-navigation SVG XSS are blocked**.

**Requirement Traceability:** `S5.4` rows 1 & 3 (magic-byte sniff, `MAX_IMAGE_PIXELS = 40,000,000`, `<= 25 MB`, re-encode/strip EXIF/XMP/IPTC, `TTL = 300s` RLS-checked signed URLs, `X-Content-Type-Options: nosniff`, `.svg` `Content-Security-Policy: default-src 'none'; sandbox` + `Content-Disposition: attachment` when `Sec-Fetch-Dest != "image"`), `S5.2` item 1 (`attachment://att_...`), `S3.5` row "Hostile Media", requirement `#10` | **Dependencies:** `KB-P2-14` (`sanitize_svg`), `KB-P2-11` (`Capability`, `require_capability`), `KB-P2-18` (`ATTACHMENT_UPLOAD_PRINCIPAL` rate limiter)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_attachments.py`, `database/models/attachments.py` (`Attachment`)
   - `kanban/attachments/__init__.py`, `kanban/attachments/sniff.py`, `kanban/attachments/raster.py`, `kanban/attachments/storage.py`, `kanban/attachments/signing.py`, `kanban/attachments/service.py`
   - `kanban/api/v1/attachments.py` (`POST /api/v1/projects/{project_ref}/attachments`, `POST /api/v1/attachments/{attachment_id}/signed-url`, `GET /api/v1/attachments/{attachment_id}/content`)
   - `kanban/pyproject.toml` (add pinned `pillow`, `MIT-CMU`)
2. **DDL `attachments` & Content-Addressed Storage (`storage.py`):**
   - Table `attachments` (`ENABLE` + `FORCE ROW LEVEL SECURITY` using `effective_resource_access` on `COALESCE(issue_id, project_id)`):
     ```sql
     CREATE TABLE attachments (
       id                 UUID PRIMARY KEY DEFAULT uuidv7(),
       workspace_id       UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       project_id         UUID NOT NULL REFERENCES projects(id) ON DELETE RESTRICT,
       issue_id           UUID REFERENCES issues(id) ON DELETE SET NULL,
       uploaded_by_id     UUID NOT NULL REFERENCES principals(id) ON DELETE RESTRICT,
       original_filename  TEXT NOT NULL CHECK (char_length(btrim(original_filename)) BETWEEN 1 AND 255),
       content_type       TEXT NOT NULL CHECK (content_type IN (
                            'image/png','image/jpeg','image/webp','image/avif','image/gif','image/svg+xml')),
       byte_size          INTEGER NOT NULL CHECK (byte_size BETWEEN 1 AND 26214400),
       pixel_width        INTEGER CHECK (pixel_width IS NULL OR pixel_width > 0),
       pixel_height       INTEGER CHECK (pixel_height IS NULL OR pixel_height > 0),
       blob_sha256        BYTEA NOT NULL CHECK (octet_length(blob_sha256) = 32),
       storage_key        TEXT NOT NULL CHECK (storage_key ~ '^sha256/[0-9a-f]{2}/[0-9a-f]{2}/[0-9a-f]{64}$'),
       created_at         TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
     );
     ```
   - `LocalFilesystemBlobStore(root_dir: Path)`: writes sanitized output bytes atomically (`O_CREAT | O_EXCL | O_NOFOLLOW`, mode `0600`) to `{root_dir}/sha256/{h[:2]}/{h[2:4]}/{h}` where `h = sha256(clean_bytes).hexdigest()`. User-supplied `original_filename` NEVER touches filesystem paths; `KB-P3-08` (`include_attachments` copy) can clone metadata rows referencing the same immutable `storage_key`.
3. **Streaming Cap & Magic-Byte Sniffer (`sniff.py`):**
   - Stream upload chunks enforcing `MAX_ATTACHMENT_BYTES = 26_214_400` (`25 MiB`); abort immediately on byte `26,214,401` with `413 PAYLOAD_TOO_LARGE` (`0` bytes written to blob store).
   - `sniff_media_type(header_bytes: bytes, declared_content_type: str | None, filename: str) -> str`:
     - Inspects raw leading bytes: PNG (`\x89PNG\r\n\x1a\n` -> `image/png`), JPEG (`\xff\xd8\xff` -> `image/jpeg`), GIF (`GIF87a` / `GIF89a` -> `image/gif`), WebP (`RIFF` + bytes `8..12 == b"WEBP"` -> `image/webp`), AVIF (ISO-BMFF `ftyp` box with major/compatible brand `avif` or `avis` -> `image/avif`), SVG (UTF-8 starting after optional BOM/whitespace with `<svg` or `<?xml`...`<svg` AND extension `.svg` or declared `image/svg+xml`).
     - Rejects (`415 UNSUPPORTED_MEDIA_TYPE`, code `MIME_MISMATCH_OR_UNSUPPORTED`) when: magic bytes are unknown (e.g. PDF, ZIP, ELF, HTML `<!DOCTYPE html>`) OR declared extension / `Content-Type` conflicts with magic bytes (e.g. `.svg` containing PNG bytes, `.png` containing `<svg>` or `<script>`, or GIFAR polyglot).
4. **Decompression-Bomb Guard & EXIF/XMP/IPTC Strip (`raster.py`):**
   - Runs in worker thread via `anyio.to_thread.run_sync` behind `asyncio.Semaphore(4)`.
   - Sets `PIL.Image.MAX_IMAGE_PIXELS = 40_000_000`. Opens image header first: rejects if `width * height > 40_000_000`, `width > 16_384`, or `height > 16_384` (`422 IMAGE_DIMENSIONS_EXCEEDED`, catching `Image.DecompressionBombError` / `DecompressionBombWarning` treated as error). For animated `GIF`/`WebP`/`AVIF`, caps `n_frames <= 200` and `sum(frame_w * frame_h) <= 80_000_000`.
   - Re-encodes pixel matrix into a brand-new `Image` buffer in the detected format with empty `info={}` / `exif=b""`, stripping 100% of EXIF (GPS lat/lon, camera serial, MakerNote), XMP, IPTC, PNG text chunks (`tEXt`, `zTXt`, `iTXt`, `eXIf`), JPEG `APP1`/`APP13`/`COM` segments, and trailing appended polyglot bytes; rejects re-encoded output if `> 26,214,400` bytes.
   - For `image/svg+xml`: passes raw bytes through `sanitize_svg` (`KB-P2-14`, mapping `SvgSanitizeError` -> `422 SVG_UNSAFE`).
5. **Upload, RLS Signed URLs (`TTL = 300s`) & `.svg` Serving Shield (`signing.py`, `attachments.py`):**
   - `POST /api/v1/projects/{project_ref}/attachments`: requires CSRF + `ATTACHMENT_UPLOAD_PRINCIPAL` (`30 / 60s`) + `Capability.COMMENT` or `Capability.EDIT` on project (`KB-P2-11` `require_capability`: `404` if no `VIEW`, `403 INSUFFICIENT_CAPABILITY` if `VIEW`-only). Returns `201 {"id", "markdown_uri": f"attachment://att_{id}", "content_type", "byte_size", "pixel_width", "pixel_height", "signed_url", "expires_in": 300}` and appends `ATTACHMENT_UPLOADED` activity.
   - `POST /api/v1/attachments/{attachment_id}/signed-url` (and batch/single lookup): inside `timing_floor(25.0)` + `get_rls_session`, verifies `Capability.VIEW` on the attachment's owning issue/project (`404 NOT_FOUND` if unreadable or absent) and mints `/api/v1/attachments/{attachment_id}/content?exp={now+300}&p={principal_id}&sig={b64url_hmac}` using `derive_subkey(session_hmac_key, "attachment/signed-url")` over `f"v1|{attachment_id}|{principal_id}|{exp}"`.
   - `GET /api/v1/attachments/{attachment_id}/content?exp=...&p=...&sig=...`:
     1. Rejects expired `exp < now` or invalid `hmac.compare_digest` signature (`403 INVALID_SIGNED_URL`) BEFORE any DB or disk access.
     2. Requires active authenticated principal matching `p` AND re-verifies `Capability.VIEW` under `get_rls_session` (`404` via `timing_floor` if ACL was revoked after URL minting).
     3. Emits on ALL attachments: `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: private, max-age=300`.
     4. **`.svg` Direct-URL Navigation Shield (`S5.4` line 398):** when `content_type == "image/svg+xml"`, ALWAYS sets `Content-Security-Policy: default-src 'none'; sandbox`, AND inspects request header `Sec-Fetch-Dest`: if `Sec-Fetch-Dest` (lowercased) `== "image"`, sets `Content-Disposition: inline; filename="<ascii_safe>.svg"`; for EVERY other value or missing header (`document`, `iframe`, `object`, `empty`, absent), sets `Content-Disposition: attachment; filename="<ascii_safe>.svg"`.
6. **Security invariants asserted:** (a) zero raw unsanitized upload bytes ever touch disk; (b) zero EXIF/XMP/IPTC/comment metadata or trailing polyglot bytes survive raster re-encoding; (c) signed URLs expire in `300s`, are bound to `(attachment_id, principal_id)`, and re-check live RLS; (d) direct browser tab navigation to `.svg` forces download inside a `default-src 'none'; sandbox` CSP.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/attachments/test_sniff_and_raster.py`, `kanban/tests/attachments/test_attachments_api.py`
- **Required Test Cases:**
  1. Positive raster round-trip (`PNG`, `JPEG`, `WebP`, `GIF`, `AVIF`): upload JPEG carrying EXIF GPS coordinates (`GPSLatitude`, `CameraSerialNumber`), XMP packet, and trailing `<?php` bytes -> `201` with `attachment://att_...` URI; downloaded bytes decode as valid JPEG with `0` EXIF/XMP/comment segments and `0` trailing bytes.
  2. Positive `.svg` upload & `Sec-Fetch-Dest` shield: upload SVG containing valid `<rect>` + `<script>alert(1)</script>` -> `<script>` stripped; `GET .../content` with `Sec-Fetch-Dest: image` returns `Content-Security-Policy: default-src 'none'; sandbox`, `X-Content-Type-Options: nosniff`, and `Content-Disposition: inline; ...`; `GET .../content` with `Sec-Fetch-Dest: document` or no `Sec-Fetch-Dest` header returns `Content-Disposition: attachment; ...` and the same sandbox CSP.
  3. Security (magic-byte spoofing): HTML file named `diagram.svg` with `Content-Type: image/svg+xml`, PNG bytes named `icon.svg`, and `<script>alert(1)</script>` named `photo.png` all fail with `415 MIME_MISMATCH_OR_UNSUPPORTED`.
  4. Security (decompression bomb): synthetic PNG header claiming `10000 x 5000` (`50,000,000 > 40,000,000` pixels, compressed to a few KB) rejected with `422 IMAGE_DIMENSIONS_EXCEEDED` without allocating full raw bitmap; `6000 x 6000` (`36MP`) header check logic verified; animated GIF with `201` frames rejected.
  5. Boundary (`25 MiB` streaming cap): `26,214,400`-byte stream limit vs `26,214,401`-byte upload -> `413 PAYLOAD_TOO_LARGE` and zero blob files created on disk.
  6. Security (path traversal filename): `original_filename="../../etc/passwd\x00.png"` -> stored purely under `sha256/xx/yy/<hex>` on disk, sanitized filename in `Content-Disposition` contains no `/`, `\`, `..`, or control chars.
  7. Security (signed URL tamper, expiry, cross-user & live ACL revocation): tampered `sig` or `exp = now - 1` -> `403` without DB hit; URL minted for user `U1` replayed with user `U2`'s session -> `403`; URL minted for `U1` at `t=0`, `U1` granted `DENY VIEW` at `t=10`, `U1` fetches at `t=20` (`< 300s`) -> `404 NOT_FOUND`.
  8. Anti-enumeration & rate limit: minting signed URL for non-existent UUID vs existing attachment in unreadable project `SEC` returns identical `404 NOT_FOUND`; 31st upload within 60s -> `429 RATE_LIMITED`.
