### User Story
As an **execution or QA sub-agent**, I need **`search_tickets` to find tickets by text and structured filters in one call and `read_ticket` to load a ticket's canonical Markdown, sharing manifest, links, comments, and activity at a chosen LOD** so that **I can gather full ticket context in two calls without seeing anything the delegating human cannot see.**

**Requirement Traceability:** `S11.2` items 1-2, `S3.4` (`access_manifest`, indistinguishable 404), `S3.2` (OBO intersection), requirement `#12` | **Dependencies:** `KB-P4-03`, `KB-P4-02a`, `KB-P3-17` (search API), `KB-P3-11` (filter DSL), `KB-P3-05`, `KB-P3-07`, `KB-P3-13`, `KB-P2-11`

### Scoped Technical Actions
1. **Target Files:** `mcp/surfaces/agent/__init__.py` (agent registry builder; removes the `ping_agent` placeholder from KB-P4-01), `mcp/surfaces/agent/search_tickets.py`, `mcp/surfaces/agent/read_ticket.py`, `mcp/auth.py` (add `SCOPE_REQUIREMENTS` entries: both tools -> `agent:read`).
2. **`search_tickets` input schema (JSON Schema, `additionalProperties: false`):**
   ```yaml
   query: {type: string, maxLength: 500}          # optional lexical text
   project: {type: string}                         # key or uuid; optional
   states: {type: array, items: string, maxItems: 20}
   assignees: {type: array, items: string, maxItems: 20}   # "@handle" | "me" | uuid
   cycle: {type: string}
   modules: {type: array, items: string, maxItems: 20}
   labels: {type: array, items: string, maxItems: 20}
   blocked: {type: boolean}                        # true = has open inbound BLOCKS
   gate_status: {enum: [pending, approved, rejected]}
   mode: {enum: [lexical, hybrid], default: lexical}
   lod: {enum: [summary, standard], default: summary}
   limit: {type: integer, minimum: 1, maximum: 50, default: 20}
   cursor: {type: string, maxLength: 200}
   ```
   - All refs go through `EntityResolver`. Text query -> KB-P3-17 search API; structured filters -> KB-P3-11 filter DSL; when both present the filter DSL is applied server-side to the search result set (single kanban-api call `POST /api/v1/search/issues` with `filters`; add that composition in `kanban/api/v1/search.py` if KB-P3-17 lacks it, `<= 60` LOC).
   - `mode: hybrid` is accepted but executes lexical until Phase 5 embeddings exist; response includes `mode: lexical` so the agent sees what ran.
   - `gate_status` filters on `issues.pending_transition_exec_id IS NOT NULL` for `pending`; `approved`/`rejected` return an empty result with `note: gate history available in Phase 5` (no error).
   - Response at `summary` LOD:
   ```yaml
   mode: lexical
   total: 2
   items:
     - {key: KAN-142, summary: Harden Multi-Card OIDC & LDAPS Auth Studio, state: In Progress, priority: urgent, assignees: ["@adam"]}
     - {key: KAN-150, summary: LDAPS StartTLS bind verification, state: Todo, priority: high}
   next_cursor: eyJvIjoyMH0
   ```
3. **`read_ticket` input schema:**
   ```yaml
   identifier: {type: string}                      # required; "KAN-142" | uuid | "help"
   lod: {enum: [summary, standard, full], default: standard}
   comments_limit: {type: integer, minimum: 0, maximum: 50, default: 20}
   ```
   - Loads issue (KB-P3-02), `access_manifest` (KB-P2-11, redaction preserved verbatim), links (KB-P3-07, unreadable targets stay masked), comments (KB-P3-05), activity (KB-P3-13). Custom field values and gate verdicts are omitted (empty -> stripped) until Phase 5.
   - Response at `summary` LOD:
   ```yaml
   key: KAN-142
   summary: Harden Multi-Card OIDC & LDAPS Auth Studio
   state: In Progress
   priority: urgent
   assignees: ["@adam"]
   ```
   - At `standard`/`full`, `description_markdown` is emitted verbatim as a YAML literal block; `etag` = hex `description_sha256`.
4. **Errors:** `NOT_FOUND` (missing or unreadable - identical text `"ticket not found"`), `AMBIGUOUS_IDENTIFIER`, `VALIDATION_FAILED` (schema violation, `limit` 51, unknown filter key), `INSUFFICIENT_SCOPE`, `UPSTREAM_UNAVAILABLE`.
5. **Security invariants:** every kanban-api call carries `X-KB-Subject-Token` so RLS evaluates `User ∩ AgentGrant ∩ TokenScope`; no result count or cursor leaks rows hidden by RLS (`total` is computed under RLS).

### Mandatory Feature Unit Tests
- **Test File(s):** `mcp/tests/agent/test_search_tickets.py`, `mcp/tests/agent/test_read_ticket.py` (in-process kanban app via `httpx.ASGITransport` on the clean-DB `SAVEPOINT` harness with a fixture of 3 projects / 30 issues, one project restricted)
- **Required Test Cases:**
  1. Positive: `search_tickets(query="OIDC", project="KAN", states=["In Progress"], assignees=["me"])` returns exactly the fixture-expected keys in rank order at `summary`; `read_ticket("KAN-142", lod="full")` contains `description_markdown`, `access_manifest`, `links`, `comments`, `activity`.
  2. RLS/security: caller without access to project `SEC` gets `NOT_FOUND` for `read_ticket("SEC-1")` with body byte-identical to `read_ticket("KAN-99999")`; `search_tickets(query="secret")` returns `total` excluding `SEC` issues; an agent key whose principal has no `AgentGrant` on `KAN` sees `total: 0` even though the human user can see `KAN`.
  3. Boundary: `limit=51` -> `VALIDATION_FAILED`; `limit=50` with 30 matches returns 30 and no `next_cursor`; cursor pagination over 30 items at `limit=20` returns 20 then 10; `query` of 501 chars -> `VALIDATION_FAILED`; unknown key `foo` -> `VALIDATION_FAILED`.
  4. LOD: `summary` output contains no `description_markdown`; `mode="hybrid"` returns `mode: lexical`; `gate_status="pending"` returns only issues with non-null `pending_transition_exec_id`.
  5. Help: `read_ticket(identifier="help")` returns the KB-P4-03 help block for tool `read_ticket`.
