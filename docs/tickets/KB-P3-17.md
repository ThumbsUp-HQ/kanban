### User Story
As a **user pressing `Cmd+K` or an MCP agent calling `search_tickets` / `search_knowledge`**, I need **ranked lexical full-text (`tsvector`) + trigram (`pg_trgm`) search across issues, docs, pages, and stickies with heading-anchored Markdown snippets and structured `FilterSpec` composition under `FORCE RLS`** so that **exact identifiers, partial identifiers, typos, and prose phrases resolve in milliseconds without ever counting or echoing unreadable objects**.

**Requirement Traceability:** Spec S11.2 item 1 (`search_tickets` lexical + filter composition); S11.3 item 1 (`search_knowledge` heading-anchored snippets across `Docs`, `Pages`, `Stickies`); S6.3 (`Cmd+K` command palette search); S12.2 (`search_tsv`, `build_markdown_tsvector()`); S3.3 (`FORCE RLS`); requirements `#11`, `#12`, `#1` | **Dependencies:** `KB-P3-02`, `KB-P3-11`, `KB-P3-14`, `KB-P3-15` (manifest lists `KB-P3-02, KB-P3-14`; `KB-P3-11` added for `FilterSpec` composition required by `KB-P4-04` and `KB-P3-15` added for sticky search required by `KB-P4-08`)

### Scoped Technical Actions
1. **Target Files:** `database/migrations/versions/<rev>_p3_17_search_indexes.py`, `kanban/api/v1/search.py`, `kanban/api/v1/schemas/search.py`, `kanban/services/search.py`, `kanban/services/snippets.py`.
2. **Migration (`<rev>_p3_17_search_indexes.py`):**
   - Adds `STORED` `search_tsv` columns using `build_markdown_tsvector()` (`KB-P1-05`) on `docs`, `pages`, and `stickies` (matching `issues.search_tsv` from `KB-P1-05`):
     ```sql
     ALTER TABLE docs ADD COLUMN search_tsv tsvector GENERATED ALWAYS AS (
         setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
         setweight(build_markdown_tsvector(body_markdown), 'B')
     ) STORED;
     ALTER TABLE pages ADD COLUMN search_tsv tsvector GENERATED ALWAYS AS (
         setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
         setweight(build_markdown_tsvector(body_markdown), 'B')
     ) STORED;
     ALTER TABLE stickies ADD COLUMN search_tsv tsvector GENERATED ALWAYS AS (
         build_markdown_tsvector(body_markdown)
     ) STORED;
     CREATE INDEX issues_search_tsv_gin ON issues USING gin (search_tsv);
     CREATE INDEX issues_summary_trgm_gin ON issues USING gin (summary gin_trgm_ops);
     CREATE INDEX docs_search_tsv_gin ON docs USING gin (search_tsv);
     CREATE INDEX docs_title_trgm_gin ON docs USING gin (title gin_trgm_ops);
     CREATE INDEX pages_search_tsv_gin ON pages USING gin (search_tsv);
     CREATE INDEX pages_title_trgm_gin ON pages USING gin (title gin_trgm_ops);
     CREATE INDEX stickies_search_tsv_gin ON stickies USING gin (search_tsv);
     CREATE INDEX stickies_body_trgm_gin ON stickies USING gin (body_markdown gin_trgm_ops);
     ```
   - Reversible `downgrade()` drops the 8 indexes and 3 generated columns cleanly.
3. **Query Normalization & Ranking (`kanban/services/search.py`):**
   - `query`: `1..500` chars after `btrim` (`422 QUERY_LENGTH` otherwise); control characters (`\x00..\x1f`) stripped. Never uses raw `to_tsquery`: parses strictly via `websearch_to_tsquery('english', :q)` (injection-safe against arbitrary punctuation/operators) paired with `word_similarity(:q, title_or_summary)` (`pg_trgm`, threshold `>= 0.25` when `char_length(:q) >= 3`).
   - Exact / prefix issue key boost: when `:q` matches `^[A-Za-z][A-Za-z0-9]{1,9}-\d+$` (e.g., `kan-142`), resolves exact `(identifier, sequence_id)` at rank `100.0` ahead of prose hits.
   - Combined score: `score = (0.75 * ts_rank_cd(search_tsv, tsq, 32)) + (0.25 * greatest(word_similarity(:q, title_col), 0.0))` ordered by `score DESC, id DESC`. Excludes soft-deleted (`objects.deleted_at IS NOT NULL`) and archived (`objects.archived_at IS NOT NULL`, unless `include_archived=true`) objects, plus promoted sticky stubs by default unless `include_promoted_stubs=true`.
4. **Heading-Anchored Plain/Markdown Snippets (`kanban/services/snippets.py`):**
   - `build_anchored_snippet(markdown: str, query: str, max_chars: int = 300) -> AnchoredSnippet`:
     - Uses `extract_markdown_outline()` (`KB-P3-14`) to locate the nearest preceding ATX heading above the highest-scoring match span and sets `anchor = f"#{heading.anchor}"` (or `None` when match precedes all headings or on stickies/issues without headings).
     - Produces a plain/canonical Markdown excerpt `<= 300` chars around the match window (never emitting raw HTML tags such as `<b>` from `ts_headline` so consumers never need `dangerouslySetInnerHTML`; match offsets `match_spans: [[start, end]]` are returned structurally for safe client `<mark>` rendering).
5. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `GET /api/v1/search?q=&kinds=issue,doc,page,sticky&project=&limit=20&cursor=` | authenticated workspace `VIEW` (RLS per row) | `200` | `404` (unreadable `project`), `422` |
   | `POST /api/v1/search/issues` | authenticated `VIEW` | `200` | `404`, `422` |
   | `POST /api/v1/search/knowledge` | authenticated `VIEW` | `200` | `404`, `422` |

   - `POST /api/v1/search/issues` body: `{"query": "OIDC", "project": "KAN", "filters": FilterSpec | null, "mode": "lexical" | "hybrid", "limit": 20, "cursor": null}` (`limit` `1..50`, default `20`). Composes lexical ranking with `compile_issue_filter_predicates` (`KB-P3-11`). Accepts `"mode": "hybrid"` and executes `"lexical"` in Phase 3, returning `"executed_mode": "lexical"` (upgraded transparently when `KB-P5-06` embeddings land).
   - `POST /api/v1/search/knowledge` body: `{"query": "PKCE", "kinds": ["doc", "page", "sticky"], "project": "KAN" | null, "limit": 20, "cursor": null}` (`limit` `1..50`, default `20`). Returns `{total, executed_mode: "lexical", items: [{kind, id, key, title, project_identifier, anchor, snippet, match_spans, score}], next_cursor}`.
