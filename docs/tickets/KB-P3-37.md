### User Story
As a **project member triaging and moving issues on `/projects/:projectKey/issues?layout=board`**, I need **a breathable Plane-parity Kanban board (`324px` lanes, `20px` column gutter, `16px x 18px` cards, `12px` card gap) powered by `@atlaskit/pragmatic-drag-and-drop` and `@tanstack/react-virtual` with `< 12ms` optimistic fractional-rank moves and Soft/Hard WIP `⚠️` enforcement** so that **boards with hundreds of cards scroll and drag without jank, card metadata stays calm via `<EmojiHint>` pills, and column WIP thresholds are visibly respected**.

**Requirement Traceability:** `S6.1` (`--board-canvas-pad`, `--board-col-w`, `--board-col-gap`, `--card-pad`, `--card-gap`), `S6.2` (`🛡️`, `⚠️`, `🔥/⚡/🔹/💤`, `🏷️`, `🤖`, `⏳🤖`, `🛑🤖`, `✅🤖`), `S6.3` (board wireframe lines 489-508), `S6.4 items 1 & 3` (`COLLATE "C"` Base-62 midpoints, `< 12ms` 1-row optimistic move, Soft WIP amber highlight, Hard WIP block + admin override reason), `S1.3 item 2`, `S2.5` (`@atlaskit/pragmatic-drag-and-drop` `Apache-2.0`, `@tanstack/react-virtual` `MIT`), requirements `#9j`, `#15`, `#1` | **Dependencies:** `KB-P3-34` (AppShell, `?layout=board`, `shortcuts.ts`), `KB-P3-12` (board rank & move API with WIP limits), `KB-P3-01b` (`workflow_states` `wip_soft_limit` / `wip_hard_limit`)

4. **Virtualization & CSP-clean positioning (`BoardColumn.tsx`):**
   - `@tanstack/react-virtual` `useVirtualizer({ count, getScrollElement, estimateSize: () => 124, gap: 12, overscan: 6, measureElement })`.
   - With 500 cards in a single lane (`board-kan-500.json`), rendered `.board-card` DOM node count stays `<= 25` at `900px` viewport height.
   - Dynamic virtual item offsets (`translateY(...)`) and total container height are applied via `ref` CSSOM (`el.style.transform = ...`, `el.style.height = ...`) inside `useLayoutEffect`, never via JSX `style={{...}}` HTML attribute strings, preserving strict `style-src 'self'` CSP compliance (`KB-P3-32`).
5. **Drag-and-drop, `< 12ms` 1-row optimistic move & WIP rules (`BoardView.tsx`, `fractionalRank.ts`, `HardWipOverrideModal.tsx`):**
   - `@atlaskit/pragmatic-drag-and-drop` (`draggable`, `dropTargetForElements`, `monitorForElements`, `extractClosestEdge` from `@atlaskit/pragmatic-drag-and-drop-hitbox/closest-edge` if included or local top/bottom midpoint calculation from `clientY` vs card rect). Plus accessible keyboard card move (`Alt+ArrowUp/Down/Left/Right` on a focused card announces new column and rank via `announce()`).
   - Drop computes `newRank = midpointRank(aboveCard?.board_rank ?? null, belowCard?.board_rank ?? null)` (Base-62 `COLLATE "C"`) and mutates ONLY the moved issue in `qk.issues(projectKey, *)` via `useOptimisticMutation` (`< 12ms` synchronous `apply` budget on 500 issues).
   - Calls `POST /api/v1/issues/{issue_ref}/move` (from `KB-P3-12`; body `{ target_state_id, board_rank, before_issue_key?, after_issue_key?, wip_override_reason? }`, record any path/field delta in `message-to-reality-checker.md`).
   - **Soft WIP (`count > wip_soft_limit`):** move succeeds immediately; column header and border switch to `--warn-bg`/`--warn-fg` amber styling and render `⚠️` `<EmojiHint kind="warning">` (`content`: `"Soft WIP limit exceeded (<count> / <wip_soft_limit>). Transitions remain allowed."`).
   - **Hard WIP (`targetState.id !== sourceState.id && targetCount >= wip_hard_limit`):**
     - Same-column rank reorder within an already-at-limit column is ALWAYS allowed (`targetCount` unchanged).
     - Cross-column drop by a caller WITHOUT `ADMIN` in `project.capabilities`: rejected before network call (or rolled back on `409 WIP_HARD_LIMIT_EXCEEDED`), card remains in origin lane, `role="alert"` toast announces `"Hard WIP limit reached (<count>/<wip_hard_limit>) on <state>. Ask a Project Admin to raise the limit or override."`.
     - Cross-column drop by a caller WITH `ADMIN`: opens `HardWipOverrideModal` (`role="dialog"`, `aria-modal="true"`) requiring `wip_override_reason` (`10..500` trimmed chars) before dispatching `POST .../move`; canceling leaves the card in its origin lane.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/web/src/features/board/fractionalRank.test.ts`, `kanban/web/src/features/board/BoardCard.test.tsx`, `kanban/web/src/features/board/BoardColumn.test.tsx`, `kanban/web/src/features/board/BoardView.test.tsx`, `kanban/web/src/features/board/HardWipOverrideModal.test.tsx`
- **Required Test Cases:**
  1. Positive (fractional rank & move): `midpointRank('a000001', 'a000002')` produces `m` where `'a000001' < m && m < 'a000002'` in bytewise ASCII order; moving a card between lanes updates only 1 issue object reference in the 500-issue cache and calls `POST .../move` with the computed `board_rank` and `target_state_id`.
  2. Performance benchmark: median synchronous cache `apply` + state update across 20 runs on a 500-issue board cache completes in `< 12ms` (`performance.now()`).
  3. Virtualization boundary: rendering `BoardColumn` with 250 issues in a `900px`-tall scroll container mounts `<= 25` `.board-card` elements in the DOM.
  4. Soft & Hard WIP rules: Soft WIP breach renders `⚠️` `<EmojiHint>` with exact count/limit text while allowing the move; Hard WIP cross-column move by non-admin sends `0` network requests and announces the block alert; Hard WIP cross-column move by `PROJECT_ADMIN` requires `>= 10`-char `wip_override_reason` (`9` chars rejected) and sends `wip_override_reason` in `POST .../move`; intra-column reorder at Hard WIP succeeds without modal.
  5. Negative / security: card with `summary = "<img src=x onerror=alert(1)>"` and `free_text = "<svg onload=alert(1)>"` renders literal text with `0` `img`/`svg` elements; server `409` or `500` rolls back the card to its exact pre-drag column and rank; overdue styling is absent on `Done` (`completed`) and `Canceled` (`cancelled`) cards even when `due_date` is in the past.
  6. Keyboard a11y: `Alt+ArrowRight` moves focused card to the next column and calls `announce()`; `Enter` navigates to `?layout=board&peek=<KEY>`.
- Coverage on touched files `>= 95%` lines/functions/branches/statements.
