### User Story
As a **developer writing database-backed tests**, I need **a RAM-backed PostgreSQL 16 test server, a golden `kanban_template` database cloned once per `pytest-xdist` worker, and a per-test outer transaction with `SAVEPOINT`-joined `AsyncSession` rollback** so that **every test sees a 100% clean database in sub-millisecond teardown and the suite stays inside the `< 10s` budget for 1,000+ tests**.

**Requirement Traceability:** `S15.1` items 1-3 (tmpfs PG16, `kanban_template` + `CREATE DATABASE ... TEMPLATE`, `join_transaction_mode="create_savepoint"`, `committed_db` TRUNCATE), `S15.2` (`pytest-socket --disable-socket --allow-unix-socket`), Requirement "`>=95%` Unit Coverage, Fast Clean DB" | **Dependencies:** `KB-P0-01`

### Scoped Technical Actions
1. **Target Files:** `docker-compose.test.yml`, `conftest.py` (repo root), `database/testing/__init__.py`, `database/testing/pg_harness.py`, `database/testing/template_sql/000_kb_harness.sql`, `database/pyproject.toml` (deps), root `pyproject.toml` (`[tool.pytest.ini_options]`, dev group), `uv.lock`, `Makefile` (targets `testdb-up`, `testdb-down`), `database/tests/test_pg_harness.py`, `database/tests/test_harness_benchmark.py`
2. **`docker-compose.test.yml`:**
   ```yaml
   services:
     pg-test:
       image: pgvector/pgvector:pg16@sha256:<pinned-digest>
       command: ["postgres", "-c", "fsync=off", "-c", "synchronous_commit=off",
                 "-c", "full_page_writes=off", "-c", "max_connections=200",
                 "-c", "listen_addresses=", "-c", "unix_socket_directories=/var/run/postgresql",
                 "-c", "unix_socket_permissions=0777"]
       environment: { POSTGRES_USER: kanban_test, POSTGRES_DB: postgres, POSTGRES_HOST_AUTH_METHOD: trust }
       tmpfs: ["/var/lib/postgresql/data:rw,size=1g"]
       volumes: ["${KB_TEST_PGSOCKET_DIR:-/tmp/kb-pgsock}:/var/run/postgresql"]
       healthcheck: { test: ["CMD", "pg_isready", "-h", "/var/run/postgresql", "-U", "kanban_test"], interval: 1s, retries: 30 }
   ```
   Zero TCP ports published (`listen_addresses=` empty). `trust` is acceptable only because the sole access path is a host-local Unix socket directory created by `make testdb-up` with mode `0700` owned by the invoking user, and the database contains only disposable test data; this justification MUST appear as a YAML comment. (If the implementer chooses `scram-sha-256` instead, the password lives in an untracked file referenced via `secrets:`; never inline.)
3. **Connection contract:** `KB_TEST_PGHOST` (default `/tmp/kb-pgsock`), `KB_TEST_PGUSER` (default `kanban_test`). The harness builds `postgresql+asyncpg://<user>@/<db>?host=<socket_dir>`. TCP hosts are rejected with `HarnessConfigError("TCP test hosts are forbidden; use a Unix socket directory")`.
4. **Template build (controller process only):** In `pytest_configure`, when `not hasattr(config, "workerinput")`, run `asyncio.run(ensure_template())`:
   - Compute `template_fingerprint = sha256` over the sorted contents of `database/testing/template_sql/*.sql` plus, if `alembic.ini` exists at repo root, all files under the Alembic `script_location`.
   - If database `kanban_template` exists and `shobj_description` (database comment) equals the fingerprint, reuse it. Otherwise `DROP DATABASE IF EXISTS kanban_template WITH (FORCE)`, `CREATE DATABASE kanban_template`, apply build steps in order: (a) `alembic upgrade head` against `kanban_template` if `alembic.ini` exists (log `HARNESS_ALEMBIC_SKIPPED` otherwise; Alembic arrives in KB-P1-01), (b) every `template_sql/*.sql` file in lexical order, then `COMMENT ON DATABASE kanban_template IS '<fingerprint>'` and `ALTER DATABASE kanban_template WITH ALLOW_CONNECTIONS false`.
   - `000_kb_harness.sql` creates schema `kb_harness` and table `kb_harness.probe(id bigint generated always as identity primary key, note text not null)` used only by harness self-tests. Later RLS catalog tests MUST exclude schema `kb_harness` (documented in `database/GEMINI.md`).
5. **Per-worker DB (session fixture `pg_worker_db`):** name `kanban_test_<worker_id>` (`gw0..gwN`, or `master` without xdist); `DROP DATABASE IF EXISTS ... WITH (FORCE)` then `CREATE DATABASE kanban_test_<id> TEMPLATE kanban_template`. Session-scoped `AsyncEngine` (`pool_size=2`, `max_overflow=0`). Dropped at session end.
6. **Per-test isolation (function fixture `db_session`):**
   ```python
   async with engine.connect() as conn:
       outer = await conn.begin()
       session = AsyncSession(bind=conn, join_transaction_mode="create_savepoint", expire_on_commit=False)
       try:
           yield session
       finally:
           await session.close()
           await outer.rollback()
   ```
   Also exposes `db_conn` (the raw `AsyncConnection` inside the same outer transaction).
7. **`@pytest.mark.committed_db` + fixture `committed_db_session`:** session bound directly to the worker engine (real commits). Teardown executes one statement `TRUNCATE <all tables in schemas public, kb_harness except alembic_version> RESTART IDENTITY CASCADE`, discovered from `pg_tables` once per session. Marker registered in `pyproject.toml`; using `committed_db_session` without the marker raises `pytest.UsageError`.
8. **Pytest config (root `pyproject.toml`):**
   ```toml
   [tool.pytest.ini_options]
   addopts = "--disable-socket --allow-unix-socket -p no:cacheprovider --strict-markers"
   asyncio_mode = "auto"
   asyncio_default_fixture_loop_scope = "session"
   asyncio_default_test_loop_scope = "session"
   markers = ["committed_db: test commits real transactions; TRUNCATE cleanup applied"]
   ```
   Root `conftest.py` contains only `pytest_plugins = ["database.testing.pg_harness"]`.
9. **Failure modes:** socket directory missing or server not ready within `10s` -> `pytest.exit("PG test server unavailable at <dir>; run make testdb-up", returncode=3)`. Never silently skip DB tests.
10. **`Makefile`:** `testdb-up` (`install -d -m 0700 $${KB_TEST_PGSOCKET_DIR:-/tmp/kb-pgsock} && docker compose -f docker-compose.test.yml up -d --wait`), `testdb-down`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_pg_harness.py`, `database/tests/test_harness_benchmark.py`
- **Required Test Cases:**
  1. Positive isolation: test A inserts a row into `kb_harness.probe` and calls `await db_session.commit()`; test B, defined directly after A in the same module (run with `--dist loadfile` so both execute on the same worker DB in file order), asserts `SELECT count(*) FROM kb_harness.probe` is `0`.
  2. Positive: after `await db_session.commit()` inside a test, a `SELECT txid_current_if_assigned()` on `db_conn` shows the outer transaction is still open (savepoint join verified).
  3. Positive `committed_db`: a `@pytest.mark.committed_db` test commits a row; the following test sees `0` rows (TRUNCATE ran) and identity restarts at `1`.
  4. Negative/security: `socket.socket(socket.AF_INET).connect(("127.0.0.1", 9))` raises `pytest_socket.SocketBlockedError`; building a DSN with `KB_TEST_PGHOST=127.0.0.1` raises `HarnessConfigError`.
  5. Boundary: `ensure_template()` called twice with unchanged fingerprint does not recreate the DB (database OID unchanged); changing a `template_sql` file (monkeypatched dir) recreates it (OID changes).
  6. Negative: using `committed_db_session` without the marker raises `pytest.UsageError`.
  7. Benchmark: `test_harness_benchmark.py` contains 200 parametrized async tests, each inserting and selecting one `kb_harness.probe` row via `db_session`.
