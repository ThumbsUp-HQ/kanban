### User Story
As an **operator outgrowing single-container `docker run` mode or protecting a production deployment**, I need **`kanban-ctl backup` / `restore` producing AES-256-GCM encrypted `pg_dump -Fc` archives and `kanban-ctl promote export-compose` generating a hardened multi-container `docker-compose.yml` bundle that preserves `MASTER_KEK` and `KB_AUTH_PEPPER` while rotating transport credentials** so that **backups are confidential at rest and promoting standalone data into external PostgreSQL 16 loses zero tickets, audit hashes, or envelope-encrypted auth cards**.

**Requirement Traceability:** Spec S2.2 (`pg_dump -Fc` -> `pg_restore` 1-command lossless promotion into external PG16+, `⚠️` standalone backup & `docker-compose.yml` export); S2.4 (5-network `docker-compose.yml` matrix); S4.1 (`MASTER_KEK` wrapped `auth_provider_cards` DEKs & `KB_AUTH_PEPPER`); requirement `#3`, `#6` | **Dependencies:** `KB-P0-08`, `KB-P0-09`, `KB-P0-11`, `KB-P1-12`, `KB-P1-15`

### Scoped Technical Actions
1. **Target Files:** `kanban/ops/__init__.py`, `kanban/ops/backup_crypto.py`, `kanban/ops/backup_service.py`, `kanban/ops/compose_export.py`, `kanban/cli/ops.py` (register `backup`, `restore`, `promote` under `kanban-ctl`), `docs/PROMOTION_AND_BACKUP.md`.
2. **Streaming Chunked AEAD Archive Format (`kanban/ops/backup_crypto.py`):**
   - Uses `pyca/cryptography` + `argon2-cffi` (already approved in S2.5; zero new dependencies):
   - Binary header `KBBAK1\x00\x01`:
     - `kdf_mode`: `0x01` (256-bit raw base64url key from env `KB_BACKUP_KEY`) or `0x02` (Argon2id `m=64MiB, t=3, p=4` over passphrase from `KB_BACKUP_PASSPHRASE_FILE` / stdin prompt - **never** accepted as a CLI `--passphrase` argv flag so `ps` cannot leak secrets!) + `16`-byte CSPRNG salt + `12`-byte base nonce.
     - Payload is encrypted in `4 MiB` (`4,194,304`-byte) streaming chunks using `AESGCM`; each chunk's `12`-byte nonce XORs the monotonic `uint64` chunk index and binds AAD `b"KBBAK1:" + chunk_idx_be64 + is_final_byte`, so chunk reordering, splicing, or EOF truncation fails GCM authentication immediately (`BackupIntegrityError`) without buffering multi-GB dumps in RAM.
   - Inner tar stream (`tarfile` deterministic format, path-traversal sanitized on extract) bundles:
     1. `manifest.json`: `{format_version: 1, created_at, alembic_revision, pg_server_version, sha256_pgdump, sha256_attachments_index, includes_keyring_secrets: bool}`.
     2. `database.pgdump`: produced via `subprocess.run(["/usr/lib/postgresql/16/bin/pg_dump", "--format=custom", "--no-owner", "--no-privileges", ...], shell=False)`.
     3. `attachments/` (optional `--exclude-attachments=false` default `true`): content-addressed attachment blobs with per-file SHA-256 verified against `manifest.json`.
     4. `secrets_carryover.json` (included only when `--include-secrets` is passed): `MASTER_KEK` and `KB_AUTH_PEPPER` so restored `auth_provider_cards` (`wrapped_dek`, `KB-P2-03`) and Local Admin Argon2id+pepper hashes (`KB-P2-04`) remain decryptable/verifiable on a new host.
3. **Backup, Verify & Restore Service (`kanban/ops/backup_service.py`):**
   - `create_backup(db_url, out_path, key_source, *, include_secrets, keyring_path, attachments_dir) -> BackupSummary`: writes atomically via `.tmp` (`0600` permissions) + `fsync` + `os.replace`.
   - `verify_backup(archive_path, key_source) -> BackupManifest`: decrypts all chunks in streaming mode verifying every GCM tag + `sha256_pgdump` without touching PostgreSQL.
   - `restore_backup(archive_path, target_db_url, key_source, *, confirm_overwrite: bool) -> RestoreReport`:
     - Refuses to run against a non-empty target database unless `confirm_overwrite=True` (`--confirm-overwrite-empty-or-drop`, fail-closed).
     - Runs `/usr/lib/postgresql/16/bin/pg_restore --clean --if-exists --no-owner --no-privileges --exit-on-error` (`shell=False`), re-applies role grants (`kanban_app` `NOBYPASSRLS`, `app_rls_reader`), verifies `alembic current` matches `manifest.alembic_revision`, runs `verify_activity_chain()` (`KB-P1-12`) across every workspace, and runs `audit_object_links()` (`KB-P1-15`) asserting `0` newly broken links!
4. **Standalone -> Production Compose Exporter (`kanban/ops/compose_export.py`):**
   - `export_production_bundle(out_dir: Path, *, keyring_path: Path | None, domain: str)`:
     - Emits `out_dir/docker-compose.yml` and `out_dir/Caddyfile` matching the exact 5-network isolation contract from `KB-P0-11` / `S2.4` (`edge_net`, `app_net`, `data_net` `internal: true`, `sandbox_net` `internal: true`, `egress_llm_net`; `mcp-server` strictly off `data_net`).
     - Emits `out_dir/.env.production` (`chmod 0600`): carries over `KB_MASTER_KEK_B64` and `KB_AUTH_PEPPER_B64` from standalone `keyring.json` (when `--carry-over-keyring` is passed) while generating fresh 256-bit CSPRNG `KB_SESSION_HMAC_KEY_B64` (forcing clean re-login on cutover), fresh PostgreSQL `kanban_app` / `kanban_migrator` passwords, and fresh Valkey ACL password.
5. **CLI & Runbook (`kanban/cli/ops.py`, `docs/PROMOTION_AND_BACKUP.md`):**
   - Commands:
     - `uv run kanban-ctl backup create --out <file.kbbak> [--key-env KB_BACKUP_KEY | --passphrase-file <path>] [--include-secrets]`
     - `uv run kanban-ctl backup verify --in <file.kbbak> [...]`
     - `uv run kanban-ctl restore --in <file.kbbak> --target-db-url <url> --confirm-overwrite [...]`
     - `uv run kanban-ctl promote export-compose --out-dir <dir> --domain <fqdn> [--carry-over-keyring /var/lib/kanban/data/secrets/keyring.json]`
   - Rejects any `--key` or `--passphrase` literal value on `sys.argv` with `exit 2` (`SECRET_IN_ARGV_FORBIDDEN`).

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/ops/test_backup_crypto.py`, `kanban/tests/ops/test_backup_restore.py`, `kanban/tests/ops/test_compose_export.py`
- **Required Test Cases:**
  1. Positive standalone -> external PG16 promotion round-trip (`test_backup_restore.py`): seed source DB with workspace, project `KAN`, issues, docs, pages, stickies, `object_links`, hash-chained `activity_records`, an envelope-encrypted `auth_provider_cards` row (`KB-P2-03`), and a Local Admin Argon2id+pepper user (`KB-P2-04`); run `backup create --include-secrets` -> `backup verify` -> `restore` into a second clean PostgreSQL 16 database; verify row counts, `verify_activity_chain() == True`, `audit_object_links() == 0`, `FORCE RLS` active on all tenant tables, OIDC secret decrypts with carried-over `MASTER_KEK`, and Local Admin password verifies with carried-over `KB_AUTH_PEPPER`.
  2. Cryptographic tamper & truncation defense (`test_backup_crypto.py`): multi-chunk (`> 9 MiB` synthetic stream = 3 chunks) round-trip succeeds; flipping `1` bit in ciphertext, swapping chunk `0` and chunk `1`, truncating the final chunk (missing `is_final` marker), or supplying wrong key each raise `BackupIntegrityError` (`exit 2`).
  3. Safety & CLI secret hygiene: passing `--passphrase secret` on `argv` exits `2` (`SECRET_IN_ARGV_FORBIDDEN`); `restore` onto a non-empty DB without `--confirm-overwrite` exits `2` without modifying existing tables; no `subprocess` call uses `shell=True`; output `.kbbak` and `.env.production` have mode `0600`.
  4. Compose export isolation (`test_compose_export.py`): exported `docker-compose.yml` parses cleanly, places `mcp-server` on `app_net` only (`data_net` absent), marks `data_net` and `sandbox_net` `internal: true`, preserves `KB_MASTER_KEK_B64` + `KB_AUTH_PEPPER_B64`, and rotates `KB_SESSION_HMAC_KEY_B64` to a new distinct 32-byte value.
