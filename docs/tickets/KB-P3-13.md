### User Story
As a **project member or auditor reviewing an issue's timeline**, I need **a cursor-paginated activity feed endpoint supporting the four Plane-parity filter tabs (`all`, `comments`, `history`, `gates`) backed by the SHA-256 hash-chained `activity_records` ledger** so that **discussions, field provenance, creator overrides, and workflow gate verdicts render in one tamper-evident stream without leaking out-of-boundary principals**.

**Requirement Traceability:** Spec S7.1 wireframe (`[All] [Comments (4)] [History] [🤖 Gates (2)]`); S7.2 `8j` (4-tab partitioned hash-chained activity record); S12.2 (`activity_records`); S3.4 (actor/target redaction, indistinguishable `404`); requirements `#8j`, `#1` | **Dependencies:** `KB-P3-05`, `KB-P1-12`

### Scoped Technical Actions
1. **Target Files:** `kanban/api/v1/activity.py`, `kanban/api/v1/schemas/activity.py`, `kanban/services/activity_feed.py`, `kanban/services/activity.py` (formalize `ActivityCategory` enum `COMMENT | HISTORY | AGENT_GATE` and category-to-event-type mapping).
2. **Event Category Taxonomy (`kanban/services/activity.py`):**
   - Every `ActivityEventType` maps deterministically to one `ActivityCategory` stored on `activity_records.category`:
     - `COMMENT`: `COMMENT_CREATED`, `COMMENT_EDITED`, `COMMENT_DELETED`, `MENTION_ACCESS_ACKNOWLEDGED`.
     - `HISTORY`: all issue, provenance (`CREATOR_OVERRIDDEN`), link, state, label, module, cycle, WIP override (`WIP_HARD_LIMIT_OVERRIDDEN`), archive, trash, doc/page/sticky, and admin lifecycle events.
     - `AGENT_GATE`: `SYNC_HOOK_REJECTED`, `HOOK_FAIL_OPEN_WARN`, `GATE_PENDING`, `GATE_APPROVED`, `GATE_REJECTED`, `GATE_TIMED_OUT`, `GATE_CANCELLED` (registered now so Phase 5 `KB-P5-17a`/`KB-P5-18` write directly into the `gates` tab without altering feed routes).
3. **Endpoints:**

   | Method + Path | Capability | Success | Errors |
   | :-- | :-- | :-- | :-- |
   | `GET /api/v1/issues/{issue_ref}/activity?tab=all&order=desc&limit=50&cursor=&include_hashes=false` | `VIEW` on issue | `200` | `404`, `422 INVALID_CURSOR`, `422` |
   | `GET /api/v1/projects/{project_ref}/activity?tab=all&order=desc&limit=50&cursor=&include_hashes=false` | `VIEW` on project (RLS filters per-object rows) | `200` | `404`, `422 INVALID_CURSOR`, `422` |

   - Query parameters:
     - `tab`: enum `all | comments | history | gates` (default `all`).
     - `order`: enum `desc | asc` (default `desc`, ordered by `(created_at, id)`).
     - `limit`: integer `1..100` (default `50`).
     - `cursor`: opaque base64url HMAC-signed token encoding `{scope_id, tab, order, created_at_ns, id}`; mismatched `tab`, `order`, or `scope_id` returns `422 INVALID_CURSOR`.
     - `include_hashes`: boolean (default `false`); when `true`, includes `prev_hash` and `row_hash` hex strings on each item for forensic audit inspection.
   - Hydration & Redaction (`kanban/services/activity_feed.py`):
     - For `COMMENT_CREATED` / `COMMENT_EDITED` items, batch-joins `issue_comments` and `comment_reactions` in 1 query per page: active comments include `comment: {id, body_markdown, permalink, edited_at, reactions}`; soft-deleted comments (`issue_comments.deleted_at IS NOT NULL`) return `comment: {id, deleted: true}` with **zero** `body_markdown` leakage even if old hashes exist in `payload`.
     - Actor and referenced principals (`actor_principal_id`, `old_created_by_id`, `new_created_by_id`, assignee diffs) pass through the `KB-P2-11` visibility redactor: principals outside the caller's workspace visibility boundary serialize as `{"redacted": true, "label": "1 External Collaborator"}` (zero email/handle leakage).
     - Referenced linked objects (`LINK_CREATED` / `LINK_DELETED`) whose target object is unreadable under RLS mask the target as `{"restricted": true, "label": "Restricted Object"}`.
   - Response shape:
     ```json
     {
       "tab": "all",
       "counts": {"all": 7, "comments": 4, "history": 1, "gates": 2},
       "items": [
         {
           "id": "0193...",
           "category": "AGENT_GATE",
           "event_type": "GATE_APPROVED",
           "actor": {"id": "...", "type": "AGENT", "slug": "sec-review", "display_name": "Sec Review (cli: agy -p)"},
           "created_at": "2026-11-11T19:00:00Z",
           "payload": {"hook_name": "sec-review", "from_state": "In Review", "to_state": "Done"}
         }
       ],
       "next_cursor": null
     }
     ```
     `counts` is computed for the target issue (under RLS) so the drawer tab header renders exact badges (`Comments (4)`, `🤖 Gates (2)`) in one request.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/api/test_activity_feed.py`
- **Required Test Cases:**
  1. Positive 4-tab filtering: seed an issue with 2 comments (1 edited, 1 soft-deleted), 3 history changes (including `CREATOR_OVERRIDDEN`), and 2 `AGENT_GATE` rows (`GATE_PENDING`, `GATE_APPROVED`); verify `tab=all`, `tab=comments`, `tab=history`, and `tab=gates` each return exact matching rows and identical `counts` summary.
  2. Deleted comment & redaction security: verify `COMMENT_CREATED` for a subsequently soft-deleted comment omits `body_markdown` in `tab=all` and `tab=comments`; verify an out-of-boundary actor renders as `{"redacted": true, "label": "1 External Collaborator"}`; verify non-viewer `GET /api/v1/issues/KAN-1/activity` returns equalized `404` identical to `KAN-99999`.
  3. Project-scoped RLS filtering: on `GET /api/v1/projects/KAN/activity`, an issue inside `KAN` with an explicit `DENY VIEW` ACL for the caller contributes `0` items and `0` to `counts`.
  4. Hash-chain exposure: `include_hashes=true` returns 64-char hex `row_hash` and `prev_hash` matching `verify_activity_chain()` (`KB-P1-12`), while `include_hashes=false` omits them.
  5. Boundary & pagination: paginate 65 events across monthly partition boundary (`2026-10-31T23:59:59Z` -> `2026-11-01T00:00:01Z`) with `limit=25` in both `order=desc` and `order=asc`; verify `limit=0` and `limit=101` return `422`; cursor minted for `tab=comments` passed to `tab=history` returns `422 INVALID_CURSOR`.
- Clean-DB `SAVEPOINT` harness (`KB-P0-05`). Touched-module coverage `>= 95%`.
