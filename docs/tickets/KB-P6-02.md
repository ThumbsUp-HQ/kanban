### User Story
As a **release engineer executing the live cutover from `https://kanban.hackedyour.info/kanban/` to self-hosted dogfooding**, I need **a deterministic verification CLI (`kanban-ctl cutover verify`) that audits 1:1 entity/key parity, `audit_object_links() == 0`, hash-chain integrity, Markdown-only storage, and `docs/qa/KANBA-*/` proof-bundle resolution, paired with an operator runbook and `< 5 minute` rollback procedure in `docs/CUTOVER.md`** so that **switching traffic is gated on mathematical proof rather than manual spot-checking**.

**Requirement Traceability:** Spec S15.5 item 7 (lossless `KANBA-*` migration, Link Auditor zero-invalid check, self-hosted dogfooding); S1.3 item 4 (key, comment, and QA proof preservation); S12.3 (`audit_object_links()`); requirement `#4`, `#13j` | **Dependencies:** `KB-P6-01`, `KB-P1-15`, `KB-P1-12`

### Scoped Technical Actions
1. **Target Files:** `kanban/importer/cutover_verifier.py`, `kanban/cli/verify_cutover.py` (`kanban-ctl cutover verify`), `docs/CUTOVER.md`.
2. **Scripted Cutover Verifier (`kanban/importer/cutover_verifier.py`):**
   - `async def verify_cutover(session, *, bundle_dir: Path, workspace_slug: str, project_identifier: str, qa_root: Path) -> CutoverAuditReport`:
     - Executes 6 non-bypassable checks and emits a structured JSON report (`overall_passed: bool`, `checks: list[CheckResult]`):
       1. **`entity_count_and_key_parity`**: compares Plane snapshot JSON counts and exact `KANBA-<sequence_id>` key set against PostgreSQL rows (`projects`, `workflow_states`, `project_priorities`, `project_labels`, `cycles`, `modules`, `issues`, non-deleted `issue_comments`, `object_links`, `attachments`). Any missing/extra issue key or sequence counter `< max(sequence_id)` fails (`KEY_PARITY_MISMATCH`).
       2. **`zero_invalid_object_links`**: runs `SELECT * FROM audit_object_links(:workspace_id)` (`KB-P1-15`) AND queries `SELECT count(*) FROM object_links WHERE workspace_id = :workspace_id AND link_state = 'FLAGGED_INVALID'`. Fails (`INVALID_OBJECT_LINKS_DETECTED`) if either count is `!= 0`.
       3. **`activity_hash_chain_intact`**: runs `verify_activity_chain(:workspace_id)` (`KB-P1-12`) across all monthly partitions. Fails (`ACTIVITY_CHAIN_BROKEN`) if `valid != True`.
       4. **`canonical_markdown_purity`**: verifies catalog contains `0` `*_html` / `*_ast` columns AND scans imported `issues.description_markdown` and `issue_comments.body_markdown` outside fenced code blocks (` ``` ` / `~~~`) for un-converted block/script HTML residue (`<script`, `<iframe`, `onerror=`, `onload=`, `style="display:none"`). Fails (`HTML_RESIDUE_DETECTED`) on any hit.
       5. **`qa_proof_bundle_continuity`**: for every imported issue in a `completed` state group (or whose description/comments reference `docs/qa/<KEY>/`), verifies `<qa_root>/<KEY>/` exists on disk and contains non-empty `git-diff.patch`, `unit-test-results.txt`, and `build-check.txt` (unless explicitly listed in `--pre-cutover-exempt-keys` for historical bootstrap meta-tickets, which are still logged in `exempted_keys`). Fails (`MISSING_QA_PROOF_BUNDLE`) on any missing/0-byte file.
       6. **`rls_enforcement_active`**: queries `pg_class` for all public tenant tables asserting `relrowsecurity = true AND relforcerowsecurity = true` and `pg_roles` asserting `kanban_app` has `rolsuper = false AND rolbypassrls = false`.
3. **CLI Subcommand (`kanban/cli/verify_cutover.py`):**
   - `uv run kanban-ctl cutover verify --bundle-dir <path> --workspace <slug> --project KANBA --qa-root ./docs/qa [--json-out <path>]`.
   - Prints human-readable table + writes raw JSON report when `--json-out` is supplied; exits `0` iff `overall_passed is True`, `2` if any check failed, `1` on runtime/connection error.
4. **Operator Runbook (`docs/CUTOVER.md`, zero em/en-dashes):**
   - Documents exact copy-pasteable commands for:
     1. Pre-cutover Plane write-freeze & `fetch-snapshot` archive + SHA-256 manifest checksum.
     2. Pre-flight encrypted backup (`kanban-ctl backup create` or `pg_dump -Fc`) and target stack health check.
     3. `--dry-run` diff inspection & `--user-map` verification (`0` unexpected unmapped admins).
     4. Live `kanban-ctl import plane` execution.
     5. Mandatory `kanban-ctl cutover verify` gate (`overall_passed: true` required before traffic switch).
     6. Caddy / MCP client endpoint cutover (`/mcp/agent`, `/mcp/docs`, `/mcp/admin` key provisioning) and Plane read-only archive mode.
     7. Deterministic `< 5 minute` rollback plan (revert Caddy upstream / MCP config, restore pre-cutover snapshot, unfreeze Plane) if any post-switch smoke check fails.
