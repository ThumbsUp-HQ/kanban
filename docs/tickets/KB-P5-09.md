### User Story
As a **writer who relies on the browser's spellcheck, Copy and Paste menus**, I need **right-click to accept a Sparkle suggestion only when I right-click on the `✨` badge or within `28px` of the blinking caret (and not on a misspelled word), with `Shift + Right-Click` always giving me the native menu** so that **the AI shortcut never takes away native editing affordances**.

**Requirement Traceability:** `S9.2 rows 1-6`, `S9.1 (READY_BLINKING -> ACCEPTED on Right-Click <=28px or on ✨)`, original requirement `#7` | **Dependencies:** `KB-P5-08`

### Scoped Technical Actions
1. **Target Files:**
   - `kanban/web/src/editor/sparkle/contextMenuMatrix.ts` (new: pure `resolveContextMenu()`)
   - `kanban/web/src/editor/sparkle/SparkleCompletionPlugin.ts` (modify: `handleDOMEvents.contextmenu`)
   - `kanban/web/src/editor/sparkle/SparkleOverlayPortal.tsx` (modify: `pointerdown` (button `2`) + `contextmenu` on badge)
2. **`resolveContextMenu(input): "ACCEPT" | "NATIVE"`, input `{ sparkleState, selectionEmpty, onBadge, distancePx, overSpellingNode, shiftKey }`, evaluated in this order:**
   1. `sparkleState !== "READY_BLINKING"` -> `NATIVE` (row 6).
   2. `shiftKey` -> `NATIVE` (row 3).
   3. `!selectionEmpty` -> `NATIVE` (row 4).
   4. `onBadge` -> `ACCEPT` (row 1).
   5. `overSpellingNode || distancePx > 28` -> `NATIVE` (row 5).
   6. `distancePx <= 28` -> `ACCEPT` (row 2).
   - Only `ACCEPT` calls `event.preventDefault()`; `NATIVE` never touches the event (no `stopPropagation`).
3. **Inputs computation:**
   - `distancePx` = Euclidean distance from `(event.clientX, event.clientY)` to the caret point (`coordsAtPos(selection.from)`: `x = left`, `y = (top + bottom) / 2`); inclusive `<= 28`.
   - `onBadge` = `event.target` is the badge element or its descendant.
   - `overSpellingNode` = `event.target.closest(".cm-lint-spelling, [data-spell-error]")` is non-null (spec names `.cm-lint-spelling`; `[data-spell-error]` covers any ProseMirror spelling decoration). Native browser squiggles are not DOM-observable; this limitation is documented in a code comment and in `message-to-reality-checker.md`.
   - Right-click on the badge accepts on `pointerdown` (button `2`) and the subsequent `contextmenu` is suppressed for that gesture only (a single-use flag cleared after `500ms` or the next `contextmenu`).
4. **Accept action** reuses the KB-P5-08 accept transaction (same undo boundary). No new network calls.
