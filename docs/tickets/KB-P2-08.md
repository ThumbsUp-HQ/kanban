### User Story
As a **security architect**, I need **external logins to resolve strictly by `(auth_card_id, immutable_subject_id)`, never auto-merging accounts with a matching email address across cards, and requiring a fresh AAL2 session plus live authentication on the target card to link an additional identity** so that **account pre-hijacking and compromised or misconfigured secondary IdPs cannot take over existing workspace accounts**.

**Requirement Traceability:** `S4.2` item 4 (zero implicit cross-card email auto-linking, strict `(auth_card_id, immutable_subject_id)` mapping, explicit link flow requiring existing `AAL2` session + new card auth), `S4.1` (`auto_provision_users`, `allowed_email_domains`), `S3.1` (`principals`, `users`), requirement `#6` | **Dependencies:** `KB-P2-06` (OIDC/OAuth2 flow + `IdentityResolver` protocol), `KB-P2-07` (LDAPS flow + group sync), `KB-P2-05a` (`require_aal2` policy, `mfa_pending` admin enforcement; split from `KB-P2-05`)

### Scoped Technical Actions
1. **Target Files:**
   - `database/migrations/versions/<rev>_user_identities_and_link_intents.py`, `database/models/auth.py` (add `UserIdentity`, `IdentityLinkIntent`)
   - `kanban/auth/identity_service.py` (`DatabaseIdentityResolver`, `IdentityLinkService`)
   - `kanban/api/v1/auth_identities.py` (`GET /api/v1/auth/identities`, `POST /api/v1/auth/identities/link/start`, `POST /api/v1/auth/identities/link/ldap`, `DELETE /api/v1/auth/identities/{identity_id}`)
   - `kanban/app.py` (wire `DatabaseIdentityResolver` in place of `RejectAllIdentityResolver`)
2. **DDL** (`kb_auth` boundary: owned by `kb_auth_owner`, revoked from `kanban_app` and `app_rls_reader`, `FORCE RLS`, accessed solely via `SECURITY DEFINER` functions with `SET search_path = pg_catalog, public`):
   ```sql
   CREATE TABLE user_identities (
     id                    UUID PRIMARY KEY DEFAULT uuidv7(),
     workspace_id          UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
     principal_id          UUID NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
     auth_card_id          UUID NOT NULL REFERENCES auth_provider_cards(id) ON DELETE RESTRICT,
     immutable_subject_id  TEXT NOT NULL CHECK (char_length(btrim(immutable_subject_id)) BETWEEN 1 AND 255),
     subject_email_at_link TEXT,
     created_at            TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
     last_login_at         TIMESTAMPTZ,
     UNIQUE (auth_card_id, immutable_subject_id)
   );
   CREATE TABLE identity_link_intents (
     id              UUID PRIMARY KEY DEFAULT uuidv7(),
     principal_id    UUID NOT NULL REFERENCES principals(id) ON DELETE CASCADE,
     session_id      UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
     target_card_id  UUID NOT NULL REFERENCES auth_provider_cards(id) ON DELETE CASCADE,
     expires_at      TIMESTAMPTZ NOT NULL,
     consumed_at     TIMESTAMPTZ
   );
   ```
   `kb_auth` functions: `kb_auth.identity_lookup(p_card_id uuid, p_subject text)` (exact match on `(auth_card_id, immutable_subject_id)` ONLY; zero email parameter exists), `kb_auth.identity_provision_new_user(...)`, `kb_auth.identity_list_for_principal(p_principal uuid)`, `kb_auth.identity_link_intent_create(...)`, `kb_auth.identity_link_consume_and_bind(...)`, `kb_auth.identity_unlink(p_principal uuid, p_identity_id uuid)`.
3. **Standard Login Resolution (`DatabaseIdentityResolver.resolve` when `link_intent_id is None`):**
   - Look up `(assertion.card_id, assertion.subject)` via `kb_auth.identity_lookup`.
   - **Bound identity found:** verify `principals.status == 'ACTIVE'` (else `403 ACCOUNT_DISABLED`), update `last_login_at`, synchronize IdP groups (`OIDC` mapped `groups_claim` or `LDAP` `sync_ldap_groups`), check whether principal holds `SERVER_ADMIN` or `PROJECT_ADMIN` role (`KB-P1-13`): if admin role, issue session with `aal=1, mfa_pending=True` (`SessionService.create_after_login`) so second-factor verification is required before admin routes; otherwise `aal=1, mfa_pending=False`. Append `EXTERNAL_LOGIN_SUCCEEDED` to `activity_records`.
   - **Unbound identity + `card.auto_provision_users == False`:** append `EXTERNAL_LOGIN_UNPROVISIONED` and raise `403 IDENTITY_NOT_PROVISIONED`.
   - **Unbound identity + `card.auto_provision_users == True`:**
     - Require `assertion.email` valid and `assertion.email_verified == True` (unverified IdP email -> `403 EMAIL_NOT_VERIFIED`).
     - When `card.allowed_email_domains` is non-empty, domain part `email.rsplit("@", 1)[1].lower()` must be in `[d.lower() for d in card.allowed_email_domains]` (else `403 EMAIL_DOMAIN_FORBIDDEN`).
     - **Zero Email Auto-Merge Invariant:** check if `users` in `workspace_id` already has a row with `lower(email) = lower(assertion.email)`. If an existing user holds that email, **NEVER** attach the new `(card_id, subject)` to that user; instead raise `409 IDENTITY_LINK_REQUIRED` (instructing the user to sign in with their existing method, reach AAL2, and explicitly link the new provider) and append `IDENTITY_AUTO_MERGE_BLOCKED` to `activity_records`.
     - Only when no user owns `lower(email)` does `kb_auth.identity_provision_new_user` atomically create `objects(object_type='user')` + `principals(principal_type='USER')` + `users` + `user_identities` and issue the session.
4. **Explicit AAL2 Link Flow (`IdentityLinkService` + `auth_identities.py`):**
   - `POST /api/v1/auth/identities/link/start {card_slug: str}`: requires authenticated session + `require_aal2(max_age_seconds=900)` (`KB-P2-05a`) + CSRF. Target card must be enabled and `provider_kind in ('OIDC', 'OAUTH2', 'LDAP')`. Creates `identity_link_intents` row (`TTL = 300s`, bound to `principal_id`, `session_id`, `target_card_id`). For `OIDC`/`OAUTH2`, calls `OidcFlow.start(..., link_intent_id=intent.id)` returning `{mode: "redirect", authorize_url}` (sets `__Host-kb_oidc` browser-binding cookie); for `LDAP`, returns `{mode: "ldap_credentials", link_intent_id: intent.id}`.
   - `POST /api/v1/auth/identities/link/ldap {link_intent_id: UUID, username: str, password: str}`: requires same active AAL2 session + CSRF, authenticates against target LDAP card (`KB-P2-07`), and invokes `resolve(assertion, request, link_intent_id=link_intent_id)`.
   - When `resolve` receives non-null `link_intent_id`: atomically consume `identity_link_intents` verifying `consumed_at IS NULL`, `expires_at > clock_timestamp()`, `target_card_id == assertion.card_id`, and caller's current `session_id == intent.session_id` and `principal_id == intent.principal_id` (mismatch/expired/reused -> `400 LINK_INTENT_INVALID`). Insert `user_identities(principal_id=intent.principal_id, auth_card_id=assertion.card_id, immutable_subject_id=assertion.subject, ...)`; if `(auth_card_id, immutable_subject_id)` is already bound to any principal -> `409 IDENTITY_ALREADY_LINKED`. Existing AAL2 session remains owned by `intent.principal_id`; append `IDENTITY_LINKED` activity.
   - `GET /api/v1/auth/identities`: lists caller's own bound identities (`id`, `card_slug`, `card_display_name`, `provider_kind`, `subject_email_at_link`, `created_at`, `last_login_at`; `immutable_subject_id` truncated/redacted or shown to self only, zero card secrets).
   - `DELETE /api/v1/auth/identities/{identity_id}`: requires `require_aal2(max_age_seconds=900)` + CSRF; refuses with `409 LAST_AUTH_METHOD` if principal has `<= 1` bound `user_identities` AND zero `local_admin_credentials`. Appends `IDENTITY_UNLINKED`.
5. **Security invariants asserted:** (a) zero SQL query or code path maps `assertion.email` to an existing `principal_id`; (b) pre-hijack and rogue-IdP duplicate-email logins always fail closed with `409 IDENTITY_LINK_REQUIRED`; (c) linking requires fresh `AAL2` (`<= 900s`) in the exact same browser session; (d) each `(auth_card_id, immutable_subject_id)` maps to at most one principal.

### Mandatory Feature Unit Tests
- **Test File(s):** `kanban/tests/auth/test_identity_resolution.py`, `kanban/tests/auth/test_identity_linking.py`
- **Required Test Cases:**
  1. Positive (auto-provision + subsequent login): OIDC card with `auto_provision_users=True`, `allowed_email_domains=["corp.example"]`, `email="maya@corp.example"`, `email_verified=True` provisions user `U1` on first login and resolves to `U1` on second login even if IdP email later changes to `maya.lin@corp.example` (subject stability).
  2. Security (pre-hijack scenario): attacker pre-creates or provisions account with `victim@corp.example` on Card B (or user already exists on Card A with `victim@corp.example`); second card asserting `email="victim@corp.example"`, `email_verified=True`, new `subject` -> `409 IDENTITY_LINK_REQUIRED`, victim/existing account untouched, `IDENTITY_AUTO_MERGE_BLOCKED` recorded in `activity_records`.
  3. Security (same subject across two cards): Card A `sub="1001"` and Card B `sub="1001"` resolve independently (composite key `(auth_card_id, immutable_subject_id)` prevents cross-card `sub` collision).
  4. Security (unverified email & domain allowlist): `auto_provision_users=True` with `email_verified=False` -> `403 EMAIL_NOT_VERIFIED`; `email="user@other.example"` -> `403 EMAIL_DOMAIN_FORBIDDEN`; `auto_provision_users=False` -> `403 IDENTITY_NOT_PROVISIONED`.
  5. Positive (explicit AAL2 link OIDC & LDAP): user `U1` elevates session to AAL2 -> starts link for GitHub OAuth2 card -> completes callback -> `user_identities` row created for `U1`; repeats for LDAP card via `/link/ldap` -> `U1` can now sign in via all linked cards.
  6. Security (AAL1 / stale AAL2 link blocked): calling `/identities/link/start` with AAL1 session -> `403 AAL2_REQUIRED`; with AAL2 older than `900s` -> `403 AAL2_STALE`.
  7. Security (cross-session link CSRF / intent replay): link intent created in session S1 presented during OIDC callback by session S2 -> `400 LINK_INTENT_INVALID`; replaying consumed intent or intent at `301s` -> `400 LINK_INTENT_INVALID`; callback from card X using intent created for card Y -> `400 LINK_INTENT_INVALID`.
  8. Security (already linked subject): attempting to link `(card_B, sub_B)` already owned by user `U2` onto user `U1` -> `409 IDENTITY_ALREADY_LINKED`, `U2` retains ownership.
  9. Security (admin MFA gate on external login): user holding `SERVER_ADMIN` role signing in via OIDC receives session with `mfa_pending=True`, `aal_level=1` (cannot call `/api/v1/admin/*` until AAL2 verification).
  10. Unlink & boundary: unlinking secondary card succeeds with fresh AAL2; unlinking sole remaining identity when user has no `local_admin_credentials` -> `409 LAST_AUTH_METHOD`; `SELECT * FROM user_identities` as `kanban_app` -> `42501`.
