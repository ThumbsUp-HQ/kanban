### User Story
As an **operator who never wants baked-in or default secrets**, I need **the standalone entrypoint to atomically generate a `0600` keyring of 256-bit secrets on first boot, reuse it unchanged on restart, fail closed if it is corrupt, and warn loudly when the data directory is on ephemeral overlay storage** so that **each container has unique keys and operators learn before data loss that they forgot `-v kanban_data:/var/lib/kanban/data`**.

**Requirement Traceability:** `S2.2` boot lifecycle item 1 (`os.urandom(32)` `MASTER_KEK`, `KB_AUTH_PEPPER`, `SESSION_HMAC_KEY`, internal DB role credentials, `/var/lib/kanban/data/secrets/keyring.json` `chmod 0600`, `/proc/mounts` overlayfs warning), `S3.5` row "Standalone `docker run` Misconfiguration" | **Dependencies:** `KB-P0-08`

### Scoped Technical Actions
1. **Target Files:** `deploy/standalone/keyring.py`, `deploy/standalone/storage_probe.py`, `deploy/standalone/entrypoint.py` (wire-in), `deploy/standalone/pg_config.py` (role password + `pg_hba` update), `tests/deploy/test_keyring.py`, `tests/deploy/test_storage_probe.py`, `tests/deploy/test_standalone_entrypoint.py` (extend)
2. **Keyring format (`/var/lib/kanban/data/secrets/keyring.json`, version 1):**
   ```json
   {
     "version": 1,
     "created_at": "2026-01-01T00:00:00Z",
     "MASTER_KEK": "<base64url, 32 bytes>",
     "KB_AUTH_PEPPER": "<base64url, 32 bytes>",
     "SESSION_HMAC_KEY": "<base64url, 32 bytes>",
     "db_roles": { "kanban_app": "<base64url, 32 bytes>", "kanban_migrator": "<base64url, 32 bytes>" }
   }
   ```
   Every secret is `base64.urlsafe_b64encode(os.urandom(32))` without padding. `secrets/` directory is `0700 root:root`; the file is `0600 root:root`.
3. **`load_or_create_keyring(path: Path) -> Keyring`:**
   - If absent: create parent with `os.makedirs(mode=0o700)`; write to `keyring.json.<random>.tmp` opened with `os.open(..., O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW, 0o600)`, `fsync` file, `os.replace` to final name, `fsync` the directory. Concurrent creation race: if `os.replace` target appears first, discard temp and load the existing file.
   - If present: refuse (raise `KeyringError`, entrypoint exits `78` with `KEYRING_INVALID`) when the path is a symlink, owner UID is not `0` (when running as root), mode is not exactly `0600`, size `> 64 KiB`, JSON invalid, `version != 1`, any key missing/extra, or any decoded secret length `!= 32`. Never regenerate over an existing file (fail closed, never silent rotation).
   - `Keyring` is a frozen dataclass holding `bytes` values; `__repr__` returns `Keyring(<redacted>)`.
4. **Applying role credentials (every boot, in `pg_config.py`):** `ALTER ROLE kanban_app PASSWORD '<scram>'` and `ALTER ROLE kanban_migrator PASSWORD '<scram>'`, where the SCRAM-SHA-256 verifier is computed in Python (`hashlib.pbkdf2_hmac`, 4096 iterations, 16-byte random salt, RFC 5802 / RFC 7677 format `SCRAM-SHA-256$4096:<salt>$<StoredKey>:<ServerKey>`) so plaintext never appears in SQL text or PG logs. `pg_hba.conf` line for `kanban_app` changes from `peer map=kanban_map` to `scram-sha-256`; `postgres` and `kanban_migrator` stay `peer`. The Uvicorn child `DATABASE_URL` includes the `kanban_app` password (URL-encoded).
5. **Child env handoff:** extend the KB-P0-08 env allowlist with `KB_MASTER_KEK_B64`, `KB_AUTH_PEPPER_B64`, `KB_SESSION_HMAC_KEY_B64`. The keyring file itself stays unreadable to UID `65532`. No secret value is ever written to stdout/stderr.
6. **`storage_probe.py`:**
   ```python
   @dataclass(frozen=True)
   class StandaloneStatus:
       mode: Literal["standalone_embedded_pg", "external_db"]
       persistent_volume: bool
       data_mount_point: str
       data_mount_fstype: str
       generated_at: str  # ISO-8601 UTC
   def probe(data_dir: Path, mounts_text: str) -> StandaloneStatus: ...
   ```
   Parse `/proc/mounts` (octal escapes like `\040` decoded), pick the longest mount point that is a path prefix of `data_dir`; `persistent_volume = fstype != "overlay"` (also `false` for `tmpfs`). Unparseable lines are skipped; if no mount matches, `persistent_volume = false` (fail toward warning).
7. **Warning:** when `persistent_volume` is false, print to stderr exactly: `⚠️ Ephemeral Storage: Mount -v kanban_data:/var/lib/kanban/data to persist data across container removal` (text verbatim from S2.2 item 1).
8. **Status handoff for later UI (KB-P3-52):** write `StandaloneStatus` as JSON to `/run/kanban/standalone_status.json` (`/run/kanban` `0755 root`, file `0644 root`, atomic write) and pass `KB_STANDALONE_STATUS_PATH=/run/kanban/standalone_status.json` in the Uvicorn env allowlist. The file contains no secrets.

### Mandatory Feature Unit Tests
- **Test File(s):** `tests/deploy/test_keyring.py`, `tests/deploy/test_storage_probe.py`, `tests/deploy/test_standalone_entrypoint.py`
- **Required Test Cases:**
  1. Positive: first call creates a file with mode `0600`, parent `0700`, valid schema, 5 distinct 32-byte secrets; second call returns byte-identical secrets and does not rewrite the file (mtime and inode unchanged).
  2. Negative/security (fail closed): mode `0644`, symlinked path, truncated JSON, missing `SESSION_HMAC_KEY`, extra key, secret decoding to 31 bytes, size `64 KiB + 1` each raise `KeyringError` and leave the file unmodified.
  3. Security: `repr(keyring)` and `str(keyring)` contain no base64 secret substring; the generated SCRAM verifier matches the RFC 7677 test vector for user `user`, password `pencil`, salt `W22ZaJ0SNY7soEsUEjb6gQ==`, 4096 iterations (StoredKey `WG5d8oPm3OtcPnkdi4Uo7BkeZkBFzpcXkuLmtbsT4qY=`, ServerKey `wfPLwcE6nTWhTAmQ7tl2KeoiWGPlZqQxSrmfPwDl2dU=`).
  4. Boundary: concurrent creation simulated by pre-placing the final file between temp write and `os.replace` results in loading the existing file, temp removed.
  5. Storage probe: `/var/lib/kanban/data` on `overlay` -> `persistent_volume=False` and warning text emitted verbatim; on `ext4` bind mount -> `True`; nested mounts pick the longest prefix; `\040` escaped mount point decoded; no matching mount -> `False`.
  6. Entrypoint: child env contains `KB_MASTER_KEK_B64` etc. and `KB_STANDALONE_STATUS_PATH`; generated `pg_hba.conf` has `scram-sha-256` for `kanban_app`; no recorded stdout/stderr line contains any secret.
