### User Story
As a **distributed systems architect**, I need **a transactional `outbox_events` table with a `pg_notify('outbox_wakeup')` trigger, a `FOR UPDATE SKIP LOCKED` relay worker with dead-letter protection, and a `RealtimeBroker` protocol implemented by both `PgNotifyBroker` (zero-Valkey standalone) and `ValkeyBroker` (multi-replica production)** so that **every committed domain mutation fans out reliably without dual-write race conditions or requiring Valkey in `docker run` mode**.

**Requirement Traceability:** `S2.2` (standalone PG `LISTEN/NOTIFY` `RealtimeBroker`, zero Valkey container), `S2.4` (`outbox-relay`: `LISTEN outbox_wakeup` + `FOR UPDATE SKIP LOCKED` -> Valkey 8 Streams & PubSub), Requirement `#3` | **Dependencies:** `KB-P1-17`

2. **`outbox_events` DDL, Wakeup Trigger & `SKIP LOCKED` Functions (`p1_18_outbox.up.sql`):**
   ```sql
   CREATE TABLE outbox_events (
       id                UUID        PRIMARY KEY DEFAULT uuidv7(),
       seq               BIGINT      GENERATED ALWAYS AS IDENTITY UNIQUE,
       workspace_id      UUID        NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
       project_id        UUID        REFERENCES projects(id) ON DELETE SET NULL,
       object_id         UUID,
       topic             TEXT        NOT NULL CHECK (topic ~ '^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$'
                                                     AND char_length(topic) <= 128),
       payload           JSONB       NOT NULL DEFAULT '{}'::jsonb
                                     CHECK (jsonb_typeof(payload) = 'object'
                                            AND octet_length(payload::text) <= 7168),
       created_at        TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       next_attempt_at   TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
       published_at      TIMESTAMPTZ,
       dead_lettered_at  TIMESTAMPTZ,
       attempts          INTEGER     NOT NULL DEFAULT 0 CHECK (attempts >= 0),
       last_error        TEXT        CHECK (last_error IS NULL OR char_length(last_error) <= 1024)
   );
   CREATE INDEX outbox_events_pending_idx
       ON outbox_events (next_attempt_at, seq)
       WHERE published_at IS NULL AND dead_lettered_at IS NULL;

   ALTER TABLE outbox_events ENABLE ROW LEVEL SECURITY;
   ALTER TABLE outbox_events FORCE ROW LEVEL SECURITY;
   ```
   - RLS policies: `outbox_events_insert_rls` (`FOR INSERT WITH CHECK (workspace_id = app_current_workspace_id() AND app_current_principal_id() IS NOT NULL)`); `outbox_events_select_rls` (`FOR SELECT USING (workspace_id = app_current_workspace_id() AND app_principal_has_role(project_id, ARRAY['SERVER_ADMIN', 'WORKSPACE_ADMIN', 'PROJECT_ADMIN']))`).
   - Statement-level wakeup trigger `outbox_events_wakeup_ai` (`AFTER INSERT ON outbox_events FOR EACH STATEMENT`): calls `PERFORM pg_notify('outbox_wakeup', '');`.
   - `SECURITY DEFINER` relay primitives (`SET search_path = pg_catalog, public`, `GRANT EXECUTE TO kanban_app`):
     - `claim_outbox_batch(p_batch_size int DEFAULT 100, p_now timestamptz DEFAULT clock_timestamp()) RETURNS SETOF outbox_events`: validates `p_batch_size BETWEEN 1 AND 500`, selects pending rows (`published_at IS NULL AND dead_lettered_at IS NULL AND next_attempt_at <= p_now ORDER BY seq ASC LIMIT p_batch_size FOR UPDATE SKIP LOCKED`), increments `attempts = attempts + 1`, sets `next_attempt_at = p_now + interval '30 seconds'` (lease visibility window so crashed workers recover automatically), and returns claimed rows.
     - `mark_outbox_published(p_ids uuid[], p_now timestamptz DEFAULT clock_timestamp()) RETURNS integer`: sets `published_at = p_now, last_error = NULL` where `id = ANY(p_ids) AND published_at IS NULL`.
     - `mark_outbox_failed(p_id uuid, p_error text, p_max_attempts int DEFAULT 5, p_now timestamptz DEFAULT clock_timestamp()) RETURNS boolean`: truncates `p_error` to `1024` chars; if `attempts >= p_max_attempts`, sets `dead_lettered_at = p_now` and returns `TRUE`, else sets exponential backoff `next_attempt_at = p_now + make_interval(secs => least(300, power(2, attempts)::int))` and returns `FALSE`.

3. **Transactional Enqueue Helper & `RealtimeBroker` Protocol (`database/outbox/broker.py`):**
   - `@dataclass(frozen=True, slots=True) class OutboxEnvelope`: `id: UUID`, `seq: int`, `workspace_id: UUID`, `project_id: UUID | None`, `object_id: UUID | None`, `topic: str`, `payload: dict[str, Any]`, `created_at: datetime` (with deterministic compact JSON `to_wire_json() -> str` and `from_wire_json(raw: str) -> OutboxEnvelope`; rejects wire payloads `> 7900` bytes with `OutboxPayloadTooLargeError` so PG `NOTIFY`'s `8000`-byte ceiling is never exceeded).
   - `async def enqueue_outbox_event(session: AsyncSession, *, workspace_id: UUID, topic: str, payload: Mapping[str, Any], project_id: UUID | None = None, object_id: UUID | None = None) -> UUID`: validates topic regex and payload size `<= 7168` bytes before DB round-trip (`OutboxPayloadTooLargeError`), inserts `OutboxEvent` inside the caller's active RLS transaction, and returns `id`.
   - `topic_matches(pattern: str, topic: str) -> bool`: supports `"*"`, segment prefix wildcard `"issue.*"` / `"workflow.gate.*"`, and exact `"notification.created"`.
   - `@runtime_checkable class RealtimeBroker(Protocol)`:
     - `async def publish(self, event: OutboxEnvelope) -> None: ...`
     - `def subscribe(self, topic_pattern: str = "*") -> AsyncIterator[OutboxEnvelope]: ...`
     - `async def close(self) -> None: ...`
   - `build_realtime_broker(deployment_mode: Literal["standalone", "production"], *, pg_dsn: str, valkey_client: ValkeyStreamClient | None = None) -> RealtimeBroker`: returns `PgNotifyBroker(pg_dsn)` when `deployment_mode == "standalone"` or `valkey_client is None`, else `ValkeyBroker(valkey_client)` (fail closed with `ValueError` if `production` is requested explicitly with `require_valkey=True` and `valkey_client is None`).

4. **`PgNotifyBroker` (`database/outbox/pg_broker.py`) & `ValkeyBroker` (`database/outbox/valkey_broker.py`):**
   - `PgNotifyBroker`: maintains a dedicated `asyncpg` listener connection (`LISTEN kanban_realtime`), publishes via `SELECT pg_notify('kanban_realtime', $1)` with `event.to_wire_json()`, dispatches matching envelopes to per-subscriber bounded `asyncio.Queue(maxsize=1024)` (dropping oldest with structured warning `REALTIME_SUBSCRIBER_LAGGED` only if full so one slow consumer never stalls the listener), and cleans up queues on generator close / `close()`.
   - `ValkeyStreamClient(Protocol)`: `async def xadd(self, stream: str, fields: Mapping[str, str], *, maxlen: int = 100_000) -> str`, `async def publish(self, channel: str, message: str) -> int`, `async def xread(self, streams: Mapping[str, str], *, count: int = 100, block_ms: int = 1000) -> list[tuple[str, list[tuple[str, dict[str, str]]]]]`. `ValkeyBroker` writes both a durable stream entry (`kb:outbox:stream`, `MAXLEN ~ 100000`) and pubsub message (`kb:rt:{event.topic}`) and streams matching envelopes via `subscribe()` (verified against an in-memory `FakeValkeyStreamClient` with zero new third-party Valkey package added in Phase 1).

5. **`OutboxRelay` Worker (`database/outbox/relay.py`):**
   - `OutboxRelay(engine: AsyncEngine, listen_dsn: str, broker: RealtimeBroker, *, batch_size: int = 100, poll_interval_s: float = 1.0, max_attempts: int = 5)`:
     - `async def drain_once() -> int`: claims up to `batch_size` rows via `claim_outbox_batch` in a short transaction, calls `await broker.publish(env)` for each, marks succeeded IDs via `mark_outbox_published`, and records any failing row via `mark_outbox_failed` (logging `OUTBOX_EVENT_DEAD_LETTERED` when `dead_lettered_at` is set; one bad row never blocks healthy rows in the batch).
     - `async def run_until_stopped(stop_event: asyncio.Event) -> None`: listens on `outbox_wakeup` via `asyncpg.Connection.add_listener` waking an `asyncio.Event` immediately on commit, with `poll_interval_s` fallback timeout, draining until empty on each wakeup. Includes `python -m database.outbox.relay` CLI entrypoint handling `SIGINT`/`SIGTERM`.

### Mandatory Feature Unit Tests
- **Test File(s):** `database/tests/test_p1_18_outbox_broker.py`, `database/tests/test_p1_18_relay_concurrency.py`, `database/tests/migrations/test_p1_18_migration.py`
- **Required Test Cases:**
  1. Positive (transactional atomicity): inside `SAVEPOINT` / rolled-back transaction, `enqueue_outbox_event` leaves `0` rows in `outbox_events` and delivers `0` messages on `PgNotifyBroker`; in `@pytest.mark.committed_db`, committing `enqueue_outbox_event(..., topic="issue.created", ...)` wakes `OutboxRelay` via `outbox_wakeup` and delivers the exact `OutboxEnvelope` to a `PgNotifyBroker.subscribe("issue.*")` consumer in `< 200ms`, setting `published_at IS NOT NULL`.
  2. Positive (contract parity across `PgNotifyBroker` & `ValkeyBroker`): shared parametrized test runs `publish` + `subscribe` (`"*"`, `"workflow.gate.*"`, `"notification.created"`, and non-matching `"doc.*"`) against both `PgNotifyBroker` and `ValkeyBroker(FakeValkeyStreamClient)` asserting identical received `OutboxEnvelope` sequences.
  3. Concurrency (`@pytest.mark.committed_db`): enqueue `60` events, run `4` concurrent `OutboxRelay.drain_once(batch_size=10)` workers in parallel via `asyncio.gather` -> `FOR UPDATE SKIP LOCKED` ensures each event is published **at least once and with zero duplicate claims** during active lease (`published_count == 60`, every `outbox_events.published_at IS NOT NULL`).
  4. Poison-pill & retry resilience (`@pytest.mark.committed_db`): broker raises `RuntimeError("transient")` on event A while succeeding on event B in the same batch -> event B is marked `published_at` immediately; advancing `p_now` across `5` failed `drain_once` attempts on event A sets `dead_lettered_at IS NOT NULL`, `attempts = 5`, and subsequent `claim_outbox_batch` calls skip event A cleanly.
  5. Negative/security: `enqueue_outbox_event` with payload `> 7168` bytes raises `OutboxPayloadTooLargeError`; invalid topic `"Issue Created"` or `"singleword"` raises `ValueError` / `23514`; inserting into `outbox_events` as `kanban_app` for another workspace raises `42501` (RLS `WITH CHECK`); KB-P1-14 `test_p1_14_rls_catalog.py` and KB-P1-17 ORM parity tests pass with `OutboxEvent` registered.
  6. Migration up/down: `MigrationHarness` upgrade `p1_18_outbox` -> `outbox_events`, wakeup trigger, and 3 relay functions exist; downgrade to `previous_of(...)` -> absent; re-upgrade succeeds.
