### User Story
As an **autonomous coding agent (Gemini CLI / Claude Code / Codex) connecting over MCP**, I need **three physically separate Streamable HTTP MCP endpoints (`/mcp/agent`, `/mcp/docs`, `/mcp/admin`), each with its own isolated tool registry, that reach data only through an authenticated internal client to `kanban-api`** so that **a tool registered on one surface can never be listed or invoked on another, and the `mcp/` module holds zero database credentials.**

**Requirement Traceability:** `S11.1`, `S2.3` (Streamable HTTP `2025-06-18`), `S2.4` (`mcp-server` on `app_net` only, calls `kanban-api` over internal mTLS HTTP/2), `S2.1` (import-linter `agent -> mcp -> kanban -> database`), requirement `#12`, `#3` | **Dependencies:** `KB-P2-01`

### Scoped Technical Actions
1. **Target Files:**
   - `mcp/app.py` - ASGI factory `create_mcp_app(settings: McpSettings) -> Starlette` mounting exactly 3 sub-apps.
   - `mcp/protocol.py` - minimal in-house MCP Streamable HTTP JSON-RPC 2.0 handler (no third-party MCP SDK; see Action 6).
   - `mcp/registry.py` - `ToolRegistry`, `ToolSpec`, `Surface` enum (`AGENT`, `DOCS`, `ADMIN`).
   - `mcp/errors.py` - `KbMcpError` and the shared error-code enum `McpErrorCode`.
   - `mcp/internal_client.py` - `KanbanApiClient`.
   - `mcp/settings.py` - `McpSettings` (Pydantic v2 `BaseSettings`).
   - `mcp/GEMINI.md` - update module manifest (responsibilities, inbound/outbound contracts, failure modes below).
   - `mcp/tests/conftest.py` - `transcript_recorder` fixture (Action 7).
   - `pyproject.toml` / `mcp/pyproject.toml` / `uv.lock` - add `httpx` + `h2` pinned with hashes.
2. **Three isolated mounts:** `create_mcp_app` mounts `/mcp/agent`, `/mcp/docs`, `/mcp/admin`. Each mount gets its own `ToolRegistry` instance constructed independently (never a shared registry filtered by surface). `ToolRegistry.register(spec)` raises `ValueError` if `spec.surface != registry.surface`. Registries are frozen (`registry.freeze()`) at app startup; `register` after freeze raises `RuntimeError`. This ticket registers one placeholder tool per surface: `ping_agent`, `ping_docs`, `ping_admin` (input schema `{}`; returns YAML `ok: true\nsurface: agent`). Later tickets remove these placeholders.
3. **Streamable HTTP contract (`MCP-Protocol-Version: 2025-06-18`):**
   - `POST <mount>` accepts a single JSON-RPC 2.0 request or notification body (`Content-Type: application/json`, body `<= 1,048,576` bytes else HTTP `413`). JSON-RPC batches (arrays) are rejected with HTTP `400` (batching was removed in `2025-06-18`).
   - Supported methods: `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`. Any other method -> JSON-RPC error `-32601`. Malformed params -> `-32602`. Malformed JSON -> `-32700`.
   - `initialize` returns `protocolVersion: "2025-06-18"`, `capabilities: {tools: {listChanged: false}}`, `serverInfo: {name: "kanban-mcp-<surface>", version: <package version>}` and an `Mcp-Session-Id` response header (`secrets.token_urlsafe(32)`). Subsequent requests without a known `Mcp-Session-Id` -> HTTP `404` (client must re-initialize). `DELETE <mount>` with a valid session id terminates it (`204`).
   - Requests whose `MCP-Protocol-Version` header is present and not `2025-06-18` -> HTTP `400`.
   - `GET <mount>` -> HTTP `405` (server does not offer a standalone SSE stream in Phase 4).
   - `Origin` header validation: if present and not in `McpSettings.allowed_origins` -> HTTP `403` (DNS-rebinding defense required by the Streamable HTTP spec).
   - Sessions are held in `SessionStore` protocol with `InMemorySessionStore` implementation: TTL `3600s` idle, cap `10,000` sessions (oldest evicted), session bound to the authenticated principal fingerprint once auth lands (KB-P4-02 fills the binding; this ticket stores `principal_fingerprint=None`).
   - `tools/call` result format: `{"content": [{"type": "text", "text": "<yaml>"}], "isError": false}`. Tool-level failures return `isError: true` with YAML body `error: {code: <McpErrorCode>, message: ..., hint: ...}` (never a Python traceback).
4. **Shared error codes (`mcp/errors.py`):** `McpErrorCode` string enum containing exactly: `UNAUTHENTICATED`, `SURFACE_KEY_MISMATCH`, `INSUFFICIENT_SCOPE`, `NOT_FOUND`, `AMBIGUOUS_IDENTIFIER`, `VALIDATION_FAILED`, `CONFLICT_ETAG`, `RATE_LIMITED`, `UPSTREAM_UNAVAILABLE`, `UPSTREAM_ERROR`, `INTERNAL`. Later tickets append codes; none may be removed. `KbMcpError.to_yaml()` emits only `code`, `message`, `hint` (hint optional, stripped when empty).
5. **Internal client (`mcp/internal_client.py`):** `KanbanApiClient` wraps `httpx.AsyncClient(http2=True)` with:
   - mTLS: `verify=settings.internal_ca_path`, `cert=(settings.client_cert_path, settings.client_key_path)`; plaintext `http://` base URLs rejected at construction unless `settings.mode == "standalone_inprocess"`, in which case `httpx.ASGITransport(app=kanban_app)` is used (same process, no socket).
   - Timeouts: connect `2.0s`, read `10.0s`, write `10.0s`, pool `2.0s`. Response bodies `> 8 MiB` aborted -> `UPSTREAM_ERROR`.
   - Identity forwarding: every call carries the caller's original credential in `X-KB-Subject-Token` (filled by KB-P4-02) and the MCP session id in `X-KB-MCP-Session`. `mcp/` never asserts a principal id to `kanban-api`; `kanban-api` re-validates the subject token itself.
   - Upstream RFC 7807 problem responses (from KB-P2-01) map: `404 -> NOT_FOUND`, `409 -> CONFLICT_ETAG` when `type` ends in `etag-mismatch` else `VALIDATION_FAILED`, `412 -> CONFLICT_ETAG`, `422 -> VALIDATION_FAILED`, `429 -> RATE_LIMITED`, `5xx`/transport errors -> `UPSTREAM_UNAVAILABLE`.
6. **Dependency decision recorded in `dependency-evaluation.md`:** The official Python MCP SDK (`mcp` on PyPI) is NOT adopted because its import name `mcp` collides with this workspace module directory/package `mcp/`; the in-house handler implements only the 5 methods above. `httpx` + `h2` are added for the internal HTTP/2 mTLS client. Evaluation must include license, pinned version + sha256 hash, alternatives (`aiohttp`, stdlib `urllib`), architect + engineer sign-off.
7. **Transcript fixture (`mcp/tests/conftest.py`):** `transcript_recorder` fixture that, when env `KB_MCP_TRANSCRIPT_PATH` is set, appends every raw HTTP request line, headers, body and the raw response status, headers, body for MCP mounts to that file. `Authorization`, `X-KB-Subject-Token` and any value matching `kb_[a-z_]+_[A-Za-z0-9_-]{20,}` are rewritten to `<prefix>***REDACTED***`. All later MCP tickets reuse this fixture for `mcp-transcript.txt`.
8. **Import boundary:** `mcp/` imports nothing from `database`; it may import `kanban.app` only inside `mcp/app.py` standalone in-process wiring. The import-linter contract from KB-P0-01 must pass; add an explicit forbidden contract `mcp -> database`.

### Mandatory Feature Unit Tests
- **Test File(s):** `mcp/tests/test_protocol.py`, `mcp/tests/test_registry_isolation.py`, `mcp/tests/test_internal_client.py`
- **Required Test Cases:**
  1. Positive: `initialize` on each of the 3 mounts returns `protocolVersion: "2025-06-18"` and a session id; `tools/list` on `/mcp/agent` returns exactly `["ping_agent"]`, on `/mcp/docs` exactly `["ping_docs"]`, on `/mcp/admin` exactly `["ping_admin"]`.
  2. Isolation/security: `tools/call` of `ping_admin` on `/mcp/agent` returns `isError: true` with `code: NOT_FOUND`; registering a `Surface.ADMIN` spec into the agent registry raises `ValueError`; registering after `freeze()` raises `RuntimeError`.
  3. Protocol negatives: JSON-RPC batch array -> `400`; body of `1,048,577` bytes -> `413`; unknown method -> `-32601`; bad JSON -> `-32700`; `MCP-Protocol-Version: 2024-11-05` -> `400`; `GET` -> `405`; disallowed `Origin` -> `403`; unknown `Mcp-Session-Id` -> `404`; `DELETE` then reuse -> `404`.
  4. Boundary: session store evicts the oldest entry when the 10,001st session is created; idle TTL expiry with a frozen clock at `3600s + 1`.
  5. Internal client: `httpx.MockTransport` returns 404/409/412/422/429/503 problem JSON -> each maps to the exact `McpErrorCode` in Action 5; `http://` base URL in `mode="mtls"` raises `ValueError`; a 9 MiB streamed body raises `UPSTREAM_ERROR`; `X-KB-MCP-Session` header present on every outbound request.
  6. Transcript fixture: redaction test asserts a recorded `Authorization: Bearer kb_agt_<43 chars>` is written as `kb_agt_***REDACTED***`.
